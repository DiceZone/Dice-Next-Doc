# 娛樂與互動

輕鬆的日常互動指令，活躍群聊氣氛。

## 指令總覽

| 指令 | 說明 |
|------|------|
| `.jrrp` | 今日人品 |
| `.mrrp` | 明日人品 |
| `.zrrp` | 昨日人品 |
| `.name` | 隨機姓名（別名 `.gn`） |
| `.nnn` | 隨機改名 |
| `.me` | 原文代述 |
| `.ak` | 抉擇分歧 |
| `.sleep` | 休息 |
| `.text` | 文本模板求值 |
| `.alias` / `.&` / `.a` | 群與個人快捷指令 |
| `.rpmode` | 骰娘人格切換 |
| 好感度 | 好感系統（見下） |

## 人品 `.jrrp` / `.mrrp` / `.zrrp`

```
.jrrp              → 今日人品（每人每天固定）
.jrrp on / off     → 群管理开启 / 关闭本群今日人品（持久保存）
.mrrp              → 明日人品（提前看明天）
.zrrp              → 昨日人品（回顾昨天）
```

人品值按「使用者 + 日期」確定性生成，同一天多次查詢結果一致。

## 隨機姓名 `.name` / `.nnn`

```
.name              → 随机一个名字（每个名字随机中/英/日）
.name en 3         → 生成 3 个英文名（cn / en / jp 可选，一次最多 10 个）
.nnn               → 随机起个名字并直接设为你的昵称
.nnn jp            → 指定日文名改名（cn / en / jp 可选）
```

不指定國家時，每個名字都隨機從中文 / 英文 / 日文中選（與原版「隨機姓名」混合牌堆一致）。`.nnn` 與 `.nn` 一樣會同步更名當前繫結的人物卡。

## 動作代述 `.me`

讓骰娘轉述你輸入的正文（跑團常用的「旁白」），不會自動添加發言人名稱：

```
.me 推开了古宅的大门       → 推开了古宅的大门
.me on / off               → 群管理开启 / 关闭本群 .me
```

- 普通使用者與 Master 都按正文代述，不自動拼接人物卡名或暱稱；需要名稱時請自行寫入正文。
- 私聊可遠端代述到指定群：`.me <群号> <动作>`。
- `.me` 可被全域性或本群停用（`.group +禁用me`）。

## 抉擇分歧 `.ak`

把幾個候選方案列出來，讓命運替你選（按視窗儲存）：

```
.ak#走哪条路               → 新建抉择「走哪条路」
.ak+左边的隧道|右边的楼梯   → 添加分支（| 分隔可一次多个）
.ak-2                      → 删除第 2 个分支
.ak show                   → 查看当前分支
.ak=                       → 随机抽取一个（抽完自动清空，同原版）
.ak clr                    → 手动清空
```

新建時也可以一句話寫完：`.ak#标题+选项1|选项2`。

## 休息 `.sleep`

```
.sleep             → 骰子去休息，返回一句休息语
```

## 好感度系統

骰子會記住與你的好感度，並給出稱號（厭惡 / 陌生 / 友好 / 親密 / 摯友 / 戀人）。

```
好感               → 查看你的好感与称号（无需前缀）
好感排行           → 全局好感排行
群内好感排行       → 本群好感排行
```

骰主 / 高信任使用者（信任等級 ≥ 4，見[群管與系統](/zh-hant/use/admin)）可以調控好感，可帶 `@某人` 指定物件：

```
.好感增加 10       → 增加好感（也可写 .favor add 10）
.好感成长          → 按原版 DiceFavor 规则掷一次成长
.好感覆写 50       → 直接覆写好感值（.favor set）
.好感擦除          → 清除全部好感记录（.favor clr）
```

好感越高，自然成長越難（復刻原版 DiceFavor 的成長判定）。

## 文本模板 `.text`

`.text` 會把文本里 `{大括号}` 內的表示式與變數求值後輸出，相容海豹 SealDice 的 `.text`。

開發中的舊版隨機分項相容也支援 `.text {sample:效果拔群|干得漂亮}`，候選項可包含 `.text` 支援的變數或骰式；build 909 及之前尚不支援。

```
.text 看看手气 {1d16}      → 看看手气 7
.text {$t玩家} 掷出 {2d6}   → 变量与掷骰混排
```

## 快捷指令 `.alias`

把常用指令存成一個短名字，相容海豹骰的呼叫習慣。它是**執行指令**，不是把輸入文字原樣回覆，也不是賬號繫結。

```text
.alias 侦查 .ra 侦查        // 在当前群保存快捷指令
.&侦查 60                  // 实际执行 .ra 侦查 60
.a 侦查 60                 // 同上；调用时可在后面追加参数
.alias --my 攻击 .r d20+3   // 保存自己的个人快捷指令
.&攻击                     // 实际执行 .r d20+3
.alias 侦查 .ra 侦查 70     // 同名定义直接覆盖
.alias show                // 列出本群及自己的快捷指令（list 同义）
.alias del 侦查             // 删除群快捷指令（rm 同义）
.alias del --my 攻击        // 删除个人快捷指令
```

- **作用域**：群聊預設儲存本群快捷指令，普通成員也可管理；加 `--my` 儲存個人指令，私聊預設就是個人。`--my` 可放在名稱前後，但引號內的 `"--my"` 保留為目標引數。
- **優先順序**：先找當前機器人賬號的本群條目，再找呼叫者自己的個人條目。群快捷指令不串群、不串機器人賬號；個人指令可跨群、跨私聊使用，跨平臺共享需先完成身份繫結。
- **許可權和開關**：內建、規則包及 JS / Lua 插件目標都按**呼叫者**執行，不繼承建立者的骰主許可權。仍遵守 bot off、徹底停用、黑名單、敏感詞與相應功能/單條指令停用；不能用快捷指令繞過這些限制。
- **限制**：名稱不含空白，最長 80 個 UTF-8 位元組；每個群/個人作用域最多 100 條。目標必須是帶當前有效字首的單條指令，追加引數後最長 4096 個 UTF-8 位元組。不可呼叫其他 `.a` / `.&`；`.bind` 使用專門的驗證資訊保護流程，不能作為目標。改變指令字首後，需同步修改已儲存的目標。
- **結果**：正常回復前顯示實際展開的指令；目標刻意靜默時也保持靜默，不轉而匹配自訂回覆。未安裝或已不可用的插件指令會給出提示，不會執行普通聊天回覆。QQ 官方結構化卡片保持原卡片格式。

定義與呼叫的回執可在[指令列表 → 工具 → 快捷指令](/zh-hant/manage/commands)中改寫，也支援人格、多條候選與權重。舊主副號許可權關聯保留資料，管理入口改為[`.admin account-alias`](/zh-hant/use/admin#許可權體系-信任等級)，不要再用 `.alias add` 管理賬號。

## 骰娘人格切換 `.rpmode`

一套「人格」是對骰娘回覆文案的一組覆蓋。切換人格後，骰子的各種回覆會換成該人格的口吻。人格在後臺[指令列表頁](/zh-hant/manage/commands)建立與編輯。

```
.rpmode                    → 查看当前人格与可用人格列表
.rpmode set 傲娇           → 切换到「傲娇」人格
.rpmode off                → 当前窗口明确关闭人格，使用基础/全局自定义文案
.rpmode default            → 清除当前选择，重新继承适配器或全局默认人格
.rpmode inherit            → 同上，继承适配器或全局默认人格
.rpmode copy 傲娇 温柔      → 从「傲娇」复制出「温柔」人格（Master）
.rpmode del 温柔           → 删除人格（Master，内置人格不可删）
```

群或頻道可以分別選擇人格；切換需要群管理員、邀請人或骰主許可權。QQ 官方機器人不再因暫時讀不到群角色而把所有成員視為管理員；未來平臺提供可信群角色後會沿用同一許可權入口。邀請人可以調整人格、骰子開關等非破壞性群設定，但不能僅憑邀請人身份執行踢人、禁言等平臺管理操作。

普通使用者在私聊中選擇人格時，隻影響自己與當前適配器的私聊，不會修改骰子的全域性人格。可選項由骰主在[指令列表 → 人格開放](/zh-hant/manage/commands)中按機器人賬號設定；未開放的人格不會出現在列表中，也不能用名稱繞過限制。`off` 是當前視窗明確不用任何人格，`default` / `inherit` 則刪除當前覆蓋並繼承適配器或全域性預設。`copy` / `del` 等管理操作仍僅 Master 可用。
