# 關鍵詞自訂回覆

Dice!Next 支援靈活的關鍵詞自動回覆，可在 [Web 管理面板 → 回覆管理](/zh-hant/manage/replies) 視覺化編排。回覆管理頁有三個選項卡：**基礎回覆**、**因果規則**、**計數器**。

聊天裡可用 `.reply on/off` 持久開關本群自訂回覆（群管理或受信任使用者）；也可用 `.group +禁用回复` 關閉（見[群管與系統](/zh-hant/use/admin)）。

## 基礎回覆

### 匹配方式

| 型別 | 說明 |
|------|------|
| 關鍵詞匹配 | 整條訊息與內容**完全相等**才觸發（忽略大小寫） |
| 字首匹配 | 訊息以某字首開頭觸發 |
| 正則匹配 | 正規表示式必須匹配**整條訊息**，可捕獲分組；與舊 Dice 的全匹配方式一致 |
| 搜尋匹配 | 訊息**包含**該內容即觸發（忽略大小寫） |

一條規則支援**多條件 AND / OR** 組合，以及**多結果隨機**（命中後從多條回覆裡隨機選一條傳送），並可設定優先順序。

正則使用忽略大小寫的 ECMAScript 方言，整條匹配不要求手動加 `^` 或 `$`。例如 `白(丽|麗).{0,6}` 僅允許在「白麗／白麗」後跟 0–6 個字元，跟 7 個字元時不觸發。需要字首式觸發可寫 `白(丽|麗).*`，包含式觸發可寫 `.*白(丽|麗).*`。

`.` 預設不匹配換行；需要覆蓋換行時使用 `[\s\S]`，例如 `[\s\S]*白丽[\s\S]*`。空格、製表符和換行都是訊息的一部分，匹配預覽不會自動刪除首尾空白。量詞按 ECMAScript 的 UTF-16 單元計算：常見漢字計 1，許多 emoji 計 2，不等於視覺上的一個字形。

這是 ECMAScript 的 `i` 模式，不是 PCRE，也不自動啟用 `u`、`m`、`s` 等標誌。表示式上限為 400 UTF-8 位元組；匹配仍有輸入、記憶體和執行時間保護，不會因恢復整條匹配而取消安全限制。

此前依賴 Next 開頭式正則、或因果規則區域性正則搜尋的規則，應明確補上允許的前後內容，例如 `abc.*`、`.*abc.*`；程式不會重寫儲存的表示式。舊 Dice 本來按整條訊息匹配的規則無需補 `$` 或重新匯入。

多條回覆可在管理面板為每條單獨填寫權重，並檢視實際抽取機率。例如權重 3 與 1 對應 75% 與 25%；預設權重為 1，範圍 0–999999，0 表示不抽取。整條規則的「觸發機率」與每條回覆的抽取權重分別計算。

舊版 `::数字::` 標記會在匯入或讀取舊資料時轉換為獨立權重，無需重新匯入；無效標記保留原文。正式編輯器已使用獨立權重欄位，回覆文字中的 `::数字::` 將按原文傳送。

### 回覆模板變數

回覆內容裡可以使用 `{…}` 佔位符，傳送時即時替換：

| 變數 | 含義 |
|------|------|
| `{nick}` | 觸發者顯示名（帶包裹符號，包裹符號可在配置中改） |
| `{name}` | 觸發者顯示名（人物卡名 > `.nn` 暱稱 > QQ 暱稱） |
| `{qqnick}` / `{card}` / `{pcname}` | QQ 暱稱 / 群名片 / 人物卡名（乾淨無包裹；加 `w` 字尾如 `{qqnickw}` 則帶包裹） |
| `{user}` | 觸發者賬號 |
| `{self}` | 骰子自稱 |
| `{group}` | 群號 |
| `{date}` / `{time}` | 日期 / 時間 |
| `{FormFeed}` | 強制分頁，將前後內容分成多條訊息；英文大小寫不敏感，不是普通換行 |
| `{$1}` `{$2}` … | 正則捕獲分組；字首匹配時 `{$1}` = 字首之後的內容，`{$0}` = 整條訊息 |

原版 Dice! 風格的舊變數名（如 `{pc}`）也有別名相容，舊回覆文案可直接沿用。

例如 `第一条{FormFeed}第二条` 會發送兩個訊息氣泡。該標記也可用於指令文案、人格、牌堆及 Lua Mod 的模板；可巢狀在 `sample:` 中。顯式分頁不受「長訊息自動分段」開關或平臺的自動分段豁免影響；連續、開頭或末尾的分頁符不會額外發送空訊息。捕獲組和暱稱中包含的 `{FormFeed}` 只作為普通文本，不會再次執行。

### 動態指令

| 寫法 | 效果 |
|------|------|
| `{roll:3d6+2}` | 求值骰子表示式，替換為結果 |
| `{draw:塔罗牌}` | 從牌堆抽一張 |
| `{deck:塔罗牌}` / `{deck:%塔罗牌}` | 顯式引用檔案牌堆；前者在當前回覆內不放回，後者放回，不受本群臨時牌堆覆蓋 |
| `{help:词条}` | 顯式引用幫助詞條 |
| `{text:strHello}` | 顯式引用從舊版 CustomMsg 匯入的全域性文案 |
| `{a\|b\|c}` | 在候選中隨機選一個 |
| `{sample:甲\|乙}` | 舊版 Dice! 隨機分項語法，等機率選一項；開發中，需包含該修復的版本 |
| `{counter:名称}` | 當前計數器值（配合因果規則） |
| `{api:URL}` | 請求一個網址，把返回內容填進回覆 |

舊版資料匯入時，會將無歧義的裸引用規範化為上述顯式字首。`{牌堆}` / `{%牌堆}` 分別轉為 `{deck:牌堆}` / `{deck:%牌堆}`，保留放回規則；幫助、全域性文案分別轉為 `help:`、`text:`。巢狀 `sample:` 的各個分支都會處理，但轉義內容不會改寫，匯入過程中也不會實際抽牌或投骰。

疑似骰子表示式會保留原文並列入待確認項，因為字元形式不能保證求值成功，且舊裸表示式失敗時保留原文，而顯式 `roll:` 失敗時顯示 `?`。確認含義後可以手工新增 `roll:`，匯入器不擅自改變失敗行為。

同名變數、多個資源型別同名及未找到的引用保留原文，列入遷移報告；僅仍有待確認引用的舊回覆保留裸牌堆引用相容，變數含義不會被牌堆覆蓋。新建回覆請使用顯式字首。已經匯入過的舊回覆可以再次匯入原資料；完整定義相同的舊規則會原位升級，不重複新增，並保留骰主調整過的啟停狀態與優先順序。

::: warning {api:URL} 外部請求
`{api:}` 會讓骰子向外部網址發起請求，**預設關閉**。需在[系統設定](/zh-hant/manage/settings)的「外部請求」中開啟。

出於安全考慮，僅允許 http/https，並自動攔截內網 / 本機地址；可在配置檔案中設定允許訪問的域名白名單（`dice.api_whitelist`）。
:::

### 示例

```
触发：天气
回复：今天{a|晴|多云|小雨}，记得带伞～

触发（正则）：^点歌 (.+)$
回复：已为你点播《{$1}》🎵

触发：今日运势
回复：{nick} 的运势：{draw:运势}
```

## 因果規則（進階）

「因果規則」是帶狀態的回覆引擎，比基礎回覆多了**條件門檻**與**動作鏈**，用視覺化編輯器編排：

因果規則的正則條件與基礎回覆一致，必須匹配整條訊息。例如 `\d+` 僅命中純數字訊息；包含數字可寫 `.*\d+.*`。捕獲變數來自真正觸發的條件：OR 使用命中的那個條件，AND 優先使用第一條正則條件，否則使用首個條件。正則條件的 `{$0}` 為整條訊息，`{$1}` 等為捕獲組；字首條件作為捕獲來源時，`{$1}` 為字首之後的內容，`{$0}` 為整條訊息。捕獲到的訊息只作為文本插入，不會再次當作變數、牌堆或擲骰表示式執行。

因果規則沿用共享引擎的長度上限：表示式 4096 UTF-8 位元組，輸入 64 KiB；執行時間和記憶體保護仍生效。

- **條件**：關鍵詞 / 字首 / 正則 / 搜尋之外，還可加 使用者過濾、群過濾、冷卻時間（按人 / 按群 / 全域性）、計數器判斷（如 `打卡次数 ≥ 7`），多條件同樣支援 AND / OR。
- **動作**：傳送回覆（可多條隨機）、計數器 設值 / 累加 / 重置、API 呼叫。
- **作用域**：全域性 / 指定群 / 指定使用者，並可設優先順序與啟停。

配合「計數器」選項卡可以做出打卡、抽獎限次、積分之類的玩法；計數器當前值可在回覆裡用 `{counter:名称}` 引用。

## 插入圖片

回覆內容支援圖片：在管理面板編輯回覆時點「插入圖片」上傳，圖片以平臺中立碼 `[img,file=<本地路径>]` 儲存，傳送時自動轉換成對應平臺的圖片訊息。也可直接寫入 CQ 碼 / 海豹碼（`[CQ:image,file=…]`、`[图片:…]`）。

傳送形式在 系統設定 →「圖片傳送方式」選擇：**base64 內嵌**（預設，QQ 框架跑在任何裝置都能收到）或 **HTTP 連結**（可配主機，需 QQ 框架所在裝置能訪問）。
