# MCP 服務

**管理面板 → 系統設定 → MCP 服務**。這是讓外部 AI 客戶端呼叫 Dice!Next 能力的服務端，與骰娘自身的 AI 對話及工具呼叫設定相互獨立。

::: info 開發版功能
本頁描述 MCP 服務端首版。使用前請確認主程式和 WebUI 都包含該功能；安裝舊版 WebUI 或主程式不會自動獲得介面。
:::

## 可以做什麼

| 工具 | 能力 | 限制 |
| --- | --- | --- |
| `roll_dice` | 使用真實 Dice!Next 數學解析器擲骰，返回結果、各骰出值與過程 | 如 `d100`、`2d6+3`；不執行 OneDice／DiceScript 指令碼、插件或模板 |
| `search_help` | 搜尋已載入的幫助文件 | 返回原文，最多 20 條，長正文截斷；不執行文件中的變數或程式碼 |
| `get_status` | 查詢版本與執行時長 | 不返回金鑰、賬號、連線地址或完整配置 |
| `get_character_card` | 讀取明確授權的人物卡 | 按具體卡片編號授權，遵守鎖讀限制，不求值公式或修改繫結 |

首版**不提供**傳送訊息、修改人物卡、執行任意指令／插件、改設定、重啟或更新程式的工具。幫助和人物卡中的文字是資料，不應被 AI 當作新的操作授權。

## 建立授權

1. 骰主登入面板，開啟 **MCP 服務**。受限管理員不能讀取或修改此頁的授權。
2. 點選 **建立憑據**，填寫應用／使用人標籤，選擇允許的工具與有效期（1–365 天，預設 30 天）。
3. 如需讀取人物卡，搜尋卡名或所屬使用者 ID，明確勾選具體卡片。留空不能獲得“全部人物卡”許可權。
4. 建立後將憑據儲存到 AI 客戶端。**明文只顯示一次**，不會儲存在瀏覽器，服務端僅持久化 SHA-256 摘要；丟失後可重新生成，或撤銷後重新建立。
5. 開啟 **啟用 MCP 服務** 並儲存。建立憑據本身不會開啟服務。

修改工具／卡片範圍、停用、撤銷和過期檢查均在每次請求重新執行，不依賴客戶端是否主動斷開連線。

- **編輯授權**預設保留原到期時間；只有開啟“重新計算有效期”才從儲存時起按所填天數續期，不會悄悄恢復已過期的憑據。
- 在客戶端條目的**更多操作 → 重新生成憑據**中可原地輪換。舊憑據立即失效，新明文只展示一次；工具／卡片範圍、啟用狀態和到期時間均不變。記得更新 AI 客戶端配置。
- 卡片刪除或鎖讀後仍可停用憑據、移除讀卡許可權或撤銷授權。卡片所有者發生變化時不會自動轉移授權：須先移除該卡的授權並儲存，再明確重新選擇。

MCP 專用憑據不能代替 WebUI Cookie、BDC 金鑰或管理 API Key；反過來也不能用這些憑據登入 MCP。

授權列表按**伺服器時間**顯示到期狀態，頁面開啟期間定時更新，並提醒 7 天內到期的條目，不受瀏覽器電腦時鐘偏差影響。不會自動續期，也不會額外發送到期通知。

“最近保留的成功呼叫”只統計當前保留的 5,000 條審計記錄中的成功工具呼叫，不包括初始化、自檢或修改授權。沒有記錄不代表從未使用；審計儲存不可讀時會明確提示，不會冒充“從未使用”。

編輯讀卡授權時，已選卡片會顯示名稱、所屬使用者及當前讀取狀態。刪除與鎖讀統一提示“人物卡不存在或已鎖定讀取”，不猜測具體原因；所屬使用者變化時會提示重新授權。此處只查詢卡片摘要，不返回屬性內容。

### 儲存、超時與恢復

頁面讀取等待上限為 10 秒，修改操作為 20 秒。網路中斷或超時**不代表修改失敗**：頁面會暫停繼續修改，並提供“核對操作狀態”，不會自動重複建立或輪換憑據。

核對狀態後還會重新讀取伺服器上的配置和憑據列表；回讀失敗時繼續保留操作鎖與原編輯內容，不會拿舊列表冒充最新狀態。可稍後再次核對。

- 仍在處理：稍後再次核對，不要重複提交。
- 已儲存但未收到一次性憑據：在列表中找到對應條目，確認後手動“重新生成憑據”；無法重新讀取已丟失的明文。
- 未生效：核對後可重新提交。
- 狀態未知：可能是程式重啟或臨時狀態記錄已清理。先核對當前設定和憑據，不能把“未知”當成失敗。狀態記錄僅臨時保留，最多 128 條，不儲存憑據明文。

配置採用單檔案原子儲存。若提示“修改已生效，但呼叫記錄未能儲存”，許可權變更已經生效，新憑據仍可正常儲存；請檢查 `data/audit` 的寫入許可權與剩餘空間，不要重複執行剛才的操作。

### 從備份恢復後

恢復配置或主資料庫時，**MCP 總開關和舊授權會停用，舊金鑰失效**，防止備份把已經撤銷的金鑰重新帶回。授權名稱、工具和人物卡範圍仍保留，供骰主核對。

1. 開啟 MCP 服務，核對保留下來的授權範圍。
2. 對仍要使用的條目選擇“重新生成憑據”，安全儲存新明文並更新 AI 客戶端。
3. 明確啟用所需授權；已過期的還需要重新計算有效期。
4. 開啟並儲存 MCP 總開關。僅重新開啟總開關或編輯授權，不能讓舊金鑰恢復有效。

僅恢復牌堆、圖片、插件等資源、不覆蓋配置或主資料庫時，不會重置 MCP 授權。Windows 和其他平臺均由核心在啟動時統一應用恢復。配置或資料庫快照寫入失敗時會中止啟動，保留恢復保護標記，修好儲存後重試；不要手動刪除標記來繞過保護。

## 連線客戶端

服務採用 **Streamable HTTP**，介面路徑為 `/mcp`。同伺服器客戶端可使用頁面顯示的 `http://127.0.0.1:端口/mcp`；遠端客戶端應使用可訪問的 HTTPS 地址。反代含路徑字首時，保留該字首。

以下是通用連線引數，不是所有客戶端都通用的配置檔案格式；按客戶端要求填入 URL、傳輸型別與請求頭：

```json
{
  "transport": "streamable-http",
  "url": "http://127.0.0.1:18088/mcp",
  "headers": {
    "Authorization": "Bearer <MCP_TOKEN>"
  }
}
```

無需在骰娘所在機器額外安裝 Node／Python，也不需要把模型 API Key 填入此頁。呼叫端須支援 HTTP MCP 與自訂 Bearer 憑據；僅支援本地 stdio 的客戶端不能直接連線此入口。首版不提供自動 OAuth 登入。

支援 `2026-07-28` 的無會話協議，以及 `2025-11-25`、`2025-06-18` 的初始化相容；不提供舊版 HTTP+SSE 端點或 stdio 啟動方式。協議訊息與請求頭由 MCP 客戶端構造，不需要使用者手寫。

## 本機與遠端訪問

### 本機連線自檢

連線指引中提供 **本機連線自檢**。不填寫憑據時，檢查已儲存的服務開關、審計儲存是否可寫及是否存在可用憑據。可填寫已有的 MCP 憑據，進一步驗證本機協議處理器的初始化和工具列表，並檢查某個工具是否獲准使用。

自檢不建立臨時授權、不執行工具、不連線任意網址；所填憑據僅用於本次檢查，完成後清空，不儲存在瀏覽器、不記錄到日誌，也不回顯到結果。無效、停用、撤銷或過期的憑據統一顯示“憑據被拒絕”；限流或面板請求失敗不會被誤報成憑據無效。

::: warning 自檢通過不等於公網可用
自檢只驗證本機協議邏輯，不驗證監聽埠可達性、公網 DNS、TLS 證書、反向代理或瀏覽器來源。仍需在實際 AI 客戶端測試真實地址；不能用自檢通過替代遠端連線驗證。
:::

### 配置訪問範圍

預設關閉遠端訪問，僅接受迴環連線，拒絕帶代理轉發資訊的請求；同時檢查 `Host`。這是請求級限制，不會更改 WebUI 既有監聽地址。

- 遠端訪問必須主動開啟，並配置精確的 Host 白名單，例如 `dice.example.com` 或 `dice.example.com:8443`。不使用 `*`，不含協議或路徑。
- 公網入口應使用 HTTPS。直接遠端明文請求會被拒絕；本機反代終止 TLS 時，須由骰主確保公網入口只提供 HTTPS，並限制對後端明文埠的訪問。不會因為偽造 `X-Forwarded-Proto` 就信任遠端明文連線。
- 本機反代即使連線來自迴環地址，也應在代理中明確限制 `/mcp`，不要把“本機模式”當成公網訪問控制的替代品。
- 原生客戶端通常不傳送 `Origin`。如瀏覽器客戶端需要跨來源訪問，須另設精確來源，例如 `https://ai.example.com`；預設不允許任何瀏覽器來源，不接受 `null` 或萬用字元，也不使用 Cookie 作為 MCP 鑑權。

主機名忽略大小寫；瀏覽器來源會統一大小寫併合並 HTTP／HTTPS 預設埠（80／443）。這不會放寬子域名或非預設埠限制，例如 `https://ai.example.com:8443` 仍須單獨授權。

管理頁面的跨站防護與 MCP 客戶端來源白名單相互獨立：授權 AI 網頁訪問 `/mcp`，不等於授權它修改骰孃的 MCP 設定。反代請保留瀏覽器的 `Origin`、`Sec-Fetch-Site` 及 `X-Dice-MCP-Request` 請求頭，不要為 `/api/system/mcp` 開放跨來源寫入。原生管理 API Key 呼叫仍可使用 JSON 請求。

## 呼叫記錄與限制

頁面提供服務端分頁的呼叫記錄，持久化保留最近 **5,000 條**。可按客戶端和成功／拒絕／失敗結果組合篩選，條數與分頁均按篩選後的結果計算。點選記錄中的客戶端名稱可檢視該客戶端的歷史，已撤銷的客戶端記錄仍可篩選。記錄授權客戶端、操作、時間和結果，**不儲存憑據、請求引數或人物卡內容**。

每個憑據每分鐘最多 60 個請求，另有連線來源限流。單次請求最多 32 KiB，結果最多 64 KiB；數學表示式最多 256 位元組、16 層括號、1,000 個隨機出值、單骰最多 1,000,000 面，整數溢位會返回錯誤而不是繼續計算。幫助單次最多遍歷 10,000 條／4 MiB 正文，達到上限會明確返回 `search_truncated`。查詢失敗、被撤銷或越權時不會執行其他工具作為回退。

工具與管理請求使用獨立的後臺工作佇列，等待佇列均有上限。繁忙或排隊超過 5 秒返回 `503`，不會繼續堆積並阻塞網頁服務執行緒。每個憑據同時只能有一個排隊或執行中的工具呼叫；其他併發呼叫返回 `429`，未執行工具，可在前一次結束後重試。連線初始化和工具目錄查詢不佔此名額。

工具執行還有 5 秒的協作取消期限，程式退出時也會通知查詢取消；過期或取消後不返回查詢結果。不會強殺 C++ 執行緒；底層暫時無法中斷的系統／資料庫呼叫，需要返回後才能檢查取消狀態。查詢結束後會再次核對授權，期間已撤銷／停用或縮小範圍的結果不會返回給客戶端。

呼叫記錄儲存在 `data/audit/mcp.db`；選擇備份“審計記錄”時，會使用 SQLite 快照包含當前記錄，不需要關閉服務。

常見錯誤：`401` 檢查專用憑據、有效期與啟用狀態；`403` 檢查訪問來源、Host／Origin 和工具／卡片授權；`429` 稍後再試；`503` 檢查繁忙狀態和審計儲存，管理修改應先核對操作狀態；`404` 確認 MCP 總開關、介面地址及客戶端支援的協議／方法。
