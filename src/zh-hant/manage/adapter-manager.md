# 適配器管理

**管理面板 → 平臺連線**，新增、啟停與監控連線。連線狀態每幾秒自動重新整理，無需手動重新整理頁面。

## 新增適配器

QQ 官方機器人已新增後，可前往 **高階回覆 → 卡片與按鈕**，或使用賬號卡片「更多 → 卡片與按鈕」快捷入口，按賬號視覺化編輯單聊選單和指令面板。具體場景、條目限制與關聯操作見 [QQ 官方 API v2 能力](/zh-hant/develop/qq-official-api#視覺化編輯)。

點選「新增連線」，表單為**漸進式引導**：先選連線方式，選定後才出現地址等後續欄位。

支援 OneBot v11、Milky、QQ 官方機器人、Discord、KOOK，以及實驗性的 OpenOPQ 內建登入。先選擇平臺，再按該平臺填寫憑據和端點；下表的連線模式說明針對 OneBot v11，Milky 和內建登入參見下方專節，其他平臺使用各自的連線欄位。

| 欄位 | 說明 |
|------|------|
| 適配器名稱 | 識別用顯示名 |
| 適配器型別 | 按實際平臺選擇；此表以 OneBot v11 為例 |
| 連線模式 | 正向 WebSocket / 反向 WebSocket |
| 連線地址 / 埠 | 正向填端點地址（如 `ws://127.0.0.1:3001`）；反向填本程式監聽的埠 |
| Access Token | 認證令牌（可選），留空則不校驗 |

- 連線模式旁有 **? 幫助圖示**，懸停顯示正向 / 反向的詳細說明；選定後表單內也會顯示對應提示。
- 正向地址會**自動糾正**協議頭（漏寫補 `ws://`，`http/https` 自動轉 `ws/wss`），非法地址與埠有即時校驗提示。

### 傳輸模式說明

| 模式 | 行為 | 框架處配置 |
|------|------|------|
| 正向 WebSocket（`forward_ws`） | 本骰作為 WS 客戶端，**主動連線**登入框架的 OneBot v11 WS 服務端 | 選「WebSocket服務端 / 主動WebSocket / 正向WebSocket」，填框架監聽埠 |
| 反向 WebSocket（`reverse_ws`） | 本骰作為 WS 服務端在本地埠監聽，**等待框架連入** | 選「反向WebSocket / 被動WebSocket / WebSocket客戶端」，填 `ws://本机IP:端口` |

::: tip 區分正向 / 反向
按「誰主動發起連線」區分：正向＝Dice!Next 去連框架；反向＝框架來連 Dice!Next。兩端配置要一一對應。
:::

反向 WS 適配器可點「連線方式」檢視**連線資訊**。地址來自執行 Dice!Next 的伺服器，不是打開面板的電腦：

- **本機**：`127.0.0.1`，只適用於框架與骰子執行在同一臺伺服器。
- **內網**：讀取伺服器的活動 IPv4 網絡卡；多網絡卡、VPN 或容器環境可選擇地址。
- **公網**：後臺通過外部服務查詢伺服器的 IPv4 出口地址，不再複用內網 IP。

程式啟動後後臺預檢測，每 15 分鐘更新快取。開啟彈窗只讀取快取，不重新發起公網檢測；「重新整理地址」可手動檢測。讀取失敗、檢測失敗與檢測中分別提示，重新整理失敗時會明確標記仍在顯示的舊地址；沒有地址時不能複製佔位文字。

公網查詢使用固定的 HTTPS 地址服務：[ipify](https://www.ipify.org/)及 [AWS checkip](https://docs.aws.amazon.com/batch/latest/userguide/create-a-base-security-group.html)。只用於獲知伺服器的出口 IPv4，不上傳配置、帳號或金鑰。系統 `curl` 不可用、網路不通或查詢超時時會提示未獲取，不阻塞程式啟動或訊息收發。

::: warning 公網 IP 不等於埠可達
公網連線仍需確認 NAT／容器埠對映、伺服器防火牆與安全組。地址檢測不會自動開放埠或修改這些設定；內網無 IPv4 或外部查詢不可用時，不影響使用正確的手動地址。
:::

## QQ 官方機器人

選擇 **WebSocket** 或 **Webhook** 接收事件。卡片會直接顯示實際連線方式，點選「連線方式」可檢視連線說明。

- 登入區為方形二維碼，點選下方「手動輸入 AppID 與 AppSecret」可切換為憑據表單。編輯已有賬號時直接顯示憑據，AppSecret 留空表示保留。機器人真實 QQ 號由官方 API 獲取，無需手填。
- 選擇 Webhook 後，表單會按當前面板訪問域名及部署路徑生成回呼地址；新增成功後也會開啟連線資訊，可複製地址到 QQ 開放平臺。例：面板地址為 `https://dice.example/bot/#/adapters`，回呼地址為 `https://dice.example/bot/qq-official/webhook`。反向代理需將該路徑轉發到骰子服務，QQ 必須能從公網訪問它；本機地址僅供本地檢視。同一個 AppID 只配置一個 Webhook 適配器。
- 通過 `127.*`、`localhost`、IP 地址或 HTTP 訪問面板時，會提示 Webhook 的部署要求：回呼伺服器具有公網 IP，域名配置有效 TLS 證書，以公網可訪問的 HTTPS 地址接收事件。已配置反向代理時，從它的 HTTPS 域名打開面板再複製地址；不具備這些條件請選擇 WebSocket。此提示不阻止儲存，也不代表面板已驗證公網可達性。
- WebSocket 由骰子主動連線 QQ，無需配置回呼地址。介面中的 WebSocket 對應配置檔案的 `receiveMode: gateway`，舊配置保持相容。
- QQ 官方 API v2 的部分介面（如群成員列表）只對內邀或白名單應用開放。普通應用呼叫時平臺返回「應用無介面訪問許可權」（錯誤碼 40012010）等無許可權錯誤，這屬於平臺許可權而非故障：程式日誌記為 DEBUG 不再刷屏，相關的暱稱等功能按可用介面降級。預設 INFO 級別看不到這些記錄；排查時可在 WebUI 設定中臨時調低日誌級別。
- 「進階選項」收納 Markdown 圖片資源強校驗、群成員進出事件訂閱、自動回應互動事件、富回覆樣式和快捷操作。**新建**預設 Markdown、訊息按鈕，群成員事件訂閱與自動回應互動事件均開啟；已有賬號編輯時保留原設定。圖片資源強校驗預設關閉。

## Milky 連線

API 填 HTTP / HTTPS 基址，事件使用 WebSocket；事件地址可單獨設定，留空由 API 基址推導 `/event`。當前不支援 Webhook。不要把 OneBot 的端點直接作為 Milky 地址，詳見[Milky 配置](/zh-hant/config/adapter#milky-適配器)。

## 內建登入（OpenOPQ，實驗性）

在「新增連線」中選擇「內建登入」，填寫 QQ 號及有效的 **BDC 骰娘 API Key**。儲存並啟用後，Dice!Next 從中心下載對應系統的協議端，在本機啟動，並在登入彈窗裡展示下載進度、二維碼、線上狀態或失敗原因。兩套 WebUI 均支援。

- 預設正向 WebSocket；埠和連線憑據由程式分配，不必填寫遠端地址。只有協議端支援時才選反向模式。
- 執行檔不隨 Dice!Next 安裝包分發；下載須通過清單簽名、大小和 SHA-256 校驗，中心必須提供當前系統的版本。沒有有效 Key、網路不可達或中心暫未提供該平臺時，會顯示錯誤，不會跳過校驗。
- 當前協議端重啟後需要重新掃碼。登入視窗可重新整理二維碼、取消掃碼或斷開 QQ；「測試連線」只檢查現有實例，不啟動第二份協議端。
- 賬號裝置資料和日誌儲存在 `data/openopq/<适配器ID>/`，執行檔放在 `runtime/openopq/<版本>/`。刪除適配器也會刪除對應賬號的本地裝置資料與日誌。
- 中心拒絕 Key（401 / 403）後停止自動重試，修改 Key 或手動重連後再試；普通 OneBot 適配器不受這套託管邏輯影響。

這是實驗性的第三方協議登入，不是 QQ 官方機器人介面，不保證平臺登入成功或長期穩定。請保護好骰娘 API Key 和本地賬號資料。

## 骰娘雲服務金鑰

適配器的骰娘 API Key 入口保留，與[雲服務 → 骰娘金鑰](/zh-hant/manage/cloud-services#骰娘金鑰)讀寫同一份配置。它不是平臺 Access Token；現有金鑰無需因入口遷移重新填寫。

## 編輯 / 測試 / 刪除

- **編輯**：修改後儲存，適配器會按新配置重連。**適配器平臺型別建立後不可修改**（需換平臺請刪除重建）。
- **測試**：檢查端點是否可達。
- **重連**：手動立即重連。
- **刪除**：移除該適配器。

## 斷線重連與退避

連線斷開後自動重連，採用退避策略：前 10 次每 5 秒重試 → 第 11~20 次每 60 秒重試 → 超過 20 次暫停並顯示「**連線超時**」狀態（區別於「已停用」），此時點「啟用」可手動恢復重連。連線需保持 30 秒以上才重置重試計數，避免「短暫連上又斷」導致無限快速重連。

連線異常時，可在[執行概覽](/zh-hant/manage/dashboard)的最近日誌裡檢視詳細的連線 / 收發資訊排查。
