# 自訂回覆

**管理面板 → 高階回覆 → 自訂回覆**，管理關鍵詞觸發的自動回覆。頁面分三個選項卡：**自訂回覆**、**因果規則**、**計數器**。

## 自訂回覆

### 全域性、平臺與賬號範圍

頁頭統一選擇 **全域性 / 適配器平臺 / 具體機器人賬號**。自訂回覆的列表、新增、編輯、匯入匯出和匹配測試都使用當前選擇；只顯示該範圍自己的規則，不把其他範圍或繼承規則混進可編輯列表。歷史規則預設仍是全域性，不會因切換選框自動遷移。

執行時只匹配適用於訊息所屬渠道的規則。賬號、平臺和全域性規則都可能成為候選，不是切到賬號範圍就整體關閉全域性規則；相同優先順序時賬號優先於平臺、平臺優先於全域性，其餘仍按規則優先順序、條件、機率與限制選擇。戳一戳使用同一頁頭範圍，但其配置採用賬號 > 平臺 > 全域性繼承。因果規則與計數器不因這個選框自動變成分渠道資料。

每條回覆內容下方的**按鈕與狀態條**可以新增、編輯、刪除元件：按鈕分別填寫標題和指令，狀態條分別填寫名稱、當前值和最大值。它們與正文一起儲存為 `[[action:掷骰指令|.r]]`、`[[bar:HP|{hp}|{hpmax}]]` 等原始碼，仍可直接編輯正文。元件會跟隨全域性、平臺或賬號的傳統 / 標準 / 高階視覺方案，不支援富訊息的平臺自動使用純文字形式。公式編輯目前用於[指令與人格文案](/zh-hant/manage/commands#文案中的公式)。

### 回覆列表

| 列 | 說明 |
|---|---|
| 匹配型別 | 關鍵詞 / 字首 / 正則 / 搜尋匹配 |
| 匹配內容 | 觸發文本 |
| 回覆內容 | 命中後的回覆 |
| 優先順序 | 多條匹配時數字越大越優先（預設 100） |
| 狀態 | 啟用 / 停用開關 |
| 操作 | 編輯 / 刪除 |

頂部搜尋框可按匹配內容或回覆內容過濾。

### 新增 / 編輯回覆

點「添加回復」開啟編輯器：

常用的觸發條件與回覆內容直接顯示；啟停、機率、冷卻、每日上限、群 / 使用者限制及優先順序等收在「進階選項」。窄屏預設收起，寬屏預設展開並按網格排列，使用者仍可手動切換。展開後編輯區獨立滾動，儲存 / 放棄按鈕保留在底部，不覆蓋文本。

- **觸發條件**：可新增多個條件，選擇「全部滿足 (AND)」或「任一滿足 (OR)」；每個條件的匹配型別可選關鍵詞 / 字首 / 正則 / 搜尋（訊息包含）。
- **回覆內容**：可新增多條，命中後**按權重隨機選一條**傳送。每條都有獨立的權重輸入框（0–999999，預設 1），並顯示實際抽取機率；權重 0 表示暫不抽取。例如權重 3 和 1 對應 75% 和 25%。至少保留一條非空且權重大於 0 的回覆。舊版 `::5::回复文字` 在匯入或讀取舊資料時自動轉為權重 5，不再需要手寫標記；正式編輯器中的回覆文字按原文儲存。點「插入圖片」上傳圖片，以平臺中立碼 `[img,file=<本地路径>]` 儲存，傳送時按[系統設定的「圖片傳送方式」](/zh-hant/manage/settings)自動轉換；也支援 CQ 碼 / 海豹碼。
- **變數**：`{nick}` 暱稱 · `{user}` QQ · `{group}` 群號 · `{roll:1d100}` 投骰 · `{draw:牌堆}` 抽牌堆 · `{a|b|c}` 隨機選一 · 正則時 `{$1}` 為捕獲組。更多變數見[關鍵詞回覆](/zh-hant/use/reply)。
- **優先順序**：多條規則同時命中時的先後。
- **觸發機率**：決定整條規則是否觸發，與上述「命中後選哪條回覆」的權重不同；例如規則觸發機率 50%、某條回覆佔 25%，該條回覆的總機會為 12.5%。

舊版回覆引用會在匯入時規範化；有歧義的內容不會自動替換。請在「系統設定 → 備份恢復」檢視或下載引用遷移報告，並按用途補上 `deck:` / `help:` / `text:` / `roll:` 字首。詳見[回覆模板變數](/zh-hant/use/reply#動態指令)。

### 戳一戳回覆

點選「新增廣播」左側的「戳一戳回覆」按鈕。它是一個唯一事件觸發器，不需要填寫關鍵詞，也不參與關鍵詞規則的優先順序排序。

- 同樣支援多條帶權重的回覆、變數、圖片、觸發機率、冷卻、每日上限及群 / 使用者範圍限制。
- 使用頁頭的全域性、適配器平臺或具體機器人賬號選擇，不再在彈窗重複選擇範圍；沒有覆蓋配置時繼承上級設定，區域性配置可恢復繼承。
- 舊版單條回覆和「對映指令」繼續保留；對映指令非空時優先執行指令，否則傳送隨機回覆。
- 戳一戳回覆遵守機器人全域性開關和本群的自訂回覆開關。

### 匹配測試

列表下方的「匹配測試」輸入文本，按所選平臺或賬號上下文顯示候選規則與結果；賬號範圍會使用該賬號所屬平臺，不能用其他渠道的結果判斷當前賬號是否配置成功。測試不會向真實群傳送訊息。

### 觸發式廣播

「新增廣播」可設定一條**觸發式廣播**（如活動公告）：

- 廣播**不會主動群發**（防止頻繁發訊息被封號），而是在每個群**下一次觸發任意骰子指令**時附在該指令回覆後自動發出，每個群僅發一次。
- 緩衝區只保留一條待推送廣播；新增 / 替換會覆蓋上一條並重新計數，也可隨時撤銷。上限 200 個漢字。
- 有待推送廣播時頁面頂部顯示橫幅，標註已推送到多少群。

## 因果規則

比自訂回覆更強的「條件 → 動作」引擎，視覺化編輯器支援**從模板開始**（早安問候、每日打卡、限頻抽卡、點歌、專屬回應），點一個套用後改文字即可。

- **當滿足**（條件，可多條 AND/OR）：包含 / 完全等於 / 以…開頭 / 正則匹配（捕獲組可在回覆裡用 `{$1}` 取值）/ 傳送者白名單 / 傳送者黑名單 / 指定群 / 計數器滿足。
- **就執行**（動作，可多條）：回覆訊息（多行隨機選一）/ 計數器加減 / 計數器設為 / 計數器清零 / 呼叫介面（把返回內容存到變數，回覆裡 `{变量名}` 引用；需在系統設定開啟外部請求）。
- **進階設定**：優先順序、冷卻秒數（按每人 / 每群 / 全域性維度計算）。
- **試一試**：輸入一條訊息，即時看這條規則會不會觸發、回覆什麼。

規則列表支援搜尋、啟停開關、編輯與刪除。

## 計數器

檢視、編輯、重置因果規則引擎的**持久化計數器**（如打卡次數）。計數器按「每使用者 / 每群 / 全域性」維度各自獨立儲存，回覆裡用 `{counter:名字}` 引用。
