# 指令列表

**管理面板 → 指令列表**，一處檢視全部指令並**自訂骰孃的回覆文案**，同時管理骰孃的**人格**。

頁面頂部有人格下拉、「人格管理」和「人格開放」按鈕，下方按分類分選項卡展示所有可編輯文本。

## 全域性搜尋

分類選項卡上方的搜尋框對全部分類生效：可按指令名（帶不帶 `.` 都行）、示例、說明、分類、回覆鍵名或當前回覆文本查詢，多個關鍵詞需同時命中。搜尋時列表顯示所有分類中的匹配指令並標註所屬分類，點選分類標籤可清除搜尋並跳到該分類；左側選項卡顯示各分類的命中數。若還有匹配的回覆文本，結果上方會提示數量，點選即可在「全部文本」中檢視。

## 在擲骰回覆中顯示人物卡狀態

編輯一條擲骰文本，在正文下方的**按鈕、狀態條與公式 → 新增狀態條**中填寫名稱、當前值和最大值。預設插入 `[[bar:HP|{hp}|{hpmax}]]`。儲存後，回覆傳送時讀取當前人物卡的生命值和上限；可換為 `[[bar:SAN|{san}|{sanmax}]]`。全域性搜尋“SN”或“狀態條”也能找到入口。

另有獨立的 `.sn` 功能：在 QQ 官方群裡執行 `.sn` 或 `/sn`，之後的回覆頂部會顯示當前人物卡狀態；`.sn off` 關閉自己的狀態行。骰主可在[基礎設定 → 回覆與顯示 → QQ 官方 SN 狀態行](/zh-hant/manage/settings#qq-官方-sn-狀態行)調整外觀或關閉顯示。QQ 官方無法修改真實群名片，因此採用回覆頂部展示。其他支援修改群名片的適配器繼續修改真實群名片。動態狀態條則用於把數值插入你指定的擲骰文案位置，不需要先執行 `.sn`。

## 選項卡

| 選項卡 | 內容 |
|---|---|
| 全部文本 | 所有指令的回覆文案（可逐條自訂） |
| 全部變數 | 文案裡可用的變數說明 |
| 無效文本 | 引用了但已不存在的孤立文案鍵（便於清理） |
| 擲骰 | 表示式擲骰、骰池和擲骰錯誤提示 |
| COC | COC 檢定、理智、技能成長，以及 BRP 檢定與對抗；含成功等級短語 |
| DND | DND 建卡、屬性檢定、先攻與相關規則 |
| 團務 | 跑團日誌、會話和團務操作 |
| 互動 | 牌堆、娛樂、AI 對話和骰娘人格切換 |
| 工具 | 人物卡、屬性管理、暱稱等實用功能 |
| 管理 / 許可權 / 系統 | 群與賬號管理、許可權提示、系統設定及舊版文案相容 |

「全部文本」按 **指令示例 → 描述 → 鍵名 → 當前文本** 展示，每列標題均可點選切換升序 / 降序，窄屏卡片模式也提供排序選項。頂部的全域性搜尋同樣作用於此表，可同時匹配指令示例、功能描述、原版鍵名和當前文本，並可按功能分類篩選。沒有固定指令的自動事件與共用提示會明確標註，不生成不存在的指令。

各功能分組也可直接展開編輯相應文案，例如「COC → 檢定結果等級」可修改大成功、極難、困難、普通成功、失敗和大失敗。BRP 保留獨立的功能條目與結果文案，但與 COC 共用選項卡。人物卡功能歸入「工具」，牌堆、娛樂與 AI 歸入「互動」。匯入或擴展帶來的未知文案仍保留在「全部文本」中，標為未歸類；但獨立的 `help.topic.*` 自訂幫助已歸入[幫助文件](/zh-hant/manage/help-docs)，不應作為無效文案清理。關聯指令的用法文本及人格層的幫助文本編輯不受影響。

每條文本右側的 `编辑` 可改寫；被改過的條目會標一個 `●`，可一鍵**還原**為預設文案。「系統 → 舊版文案相容」也收錄 `.strSelfName` / `.strSelfCall` 的回執；名稱與自稱本身仍使用專用配置，不改成普通模板覆蓋。

「工具 → 快捷指令」收錄 `.alias` / `.&` / `.a` 的管理回執、列表和呼叫結果字首；標題旁的問號可檢視完整用法。文案專屬變數包括 `{shortcut}`（快捷名稱）、`{source}`（群/個人）、`{command}`（展開後的目標指令）、`{list}`（列表），預覽使用本語言的示例值，不執行目標。呼叫字首與正文自動分行；可以把字首設為空以隱藏它，但不會改變目標邏輯或開關。舊賬號許可權關聯的回執仍在「許可權 → 賬號別名」，對應 `.admin account-alias`，不會被新快捷指令文案覆蓋。

## 自訂回覆文案

骰子幾乎所有回覆（擲骰結果、檢定成功 / 失敗、各種提示）都以模板文本儲存，可在此改寫口吻。點選條目的「編輯」開啟編輯彈窗：

- **寬屏**：左側編輯，右側即時預覽，兩欄各自滾動，修改時隨時能看到預期回覆。
- **窄屏**：頂部用「編輯 / 預期回覆示例」切換。
- 儲存、放棄與「載入預設」固定在底部。

### 擲骰理由與文案繼承

普通單輪迴復 `dice.roll.result` 與帶理由回覆 `dice.roll.result_reason` 可分別設定。未單獨設定帶理由回覆時，繼承當前人格或全域性自訂的普通單輪文案；兩者都未設定時使用原有內建文案。多輪同理，`dice.roll.multi_reason` 繼承已自訂的 `dice.roll.multi`。顯式儲存的空白回覆仍表示不輸出。

例如輸入 `.r 5-\(-1\)` 含有反斜槓，不是合法的算術表示式；舊版相容邏輯將其視為預設骰的理由，它也應遵守上述文案繼承。計算減去負數請使用 `.r 5-(-1)`，結果為 `6`。

### 編輯與格式工具欄

文本框上方是 Markdown 格式工具欄：**粗體、斜體、刪除線、行內程式碼、標題、引用、無序列表、有序列表、分割線、連結**。選中文字點一下即可套用，再點一次取消；沒有選中時會插入一段可直接改寫的示例文字。粗體和斜體也可用 Ctrl/⌘+B、Ctrl/⌘+I。

- 跨多行的選擇按行分別套用，因為 QQ、Discord、KOOK 的行內格式都不能跨行。
- 普通文字後面加列表時，會自動補上 QQ 要求的空行。
- 分割線 `***` 只有 QQ 官方會顯示，Discord 與 KOOK 會顯示為原文。
- QQ 官方 Markdown 支援標題、粗體 / 斜體 / 刪除線、連結、圖片、列表、引用和分割線，不支援表格與程式碼塊，內建預設也只用這些寫法。

工具欄只在原稿上加減標記，`{变量}`、`[[按钮]]`、`{sample:…}` 等模板語法始終保持你看到的樣子，不會被改寫或轉義。

變數與插圖按鈕緊貼在文本框下方：

- 指令專屬變數以淺色 chip 展示，點選插入到游標處；
- 通用變數用「插入全域性變數」插入，如 `{nick}`、`{user}` 等；
- `{FormFeed}` 是舊版相容的強制分頁標記，不是暱稱一類的顯示值，預覽會按實際訊息分開展示。

按鈕、狀態條與公式都寫在同一份模板裡，可以在正文下方分別新增、編輯、刪除，也可以直接修改原始碼，修改正文後仍保留。

### 內容格式

**新編輯的文案預設使用 Markdown**。QQ 官方機器人、Discord、KOOK 等平臺按富文本傳送；OneBot 等純文本平臺自動使用儲存時生成的純文字版本，保留可見文字、CQ 碼和骰子表示式。

**純文本**用於舊版文案、插件回覆和歷史人格文案：`**`、`#`、`>` 等字元原樣傳送。已儲存為純文本的條目，編輯時頂部會提示，並提供「轉為 Markdown」：

- 服務端只為 `{变量}`、`[[按钮]]` 之外真正會觸發格式的字元加上轉義，玩家看到的文字不變；
- 轉換後格式工具欄即可使用。

**從舊版遷移時不必逐條修改**：在指令列表右上角「更多 → 全部轉為 Markdown」中，按當前語言與當前編輯的層（全域性或某個人格）批次轉換。轉換前先顯示數量以及其中需要加轉義的條數，確認後才寫入。

格式選擇收在「進階選項」裡，預設收起，同時顯示這一條的預設文案。

暱稱、理由等動態值仍會在服務端轉義，避免玩家輸入改變模板排版。等級短語（如「COC → 檢定結果等級」中的失敗）、心理學回執、好感稱號等本身也是文案：

- 儲存為 Markdown 時，代入檢定結果後保留自己的樣式，純文本平臺只顯示文字；
- 儲存為純文本時，`**` 等字元按原文顯示；
- 編輯預覽與實際回覆按同一規則處理。

你只需編輯這一份 Markdown 原稿。儲存時服務端會同步重建純文字版本：內建模板在啟動 / 過載時生成，人格模板在載入時生成。兩種版本保留相同的 `{变量}`，等真正回覆時才代入實際值，所以切換展示形式不需要逐條重存。

### 載入預設

底部的「載入預設」選單用於選擇編輯起點：

- **傳統 / 標準 / 高階視覺**：把該顯示方案的完整內建文案、按鈕和狀態條放進當前這一條回覆。有內容時會先確認，其他隨機回覆和權重保留；儲存後生效。賬號單獨採用另一套顯示方案時，可在這裡載入相應預設。
- **清除自訂（跟隨預設）**：刪除已儲存的自訂文案，回覆重新跟隨全域性顯示方案。按結果分級的條目顯示為「恢復繼承」。

載入預設只改變編輯框內容，不會修改全域性或賬號的顯示方案；已有自訂文案不會被自動替換。高階視覺預設使用粗體標題與引用塊排版，不含 emoji。

### 即時預覽

預覽區提供：

- **平臺選擇**：QQ 官方群聊、C2C 與頻道分別選擇，另有 KOOK、Discord、OneBot / Milky / 純文本；頻道不會預覽成 QQ Markdown。
- **方案選擇**：傳統、標準、高階視覺，並可模擬 `.bot text plain`。這些選擇只用於預覽，不修改已儲存的全域性 / 賬號配置。
- **文字示意 / 傳輸結構**：後端使用實際的文本 / 卡片序列化器。公式使用受限的本地數學渲染展示，不是 QQ 客戶端截圖；不模擬 CQ / 媒體上傳、身份對映或平臺許可權。介面不可用時顯示錯誤，不以原文冒充降級結果。

模板變數會用示例值代入預覽；這隻用於檢視排版，不會執行真實骰點，也不會發送訊息。

::: tip 切換整套展示方案
到 **系統設定 → 回覆與顯示 → 回覆文案與視覺方案** 可選擇傳統、標準或高階視覺文案；也可以只覆蓋某個平臺或賬號。人格繼續控制口吻，展示方案只控制排版與互動。
:::

> 改寫文案不會改變指令邏輯，只改變對外措辭。想給不同場景多套口吻，請用下面的「人格」。

## 按檢定結果設定完整回覆

在「COC → 按結果分級的標準回覆」中，可分別設定大成功、極難成功、困難成功、成功、失敗和大失敗的**完整回覆**，而不只是末尾的等級短語。另有 BRP 用的「特殊成功」與對抗用的「平局」。

其他檢定的功能條目中也有對應等級，可單獨開啟「單獨設定此等級回覆」。繼承順序為：

```text
本类检定的该等级回复 → 标准检定的同等级回复 → 此指令原有文案
```

未設定的等級保持繼承，不會自動複製一份固定文本。點選「恢復繼承」只刪除當前編輯層的覆蓋；編輯人格時，人格沒有設定的同名項先繼承全域性同名項。介面會顯示當前來源，並預覽繼承的文本。

| 檢定 | 可單獨設定的結果 |
| --- | --- |
| COC `.ra/.rc/.rad`，含暗檢定 | 六個 COC 等級；暗檢定的詳細回覆仍只發私聊 |
| 獎勵 / 懲罰 `.rb/.rp`、`.rab/.rap`、`.ra b/p` | 各自六個等級；無技能 / 成功率的純獎勵、懲罰骰不判成功失敗 |
| BRP `.ba` | 大成功、特殊成功、成功、失敗、大失敗，不把特殊成功冒充 COC 極難成功 |
| SAN `.sc`（含獎勵 / 懲罰） | 六個 COC 等級；僅改變文字，損失與人物卡扣減照常進行 |
| 成長 `.en` | 成功 / 失敗，按成長的高骰判定，不套用 COC 的低骰成功規則 |
| 心理學暗骰 `.rx` | 六個等級的私聊詳細結果，群回執仍不透露結果 |
| 對抗 `.rav/.rcv` | 第一方勝 / 負 / 平局，分別使用成功 / 失敗 / 平局回覆 |
| BRP 抵抗 `.bav` | 主動方成功 / 失敗 |
| DND `.rdc` | 指定目標難度後判成功 / 失敗；不指定難度的 `.rdc` 與 DND `.rc` 保持普通結果 |
| 死亡豁免 `.ds` | 自然 20（大成功）、成功、失敗、自然 1（大失敗）；穩定 / 死亡狀態提示仍保留 |

普通 `.r`、WOD 成功數骰池和雙十字點數沒有整體目標值，不會強行歸入成功 / 失敗。連續檢定逐次選擇對應等級，不用第一骰的結果替代整條指令；沒有配置任何結果回覆時，保留原來的輸出組織方式。

每個等級都可使用原生多條回覆、權重、人格覆蓋及巢狀 `{sample:…}`。例如獎勵骰「成功」可設定：

```text
**{nick}** 的奖励骰检定：`{roll}/{rate}` **{level}**
{sample:好运站在你这边|这次抓住了机会}
```

通用變數包括 `{nick}`、`{attr}`、`{reason}`、`{roll}`、`{rate}`、`{level}`、`{res}`、`{result}`、`{outcome}`。`{result}` 是純數字判定值；`{roll}` 是擲骰詳情；`{res}` 保留所屬指令原有含義。SAN 的 `{loss}/{final}`、成長的 `{change}/{final}` 等只在相應功能的編輯器中提供，不能放進跨指令共用的標準等級回覆。自訂完整回覆若要展示理由，應自行保留 `{reason}`。

預覽使用所選等級的示例值，不執行真實骰點，也不傳送訊息。繼承「指令原有文案」時，預覽展示代表模板；實際仍根據理由、理智損失、成長是否變化等選擇原有變體。

既有全域性 / 人格文案及舊版匯入項不會因為新增結果槽位而被覆蓋；新槽位預設留空。不過這不代表舊版所有文案宏都已相容，詳見[舊版文案遷移邊界](/zh-hant/guide/migration#自訂文案與幫助)。

## 舊版檢定文本相容

「COC → 舊版檢定文本相容」分別提供單輪等級短句與檢定字首；SAN 和成長條目內還有各自的舊版模板。**內建相容預設值不自動啟用**，儲存覆蓋或遷入舊文案後才使用，優先順序為：

```text
本类等级完整回复 → 标准同等级完整回复 → 已设置的原生指令模板 → 已启用的旧版兼容模板 → 原生默认模板
```

舊版單輪短句隻影響等級文字，多輪仍用原來的共享等級短句；普通原生模板中的 `{level}` 也會採用已設定的對應短句。連續多輪採用舊字首時，只在第一條相容輸出前插入一次。暗檢定仍只向私聊傳送結果，群內保留簡短回執。

純文案條件宏支援巢狀：

```text
{grade:rank?2={strSuccess}&1={strFailure}&0={strFumble}}
{case:loss?0=没有理智损失&else=理智减少{change}，剩余{final}}
{sample:今天精神不错|{case:loss?0=松了口气&else=保持冷静}}
```

`case` 以欄位字串精確匹配，`grade` 選取不超過欄位值的最大數值閾值；可用 `else=` 指定未命中分支。條件本身只選擇文本，不執行指令碼、網路請求或檔案操作。

也可使用 `{var:本次={ran:1~100}}{本次}`、`{len:nick}`、`{len:game.pls}`、`{expired:时间戳字段}`、`{at:}`、`{print:uid}` 等安全函式，欄位以當前入口可用上下文為準。`len` 對文本按 UTF-8 位元組計數，對當前團的玩家 / GM 集合返回人數；`print` 只讀取當前賬號快取中的名稱，快取缺失時保留 ID。

`{wait:1000}` 請求延後最終回覆一秒，不阻塞收訊息；預覽只移除這段控制語法，不實際等待。每條回覆最多等待十分鐘，佇列有數量和大小上限；停用、黑名單、斷線、插件過載或程式重啟可能取消尚未傳送的回覆。它不會延後指令已經執行的管理操作。完整語法與邊界見[安全文本函式](/zh-hant/develop/lua-mod#安全文本函式)。

舊版 SAN 槽中，`{res}` 是「擲骰詳情 / SAN」，`{rank}` 依次為大失敗 0、失敗 1、成功 2、困難 3、極難 4、大成功 5；`{change}` 是同一次理智損失擲骰的詳情，`{loss}/{final}` 是實際損失和剩餘理智。這些舊含義只適用於相容槽，**不會改變新 SAN 等級回覆中 `{res}` 的數字含義**。成長相容槽中的 `{res}` 保留舊版擲骰、技能值和等級描述。

`{strEnRoll}` 等已對映引用會在當前語言、人格下解析，也可明確寫成 `{text:dice.compat.growth.base}`。引用保留動態關係，不復制固定文案；被引用的多條機率回覆和巢狀 sample 仍在每次輸出時選擇。迴圈或過深引用有上限，不能把玩家暱稱或理由中的內容當作宏再執行。

編輯器預覽使用同一後端解析器，當前語言和人格也帶入引用解析；繼承舊槽時會按對應舊變數含義展示。模板解析及 Markdown / 純文本轉換仍在載入、儲存時快取。匯入或歷史修復報告見「備份與匯入」，詳見[遷移邊界](/zh-hant/guide/migration#自訂文案與幫助)。

## 狀態條與操作提示元件

內建文案、人格文案和高階回覆共用兩種語義元件。編輯器可直接插入示例，再把數值或文字替換成當前文案支援的變數：

```text
[[bar:HP|{hp}|{hpmax}]]
[[action:掷骰指令|.r]]
```

按鈕編輯區可分別填寫按鈕文字和填入的指令。QQ 標題最多 10 個字元，長標題會精簡；指令引數不截斷。指令模板支援當前回覆的變數，例如檢定文案可以用 `[[action:再次检定|{command}]]` 保留原來的指令、修正與原因。

元件不是某個平臺的 Markdown 片段。Dice!Next 會在變數替換後按當前展示方案渲染：傳統方案保留簡潔資料，標準方案使用常規強調，高階視覺方案生成字元狀態條與操作提示。QQ 官方在具備 Markdown 與互動許可權時，會把操作提示渲染成指令輸入快捷項，點選後先填入點選者自己的輸入框，不會立即執行；OneBot、Milky 或富訊息失敗時仍傳送 `.r // 掷骰指令` 這類可讀文字，不會自動生成圖片。

高階視覺方案還會識別內建用法中的 `.指令 // 说明` 行。例如 `.bot on/off` 會分別生成 `on` 和 `off` 兩個待選項，含 `<名字>`、`[参数]` 的用法會把游標停在待填寫的位置。按鈕只是幫助填寫，最終仍由使用者確認傳送，原有許可權檢查不會繞過。

### 文案中的公式

指令文案與人格文案另有「新增公式」：左側填寫不帶 `$` 的 TeX，右側填寫普通文本替代文字。例如在檢定結果中：

```text
[[math:\textcolor{#E5484D}{\frac{ {{roll}} }{ {{rate}} }}|{roll}/{rate}]]
```

公式中的模板變數使用雙花括號 `{{roll}}`，以區別於 TeX 的分組花括號；右側替代文字仍使用 `{roll}`。變數值由程式轉義為公式中的數值或文字，玩家暱稱不會變成 TeX 命令。公式不重新擲骰，只展示這次檢定已有的資料。欄位內的豎線使用 `\vert`，不要使用元件的 `|` 分隔符或 `]]` 結束標記。

支援公式的 Markdown 展示使用左側公式；傳統方案、強制純文本和純文本平臺使用右側文字。編輯器可以切換平臺與純文本模式檢查兩種效果。QQ 公式支援範圍以平臺實際能力為準，本地預覽不執行公式中的 HTML、外部連結或圖片。

## 隨機文案 `{sample:…}`

2026-10-19 的本地相容補齊增加了模板區域性變數與小型函式，尚需隨安裝包釋出。例如：

```text
{var:今日签={ran:1~100}}{nick} 抽到 {今日签} 号，再次引用还是 {今日签} 号。
```

`{var:名?值}` 同時顯示賦值結果，`{var:名=值&另一名=值}` 只儲存本次渲染的區域性變數；不會寫入人物卡或系統設定。可以與巢狀 sample、case、grade 混用。

`{ran:下限~上限}` 是與遊戲擲骰獨立的整數隨機數，含上下界；`{len:字段}` 返回 UTF-8 文本位元組數，`{expired:字段}` 檢查 Unix 時間是否過期。`{at:}` 提及當前使用者，`{at:账号}` 提及指定賬號，`{at:self}` 提及當前機器人，統一輸出平臺可轉換的 CQ 提及段；非法目標不會生成訊息段。`{print:uid}` / `{print:gid}` 顯示當前身份，顯式指定賬號時不額外聯網查詢名字。

當前上下文還可讀取 `uid`、`gid`、`selfId`、`user.trust`、`user.favor`，以及未鎖讀的本人人物卡數值 `char.属性`。`list_all_deck` 等目錄變數適合編寫自動更新的使用說明，詳見[Lua mod 的自動目錄](/zh-hant/develop/lua-mod#自動目錄)。預覽使用同一後端解析器，但只帶入示例資料，不列舉真實群成員或私有目錄。

舊版 Dice! 的隨機分項語法已隨後續 Release 釋出，beta.925 包含；build 909 及之前不支援。可在擲骰回覆或人格文案中直接填寫，例如編輯 `dice.roll.result`，保留原有變數並追加：

```text
{nick} 掷骰：{res}
{sample:效果拔群|干得漂亮}
```

每次渲染按分項等機率抽取一項，`sample:` 不會出現在結果中。不改變骰點或檢定規則。候選項可以引用該文案原本支援的變數，也可巢狀：

```text
{sample:本次结果是 {res}|{sample:效果拔群|干得漂亮}}
```

支援純文本和顯式 Markdown 文案；只會處理被選中的分項。各項用半形 `|` 分隔，巢狀大括號內部的分隔符不拆成外層候選。自訂回覆原有 `{甲|乙}` 簡寫保留；擲骰與人格文案請使用明確的 `{sample:甲|乙}`。

## 原生多條機率文案（已釋出，build 926）

編輯擲骰回覆或人格條目時，可用「添加回復」「刪除此條」管理多個候選。每條單獨填寫正文和整數權重，旁邊顯示實際機率：權重 1、3 對應 25%、75%；0 暫停該條，至少一條必須大於 0。最多 256 條，候選正文合計最多 64 KiB。

每次只抽取一條候選，換行只是該條內部的換行。插入變數和格式工具欄針對當前候選；整個回覆鍵使用同一種輸出格式。

舊版 {sample:甲|乙} 不需改寫。完整外層 sample 可通過「將外層 sample 轉為等機率多條回覆」展開，再調整各條權重；句子中間或內層 sample 不會被誤拆。原生候選內也可繼續巢狀 sample，例如選擇 Markdown 格式，填寫：

```text
**{nick}** 掷骰：`{res}`
{sample:效果拔群|{sample:干得漂亮|再接再厉}}
```

普通擲骰結果的 {res} 包含表示式與結果；各回復鍵只能使用編輯器列出的變數，不能把預覽示例中的其他變數當作任意指令都支援的變數。

預覽先按候選權重抽取，再解析其中的 sample，最後代入示例變數。點選「重新抽取預覽」可檢視另一個隨機結果；一次預覽的各傳輸表示共享同一次抽取。不傳送真實訊息，也不消耗遊戲骰點。

儲存時快取每條候選的 Markdown / 純文本版本，不在每次傳送時重新轉換整套文案。複製人格、匯入匯出和重啟保留文本、權重及格式。需要同時升級本體與 WebUI；新版前端會拒絕向不支援的舊後端儲存原生機率文案。

## 骰娘人格

一套**人格**是對上述回覆文案的一組覆蓋。啟用人格時，人格中的同名條目優先於「預設（全域性）」文案；人格沒有改寫的條目仍會回退到全域性自訂文案或內建文案。切到某個人格後編輯文案，改動只儲存到該人格；群或頻道內用 [`.rpmode`](/zh-hant/use/fun) 切換人格即可整體換一套口吻。

- **人格下拉**：選「預設（全域性）」編輯全域性文案，或選某人格編輯其專屬覆蓋。選中人格時頁面會提示「正在編輯人格『…』」。
- **人格管理**（按鈕）：新建 / 複製 / 重新命名 / 刪除人格，或設為全域性預設。內建人格不可刪除。群詳情的「功能管理」可以讓單個群繼承適配器或全域性預設、明確關閉人格，或選用自己的覆蓋人格。

點選本頁頂部的「人格開放」，先選擇機器人賬號，再指定該賬號的預設人格，以及使用者通過 `.rpmode` 能看到和選擇的人格範圍：全部人格、僅選中的人格或禁止使用者切換。選擇「僅選中的人格」後，勾選要開放的人格並儲存。設定按機器人賬號分別儲存；頂部用於編輯文案的人格下拉不會改變這裡的賬號設定。

賬號預設人格與使用者開放列表彼此獨立，因此可以讓機器人固定使用某個人格，同時只開放少量同角色人格，避免另一個機器人的角色意外出現在列表中。開放列表不會授予額外操作許可權：群內切換仍需要群管理員、邀請人或骰主許可權，私聊切換隻影響當前使用者。骰主仍可在後臺為群繫結任意人格。編輯平臺連線資訊不會覆蓋這裡的設定。

聊天側對應指令見[娛樂與互動 → 骰娘人格切換](/zh-hant/use/fun)。

### 隨機多人格（已釋出，build 926）

在「人格管理」開啟「隨機多人格」，啟用多個候選人格，分別設定權重，再點選「儲存人格機率」。基礎回覆也可作為候選，機率計算與原生多條文案相同。

一次指令先抽取一個人格，整個回覆使用同一個人格；再由各回復鍵抽取文案和內層 sample。未改寫的鍵仍回退到全域性文案或內建文案。人格與文案抽取不使用遊戲骰點隨機源。

優先順序保持為：私聊個人 / 群聊明確選擇 → 賬號預設人格 → 全域性隨機池 → 全域性單人格。明確關閉人格仍然有效；.rpmode inherit 或群詳情的「繼承」可重新使用賬號 / 全域性策略。.rpmode 查詢狀態時顯示隨機多人格，不額外抽取。

配置重啟後保留。切回單人格會清空全域性隨機池；刪除人格時從池中移除，若最後一個正權重候選被刪除，恢復單人格 / 基礎回覆，不保留全零機率池。
