# 基礎設定

**管理面板 → 系統設定 → 基礎設定**，配置骰主、指令、審批、圖片與回覆行為。面板自身的登入密碼、埠等在同組的 [WebUI 設定](#webui-設定頁) 管理。

骰娘金鑰、心跳、雲黑名單、雲人物卡及日誌站統一在[雲服務](/zh-hant/manage/cloud-services)管理；圖床仍在本頁。

外部 AI 客戶端的連線、獨立憑據、工具許可權和呼叫記錄在同組的 [MCP 服務](/zh-hant/manage/mcp)管理，預設關閉。

## 檢測與自動更新

**管理面板 → 關於專案 → 檢測與自動更新**集中顯示當前版本、最新 Release、平臺安裝包、下載來源與更新階段，並提供檢查、下載、安裝及自動策略設定。

也可點選右上角的版本文字直達更新區域。Beta 版本顯示為 `beta-3.0.0(123)`，正式構建為 `v3.0.0(123)`；發現新版本時旁邊顯示紅色 **New**。側欄不再展示固定版本號，頂欄不再使用“已連線”徽章代替版本資訊。編譯時間按 **UTC+8** 顯示並明確標註，不跟隨瀏覽器本地時區。

- 預設每 6 小時檢查一次，發現新版本時**僅通知**，不會擅自下載或重啟。
- 選擇“自動安裝並重啟”後，可開啟**定時安裝**，預設每天 **04:00**。程式先下載並校驗，安排到下載完成後的下一次設定時間；當天時間已過則安排到次日。使用**基礎設定中的伺服器時區**，不是瀏覽器時區，面板會顯示完整安裝日期、時間與 UTC 偏移。
- **定時只決定程式何時主動重啟**。自動安裝策略開啟且包已就緒時，任何提前發生的重新啟動都會順帶安裝，包括面板重啟、退出後重新開啟、系統重啟及守護程序拉起；不必等到定時視窗。僅下載 / 僅通知策略不會在啟動時安裝。
- 計劃與暫存包持久化。程式每分鐘檢查一次主動重啟計劃，更新操作進行中時會先完成。修改時間或伺服器時區會重新安排；關閉定時只取消主動重啟計劃，已授權更新仍會在下一次啟動時安裝。若要同時禁止啟動時安裝，應將策略改成“僅下載”或“僅通知”。關閉自動檢查只停止尋找新版本，不取消已有計劃。也可直接點選“安裝並重啟”。
- 發現新版本時會通過通知系統傳送“發現新版本”；自動下載 / 安裝成功傳送“更新結果”，失敗傳送“更新失敗”。同一 Release 只提醒一次。已有通知視窗若逐項篩選事件，需要在通知設定中額外勾選這三個新增事件。
- 下載來源可選：自動選擇、僅 GitHub、僅內建映像、自訂映像。自動模式並行探測 GitHub 直連與內建映像，使用最先成功且清單有效的來源，並短期快取可用來源。
- 下載期間可點**取消下載**，等待“已取消”後再次下載；連線、下載、校驗和準備階段可取消，正式安裝不可取消。連續 60 秒沒有新增資料或單個來源嘗試達到 20 分鐘時會停止本次傳輸，並按配置嘗試其他來源；所有來源失敗後顯示錯誤，可重試，不需要重啟程式。
- 前端請求超時不表示後臺已停止。頁面會重新獲取狀態後才開放下一步操作；狀態暫不確定時可以重新整理狀態，不應重複點選下載或安裝。
- Release 安裝包只使用 GitHub 不會改寫的安全檔名；更新器也相容歷史清單中圓括號被 GitHub 規範化為點號的安裝包名。下載失敗會同時顯示 HTTP 狀態和 curl 退出碼，便於區分檔案不存在與網路故障。
- 完整包的管理器模式支援“安裝並重啟”與可選定時自動安裝：Windows 使用 `dice-next.exe`，包含 POSIX 管理器的新 Linux/macOS 包使用 `start.sh` 或 `dice-next`。beta.928 及更早的 Linux/macOS 包需先手動完整升級一次；該能力待新包釋出。直接執行核心僅檢測、下載。容器內只保留檢查和新版本通知，下載與安裝由服務端拒絕；請更新映像後重新建立容器。
- 下載會核對 Release 清單中的檔案大小和 SHA-256，並在解壓前攔截絕對路徑與目錄穿越；Windows 替換失敗會自動恢復舊程式。`config/`、資料庫和使用者檔案不會進入替換清單，未與內建檔案同路徑的第三方插件也會保留。
- SHA-256 是損壞 / 一致性校驗，不是獨立發行簽名。使用映像（尤其自訂映像）等同信任該來源；不確定時請選擇“僅 GitHub”並保持“僅通知”。

完整升級流程見[安裝部署 → 升級](/zh-hant/guide/install#升級)，介面欄位見[API 參考 → 更新介面](/zh-hant/develop/api#更新介面)。

## Master（骰主）

新增 / 移除骰主賬號（支援多個、按平臺區分）。骰主擁有最高許可權，可使用遠端開關、黑白名單等管理指令。

## QQ 郵箱繫結驗證

在本頁配置專用 SMTP 並啟用，供 QQ 官方、Discord、KOOK 使用者在私聊中驗證 QQ號@qq.com。
填寫伺服器、埠、賬號、密碼或授權碼與發件郵箱；465 通常使用隱式 TLS，587 使用強制 STARTTLS。
密碼儲存後不回顯，留空編輯保留原值。不接受任意收件郵箱，也不用於群歸屬驗證。
此配置為全域性設定，與骰主通知郵件獨立。使用者統一輸入 `.bind qq <QQ号>`：當前客戶端有正式骰娘 key 時優先 OAuth，否則自動申請郵件。
郵件用 `.bind confirm <8位验证码>` 完成；有 key 但主動選擇郵件時，用 `.bind qq <QQ号> email`。OAuth 則網頁同意後用 `.bind confirm`，失敗不會自動傳送郵件。
指令和安全限制見[QQ 郵箱驗證碼](/zh-hant/use/cloud#qq-郵箱驗證碼)。

## 表示式引擎

擲骰表示式可按“全域性 → 分適配器 → 分賬號”分層設定；分賬號設定優先於分適配器，分適配器優先於全域性。系統只在前一個引擎明確表示“不支援該語法”時繼續嘗試下一個引擎；除零、非法骰面、骰數超限等執行錯誤會直接返回，不會換引擎重新擲骰。

| 模式 | 引擎順序 | 適用場景 |
|------|----------|----------|
| 增強相容模式（預設） | Dice!Next → OneDice → DiceScript | 儘量相容更多表達式語法 |
| 相容模式 | Dice!Next → OneDice | 保留 Dice!Next 行為，並補充常用擴展骰式 |
| 原始模式 | Dice!Next | 只使用舊版 Dicebot 風格的原生表示式，不啟用相容引擎 |
| 自訂模式 | 自選一個或多個引擎，並調整固定優先順序 | 按骰主需要控制可用語法和解析順序 |

::: info DiceScript C99 兼容範圍
Dice!Next 通過獨立維護的 [dicescript-c-lib](https://github.com/DiceZone/dicescript-c-lib) 接入 DiceScript。C99 執行時已覆蓋整數、浮點數、字串、空值、陣列、字典、區間、變數、computed value、函式、控制流、模板、容器方法與宿主回呼，並支援普通骰、連續 `d`、`kh/kl/dh/dl/min/max`、優勢/劣勢、COC 獎勵/懲罰骰、Fate、WOD 和 DoubleCross。

普通 `.r` 仍使用“單個表示式”入口，以便與指令後的檢定理由可靠分隔；人物卡數值可作為 DiceScript 變數讀取。完整語句、持久上下文、模板、原生函式/物件、自訂骰與 tagged VMValue 序列化由庫的完整 C API 提供。

回退探測使用完整 VM 的只解析介面，不執行表示式、不訪問宿主變數，也不消耗隨機數。只有完整語法不支援時才進入下一個引擎；已經進入求值後的錯誤不會重複擲骰。
:::

自訂模式中，拖動行首把手即可排序，**從上到下是實際優先順序**，儲存後生效。也可點選上下箭頭，或聚焦把手後按鍵盤上下鍵；關閉的引擎列在下方，不參與解析。不同引擎保留各自的過程格式，例如 OneDice 的 `1d6[4]=4` 中 `[4]` 表示該骰的點數，原生引擎使用 `1D6=4`。

::: tip 回退不會提前消耗隨機數
系統會先用不消耗正式隨機源的方式判斷相容引擎能否完整解析表示式，再執行實際擲骰。因此前一個引擎拒絕語法時，不會偷偷消耗骰點或改變後一個引擎的結果。
:::

## 指令字首

增刪觸發字首（預設 `.` `。` `!` `！` `/`）。訊息以任一字首開頭才會被當作指令；儲存後即時生效。QQ 官方平臺可使用 `/r` 等寫法。已有自訂字首列表不會被覆蓋，需要時可在此補上 `/`。

## 擲骰隨機源

在**基礎設定 → 擲骰隨機源**選擇並儲存（全域性搜尋“隨機源”可直達），全域性應用於 Dice!Next、OneDice、DiceScript 與 MCP 擲骰，立即生效並持久儲存。舊的“骰子規則”頁面已移除，原地址會自動跳到這裡。

| 方案 | 特點 |
|------|------|
| 作業系統安全隨機（預設） | Windows 使用 BCryptGenRandom，Linux 使用 getrandom，macOS 使用 getentropy。系統會持續混入 CPU 硬體隨機、中斷時序等熵；應用不額外維護隨機狀態，不依賴網路 |
| OpenSSL 安全隨機 | 使用 RAND_bytes，由系統熵源播種的 DRBG；同樣不依賴網路 |
| CPU 硬體熵源 | 每次讀取 CPU 的物理噪聲熵源 RDSEED，再與作業系統安全隨機按位異或，結果不弱於系統隨機。僅 x86-64 CPU 提供，不支援時該選項不可選；RDSEED 繁忙或失敗時本次自動改用系統隨機 |

三種方案每次擲骰的開銷都約為 1 微秒，不佔額外記憶體。插件自行生成的隨機數、每日運勢與預覽示例不受此選項控制。

**不會因隨機源故障停止擲骰。** 所選來源不可用時，依次改用另一個安全隨機源；全部不可用時才使用應急偽隨機（xoshiro256**），程式日誌記錄一次 WARN，來源恢復後自動切回並記錄 INFO。設定卡片會顯示最近一次擲骰實際使用的來源。實際中系統介面極少失敗，常見原因是 Linux 核心早於 3.17（如 CentOS 7）沒有 getrandom，或容器的安全策略遮蔽了它。

為什麼不直接用“真隨機”服務：海豹核心提供 PCG（預設）、系統 CRNG、NIST AES-CTR-DRBG、國密 SM3（預設停用，啟用需約 32 MB 記憶體採集熵）及混合模式；青果預設使用 Python 的梅森旋轉，可選從 random.org 拉取隨機數。Dice!Next 預設已直接使用系統安全隨機，硬體熵源方案在 CPU 支援時提供更直接的物理噪聲來源；線上隨機服務依賴網路、存在限流與隱私問題，因此未採用。

## QQ 官方 SN 狀態行

在**基礎設定 → 回覆與顯示 → QQ 官方 SN 狀態行**調整 `.sn` 的頂部顯示；全域性搜尋“SN”“彩色文字”可直達。支援全域性、適配器型別、單個賬號，優先順序為賬號 > 型別 > 全域性，儲存後立即生效，可恢復繼承。

| 預設 | 顯示方式 |
|---|---|
| 彩色文字（預設） | 使用 QQ 公式格式 `scriptsize` 與 `\textcolor`，預設紅色 `#E5484D`；選中後下方出現色盤、取色器、常用色塊和 #RRGGBB 輸入框，可直接改顏色。取色器可從螢幕任意位置吸取顏色（Esc 取消），需 Chrome / Edge 且通過 HTTPS 或 localhost 打開面板，其他情況按鈕不可用。不傳送 HTML `<font>` |
| 引用 | Markdown 引用塊 |
| 普通文字 | 不加額外裝飾 |
| 自訂格式 | 編輯 Markdown，用佔位符插入狀態內容 |
| 關閉狀態行 | 不顯示頂部狀態，保留玩家設定 |

此處只控制外觀；玩家仍需在群內執行 `.sn` 或 `/sn` 開啟自己的狀態行，`.sn off` 關閉。`.setsn` 設定群預設屬性，`.sn {nick} SAN{san}` 設定個人內容。其他平臺的真實群名片行為不變。

自訂格式示例：

```text
> {sn}
```

```text
$\scriptsize\textcolor{#E5484D}{\text{{sn_tex}}}$
```

`{sn}` 插入已經轉義的 Markdown 文字；公式中請把 `{sn_tex}` 放在 `\text{…}` 內，用於安全處理暱稱中的反斜線、括號等字元。格式至少包含一個佔位符，最多 2048 UTF-8 位元組；反覆插入佔位符導致狀態行超過 3000 位元組時退回一份普通狀態文字。切換預設不會丟失已編輯的自訂格式。預覽使用固定示例資料，最終顯示以 QQ 客戶端為準。

裝飾樣式需要 Markdown：選擇傳統文本方案、用 `.bot text plain` 強制純文本，或平臺明確拒絕格式時，狀態行降級為普通文字，不輸出公式程式碼。狀態與後面的正文用獨立段落分隔。

## BotMsg 附加說明

在**基礎設定 → 回覆與顯示 → BotMsg 附加說明**編輯 `.bot` 固定資訊之後的介紹、聯絡方式或幫助提示。支援全域性、分適配器和分賬號設定，優先順序為賬號 > 適配器 > 全域性；留空可隱藏附加說明。

`.bot` 的前三行始終由系統生成，不能通過附加說明或舊版頁首替換：

1. 程式版本、構建號與作者名。使用後端持久化的 `i18n.default_locale`：中文顯示“希亞”，其他語言顯示“ShiaNyaa”。右上角的 WebUI 語言儲存在當前瀏覽器，不改變此預設回覆語言。
2. 當前程式的編譯器、編譯時間與適配器資訊。
3. 當前賬號實際啟用的兼容表達式引擎。預設顯示 `OneDice V1 & DiceScript Compatible`；只開啟 OneDice 或 DiceScript 時僅顯示對應名稱，只使用原生引擎時顯示 `Dice!Next Native`。

預設附加說明為：

```text
Dice!Next 测试群：933145116
如有故障或建议欢迎加群反馈
使用 .help 查看帮助
```

從舊版匯入時，`strBotMsg` 保留原文，並在末尾另起一行追加上述預設說明；重複匯入不會重複追加。`strBotHeader` 也會保留，但移動到三行固定資訊之後。已有自訂說明且未授權覆蓋時，遷移報告會提示衝突並保留現有設定。

## 敏感詞攔截

位於**安全與許可權**分割槽，復刻原版 Dice! 的指令敏感詞檢測。功能預設關閉且**不附帶任何內建詞表**；只有骰主在頁面儲存的規則，或從舊版 `conf/CustomCensor.json` 遷入的規則會參與匹配。

- 只檢查以當前指令字首開頭的入站訊息，不掃描普通群聊，也不修改骰娘回覆或插件輸出。
- 匹配自動跳過空格和 ASCII 特殊符號，英文大小寫不敏感；一條指令命中多項時取最高等級。
- Master 與信任等級 4 及以上跳過檢測。信任等級 1–3 會按原版規則降低實際處置：只有規則等級不低於使用者信任等級時才攔截。
- 命中會寫入本機日誌併發到對應級別的[骰主通知視窗](/zh-hant/manage/notice)。為避免 QQ 官方平臺二次觸發同一平臺敏感詞，通知訊息不復述命中詞和原指令，詳細內容只保留在本機日誌。
- 頁面可在啟用前測試一條指令，測試使用與即時訊息相同的服務端匹配器。

| 等級 | 行為 |
|------|------|
| Ignore (0) | 忽略這條規則，可用於保留舊版停用項 |
| Notice (1) | 僅記錄併發送例行通知，不阻止指令 |
| Caution (2) | 提醒使用者並攔截指令，傳送重要通知 |
| Warning (3，預設) | 警告使用者並攔截指令，傳送重要通知 |
| Danger (4) | 拒絕指令，傳送關鍵通知 |
| Critical (5) | 相容舊資料；按最高風險處理，與 Danger 一樣拒絕指令，併發送錯誤通知 |

聊天側也可由骰主使用 `.admin censor` 增刪或開關規則，詳見[管理指令](/zh-hant/use/admin#敏感詞管理)。

## 好友 / 加群邀請審批

設定機器人如何自動處理好友申請與加群邀請：

| 專案 | 可選策略 |
|------|----------|
| 好友申請 | 不自動處理（人工）/ 任意人自動通過 / 含關鍵詞才自動通過 / 自動拒絕 |

| 拒絕非好友邀請加群 | 非好友邀請自動拒絕；若被強行拉入群，骰娘提示後自動退群（骰主與白名單使用者豁免） |

## 開關與傳送行為

### 回覆文案與視覺方案

回覆展示可選擇三種方案，切換後立即儲存：

- **傳統文案**：使用早期版本的簡潔措辭和純文字排版。
- **標準文案**：使用當前標準措辭；支援的平臺渲染 Markdown，不支援時自動轉成可讀文字。
- **高階視覺文案**：在標準文案上加入狀態條、操作提示等語義元件；QQ 官方可把用法提示變成點選後填入輸入框的按鈕，純文本平臺則顯示為 `HP [██████░░░░] 6/10`、`.r // 掷骰指令` 等穩定形式，不生成圖片。
- **作用域覆蓋**：全域性、平臺型別和單個適配器賬號可以分別選擇，優先順序為賬號 > 平臺 > 全域性；清除覆蓋後繼續繼承上一級。
- **傳送效能**：Markdown 文案的純文字版本在載入或儲存時預先生成。QQ 官方連續兩次拒絕卡片後會自動使用純文字 10 分鐘，再恢復探測。

高階視覺預設可以完整載入編輯器，正文、按鈕、狀態條和公式均可自行修改；修改正文不會使已有按鈕消失。舊自訂文案保持不變，需要時手動載入預設再調整。編輯方法見[指令列表 → 自訂回覆文案](/zh-hant/manage/commands#自訂回覆文案)。

| 設定項 | 說明 |
|--------|------|
| 開機自啟動 | 隨 Windows 登入自動啟動（僅 Windows） |
| Windows 托盤提示文字 | 「網路與系統」選項卡內設定托盤圖示懸停名稱，最多 10 個字元，留空使用 `Dice!Next`；自動追加實際埠，儲存後立即生效，僅 Windows 可修改 |
| 儲存日誌圖片 | 跑團記錄中的圖片落地到 `data/logs/images`，匯出網頁時內嵌顯示 |
| 自響應訊息（自控） | 骰娘賬號自己發的訊息也會被處理，可用骰娘賬號自控；內建自回聲去重與跨骰防環護欄，預設關閉 |
| 停用擲骰理由 | 開啟後 `.r` 只顯示結果，不顯示原因：`.r 1d6 攻击` 只回復 1d6 的結果，只寫文字時直接投預設骰。預設關閉，原因照常顯示 |
| 引用投擲物件發言 | 回覆以 QQ「引用」樣式回覆觸發指令的那條訊息 |
| 自動卡面（HP/SAN 摘要） | `.st` 設定基礎屬性後自動算出生命 / 理智 / 魔法並附摘要（僅 COC 類規則） |
| 長訊息合併轉發 | 回覆超過閾值（預設 1200 字元）強制以合併轉發形式傳送，防刷屏（僅群聊、僅 OneBot） |
| 分段傳送長度 | 回覆超長自動分段（預設 600，約 300 漢字；儘量在換行處切分） |
| 使用者名稱包裹 | 回覆裡使用者名稱的前後綴（預設 `<` `>`，如「\<希亞\>擲骰」；留空＝不包裹） |

自訂托盤名稱從 build 926 起支援，儲存為 `config/dice.json` 的 `tray_text`，不屬於平臺或適配器賬號覆蓋項。也可通過已認證的 `GET /api/system/tray` 檢視 `{ text, port, tooltip, supported }`，使用 `PUT /api/system/tray` 提交 `{ "text": "希亚骰" }`；埠不可通過此介面修改。名稱按 Unicode 字元計數，不允許內部換行或控制字元。

## 圖片相關

- **圖片傳送方式**：回覆裡插入的圖片以 `[img,file=本地路径]` 儲存，傳送時轉換為 base64 內嵌（預設，跨裝置通用）或 HTTP 連結（需 NapCat 能訪問本機）。
- **圖床（穩定圖片連結）**：決定日誌圖片如何在日誌站長期可見——不上傳 / 第三方圖床（通用 multipart 上傳，適配 ImgBB、sm.ms、蘭空等）/ 本地連結（自託管，需公網 HTTPS）。

## 聊天與好友維護

- **聊天記錄保留期**：模擬聊天的訊息持久化儲存（`chat.db`），按天數自動清理。
- **使用者群**：設定官方使用者群，可選強制成員加群、允許邀請。
### 自動清理好友、群聊與本地記錄

此卡片是全域性設定，分為兩組；修改後點選儲存，不需要重新啟動。啟動約 5–6 分鐘首次檢查，之後每 12 小時檢查。

| 設定 | 實際行為 | 0 的含義 |
| --- | --- | --- |
| 使用者記錄不活躍期限（天） | 按最後收到訊息時間清理使用者檔案；舊檔案回退到指令/建檔時間 | 關閉 |
| 群記錄不活躍期限（天） | 按最後訊息/指令時間清理群列表資料，收到新訊息後恢復顯示 | 關閉 |
| 好友未使用指令期限（天） | 呼叫適配器刪除好友；無指令記錄時參考建檔時間 | 不刪好友 |
| 群聊未使用指令期限（天） | 退出當前骰娘賬號長期沒有收到指令的群；普通聊天不算指令。退群前傳送閒置天數告別 | 不因不活躍退群 |
| 超過多少群成員時退出（人） | 成員數量嚴格超過上限時退出，不是可加入的群數 | 不按人數退群 |
| 每輪最多退出群數（個） | 限制本輪退群數量，剩餘留到下輪 | **不限制數量**，並非關閉清理 |

本地記錄清理不會呼叫刪好友/退群介面，保留人物卡、跑團日誌、身份繫結、插件變數、群規則和許可權。使用者檔案內的暱稱、好感度和計數隨檔案清除；群列表資料到期後暫不顯示，實際訊息會重新建檔。手工移除/退群標記不會被普通訊息擅自清除。

骰主、信任/白名單使用者免清；群白名單、舊版免清/忽略設定以及正在記日誌的群受保護。未知或無效活動時間不會被當作“很久沒活動”。好友刪除與退群只在已連線且支援相應介面的適配器上執行；不會因另一個骰娘賬號的活動記錄判斷當前賬號該退群。清群會先發退場文案再提交退群；刪除好友不發私聊。

現有定時任務的配置、啟用狀態和執行方式不變。若以前已通過定時任務設定自動退群，請先核對，避免同時啟用兩個相同策略。

## WebUI 設定頁

**管理面板 → 系統設定 → WebUI 設定**，管理面板自身的設定：

管理面板只有一套介面（原 V2 已轉為正式版，舊版介面不再隨安裝包提供）。以前收藏的 `/v1/`、`/v2/` 地址會自動跳回後臺首頁；`config/webui.json` 中舊的 `ui_version` 欄位不再使用，保留也不影響啟動。

| 設定項 | 說明 |
|--------|------|
| API Key | 訪問後端 API 的認證金鑰，與配置檔案 `server/api_key` 保持一致 |
| 管理面板登入密碼 | 設定後打開面板需先輸入密碼（Cookie 會話認證）；登入時可選擇信任裝置 30 天並跨程式重啟恢復。清空後需重新設定密碼，修改 / 清除會使現有登入會話失效；同機多套安裝使用獨立 Cookie，退出隻影響當前實例 |
| 執行 IP 與埠 | 面板與介面的監聽地址（`0.0.0.0` 表示監聽所有網絡卡）與埠（預設 18088）。**修改後需重啟生效**（HTTP 監聽在啟動時繫結，無法熱切換），儲存後可點「立即重啟」 |
| 主題偏好 | 淺色 / 深色 / 跟隨系統 |
| 控制台日誌 | 最低記錄級別 TRACE / DEBUG / INFO / SUCCESS / WARN / ERROR，預設 INFO；協議事件診斷仍遵守級別，正常心跳 TRACE、輪詢 DEBUG，不提升到 INFO |

記錄級別控制之後寫入控制台和檔案的日誌；首頁的“最低展示級別”只篩選當前瀏覽器中的記錄。降低展示級別不能補出此前未儲存的 DEBUG／TRACE。格式、插件來源和訊息對應方式見[程式日誌](/zh-hant/manage/dashboard#程式日誌)。

設定工作區按功能分選項卡，儲存行為仍以各項按鈕或即時儲存提示為準。瀏覽器安裝獨立視窗的方法見[安裝部署 → 將管理面板安裝為應用](/zh-hant/guide/install#將管理面板安裝為應用)。
