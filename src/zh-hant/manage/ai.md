# 人工智能

**管理面板 → 人工智能**，接入 OpenAI 相容的大模型，為骰娘提供回覆潤色、翻譯、對話、NPC 扮演、影像識別等能力。側欄分為六個子頁：**模型 / 對話 / NPC 扮演 / 知識庫 / 回覆潤色 / 回覆翻譯**（除知識庫外編輯狀態共享，任意子頁點「儲存」即儲存全部；知識庫頁有自己的儲存按鈕）。

::: warning 費用與延遲
開啟 AI 後，相關功能會按你配置的模型計費，且被 AI 處理的回覆會有延遲（取決於網路與大模型響應速度）。請給每個模型設好 token / 費用限額。所有 AI 功能失敗或超時都會回退：潤色 / 翻譯發原文，對話不回覆。
:::

## 模型

### 總開關

「啟用人工智能」是所有 AI 功能的總開關，關閉時潤色、翻譯、對話等全部不生效（其它子頁會置灰並提示先到「模型」頁開啟）。

### 全域性請求引數

所有 AI 呼叫共用的引數（潤色 / 翻譯會另用較低溫度以求忠實）：溫度 temperature、top_p、最大 token、頻率懲罰、存在懲罰。

模型設定分為三個選項卡：**提供商 → 模型 → 用途分配**。先填介面和金鑰，再列出要用的模型，最後決定每個功能用哪些模型。

### 提供商

一個提供商對應一組介面地址和金鑰，旗下所有模型共用，同一家服務不必每個模型重複填寫 Key。

| 欄位 | 說明 |
|------|------|
| 名稱 | 自訂名稱，如「OpenAI」「DeepSeek」「本地 Ollama」 |
| 接入地址 Base URL | OpenAI 相容介面地址，填到 `/v1` 即可，如 `https://api.openai.com/v1` |
| API Key | 本地模型可留空 |

停用提供商後，旗下所有模型都不再呼叫。仍有模型使用的提供商不能刪除。

### 模型

| 欄位 | 說明 |
|------|------|
| 顯示名 | 自訂名稱，如「GPT-4o mini」「本地 Qwen」 |
| 提供商 | 從「提供商」頁已新增的裡選 |
| 模型名 model | 如 `gpt-4o-mini`、`qwen2.5`、`text-embedding-3-small` |
| 類別 | **通用模型**：對話、潤色、翻譯、識圖、語音識別等；**嵌入模型**：只把文字轉成向量，用於長期記憶檢索 |
| 支援圖片輸入 | 僅通用模型。開啟後才能分配到「影像識別」 |
| 輸入價 / 輸出價 | 每百萬 token 單價，用於費用統計（嵌入模型只有輸入價） |
| token 上限 / 費用上限 | 0 = 不限；超限後該模型停止呼叫，自動改用同一用途的下一個模型 |

每個模型顯示已用 token 與累計費用，並有「測試」按鈕：通用模型實測一次對話，嵌入模型實測一次向量化並顯示向量維度。

### 用途分配

為每個功能指定使用的模型：

| 用途 | 說明 | 未分配時 |
|------|------|----------|
| 對話回覆 | 骰娘在群裡聊天 | 第一個啟用的通用模型 |
| 決策 | 待機搭話前判斷要不要插話（見下文「對話」） | 沿用「對話回覆」 |
| 潤色 / 翻譯 | 回覆潤色、`.lang` 翻譯 | 沿用「對話回覆」 |
| 記憶摘要 / 事實抽取 | 群歷史摘要、長期記憶抽取 | 沿用「對話回覆」 |
| NPC 扮演 | NPC 回覆（NPC 設了專屬模型時優先用專屬模型） | 沿用「對話回覆」 |
| NPC 情緒評估 | 評估 NPC 好感變化 | 沿用「NPC 扮演」 |
| 影像識別 | 識別訊息圖片，只能選「支援圖片輸入」的模型 | 沿用「對話回覆」裡支援圖片的模型 |
| 語音識別 | 把語音轉成文字 | 不可用 |
| 嵌入 | 長期記憶的向量化，只能選嵌入模型 | 不可用 |

每種用途可以選多個模型，並選擇**使用策略**（預設負載均衡）：

- **負載均衡**：每次選正在處理的請求最少的模型，相同時輪流使用。
- **隨機選擇**：每次隨機選一個。
- **順序優先**：按列表順序用第一個，失敗或超過限額才換下一個（可用上下箭頭調整順序）。
- **分配權重**：按權重比例分配請求（權重 1–100）。

無論哪種策略，呼叫失敗時都會自動換下一個候選模型重試（每次最多試 3 個）。帶工具呼叫的對話只在第一輪失敗時換模型，避免擲骰、改卡等操作被重複執行。

::: warning 嵌入只能指定一個模型
已存的記憶向量和檢索時的向量必須來自同一個模型，所以「嵌入」只能選一個模型。更換嵌入模型後，請在「對話」頁清空長期記憶，讓向量重新生成。
:::

::: tip 從舊版本升級
舊版本每個模型都自帶介面地址和 Key，各功能分別指定模型。升級後首次啟動會自動轉換：相同「地址 + Key」的模型合併成一個提供商，各功能原先指定的模型轉成對應用途的分配，長期記憶的嵌入設定轉成一個嵌入模型。轉換前的原始設定備份在 `dice.json` 的 `ai_backup_v1` 中。
:::

## 對話

讓骰娘在群裡像真人一樣聊天（僅群聊生效）。

### 觸發方式（三態）

- **被 @骰娘**：必定回覆，不受冷卻限制。
- **命中關鍵詞**（逗號分隔，如「骰娘, 在嗎」）：必定回覆，不受冷卻限制。
- **待機機率**（0–100）：其餘訊息按機率隨機搭話，受「每群冷卻(秒)」限制，別設太高否則會頻繁插話。
- **待機搭話前先判斷**：勾選後，待機機率命中時先請「決策」用途的模型判斷此刻要不要插話（例如有人在提問、話題和骰娘有關），判斷為否就不回覆。判斷只輸出很短的結果，比直接生成回覆省用量，適合給「決策」分配便宜、快速的模型。被 @ 或命中關鍵詞時不經過判斷。

### 生成引數

上下文輪數（讀取本群近期聊天記錄作為上下文）、回覆最大字數、每群冷卻秒數、回覆時是否 @ 傳送者、是否禁止輸出 emoji、自訂過濾詞（餵給 AI 前從文本里刪掉水印 / 簽名 / 刷屏詞），以及人設與系統提示詞（留空用內建預設，可點「載入預設」在模板基礎上修改）。

### 群歷史記憶（滾動摘要）

對話超出近期視窗後，把更早的聊天按批壓縮成一份群摘要注入背景，讓骰娘記得更久之前的事。摘要用「記憶摘要」用途的模型；可配置保留輪數（摺疊批大小）、摘要字數上限與摘要提示詞；頁面內可檢視 / 清空已存的各群摘要。僅當滑出視窗的訊息攢夠一批才呼叫模型（天然限頻、控成本）。

### 長期記憶（持久事實 · 向量檢索）

從對話裡抽取值得長期記住的事實（人物卡 / 劇情 / 約定），向量化存庫；聊天時按當前話題相似度檢索最相關的幾條注入。需要先在「模型」頁新增一個類別為「嵌入模型」的模型（如 `text-embedding-3-small`），並在「用途分配 → 嵌入」指定；抽取用「事實抽取」用途的模型。可配置檢索條數 Top-K、相似度閾值、每群事實上限與抽取提示詞；同樣可檢視 / 清空已存事實。

### 工具呼叫

開啟後骰娘用 function-calling 呼叫真實功能，而不是自己編數字（需模型支援 tools）：

| 工具 | 說明 |
|------|------|
| `roll_dice` | 擲骰，走真實骰子引擎 |
| `draw_deck` | 抽牌堆 |
| `get_attr` | 讀傳送者人物卡屬性 |
| `set_attr` | 寫傳送者人物卡（有風險，預設關閉） |
| `run_command` | 執行任意指令 / 插件（許可權同傳送者） |
| `search_help` | 在幫助文件裡查詞條；開啟知識庫時改為搜尋知識庫 |

「最大工具輪數」限制連環呼叫次數，最後一輪強制輸出文本回復。僅在「對話」開啟時生效。

### AI 白名單（訪問控制）

開啟後，只有白名單內的群 / 私聊能使用 AI 對話與 NPC；非白名單群即使群管發 `.ai on` 也會被拒絕，防止未授權群消耗 API 費用。名單從群組 / 玩家列表搜尋勾選新增。白名單隻控制對話 / NPC / 群記憶；回覆潤色與翻譯是全域性功能，不受影響。

### 影像識別（多模態）

訊息帶圖片時，用多模態模型識別圖片內容得到文字描述注入對話，讓骰娘「看懂圖」。僅在被 @ 或命中關鍵詞等觸發時才識別（控成本）。識圖用「影像識別」用途的模型（模型需開啟「支援圖片輸入」）；可配置單條最多識別張數與識圖提示詞。

**圖鏈直傳**開關：開啟時直接把 QQ 圖片連結傳給大模型（快，但連結可能過期）；關閉則下載後以 base64 上傳（慢但可靠）。

開關狀態會隨其他 AI 設定一起儲存，關閉後儲存、重新開啟頁面或重啟程式都應保持關閉，無需手動編輯 `dice.json`。

### 語音識別

群裡發語音時，用「語音識別」用途的模型把語音轉成文字，再交給對話做觸發判斷和回覆（例如語音裡提到關鍵詞也能觸發）。需要支援 OpenAI 相容 `/audio/transcriptions` 介面的模型，如 Whisper、SiliconFlow 的 SenseVoice；在「模型」頁按通用模型新增，再分配到「語音識別」。

- **OneBot（NapCat 等）**：通過 `get_record` 取得 mp3。骰娘與 NapCat 不在同一臺機器時（如 Docker），請在 NapCat 開啟返回 base64 的選項，否則讀不到語音檔案。
- **Discord**：直接下載語音附件。
- 每條語音會額外請求一次語音識別模型；同一條語音只轉寫一次。

## 知識庫

**人工智能 → 知識庫**，讓骰娘回答「怎麼用 / 有沒有某功能 / 團規是什麼」這類問題時有據可查，同時儘量不增加模型用量：

- **檢索在本機完成**：按關鍵詞計分（BM25），不呼叫模型改寫問題或判斷要不要查。約一萬條資料每次檢索幾十毫秒。
- **只注入相關的少量資料**：相關度達到閾值的前幾段才加進提示詞，總字數有上限；閒聊找不到相關資料時什麼都不加。
- **FAQ 直接回答**：自訂條目勾選「直接回答」後，問題和條目的問法足夠相似時，原文回覆條目內容，**完全不呼叫模型**。

### 資料來源

| 來源 | 內容 |
|------|------|
| 幫助詞條 | 幫助系統裡的全部詞條：內建指令、規則包、插件、自訂幫助文件。檢索時直接讀取，修改幫助後立即生效 |
| DiceNext 文件 | 本文件站的使用說明，隨程式安裝，不需要聯網 |
| 自訂條目 | 在知識庫頁錄入的資料：團規、世界觀、常見問題等 |

### 設定

| 設定 | 說明 |
|------|------|
| 最多注入段數 | 每次對話最多加進提示詞的資料段數（1–8，預設 3） |
| 相關度閾值 | 0–1，問題裡的關鍵詞被資料覆蓋的比例達到它才注入（預設 0.45）。調高減少無關資料，調低找到更多 |
| 注入字數上限 | 每次注入的資料總字數（預設 1200），控制輸入 token |
| FAQ 直接回答 / 相似度 | 問題與問法的相似度達到它（預設 0.6）就直接回復 |
| 語義檢索（自訂條目） | 為自訂條目額外比較向量相似度，換了說法也能找到。需要在「用途分配 → 嵌入」指定嵌入模型；每次檢索會請求一次嵌入模型 |

### 自訂條目

每個條目有標題、內容、問法（每行一個）、標籤和「直接回答」開關。問法與標題在檢索時權重更高，FAQ 直接回答也按問法比對。可以從 JSON 檔案批次匯入：條目陣列，或 `{"entries": [...]}`，每條可含 `title`、`content`、`questions`、`tags`、`direct`。條目儲存在 `data/knowledge/entries.json`。

### 檢索測試

在頁面輸入一句玩家可能問的話，可以看到會命中哪些資料、各自的相關度、會注入多少字，以及是否觸發 FAQ 直接回答，用的是頁面上當前（尚未儲存）的設定，方便調閾值。

開啟知識庫後，工具呼叫裡的 `search_help` 也改為搜尋知識庫。對話時檢索的問題會先去掉「觸發關鍵詞」（如骰孃的名字）。

## NPC 扮演

定義 NPC（名字 / 人設 / 背景知識 / 觸發詞）。群裡訊息提到 NPC 名字或命中觸發詞時，骰娘以該 NPC 的身份、口吻、知識回覆（複用記憶與工具呼叫，優先於預設骰娘對話）。可用於扮演旅店老闆、神秘線人等。

每個 NPC 可設定：觸發詞（除名字外）、專屬模型（可選）、限定群（如 `onebot_v11:123456`，留空 = 全部群）、人設與背景知識（只有角色知道的資訊）。**情緒記憶**開啟後，NPC 對每個玩家維護好感度（-100~100）與情緒，語氣隨關係變化；每次互動後用模型評估好感增減（額外一次請求）。

## 回覆潤色

擲骰 / 檢定類回覆傳送前，用大模型按人設與情境潤色。兩種方式：

- **僅潤色措辭**：保留數字 / 結果，只改說法。
- **按情境增加 rp 描述**：在結果基礎上加入角色扮演描寫。

可設定人設 / 風格與系統提示詞（可「載入預設」修改）。模型須嚴格保留原始數字與成功 / 失敗結果——服務端會校驗數字，被改壞時自動回退原文；失敗或超時也發原文。

**覆蓋範圍**：潤色與翻譯都按類別勾選生效——擲骰/檢定、牌堆抽取、娛樂指令（今日人品 / 瘋狂 / 隨機名等）、自訂回覆、插件結果。

## 回覆翻譯

配合 `.lang` 實現自訂語言：先在頁面定義語言（名稱 + 切換關鍵詞，如名稱「德語」、關鍵詞「de, german, 德語」），群裡 / 私聊發 `.lang <关键词>` 即可切換。回覆先按預設語言生成，傳送前由大模型翻譯成目標語言（帶快取，同文本不重複計費）。翻譯提示詞可用 `{lang}` 佔位目標語言名。失敗或超時自動發原文；切回內建語言或 `.lang clr` 即停用翻譯。

## 聊天側指令

`.ai on/off` 可分群開關本群 AI 功能（對話 / NPC），詳見[管理指令](/zh-hant/use/admin)。白名單模式開啟時，非白名單群 `.ai on` 也會被拒絕。

::: tip AI 不會拖慢指令
所有大模型呼叫都在獨立的後臺佇列序列執行，不佔用訊息執行緒——即使 AI 適配器住 30 秒，普通指令也照常秒回；堆積過多時直接丟棄新的 AI 任務（對話不回、潤色回退原文）。
:::

## 排查：DEBUG 日誌

把「WebUI 設定 → 控制台日誌」的最低記錄級別調到 **DEBUG**，可以看到 AI 處理的每一步：

- 觸發判斷：被 @、命中哪個關鍵詞、待機機率擲出多少；決策模型的判斷與理由。
- 選模型：用途、策略、嘗試順序，以及失敗後換了哪個模型。
- 每次請求的完整內容（系統提示、上下文、使用者訊息、工具列表）、模型的思考過程與回覆，失敗時的原始響應。
- 工具呼叫的引數與結果、影像識別 / 語音識別的結果。
- 知識庫檢索：計分條數、耗時、命中的資料與相關度、FAQ 直接回答。
- 記憶整理：本次摺疊了哪些訊息、更新後的摘要、抽取到的事實、跳過的重複事實、檢索命中的記憶與相似度。

模型輸出的思考過程（`<think>` 段或 `reasoning_content` 欄位）只寫入日誌，不會發到群裡。

::: warning DEBUG 日誌包含聊天內容
DEBUG 級別會記錄群聊訊息與人物卡等完整內容（API Key 不會寫入）。排查完畢後請調回 INFO。
:::

::: tip 先在測試臺預覽
可在「指令測試」頁發 `.r` 或聊天內容，直接預覽潤色 / 翻譯 / 對話效果，無需進群。見[指令測試](/zh-hant/manage/playground)。
:::
