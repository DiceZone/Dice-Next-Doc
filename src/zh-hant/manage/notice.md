# 通知設定

**管理面板 → 系統設定 → 通知設定**，按接收視窗管理通知來源、訂閱範圍與審計日誌。

## 通知視窗

頁面支援卡片／列表、搜尋和伺服器端分頁。卡片顯示接收物件的暱稱、帳號和頭像；點選編輯再調整訂閱事件。

點選頂部的新增按鈕，先選擇**一個通知視窗**：一個群、一個使用者、一個收件郵箱或一個 Webhook。聊天視窗再選擇傳送帳號，可選擇同平臺的多個帳號；郵件和 Webhook 也各自作為一個獨立視窗管理。同一個目標不能重複新增，請編輯已有視窗。

隨後配置這個視窗的監聽來源（全部適配器、一個或多個平臺、一個或多個骰娘帳號）及訂閱範圍（全部通知、按級別、按具體事件）。系統更新等沒有具體來源帳號的事件由「同時接收程式級通知」單獨控制。彈窗頂部儲存，內容區域獨立滾動，寬屏分兩列，窄屏改為單列。

歷史上指向同一視窗的多條規則會歸併展示，各條規則的來源與事件範圍仍獨立儲存，不會擴大訂閱。例如「帳號 A 的好友通知」和「帳號 B 的錯誤通知」不會被合成「A、B 的所有好友和錯誤通知」。如果舊規則使用不同的傳送帳號，預設保留，只有明確選擇統一發送帳號後才會改變。

來源過濾與傳送帳號選擇獨立：明確指定的傳送帳號不會在失敗後擅自換號；自動選擇模式才會按既有策略嘗試同平臺可用帳號。

也可在聊天裡發 `.notice on`（僅骰主）把當前視窗設為通知視窗，詳見[管理指令](/zh-hant/use/admin)。

每個視窗可**逐項勾選**要接收的通知事件；事件按四個區域分組：

| 區域 | 級別值 | 包含事件 |
|------|--------|----------|
| 例行通知 | 1 | 信任、帳號許可權關聯、定時任務與通知訂閱變更 |
| 重要通知 | 2 | 好友與群申請、骰娘入退群、禁言與群管理員許可權、各類主動退群規則、群開關、任務觸發、全域性靜默、更新進度；敏感詞實際級別依規則變化 |
| 關鍵通知 | 4 | 骰娘管理許可權、黑白名單與骰娘名單變更 |
| 錯誤通知 | 8 | 執行錯誤、退群請求失敗、更新失敗 |

用指令 `.notice level <n>` 訂閱時（1 例行 / 2 重要 / 4 關鍵 / 8 錯誤，可疊加，15 = 全部），預設勾選對應區域的全部事件。

這與程式日誌的 TRACE／DEBUG／INFO／SUCCESS／WARN／ERROR 過濾不同。從舊版匯入的空事件列表會保留級別訂閱語義，並按實際生效事件顯示；明確切換到按事件訂閱且清空列表，才是不接收事件。

更新檢測屬於系統事件，沒有具體來源群。自動安裝結果由管理器重啟後回報，並核對實際執行版本。級別訂閱包含新增的同級事件；已經逐項篩選的規則不會被擅自擴展，請按需勾選新增事件。

## 通知如何表達結果

```text
[骰娘被踢出群聊] 骰娘被小明(3569827618)踢出群未归星璇(792364383)。
适配器 OneBot:3626455591
```

主動退群分成“請求已提交，等待平臺確認”和平臺實際回執。點名了其他人的被踢回執，以及解散回執，優先於此前的主動請求。沒有其他操作者的「踢出」回執（操作者為空、為 0，或就是骰娘自己），如果能對上本程式剛提交的退群請求，按主動退出確認，不寫入黑名單或雲黑名單。

被踢/被禁言自動拉黑在[系統設定 → 原版全域性設定 → 事件響應](/zh-hant/manage/settings#原版全域性設定)中配置，新裝預設關閉。只有點名了其他人的踢出才會拉黑操作者；上述退群回執不會觸發拉黑。原因未知就明確寫未知，不僅憑操作者帳號推斷。

好友與加群申請會寫出申請人、群、處理決定與依據。審批呼叫只提示“已提交自動同意／拒絕”，關係建立由實際平臺事件確認。

名稱優先使用事件及來源帳號快取，再查歷史記錄；沒有可靠名稱則保留帳號，不編造暱稱。面板密碼登入沒有可核實 QQ 身份時會如實註明。插件錯誤保留插件名、操作和真實直譯器錯誤（含真實行號），不推測底層沒有報告的根因。

## 郵件與 Webhook 視窗

不在 QQ 上也能收到通知：

### SMTP 郵件推送

優先複用許可權／身份驗證頁面的共享 SMTP 配置，視窗只需填寫一個收件郵箱，不需要重複填寫 SMTP 口令；共享傳送配置未設定時相容舊通知 SMTP。465 使用 SSL，587 等按郵件傳輸設定執行。

沒有有效 SMTP 配置時，編輯器會顯示提示並阻止儲存，點選「配置 SMTP」可在新標籤頁開啟已有設定。返回後會重新整理配置狀態，原視窗草稿保留。舊通知 SMTP 憑據不會因編輯或刪除收件視窗而被清除。

郵件主題為 `[Dice!Next] 事件标题`，正文與聊天通知一致，不在變更通知裡暴露授權碼等資訊。

### Webhook 推送

新增視窗時選擇 Webhook，填寫完整 HTTP(S) 地址。地址未填寫或無效時會提示，並提供定位到地址輸入框的按鈕。

內建通用 JSON、企業微信、釘釘、飛書預設。選擇對應型別即可生成文本訊息請求體；釘釘或飛書機器人啟用加簽時，在進階選項填寫簽名金鑰，傳送時生成時間戳與簽名。機器人自身的關鍵詞、IP 白名單等限制仍需按服務商要求配置。通用 JSON 預設使用 `POST`，格式保持相容：

```json
{ "ts": "…", "level": 2, "op": "group_left", "title": "骰娘被踢出群聊", "msg": "[骰娘被踢出群聊] …", "origin": "onebot_v11:792364383" }
```

`op` 是穩定訂閱鍵；`title` 隨具體結果區分被踢、主動退群、解散。郵件與 Webhook 同樣受規則的級別／事件及來源過濾控制；相容舊全域性渠道。

### 高階請求與通知變數

進階選項支援 `POST`／`PUT`／`PATCH`、靜態 JSON 請求頭和自訂 JSON 請求體。「請求體示例」只在瀏覽器內預覽，不會發送網路請求。切換預設會恢復該型別模板。

變數寫在 JSON 的字串值中；完整佔位符會保留變數型別，例如 `"severity": "{{level}}"` 傳送時為數字。通知正文中的引號、換行會自動進行 JSON 轉義，不要手動轉義整段正文。

```json
{
  "summary": "{{title}}",
  "text": "{{message}}",
  "severity": "{{level}}",
  "source": { "adapter": "{{adapter_id}}", "group": "{{group_name}}" }
}
```

| 變數 | 內容 |
| --- | --- |
| `{{message}}` | 完整通知正文 |
| `{{title}}` | 本條事件的標題 |
| `{{time}}` | 伺服器配置時區的通知時間 |
| `{{level}}`／`{{level_name}}` | 通知級別數字／名稱 |
| `{{event}}`／`{{origin}}` | 穩定事件鍵／發生地標識 |
| `{{platform}}`／`{{adapter_id}}`／`{{account_id}}` | 來源平臺／適配器 ID／骰娘帳號 |
| `{{group_id}}`／`{{group_name}}` | 來源群 ID／群名 |
| `{{user_id}}`／`{{user_name}}` | 來源使用者 ID／暱稱 |

系統事件可能沒有群、使用者或來源帳號，對應值為空，不編造身份。變數只替換一次，不會執行指令碼，也不會繼續解析通知正文裡恰好出現的佔位符；URL、請求頭及 JSON 物件鍵不參與替換。

請求體模板須為 64 KiB 以內的 JSON 物件，巢狀最多 16 層；渲染後最大 256 KiB。請求頭只支援字串值，不允許換行或覆蓋 Host、Content-Length 等受保護欄位。Webhook 地址、簽名金鑰、自訂請求頭和請求體中的憑據不參與列表搜尋，受限管理員檢視時會被遮蔽。

企業微信文本超過服務商長度限制時會安全截斷，完整內容仍可在審計詳情檢視。Webhook 的 HTTP 錯誤或預設服務商返回的失敗狀態會記入本地日誌，不把“提交請求”當作成功送達。

測試視窗時只嘗試這個視窗配置的傳送帳號或渠道，即使舊規則原本同時包含其他接收渠道，也不會順帶向它們傳送。手動測試可繞過視窗暫停和日常事件訂閱；全域性測試仍只使用啟用的規則。測試不修改訂閱，也不等於平臺最終送達。

## 審計日誌

全部通知事件持久化在 `data/audit/notice_*.jsonl`，可回溯時間、級別、事件、發生地與內容。通知不回推產生它的同一聊天，避免和指令回覆重複；按修改後的訂閱投遞，已關閉的視窗不會臨時恢復一次通知自己。

表格每行固定高度，過長內容單行省略，點選內容開啟詳情彈窗，檢視完整正文與事件資訊。窄屏可橫向滾動表格，表頭不會逐字換行。

同來源同種錯誤短時間合併，不遮蔽其他群或插件的新錯誤。通知視窗本身不可達只記本地錯誤日誌，不能再生成自己的失敗通知，避免無限巢狀；詳細平臺原因保留在本地結構化日誌。

完整模板審閱稿在主程式倉庫 `docs/notification-templates.md`，逐項列出觸發條件、級別、文案與資訊缺失時的處理。

::: tip
無論有沒有配置通知視窗，事件都會寫入審計日誌——視窗和推送只決定「有沒有人被主動告知」。
:::
