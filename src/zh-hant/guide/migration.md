# 資料遷移

從舊版 Dice!（V2）遷移可轉換的資料到 Dice!Next。遷移器會保留舊目錄，且不會複製登入憑據或 WebUI 密碼。

::: warning 當前範圍
這不是“把舊資料目錄原樣搬進新版”的功能。舊版與 Dice!Next 的儲存結構、團務模型和插件執行環境並不相同；匯入完成後，請保留舊目錄並在測試群核對人物卡、團務、日誌與插件。
:::

## 已支援的遷移範圍

匯入器直接解析舊版 Dice! 資料目錄的原始檔案（含二進位制 `.dat` / `.RDconf` 格式），轉換寫入 Dice!Next：

| 舊版資料 | 檔案 | 遷移到 |
|---------|------|--------|
| 人物卡 | `user/PlayerCards.RDconf` 及有效備份 | 統一人物卡庫：屬性、原名、卡型別、表示式、鎖定與選卡繫結；相容舊屬性名，全域性作用域自動轉換 |
| 使用者資料 | `user/UserConf.dat` | 玩家檔案（暱稱 / 信任等級 / 好感）及 Lua 相容使用者配置；群內暱稱單獨保留 |
| 群配置 | `user/ChatConf.dat` / `ChatConf.RDconf` 及有效備份 | 選定賬號的群停用、忽略、回覆/指令開關、COC 房規與歡迎詞；插件變數保留型別 |
| 黑名單 | `conf/BlackList.json` | 有效的本地使用者封禁；撤銷/無效記錄不復活，未知雲來源和群/關聯人策略列入確認報告 |
| 自訂回覆 | `conf/CustomMsgReply.json` | 關鍵詞回覆（多結果隨機 / 文本）；不能等價轉換的限制預設停用，無法通過執行時校驗的內容只保留原稿 |
| 自訂文案 | `conf/CustomMsg.json` | 回覆文案覆蓋（寫入簡體中文層）；`strBotMsg` / `strBotHeader` 遷為 [.bot 附加說明](/zh-hant/manage/settings#botmsg-附加說明)，保留原文並在 BotMsg 末尾追加預設反饋資訊 |
| 自訂幫助 | `conf/CustomHelp.json` | 寫入簡體中文幫助詞條，可在[幫助文件](/zh-hant/manage/help-docs)的「使用者自訂」中編輯和刪除；原內容保留，不作為無效文案 |
| 骰主 | `conf/console.yaml` / `Console.xml` | 選定賬號的 Master 列表與支援的執行設定；YAML 優先，損壞時不採用過期 XML 許可權 |
| 外接牌堆 | `PublicDeck/` | 校驗 JSON 內容後遷入 `data/decks/`；巢狀同名檔案生成唯一安全檔名，並遷入可定位的本地媒體依賴 |
| Lua 模組 | `mod/` | `data/mod/`（整棵複製，由 Lua 模組子系統識別） |
| Lua 插件 | `plugin/` | `data/plugin/`（單檔案和目錄型插件單獨複製） |
| 跨群連結 | `conf/LinkList.json` | 新版 `.link` 訊息轉發：遷入普通 QQ 群之間的 `with/to/from` 連結及暫停狀態 |
| 通知視窗 | `conf/NoticeList.json` | 所選賬號的 QQ 私聊/群聊通知及原級別掩碼；舊共享視窗可用 `.notice status/off` 管理 |
| 自訂敏感詞 | `conf/CustomCensor.json` | 系統設定中的敏感詞攔截：保留 Ignore–Critical 數字等級；有規則時自動啟用 |
| 團務會話 | `user/session/*.json` | 生成隨機 16 位團號並記錄來源；同源重導複用，早期記錄或目錄副本需確認銜接，輪盤只恢復剩餘池 |
| 跑團日誌 | `user/log/*.txt` 與 session 內日誌狀態 | 新版日誌庫：遷入文本記錄，恢復進行中 / 暫停 / 已結束狀態 |

::: tip 說明
- 自訂文案 / 幫助只寫入**簡體中文**層，其他語言保留 Dice!Next 自帶文案。
- 舊版文案鍵（`strXXX`）中在新版有已核對的對應槽位、且執行時引數相容的會自動對映；例如骰點、成功等級、牌堆、團務、旁觀、歡迎詞等。**沒有對應槽位或引數不相容的不會丟**——會以「無效文本」形式保留，可在管理面板中檢視後手工移植。
- 使用者與群的標量自訂配置會保留到 Lua 相容配置空間；這不表示每個舊版內建功能在新版都具有同一行為，但舊 Lua 規則可繼續讀取這些值。
- 使用者與群變數的布林、小數、空字串和可序列化結構會保留型別。舊函式不執行，不能等價接入的欄位會列入報告。
- 牌堆按內容校驗，不只根據副檔名判斷；非牌堆檔案仍跳過並給出原因。
- 人物卡的原生技能值仍遵循新版規則系統；保留布林/巢狀原稿不表示它們會被當作整數技能。
- 舊二進位制檔案會分別完整校驗 64 位與 32 位的 `size_t` 佈局，通過後才寫入資料庫；失敗嘗試不會留下半份檔案。舊函式不執行，巢狀函式也會列入待處理報告，原始位元組仍保留在舊檔案中。
- Lua 的舊 Set 變數會恢復集合方法，並支援使用者、群、團務配置及人物卡中的集合修改寫回；不把普通 JSON 陣列擅自當成 Set。
:::

### 人物卡讀寫與文本匯出

`STR`、`HP` 等已登記別名可讀取舊卡中的原始欄位，不要求先批次改寫卡片。若原名和標準名儲存了不同值，原資料均保留，遷移報告提示衝突；請按規則系統確認，不自動選一個值覆蓋另一個。

表示式使用統一人物卡資料，原生指令、Lua 和 JS 讀取一致。修改、刪除、清空和選卡切換不再讓舊錶達式從相容副本重新出現；清空會刪除文本、小數和結構屬性，但保留名字、型別與鎖等後設資料。

- 只有普通整數屬性時，`.st export` 仍使用原來的 `.st 力量50 …` 寫法。
- 有表示式、文本、小數或結構屬性時，輸出 `json {...}`，可用 `.st json {...}` 重新匯入。該操作替換當前卡的可編輯屬性，遵守寫鎖；讀取匯出遵守讀鎖。
- 指令 JSON 限制為 256 個欄位、64 KiB，超大卡請使用完整 JSON 卡匯出。JSON 原始卡匯出與雲卡資料不丟棄衝突欄位。

### 早期團務和目錄副本

發現已有的同名、同群舊導入團務，或相同原稿的目錄副本時，遷移器先暫停該團及其關聯日誌的遷入，報告不會顯示完整完成。面板會列出候選：

1. 若確認是同一團，選擇已有團務並應用銜接，保留原團號和當前變數。
2. 未開啟資料覆蓋時，不覆蓋已有變數；需用舊值替換時要明確開啟覆蓋並確認。
3. 確實是另一份團務時，可明確選擇新建獨立團務；預設不猜測合併，也不偷偷新增。

每次確認後繼續遷移都會先建立新的恢復備份。人物卡與舊團務仍使用共享相容空間，不能據賬號選擇推斷所有資料都完成了賬號級隔離。

### 遷入圖片的備份

完整備份及勾選「資源圖片」的區域性備份會包含根目錄 `image/` 和牌堆遷入的媒體。新版備份格式為 4，恢復時會同時還原這些資源；仍支援格式 1–3，恢復舊包不會清空它未包含的根目錄圖片。備份與恢復不跟隨符號連結或 Windows 重解析點。

## 遷移限制與尚未自動遷移的資料

下列內容已經列入遷移改進計劃。在對應版本釋出前，匯入器會保留舊目錄中的原檔案，不會擅自刪除：

| 舊版位置 / 資料 | 當前處理 | 原因與後續方向 |
|---|---|---|
| `user/GameTable.toml` | 不單獨遷移 | 它只儲存舊版自增序號；新版團號使用不可預測的隨機編碼，因此不能沿用。 |
| `conf/LinkList.json` 中的私聊、討論組、頻道連結 | 不遷移 | 新版 `.link` 僅支援普通群之間的轉發；可安全對應的 QQ 群連結已自動遷入。 |
| 舊會話內的觀察者、牌堆、tables | 原稿保留，需確認 | 完整會話原稿與這些欄位另存為相容資訊；沒有等價活動狀態的部分不自動啟用。報告明確區分“僅保留”和“已接入”。 |
| 插件自建目錄、任意自訂檔案 | 尚未遷移 | `plugin/` 本體會複製；插件執行時自行寫入的任意位置無法安全推斷用途。 |
| `CustomReply.json`、`CustomRegexReply.json` | 已支援 | 在較新的 `CustomMsgReply.json` 缺失或為空時，轉換為新版關鍵詞/正則回覆規則。 |
| 邀請人、活動時間、許可/免黑/忽略等群狀態 | 尚未遷移 | 僅能遷移在新版有明確且安全對應項的設定。舊快取群名會以相容資訊保留，不會直接覆蓋當前適配器讀取到的群名。 |
| 黑名單的群條目、關聯人、外部/雲黑來源 | 保留並報告 | 使用者 `local/ban/kick` 等有效本地記錄可遷入；無法證明來源或涉及舊免黑/信任策略的記錄不變成本地處罰。 |
| 控制台中的任務、Git/WebUI 憑據、過時雲設定 | 不遷移 | 明確對應的執行開關可匯入；可執行任務和敏感憑據需重新配置，不沿用舊環境。 |
| `selfdata/` | JSON 接入，其他格式原稿保留 | 頂層 JSON 存檔遷入 `data/self_data/`；其他格式與巢狀路徑不偽裝成已生效，列入確認報告。 |
| `CardTemp/`、`conf/censor/` 外接詞庫 | 原檔案保留 | 保存於 `data/legacy-import-preserved/`，不執行舊指令碼、不擅自啟用未經確認的詞庫。 |
| 根目錄 `image/` | 媒體遷入 | 本地媒體保留相對路徑；不能安全定位的牌堆引用留原文並報告，不讀取所選目錄外的檔案或跟隨連結。 |
| 每日統計與歷史使用計數 | 不自動接入統計系統 | 舊統計口徑與新版不同，不能當作新版測量結果。請保留舊目錄以便查閱。 |

## 自訂文案與幫助

舊版 Dice! 的自訂文案和幫助以簡體中文為主，因此匯入器**只寫入 `zh-Hans`** 是預期行為；繁體中文和英文繼續使用 Dice!Next 內建文本。

- 有新版一對一槽位的 `strXXX` 文案會接入對應模板；已設定的新等級回覆、原生指令模板仍按現有優先順序使用。
- 遷入時會把已核對的舊佔位符（如 `{pc}`、`{deck_name}`、`{game.log_name}`）轉換為新版佔位符。新版已不再提供必要引數的舊模板（例如舊 `.log off/end` 的日誌名、檔名模板）不會強行遷入。
- 沒有等價槽位或無法安全轉換佔位符的文案會儲存在管理面板的「無效文本」中，不會丟失也不會冒充已經生效。
- 每次擴充新版文案槽位時，會重新核對這批無效文本；能找到明確語義對應的鍵會加入對映，無法保證語義等價的仍保留給骰主手工處理。

新增的[按檢定結果分級回覆](/zh-hant/manage/commands#按檢定結果設定完整回覆)預設繼承原有文案，不會自動寫入覆蓋、清除已遷入文本或要求重新匯入。已相容的完整模板和成功等級短語繼續生效；只有主動配置新等級回覆時，才按新的繼承鏈選擇完整回覆。

以下檢定文案缺口已補齊，無需把舊短句改寫成新等級的完整回覆：

| 舊文案 | 新版相容處理 |
| --- | --- |
| `strRollCriticalSuccess/strRollExtremeSuccess/strRollHardSuccess/strRollRegularSuccess/strRollFailure/strRollFumble` | 單輪檢定的六個獨立等級短句，不混同多輪短句 |
| `strCriticalSuccess/strExtremeSuccess/strHardSuccess/strSuccess/strFailure/strFumble` | 繼續作為多輪檢定和 SAN 的等級短句 |
| `strRollSkill/strRollSkillReason` | 檢定字首；連續多輪只加一次字首 |
| `strRollSkillHidden` | 暗檢定群回執，不洩露私聊詳細結果 |
| `strSanityRoll` | 保留 SAN 完整模板及 `rank/loss/change/final` 的舊變數含義 |
| `strEnRoll/strEnRollNotChange/strEnRollFailure/strEnRollSuccess` | 成長基礎文本、未變化、失敗變化、成功變化分別保留，引用隨基礎文本修改而更新 |
| `strEnDefaultName` | 預設成長技能名稱 |

支援巢狀 `sample`、`case`、`grade`，以及已對映舊文本的引用（如 `{strEnRoll}`）；不會執行 JavaScript、Python、等待等可執行宏。條件欄位或變數無法對應時，報告標為「部分相容」；不支援的宏、語法不完整和迴圈自引用保留原文，等待人工遷移。**這不是舊版全部模板宏的全覆蓋宣告。**

新匯入的上述相容文本會保留 `legacy.strXXX` 原稿，不覆蓋已有且內容不同的目標。管理面板「備份與匯入」可檢視、下載逐項報告，區分已接入、部分相容、僅保留、衝突跳過。「已接入」表示成功對映到文本槽，不表示替換了優先順序更高的新回覆。

已有資料庫會在升級後的首次啟動自動補回能安全對應的歷史孤立槽位，並修正早期 `dice.crit/dice.fumble` 的單輪短句對映。全域性與人格均保留原記錄，不覆蓋已有目標（包括主動設為空的目標）。修復記錄持久儲存；恢復預設後，下一次啟動不會把已清除的舊文案重新補回。沒有可靠舊原稿的缺口仍需重新匯入，修復記錄不是當前配置的即時審計。

## 舊版指令相容邊界

Dice!Next 直接複用新版儲存、許可權與插件管理實現舊寫法，不執行一套平行的舊核心。當前已核對的遷移重點如下：

| 原版寫法 | Dice!Next 行為 |
|---|---|
| `.h` / `.H`、`.rh`、`.rs` | 短暗骰別名與僅最終值輸出均保留；`.help` 不會被 `.h` 搶佔 |
| `.coc/.coc7`、`.coc6`、`.cocd/.coc7d/.coc6d` | 分別生成 7 版、6 版及詳細制卡結果；接受舊排版標記 `s` |
| `.help on/off`、`.jrrp on/off`、`.reply on/off` | 按群持久儲存，沿用群管理 / 信任許可權 |
| `.drawh` | 私聊傳送抽牌結果，群裡只留暗抽回執 |
| `.pc nn/stat/cpy/copy/grp/tojson/type/temp` | 接到統一人物卡與規則系統；複製順序為 `目标卡=来源卡` |
| `.rule set <书>`、`.ruleset clear` | 接到統一規則書設定；設定和清除都校驗群管理許可權 |
| `.mod list/on/off/info` | 接到統一插件清單與分群啟停；更新、過載、刪除、重灌僅在 WebUI 確認 |
| `.user state/trust/tojson/diss` | 接到統一玩家檔案、許可權和名單；`diss` 不刪除檔案或卡片 |
| `.strXXX <文本/show/reset/NULL>` | 僅已審計的一對一文案鍵寫入統一覆蓋表；未知 `str…` 不會被吞掉 |
| `.cloud update/black` | 不復刻。舊版這兩條只報告狀態並把人指向網頁；版本號看不帶引數的 `.bot`，雲黑開關在網頁「系統設定」。`.cloud` 現為賬號中心授權與[雲人物卡](/zh-hant/use/cloud)入口 |

::: danger 刻意不復刻
- `.system cmd`：舊版遠端 Shell，風險等同遠端程式碼執行。
- `.user kill/clr`：聊天中不可逆刪除玩家或卡片；請在 Web 管理面板二次確認。
- `.mod update/reload/del/reinstall`：聊天中不替換或刪除插件檔案。
:::

JS 插件的相容來源是 **SealDice（海豹）`sealdice-core`**，不是舊 Dice! JS；具體鉤子、欄位和限制見 [JS 插件 API 參考](/zh-hant/develop/js-plugin-api)。

## 遷移步驟（管理面板）

1. 把舊版 Dice! 的資料目錄（**內含 `conf/` 與 `user/` 的那一層**）放到執行 Dice!Next 的這臺機器上。
2. 開啟管理面板 → **系統設定 → 備份恢復 → 匯入舊版資料**。
3. 填寫該資料目錄的**完整路徑**，選擇要遷入的 OneBot / Milky 賬號。共享相容層只寫 OneBot 共享設定；QQ 官方 OpenID 等身份不能憑舊 QQ 號推算。
4. 預設保留已有 Next 資料。資原始檔覆蓋與資料庫/配置覆蓋是兩個獨立選項；啟用資料覆蓋會再次確認，其他語言文案不會被刪除。
5. 點「開始匯入」。伺服器先建立恢復備份；備份失敗則不開始遷移。
6. 核對報告的失敗、停用、衝突和“僅保留”項。遷入的 Lua 插件不會由匯入器執行，確認後在插件管理中重新載入。

對應 REST 介面為 `POST /api/legacy/import`，引數 `{ "dir": "路径", "overwrite": false, "overwrite_data": false, "target_adapter_id": "账号ID" }`。不指定目標賬號時使用 OneBot 共享相容層。

介面傳輸成功不等於遷移完整成功：請檢查 `data.ok`、`data.complete`、`data.errors` 和 `data.diagnostics`。部分失敗的報告仍會返回，避免丟失已經完成階段的結果。只有完整成功才可能移除 BDC 遷移標記。

## 遷移報告

### 回覆引用規範化

匯入器先匯入牌堆、幫助與全域性文案，再根據實際可用資源處理回覆及冷卻 / 日限提示語中的引用。無歧義引用會自動轉換：

- `{牌堆}` / `{%牌堆}` → `{deck:牌堆}` / `{deck:%牌堆}`，保留當前回覆內不放回 / 放回規則，並只引用檔案牌堆。
- 幫助詞條 → `{help:词条}`；舊全域性文案 → `{text:文案名}`。
- `{nick}` 等上下文變數及已有顯式字首保持不變，轉義內容不改寫；巢狀 `sample:` 的所有分支均會處理。不會在匯入時實際抽牌或投骰。

變數與資源同名、同時匹配多個型別、未找到資源時，保留原文並報告原因。僅仍有待確認引用的舊回覆保留裸牌堆查詢相容；新回覆使用顯式字首，避免新增牌堆後意外覆蓋原有表示式或幫助引用。

疑似骰子算式也列入待確認項：舊裸表示式求值失敗會保留原文，而顯式 `roll:` 失敗會顯示 `?`，不能僅根據字元形式自動替換。確認含義後可手工新增 `roll:`。

匯入結果中的 `replyReferences` 包含轉換數、歧義數、未找到數及每處引用的規則、位置、原文、目標和原因。網頁可展開明細或下載 JSON 報告。請保留報告，按實際用途修正待確認項。

已經匯入過的規則可重新匯入原資料：完整定義相同的規則原位升級，不重複新增，保留骰主調整的啟停狀態與優先順序；後續補齊資源後，再次匯入也會嘗試規範化仍待確認的舊引用。

匯入完成後返回各項數量，包括：

- 人物卡數（及涉及的使用者數）、玩家檔案、黑名單、自訂回覆、幫助、文案（另計「無效文本」條數）、Master 數
- 牌堆、模組與插件的**成功 / 失敗 / 跳過**明細（逐檔案列出原因）
- 群配置：匯入的設定項數與涉及群數；跨群連結、通知視窗、敏感詞規則、團務會話、日誌和日誌訊息數量

頁面會展示逐項結果、團務/日誌彙總、恢復備份與報告位置；大量記錄限制螢幕展示數量，完整報告可下載。報告同時儲存在伺服器的 `data/legacy-import-reports/`，可能包含舊規則原稿，請勿直接公開。

## 注意事項

- **遷移前**：備份舊版完整資料目錄；確保該目錄可被 Dice!Next 所在機器訪問。
- **可重複匯入**：新遷移記錄使用穩定來源身份，同源團務不重複新增。預設保留已有資料；日誌只自動補入完整追加訊息，原正文被改寫或新版訊息已編輯時保留現狀並報告。舊匯入記錄缺少來源依據時需人工確認，不會猜測並刪除它們。
- **損壞檔案**：人物卡、使用者及群的二進位制檔案先完整校驗，再寫入該類資料；主檔案壞了會嘗試有效備份，全部損壞會報告錯誤，不把截斷內容當成功。
- **部分失敗**：不是全目錄原子事務，部分階段可能已寫入；請核對報告，必要時使用遷移前備份恢復。舊源目錄和待確認原稿均保留。
- **遷移後**：在[測試臺](/zh-hant/manage/dashboard)或測試群驗證擲骰、檢定、自訂回覆是否符合預期。
- 部分指令語法在 Dice!Next 做了規範化，差異見[擲骰與檢定](/zh-hant/use/dice)。

## 清理設定的遷移

舊 Dice 的 `InactiveUserLine` / `InactiveGroupLine` 是**本地記錄保留期限**，分別匯入 `dice/user_record_days` / `dice/group_record_days`，在基礎設定的“本地記錄保留”裡檢視。它們不會啟用刪除好友或退出群聊。使用者檔案和群列表資料的清理範圍見[基礎設定](/zh-hant/manage/settings#自動清理好友、群聊與本地記錄)。

`GroupClearLimit` 對應每輪退群數量上限；舊群配置的“免清”會對映為清理豁免，“忽略”保持徹底停用並免清，“免黑”對映為拉黑豁免。適用的 `GroupInvalidSize`、`LeaveBlackQQ`、`ListenGroupKick`、`ListenGroupBan`、`KickedBanInviter`、`BannedBanInviter` 設定按已有相容方式匯入。控制台檔案裡沒有寫出的項保持 Dice!Next 預設（被踢/禁言自動拉黑預設關）。未允許覆蓋資料時，已有設定優先。

早期 Dice!Next 曾把 `InactiveUserLine` 誤對映為刪好友天數。新版修正後續匯入，不會猜測並重置已經儲存的刪好友設定；用舊版遷移過的骰主請核對“好友未使用指令期限”，無需刪好友時設為 0。既有“自動退群”定時任務不會被遷移器重新設定、停用或刪除。
