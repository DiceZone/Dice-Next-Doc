# 安裝部署

當前為公測（Beta）階段。Release 提供 Windows（amd64 / arm64）、Linux（amd64 / arm64）與 macOS（arm64）發行包；容器化部署請參閱 Docker 專案說明。

## 下載與執行（Windows）

1. 在 [GitHub Releases](https://github.com/DiceZone/Dice-Next/releases) 獲取與你的平臺和架構相符的最新公測包。
2. **完整解壓**到一個固定資料夾（路徑建議不含特殊字元），不要放在系統臨時目錄中，也不要在壓縮包裡直接雙擊程式。
3. Windows 請雙擊 **`dice-next.exe`** 啟動；Linux/macOS 推薦執行包內 **`./start.sh`**，由 `dice-next` 管理器啟動核心。首次啟動會自動生成 `config/` 與資料目錄。
4. 程式預設**不顯示視窗，直接最小化到系統托盤**（右下角彈氣泡提示）。右鍵托盤圖示可「開啟網頁面板 / 顯示控制台 / 開啟應用目錄 / 退出」。
5. 開啟管理面板：托盤右鍵 →「開啟網頁面板」，或瀏覽器訪問 **`http://localhost:18088`**。

壓縮包內已附帶常見執行庫（VC++ 執行時），一般無需額外安裝；僅支援 64 位 Windows 10 / 11。

::: warning 臨時目錄啟動限制
從 build 926 起，Windows 啟動器和核心程式會檢查程式目錄及實際執行目錄。若位於系統臨時目錄或其子目錄，會拒絕啟動並彈出中英雙語提示，避免配置與資料留在隨時可能被清理的目錄中。請先完整解壓到固定目錄，再啟動 `dice-next.exe`。
:::

::: tip 埠說明
預設埠 `18088`（可在 `config/server.json` 的 `port` 修改）。若埠被佔用，啟動時會**自動順延到下一個可用埠並寫回配置**——此時用托盤的「開啟網頁面板」總能開啟正確地址。
:::

::: warning 單實例
同一套資料（同一個程式目錄）只能執行一個程序，重複啟動會自動退出，避免資料衝突。詳見[故障排查](/zh-hant/guide/troubleshooting)。
:::

## 驗證安裝

啟動後訪問：

- **管理面板**：`http://localhost:18088`
- **狀態檢查**：`http://localhost:18088/api/system/status`

如果管理面板能開啟，說明服務已正常執行。建議先在管理面板的 **WebUI 設定**裡設定一個登入密碼，然後去[快速開始](/zh-hant/guide/quickstart)接入你的 QQ 機器人。

## 開機自啟

管理面板 → 系統設定裡可開啟**開機自啟動**（隨 Windows 登入自動啟動，僅 Windows）。無需再手動配置任務計劃。

## 升級

### 管理面板自動更新

開啟**管理面板 → 關於專案 → 檢測與自動更新**：

1. 點“立即檢查”，程式從 GitHub Release 的 `update-manifest.json` 獲取最新版本與當前平臺安裝包。
2. 預設“自動選擇”會並行探測 GitHub 直連和內建映像；中國大陸網路不穩定時會自動採用先成功的映像，也可強制僅映像或填寫可信的自訂 HTTPS 映像。
3. 點“下載更新”後，程式核對清單倉庫、平臺、架構、檔名、檔案大小與 SHA-256。Windows 還會在解壓前檢查路徑穿越和包結構。
4. 使用完整包的管理器啟動時，可點“安裝並重啟”：Windows 使用 `dice-next.exe`；含 POSIX 管理器的 Linux/macOS 新包使用 `start.sh` 或 `dice-next`。管理器等待核心完全退出後替換程式、執行庫、WebUI、文件與內建資源；替換失敗時逆序回滾程式檔案。

右上角的版本文字可直接開啟更新區域，有新版本時顯示紅色 New。下載階段支援取消：等待“已取消”後可重試；連續 60 秒無新增資料或單個來源嘗試超過 20 分鐘時會終止本次傳輸，並按配置換源。失敗 / 取消只清理本次未完成檔案，不要求重啟程式。校驗和安裝準備階段也可取消，但已經開始的正式安裝不能取消。

網頁請求超時並不代表後臺任務停止，應等待面板重新獲取狀態，或點選重新整理狀態後再操作。

::: warning Linux/macOS 首次升級
beta.928 及更早的包沒有 POSIX 管理器，需要停服後完整覆蓋到包含 `dice-next` 的新包一次。後續用 `start.sh` 或 `dice-next` 啟動，面板才開放一鍵及定時安裝；僅換 WebUI 或直接執行 `dice-next-server` 不會啟用完整自動更新。此能力尚待新發行包釋出。
:::

Linux/macOS 管理器在前臺執行，適合由 systemd / launchd 監控；服務入口應指向 `start.sh` 或 `dice-next`。管理器將工作目錄統一為安裝目錄，自訂配置目錄請傳入絕對路徑；後續重啟保留引數。安裝目錄需對執行賬號可寫，更新器不請求 sudo、不移除 macOS 隔離屬性，也不繞過 Gatekeeper。

POSIX 更新會限制解包大小與數量，拒絕目錄穿越、硬連結和特殊檔案，僅允許 `lib/` 內部的安全符號連結。替換前探測新核心和管理器的可執行性、動態庫載入；替換中斷可由事務記錄恢復。僅程式檔案回滾，不自動降級資料庫；程式成功載入後的業務故障仍需保留備份並人工排查。

自動檢查預設開啟、間隔 6 小時、發現更新後僅通知。你可以改為自動下載；“自動安裝並重啟”需要 Windows 或新版 Linux/macOS 管理器模式。直接執行核心時可檢查 / 下載，不能安裝。容器部署只檢查並通知，不下載或安裝程式更新；請拉取新映像並重新建立容器。

管理器模式還可開啟**定時安裝**：先下載並校驗更新包，在指定時間主動重啟安裝，初始時間為 **04:00**。時間按伺服器設定計算，面板顯示具體日期和 UTC 偏移；下載完成時當天時間已過，則安排到次日。自動安裝開啟且包已就緒時，任何提前發生的重新啟動都會順帶安裝，包括手動重啟、退出後再次開啟、系統重啟和守護程序拉起。定時僅限制程式主動發起的重啟。修改時間或時區會重新安排；關閉定時只取消主動重啟計劃。若想保留下載包卻不在啟動時安裝，請改為“僅下載”或“僅通知”；仍可手動安裝。

::: tip 容器升級
官方映像帶有明確的容器標記，程式也會用 Docker / Podman 標記、Kubernetes 環境變數和 cgroup 資訊兜底識別。檢測到容器後，WebUI 會停用手動與自動下載 / 安裝，但版本檢查仍可使用。Compose 部署可執行 `docker compose pull dice-next`，再執行 `docker compose up -d --force-recreate dice-next`；掛載的 `config/` 與 `data/` 會保留。
:::

::: warning 映像信任邊界
SHA-256 可以發現下載中斷、損壞或清單與安裝包不一致，但不是獨立的發行簽名。選擇內建或自訂映像代表信任該來源；對供應鏈要求較高時，請使用“僅 GitHub”，並在 Release 頁面核對版本。
:::

### 手動升級

也可以從 [GitHub Releases](https://github.com/DiceZone/Dice-Next/releases) 下載對應平臺的新包，停服後**完整覆蓋程式檔案**——exe、執行庫、`i18n/`、`web/dist/`、`docs/` 與包內內建資源都需要更新。

個人資料不會被安裝包清空：

- 配置目錄 `config/` 不在發行包內；
- `data/` 下的資料庫、跑團日誌、媒體與使用者自建資源會保留；
- 內建 `data/helpdoc` 會隨版本重新整理，`data/plugins` 採用覆蓋內建檔案但保留其他檔案的方式更新。

升級前仍建議從管理面板製作備份，或手工備份 `config/` 與 `data/`。

## 將管理面板安裝為應用

瀏覽器允許安裝時，頂欄右側會出現「安裝應用」按鈕（窄屏在「更多」選單中），點選即可；**WebUI 設定 → 安裝為應用**也提供同一入口。瀏覽器不支援、當前地址不滿足條件或已經安裝時，這個按鈕不顯示，設定卡片會說明原因和替代方式。也可以使用瀏覽器自身的入口：Chrome / Edge 位址列圖示或選單中的“安裝 Dice!Next”；macOS Safari 的“新增到程式塢”；iOS / iPadOS Safari 的“分享 → 新增到主螢幕”。Firefox 等瀏覽器可能不支援安裝網頁應用。

**必須使用 HTTPS，或在執行 Dice!Next 的電腦上開啟 `http://localhost:端口` / `http://127.0.0.1:端口`。** 通過 `http://局域网 IP:端口` 訪問時，瀏覽器出於安全限制不允許安裝，這不是 Dice!Next 的故障；請配置 HTTPS 反向代理，不要為此關閉瀏覽器安全限制。清單使用相對地址，部署在反向代理子路徑（如 `https://example.com/dice/`）下同樣可以安裝。

安裝的只是當前地址的管理面板獨立視窗，**不會安裝或後臺啟動機器人後端**。後端仍需執行，登入校驗不變。為滿足瀏覽器的安裝條件，面板註冊了一個只處理頁面導航的 Service Worker：它**不快取任何內容**，每次請求都直接訪問後端，設定、日誌與管理 API 不會離線讀取；後端不可達時僅顯示連線提示。伺服器地址改變後需從新地址重新安裝。
