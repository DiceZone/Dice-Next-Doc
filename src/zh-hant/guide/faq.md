# 常見問題 FAQ

這裡收集首次使用、日常維護與恢復配置時常見的問題。程式無法啟動、適配器斷線或指令沒有回覆時，也可檢視[故障排查](/zh-hant/guide/troubleshooting)。

## 忘記管理面板密碼怎麼辦？ {#reset-password}

需要能訪問伺服器上的配置檔案。託管使用者沒有檔案許可權時，請聯絡託管方處理；QQ 骰主賬號、適配器 Token 和 WebUI 登入密碼不是同一個憑據。

1. **先限制管理面板的外部訪問**，例如暫時關閉反向代理入口或僅允許自己的 IP。重置後會開放首次設定密碼的入口，應避免被他人搶先設定。
2. 停止 Dice!Next；若由服務或守護程序管理，也要停止該服務，確認它不會立即重新拉起程式。
3. 備份實際使用的配置目錄。預設是 `config/`，自訂路徑或容器掛載位置見[下文](#config-location)。
4. 用文本編輯器開啟 `config/webui.json`，只把頂層 `password` 的值改成空字串：`"password": ""`，保留其他欄位。不要把整個檔案替換成這一小段。
5. 刪除同一配置目錄內的 `webui_sessions.json`（如果存在），撤銷已儲存的可信裝置會話；不要把舊會話檔案恢復回來。
6. 啟動程式，通過受限入口打開面板，在首次設定頁面設定新密碼。密碼須為 **8–64 位**，包含大寫字母、小寫字母、數字和半形特殊符號，不含空格、中文或全形字元。
7. 確認新密碼可以登入後，再恢復正常訪問入口。

**空密碼會要求重新設定密碼，不是免登入模式。** 配置裡的密碼可能是雜湊，不必嘗試還原或手工生成；讓設定頁面儲存新密碼即可。此次操作不需要刪除資料庫、人物卡或插件。

## 勾選了“信任此裝置”，為什麼還要登入？ {#login-session}

密碼登入的可信會話最長保留 30 天，需要瀏覽器 Cookie 和伺服器的 `config/webui_sessions.json` 同時存在。請檢查：

- 是否換了瀏覽器、無痕視窗或訪問域名（`localhost`、`127.0.0.1` 和自己的域名不是同一地址）。
- 瀏覽器是否清除了 Cookie，或設定了關閉時清除網站資料。
- 配置目錄是否可寫、會話檔案是否被刪除，以及服務重啟後是否仍使用同一配置目錄。
- 是否修改過密碼或主動退出登入；這些操作會使相應會話失效。

第三方賬號登入有自己的會話規則，不要把密碼登入的 30 天規則套用於所有登入方式。

## 配置檔案到底在哪？ {#config-location}

正常使用發行包管理器啟動時，預設在安裝目錄的 `config/`。啟動日誌會顯示實際讀取的配置目錄。如果服務啟動引數指定了其他配置目錄，以該路徑為準；相對路徑要結合程序的工作目錄判斷。

容器內的 `config/` 對應宿主機的掛載目錄或卷，需要檢視自己的 Docker / Compose 配置。不要只改臨時容器裡的另一份檔案。多個骰子實例應分別使用自己的配置目錄、資料目錄和監聽埠。

| 想修改的內容 | 預設檔案 |
| --- | --- |
| 面板監聽地址、埠、資料庫路徑、日誌級別 | `config/server.json` |
| 面板密碼及介面設定 | `config/webui.json` |
| 平臺連線、適配器引數 | `config/adapters.json` |
| 骰主、指令、回覆行為與 AI 配置 | `config/dice.json` |
| 好友與群邀請策略 | `config/events.json` |
| 預設回覆語言 | `config/i18n.json` |

檔案完整欄位見[基礎配置](/zh-hant/config/basic)。人物卡、跑團記錄等並不全在這些 JSON 中；備份時也需要資料檔案。

## 怎樣手動修改配置？ {#edit-config}

優先使用面板；面板無法開啟或需要恢復設定時，再編輯檔案：

1. 停止程式及自動拉起它的服務，備份原檔案到配置目錄之外。
2. 用文本編輯器以 **UTF-8** 儲存，保留原有結構，只修改目標欄位。
3. 檢查 JSON 格式：鍵和字串使用英文雙引號；不能寫註釋或尾隨逗號；布林值寫 `true` / `false`，埠等數字不要加引號。
4. 啟動程式，檢查配置載入日誌，再確認頁面或指令中的實際效果。失敗時停止程式，恢復備份檔案後重新啟動。

例如，修改 `config/server.json` 內的埠為數字 `18089`。該檔案裡直接使用 `"port": 18089`，**不用**再套一層 `"server": { ... }`。`adapters.json` 的頂層是陣列，不能照搬其他檔案的物件結構。

不要刪除整個配置目錄來“重置一個設定”，也不要把網上的完整示例覆蓋到現有檔案。手動配置備份請放在目錄外，避免 `.json` 備份被當作新的配置區讀取。

## 改了檔案卻沒生效，或重啟後又變了？ {#config-not-applied}

- 先確認改的是當前實例實際使用的檔案，且儲存成功、執行賬號有寫入許可權。
- 程式執行時，面板儲存、指令或其他配置寫入可能覆蓋手工編輯。停止程式後修改更可靠。
- 支援熱過載不等於所有設定都能立即生效。**監聽地址和埠需要重啟**；其他設定不確定時也應安排重啟驗證。
- 有分適配器、分賬號或群設定的功能，可能覆蓋全域性預設值。回到對應作用域檢查，不要反覆修改全域性值。
- JSON 解析或校驗失敗時，先看啟動日誌中的具體檔案與錯誤；不要假定修改已經載入。

## 本機能打開面板，另一臺裝置打不開？ {#panel-access}

另一臺裝置上的 `127.0.0.1` / `localhost` 指向它自己，不是骰娘伺服器。應訪問伺服器的實際地址和埠，並檢查監聽地址、防火牆與雲伺服器安全組。

預設埠是 `18088`，被佔用時可能順延，以啟動日誌或 `config/server.json` 為準。用域名反代時，代理目標埠也要同步修改。部署 HTTPS 和反向代理見[部署與運維](/zh-hant/guide/deploy)。

## 備份和換伺服器要帶哪些檔案？ {#backup}

建議先在面板製作備份，檢查備份所選專案，尤其是插件、牌堆、圖片和媒體是否包含在內，並把備份下載到另一臺裝置。

手動備份時，**停服後**複製實際使用的配置目錄和整個 `data/`，同時儲存放在這些目錄以外的自訂插件、資源及資料庫。自訂資料庫位置以 `server.json` 的 `db_path` 為準。執行中只複製一個 `.db` 可能遺漏尚未寫回的資料。

換伺服器先安裝對應作業系統和架構的完整發行包，再恢復配置與資料；不要把 Windows 執行檔直接搬到 Linux 使用。啟動前檢查絕對路徑、檔案許可權、埠和適配器地址。舊伺服器先停服，避免兩邊同時登入或處理同一批訊息。舊 Dice 的資料請使用[遷移工具](/zh-hant/guide/migration)，不要直接覆蓋 Next 資料庫。

## 升級後頁面空白、404 或樣式不完整？ {#webui-update}

先確認開啟的是正確實例和埠，嘗試重新整理頁面。若持續失敗，檢查是否只更新了執行檔而遺漏 WebUI：應使用同一版本的完整發行包，包含 `web/dist/`、執行庫及其他配套資源。不要混用不同版本的前後端，也不要用刪除 `config/` 或 `data/` 的方式排查。

手動修復前停服並備份，再按[完整升級步驟](/zh-hant/guide/install#升級)更新程式檔案。反向代理部署還應檢查靜態資源請求是否被錯誤快取或轉發到舊實例。

## 為什麼無法自動安裝更新？ {#auto-update}

完整安裝需要通過發行包管理器啟動：Windows 使用 `dice-next.exe`，Linux/macOS 使用包內的 `start.sh` 或 `dice-next`。直接執行 `dice-next-server` 僅能檢查和下載。容器內只檢查和通知，請更新映像並重新建立容器。

下載失敗時檢視頁面提供的錯誤，檢查來源可達性、磁碟空間與寫入許可權；可嘗試內建映像或 GitHub。不要關閉校驗來強行安裝不完整包。定時安裝使用伺服器設定的時區；自動安裝開啟且包已就緒時，提前重啟也會安裝，詳見[更新設定](/zh-hant/manage/settings#檢測與自動更新)。

## 已連線卻不回指令，怎麼區分問題在哪？ {#no-reply}

先發一條簡單的 `.r 1d6`，檢視首頁執行日誌：

- **沒有收到訊息的記錄**：檢查適配器登入、事件訂閱和平臺訊息投遞；QQ 官方平臺可嘗試 `/r 1d6`，並檢查自己設定的指令字首。
- **收到但沒有回覆**：檢查群內 `.bot off`、全域性靜默、停用指令、黑白名單及插件規則。
- **已生成回覆但傳送失敗**：看平臺返回的具體錯誤，檢查賬號是否仍在群裡、是否有傳送許可權及內容是否被平臺拒絕。

可在[測試臺](/zh-hant/manage/playground)驗證指令本身，但測試臺成功不代表真實平臺一定能投遞訊息。回覆格式、按鈕和圖片的支援也因適配器而異。

## 反饋問題時應該提供什麼？ {#report}

提供版本號、作業系統、適配器型別、發生時間、復現步驟、預期和實際結果，並附上同一時段的相關日誌；崩潰時加上崩潰報告。日誌位置見[故障排查](/zh-hant/guide/troubleshooting)。

發出前檢查並遮蓋密碼、Token、API Key、AppSecret、會話檔案內容及不相關的私人聊天。**不要公開上傳整個配置目錄或資料庫**。只說“沒反應”很難定位；一條可復現的指令和對應日誌通常更有效。
