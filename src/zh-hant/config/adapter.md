# 適配器配置

Dice!Next 採用插件式適配器架構。請在 [管理面板 → 適配器管理](/zh-hant/manage/adapter-manager) 裡新增和管理適配器；配置會儲存到 `config/adapters.json`，並在下次啟動時直接載入。

## OneBot v11 適配器

支援兩種傳輸模式，對應配置裡的 `connection_mode`：

| 模式 | `connection_mode` | 含義 | 端點填法 |
|------|-------------------|------|----------|
| 正向 WebSocket | `forward_ws` | Dice!Next 主動連線 OneBot 客戶端 | 完整 WS 地址，如 `ws://127.0.0.1:3001/` |
| 反向 WebSocket | `reverse_ws` | OneBot 客戶端反連 Dice!Next | 一個**埠號**（如 `6700`），Dice!Next 在該埠監聽 |

反向模式下，在 OneBot 客戶端把反向 WS 上報地址指向 `ws://<Dice!Next 所在 IP>:<端口>/`；該埠只接受一個 OneBot 連線，多餘連線會被直接關閉。

::: tip 斷線重連（正向 WS）
斷線後自動重連採用退避策略：前 10 次每 5 秒、第 11~20 次每 60 秒；連續 20 次失敗後暫停自動重連，狀態顯示「連線超時」，在面板點手動重連即可恢復（連線穩定 30 秒後失敗計數自動清零）。
:::

## 配置檔案欄位

適配器陣列寫在 `config/adapters.json`：

```json
{
  "adapters": [
    {
      "name": "MyQQBot",
      "type": "onebot_v11",
      "connection_mode": "forward_ws",
      "endpoint": "ws://127.0.0.1:3001/",
      "access_token": "",
      "enabled": true
    }
  ]
}
```

| 欄位 | 說明 |
|------|------|
| `name` | 適配器顯示名 |
| `type` | 協議型別；OneBot v11 使用 `onebot_v11` |
| `connection_mode` | `forward_ws` / `reverse_ws` |
| `endpoint` | 正向：OneBot 端的 WS 地址；反向：監聽埠號 |
| `access_token` | 連線令牌，留空則不攜帶（正向連線時以 `Authorization: Bearer` 頭髮送，與 OneBot 端保持一致） |
| `enabled` | 是否啟用 |

## 通過管理面板配置

進入 **管理面板 → 適配器管理**，新建連線並按平臺填寫連線資訊，儲存並啟用即可。面板修改即時生效，無需重啟。

## 多適配器

可以新增多個適配器，連線不同賬號或作為備用連線。

## Milky 適配器

平臺連線中選擇 **Milky**。API 通過 HTTP 呼叫，事件通過 WebSocket 接收；當前僅支援 `forward_ws`，不支援 Webhook 入站。

| 欄位 | 說明 |
| --- | --- |
| API 地址（`endpoint`） | Milky 服務的 HTTP / HTTPS 基址，例如 `http://127.0.0.1:3000`；不是 OneBot WS 地址 |
| 事件地址（`eventEndpoint`） | WebSocket 地址，例如 `ws://127.0.0.1:3000/event`；留空時由 API 地址推導 |
| 連線模式（`connectionMode`） | `forward_ws`，由 Dice!Next 主動連線事件服務 |
| Access Token（`accessToken`） | 與 Milky 服務端一致的認證令牌，不是 BDC 骰娘金鑰 |

支援群聊 / 私聊、群成員與名片、群檔案及相關管理能力，具體操作仍取決於協議端實現與骰娘許可權。臨時私聊保留來源群資訊，但不會把群號當成私聊目標。群歷史單次讀取按協議限制為 1–30 條。

連線服務不要直接無認證暴露到公網。API 連通不代表事件已連線；沒有訊息響應時同時檢查 API 地址、事件地址、認證和服務端日誌。

## QQ 官方機器人能力邊界

- 群聊、C2C 與頻道的能力並不相同。群聊 / C2C 的 Markdown 需要相應平臺許可權；頻道按自身支援的訊息格式傳送，不應預設視為同樣支援 Markdown。
- 已提供群資訊、成員、管理、撤回、選單及頻道等官方介面，可通過 [後臺 API 動作入口](/zh-hant/develop/qq-official-api#後臺呼叫入口) 呼叫 `qq_*` 動作；介面可能要求內邀或白名單，未獲許可權時仍會返回平臺錯誤。
- `.log export` 已接入富媒體檔案通道（`file_type=4`）。檔案上傳有 200MB 預檢限制，最終是否可傳送仍取決於平臺與賬號許可權；收不到檔案時可改用日誌站連結或 WebUI 下載。
- 當前介面接入和離線測試不等於所有真實賬號場景已驗收。排查時保留錯誤碼與時間，不要公開 AppSecret、Token 或玩家敏感資料。

### 官方暱稱與群名稱

群訊息、群 @ 訊息和單聊訊息中的 `author.username` 會進入暱稱快取；為空時使用已有快取，而不是用“使用者”或 OpenID 覆蓋真實暱稱。快取按機器人 AppID 區分，重啟後仍可複用，並同步到玩家檔案。成員查詢取得的暱稱也會用於成員列表、事件通知與插件事件。

連線成功後，Dice!Next 會在後臺預熱當前機器人已知且尚未退出的群。近期有訊息收發時暫緩預熱；空閒時輪流重新整理群名稱及成員暱稱，每次只取一頁，過期資料約每小時重新重新整理。收到新群訊息或入群事件後，該群也會進入佇列。普通 `bot off` 不影響名稱預熱，退群、刪除群記錄或停止適配器則會停止對應重新整理。

群成員介面每頁最多返回 30 人，Dice!Next 會儲存分頁游標繼續獲取，不再以 3000 人作為整群截斷上限。遇到限流或一次批次結束時暫停，後臺稍後接著取；每頁取得的暱稱立即進入快取，但只有完整取完的名單才用於成員列表和群管理。重複游標、異常分頁和請求失敗不會把半份名單標記為完整名單。

好友新增事件 `FRIEND_ADD` 本身沒有暱稱欄位。若已有相同 OpenID 的暱稱，或平臺提供的 `union_openid` 對應已有暱稱，通知可直接複用；首次出現且沒有任何已知名稱時仍顯示未知使用者。統一標識僅用於複用名字，不自動繫結賬號、合併人物卡或共享許可權。

群名稱通過 `GET /v2/groups/{group_openid}/info` 的 `group_name` 獲取，並持久儲存到群資料。群資訊、成員列表和成員詳情介面需要平臺白名單許可權；未獲許可權時會返回 `11253`。查詢在後臺進行，失敗保留舊名稱並退避重試，不阻塞訊息等待暱稱，也不把部分名單當作完整名單。

介面依據：[群訊息事件](https://bot.q.qq.com/wiki/develop/api-v2/autogen/event/group_message_create.html)、[好友新增事件](https://bot.q.qq.com/wiki/develop/api-v2/autogen/event/friend_add.html)、[群資訊](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_info.get.html)、[成員列表](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_members.get.html)、[成員詳情](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_members_member_openid.get.html)。

### 群成員與互動事件

官方適配器設定提供兩個開關：

- **訂閱群成員進出事件**：接入官方 `GROUP_MEMBER_EVENT (1<<24)`，將成員加入、退出事件送入歡迎詞、群管理及插件事件，並更新成員快取。面板新建時預設開啟，已有賬號保留原訂閱設定；需具備平臺對應能力，儲存後重新連線。
- **自動回應互動事件**：預設開啟，對訊息按鈕和快捷選單事件（型別 11、12）回應一次，結束 QQ 客戶端的載入狀態。收到回呼不等於指令已執行，回呼資料不會自動作為聊天指令執行。如果插件或外部處理器需要自行選擇回應碼，請關閉自動回應。

訊息反饋、清空會話、故事集、切換模型、使用者／群授權及訂閱模板授權狀態可交給原生插件事件鉤子處理。授權通知不會自動解除黑名單、開啟骰子或授予管理許可權。新的時間戳、引用索引、卡片及訊息場景資料也會保留；重複推送按訊息 ID 和訊息索引去重，避免同一指令重複執行。

官方介面呼叫、原生插件鉤子及引數示例見 [QQ 官方 API v2 能力](/zh-hant/develop/qq-official-api)。

## 回覆文案與視覺方案

在 **系統設定 → 基礎設定 → 回覆與顯示 → 回覆文案與視覺方案** 選擇傳統、標準或高階視覺文案。設定可分別作用於全域性、適配器型別和單個賬號，優先順序為賬號 > 適配器型別 > 全域性；區域性覆蓋可以獨立選擇任意方案，不再受舊版二元“全域性主開關”限制。

| 平臺 | 富文本表現 | 說明 |
| --- | --- | --- |
| OneBot v11 | 傳統文本 | OneBot 標準沒有統一的跨實現卡片協議。 |
| Milky | 傳統文本與協議訊息段 | 不套用 QQ 官方機器人的 Markdown 能力。 |
| Discord | Embed | 超過 Embed 長度限制的訊息自動保持傳統文本。 |
| KOOK | CardMessage | 使用官方卡片訊息格式；過長內容自動保持傳統文本。 |
| QQ 官方機器人 2.0 | Markdown | 平臺需要為機器人開通 Markdown 能力；若介面連續拒絕，Dice!Next 會暫時熔斷並直接傳送傳統文本。 |

Markdown 模板只保留一份可編輯原稿。Dice!Next 會在內建文案載入、自訂文案儲存或人格載入時自動生成純文字版本；傳送時先根據來源適配器和作用域設定選好版本，再代入暱稱、骰式等動態變數。傳統文案使用歷史措辭覆蓋層，標準文案使用當前預設文案，高階視覺文案在同一份語義資料上增加狀態條與操作提示，不要求骰主維護三份容易不一致的內容。QQ 官方啟用互動後，用法行與 `[[action:说明|.指令]]` 會成為待填充按鈕；其他適配器繼續收到完整文字，不會混入 QQ 專屬標籤。

## 適配器人格範圍

在[指令列表 → 人格開放](/zh-hant/manage/commands)中選擇機器人賬號後，可以單獨設定以下選項；這些設定不再放在平臺連線的新增 / 編輯彈窗中：

- **預設人格**：跟隨全域性，或為這個機器人固定指定人格。
- **使用者人格選擇**：開放全部人格、只開放勾選的人格，或禁止普通使用者通過 `.rpmode` 切換。

預設人格和開放列表相互獨立。骰主始終可以在 WebUI 為適配器或群繫結任意人格；開放列表只約束群管理、邀請人和私聊使用者通過聊天指令能夠發現和選擇的內容。這樣多個機器人可以共享同一套人物卡和回覆資料，同時保持各自的角色範圍，不會互相暴露不合適的人格。

卡片上的可點選按鈕需要對應平臺的互動事件與具體業務授權。Dice!Next 只會在某個功能確實需要使用者選擇、且該平臺能力可用時提供按鈕，不會把管理或敏感操作做成通用按鈕。

## QQ 官方機器人 2.0

在適配器管理頁選擇 **QQ 官方機器人 2.0**。在方形掃碼區域下方點選「手動輸入 AppID 與 AppSecret」可切換為憑據表單。事件接收方式可選 WebSocket 或 Webhook；Webhook 回呼地址會按當前頁面域名和部署路徑生成，新增後可通過卡片上的「連線方式」檢視和複製。訊息傳送仍使用官方 API。詳見[QQ 官方連線說明](/zh-hant/manage/adapter-manager#qq-官方機器人)。

自 [2026-08-10 的 QQ 機器人 2.0 能力更新](https://bot.q.qq.com/wiki/develop/api-v2/changelog.html#_20260810)起，OpenAPI 請求統一使用 `https://api.bot.qq.com`。Dice!Next 已統一鑑權、Gateway、資料、分享連結、訊息和富媒體等請求域名；舊域名不再用於介面呼叫。

在“標準文案”或“高階視覺文案”方案下，適配器可傳送 Markdown。適配器編輯頁可開啟 **Markdown 圖片資源強校驗**：開啟後，如果 QQ 平臺無法轉存 Markdown 中的圖片，整條訊息會失敗並回退純文字；預設關閉，以保持平臺原有相容行為。對應 `config/adapters.json` 欄位為 `force_verify_image_resource`。若同一適配器連續兩次收到 Markdown / 卡片 HTTP 拒絕，Dice!Next 會在接下來的 10 分鐘直接使用預渲染純文字；冷卻結束後自動再次探測，不需要手動重連。

QQ 官方平臺以 OpenID 標識使用者和群聊，而不是直接提供真實 QQ 號。Dice!Next 可將已驗證的 OneBot QQ 身份與官方 OpenID 關聯，使人物卡、群設定和日誌沿用同一記錄；使用 `.info` 可檢視當前視窗的身份和繫結指引。

::: warning 群許可權說明
新版官方訊息事件提供 `member_role` 時，Dice!Next 使用其中的管理員／群主角色；缺失時仍沿用骰主及本賬號已記錄邀請人的相容規則，不依據暱稱判斷許可權。禁言、入群審批和自動審批策略介面要求**機器人自身是群管理員**；若許可權不足，QQ 平臺會拒絕請求並在面板顯示錯誤。
:::

### 官方群管理

在 **群組管理 → 選擇 QQ 官方機器人賬號 → 官方群管** 中可使用以下能力：

- 查詢當前全員禁言模式和仍在生效的成員禁言，並按成員 OpenID 設定或解除禁言；
- 拉取當前群的待處理入群申請，檢視驗證訊息、問答、來源與風險提示，並人工通過或拒絕；
- 建立、啟停、修改備註、執行或刪除入群自動審批策略，並批次增刪白名單 QQ 號。

Gateway 的 `GROUP_JOIN_REQUEST` 事件也已接入統一事件管線。它會通知骰主，並複用 `.group auto pass` 及全域性加群申請策略；事件中的 `join_request_id` 會隨審批請求原樣回傳。官方自動審批策略由 QQ 平臺執行，和 Dice!Next 的本地關鍵詞自動審批可以並存。

::: tip 介面限制
入群申請事件要求機器人為群管理員，並使用 `GROUP_AND_C2C_EVENT (1<<25)` Intent。介面頻率、白名單資格和具體錯誤碼由 QQ 官方平臺控制。
:::

## Discord

在適配器管理頁選擇 **Discord**，填入 Discord Developer Portal 建立的 Bot Token 即可。適配器通過 Discord Gateway 接收伺服器頻道和私聊訊息，支援 `@机器人 指令`、頻道訊息和私聊訊息。

請在 Discord Developer Portal 的 Bot 設定中開啟 **Message Content Intent**，否則 Discord 不會向機器人提供普通訊息正文。

## KOOK

在適配器管理頁選擇 **KOOK**，填入機器人 Token。適配器通過 KOOK Gateway 與 REST API 連線，支援伺服器頻道、私聊、文本與 KMarkdown 訊息，以及 `@机器人 指令`。

## 適配器開發

適配器按統一介面接入，便於繼續擴展其他平臺。開發方式詳見[適配器開發](/zh-hant/develop/adapter-dev)。

## 常見問題

- **連線不上**：檢查端點地址與埠、防火牆、Access Token 是否匹配；在儀表盤日誌檢視詳細錯誤。
- **狀態「連線超時」**：自動重連已暫停（連續 20 次失敗），修好 OneBot 端後手動重連。
- **訊息丟失**：確認適配器狀態為「已連線」，且 OneBot 客戶端正常上報訊息事件。

更多排查見[故障排查](/zh-hant/guide/troubleshooting)。
