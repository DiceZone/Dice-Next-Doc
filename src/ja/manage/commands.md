# コマンド一覧

**管理パネル → コマンド一覧** では、すべてのコマンドを 1 か所で確認し、**ボットの返信文をカスタマイズ** して、ボットの **ペルソナ** も管理できます。

ページの上部にはペルソナのプルダウン、「ペルソナの管理」と「ペルソナの公開」のボタンがあり、その下に編集できるすべての文章を分類ごとのタブで表示します。

## 全体の検索

分類のタブの上にある検索欄はすべての分類に効きます。コマンド名（`.` の有無を問わない）、例、説明、分類、返信のキー名、現在の返信文で検索でき、複数のキーワードはすべて一致する必要があります。検索中は、すべての分類から一致したコマンドを一覧に表示して所属する分類を示し、分類のラベルをクリックすると検索を解除してその分類に移動します。左のタブには各分類の一致件数を表示します。一致する返信文もある場合は結果の上に件数を表示し、クリックすると「すべての文面」で確認できます。

## ダイスの返信にキャラクターシートの状態を表示する

ダイスの文面を 1 つ編集し、本文の下の **ボタン、ステータスバーと式 → ステータスバーを追加** で、名前、現在値、最大値を入力します。既定では `[[bar:HP|{hp}|{hpmax}]]` を挿入します。保存すると、返信の送信時に現在のキャラクターシートの HP と最大値を読み取ります。`[[bar:SAN|{san}|{sanmax}]]` に変えることもできます。全体の検索で「SN」や「状态条」（ステータスバー）と入力しても入口が見つかります。

別に独立した `.sn` の機能もあります。QQ 公式のグループで `.sn` または `/sn` を実行すると、その後の返信の先頭に現在のキャラクターシートの状態を表示し、`.sn off` で自分の状態行をオフにします。ダイスマスターは[基本設定 → 返信と表示 → QQ 公式の SN 状態行](/ja/manage/settings#qq-公式の-sn-状態行)で見た目を調整したり表示をオフにしたりできます。QQ 公式では実際のグループ内の名前を変更できないため、返信の先頭に表示する方式を採っています。グループ内の名前の変更に対応しているほかのアダプターでは、引き続き実際の名前を変更します。動的なステータスバーは、ダイスの文面の指定した位置に数値を入れるためのもので、先に `.sn` を実行する必要はありません。

## タブ

| タブ | 内容 |
|---|---|
| すべての文面 | すべてのコマンドの返信文（1 つずつカスタマイズ可能） |
| すべての変数 | 文面で使える変数の説明 |
| 無効な文面 | 参照されているがもう存在しない孤立した文面のキー（整理用） |
| ダイス | 式によるダイス、ダイスプール、ダイスのエラーの案内 |
| COC | COC の判定、正気度、技能の成長、BRP の判定と対抗。成功度のフレーズを含む |
| DND | DND のキャラクター作成、能力値の判定、イニシアチブと関連するルール |
| セッション | セッションログ、会話、セッション管理の操作 |
| 交流 | デッキ、娯楽、AI の会話、ボットのペルソナの切り替え |
| ツール | キャラクターシート、能力値の管理、ニックネームなどの便利な機能 |
| 管理 / 権限 / システム | グループとアカウントの管理、権限の案内、システム設定、旧版の文面との互換 |

「すべての文面」は **コマンドの例 → 説明 → キー名 → 現在の文章** の順に表示し、各列の見出しをクリックすると昇順 / 降順を切り替えられます。狭い画面のカード表示でも並べ替えの選択肢があります。上部の全体の検索もこの表に効き、コマンドの例、機能の説明、元祖のキー名、現在の文章をまとめて照合し、機能の分類で絞り込むこともできます。決まったコマンドのない自動のイベントや共通の案内ははっきり表示し、存在しないコマンドを作り出すことはありません。

各機能のグループを開いて、対応する文面を直接編集することもできます。たとえば「COC → 判定結果の成功度」では、クリティカル、イクストリーム、ハード、レギュラー、失敗、ファンブルを変更できます。BRP は独立した機能の項目と結果の文面を持ちますが、タブは COC と共有しています。キャラクターシートの機能は「ツール」に、デッキ、娯楽、AI は「交流」に入ります。取り込みや拡張で入ってきた未知の文面は、未分類として「すべての文面」に残ります。ただし、独立した `help.topic.*` のカスタムヘルプは[ヘルプ文書](/ja/manage/help-docs)に移っているため、無効な文面として整理しないでください。コマンドに関連付いた使い方の文章や、ペルソナの層でのヘルプの文章の編集には影響しません。

各文章の右の `編集` で書き換えられ、変更した項目には `●` が付き、ワンクリックで既定の文面に **元に戻す** ことができます。「システム → 旧版の文面との互換」には `.strSelfName` / `.strSelfCall` の返信も含まれます。名前と自称そのものは引き続き専用の設定を使い、通常のテンプレートの上書きには変えていません。

「ツール → ショートカット」には `.alias` / `.&` / `.a` の管理の返信、一覧、呼び出しの結果の前置きが含まれ、タイトルの横の疑問符で使い方の全体を確認できます。文面専用の変数には `{shortcut}`（ショートカットの名前）、`{source}`（グループ / 個人）、`{command}`（展開後の対象のコマンド）、`{list}`（一覧）があり、プレビューではその言語の例の値を使い、対象は実行しません。呼び出しの前置きと本文は自動で改行して分けます。前置きを空にして隠すこともできますが、対象の処理やスイッチは変わりません。旧来のアカウントの権限の関連付けの返信は引き続き「権限 → アカウントの別名」にあり、`.admin account-alias` に対応していて、新しいショートカットの文面で上書きされることはありません。

## 返信文のカスタマイズ

ボットのほとんどの返信（ダイスの結果、判定の成功 / 失敗、さまざまな案内）はテンプレートの文章として保存されており、ここで口調を書き換えられます。項目の「編集」をクリックすると編集のダイアログが開きます。

- **広い画面**：左で編集し、右でリアルタイムにプレビューします。2 つの列はそれぞれスクロールし、変更中も期待される返信をいつでも確認できます。
- **狭い画面**：上部の「編集 / 期待される返信の例」で切り替えます。
- 保存、破棄、「プリセットを読み込む」は下部に固定されています。

### ロールの理由と文面の継承

通常の 1 回分の返信 `dice.roll.result` と、理由付きの返信 `dice.roll.result_reason` は別々に設定できます。理由付きの返信を個別に設定していない場合は、現在のペルソナまたはグローバルでカスタマイズした通常の 1 回分の文面を引き継ぎ、どちらも設定していない場合は元の内蔵の文面を使います。複数回分も同様で、`dice.roll.multi_reason` はカスタマイズ済みの `dice.roll.multi` を引き継ぎます。明示的に保存した空の返信は、引き続き何も出力しないことを表します。

たとえば入力 `.r 5-\(-1\)` にはバックスラッシュが含まれ、有効な算術式ではありません。旧版との互換の処理ではこれを既定のダイスの理由として扱い、上の文面の継承にも従います。負の数を引く計算には `.r 5-(-1)` を使い、結果は `6` です。

### 編集と書式のツールバー

文章の入力欄の上には Markdown の書式のツールバーがあります：**太字、斜体、取り消し線、インラインコード、見出し、引用、箇条書き、番号付きリスト、区切り線、リンク**。文字を選んでクリックすると適用し、もう一度クリックすると解除します。何も選んでいない場合は、そのまま書き換えられる例の文章を挿入します。太字と斜体は Ctrl/⌘+B、Ctrl/⌘+I でも使えます。

- 複数行にまたがる選択は行ごとに適用します。QQ、Discord、KOOK のインラインの書式は行をまたげないためです。
- 通常の文章の後にリストを加えると、QQ で必要な空行を自動で補います。
- 区切り線 `***` が表示されるのは QQ 公式だけで、Discord と KOOK では原文のまま表示されます。
- QQ 公式の Markdown は見出し、太字 / 斜体 / 取り消し線、リンク、画像、リスト、引用、区切り線に対応し、表とコードブロックには対応していません。内蔵のプリセットもこれらの書き方だけを使っています。

ツールバーは原本に目印を付け外しするだけで、`{変数}`、`[[ボタン]]`、`{sample:…}` などのテンプレートの構文は、見えているとおりのまま書き換えたりエスケープしたりはしません。

変数と画像のボタンは、文章の入力欄のすぐ下にあります。

- コマンド専用の変数は薄い色のチップで表示し、クリックするとカーソルの位置に挿入します。
- 汎用の変数は「グローバル変数を挿入」で挿入します（`{nick}`、`{user}` など）。
- `{FormFeed}` は旧版と互換の強制改ページの目印で、ニックネームのような表示する値ではありません。プレビューでは実際のメッセージごとに分けて表示します。

ボタン、ステータスバー、式はすべて同じテンプレートに書き込まれます。本文の下でそれぞれ追加・編集・削除でき、ソースを直接変更することもでき、本文を変更しても残ります。

### 内容の形式

**新しく編集する文面は既定で Markdown を使います**。QQ 公式ボット、Discord、KOOK などのプラットフォームではリッチテキストとして送り、OneBot などの文章だけのプラットフォームでは保存時に生成した文章だけの版を自動で使い、見えている文字、CQ コード、ダイスの式を保持します。

**テキスト** は旧版の文面、プラグインの返信、過去のペルソナの文面に使い、`**`、`#`、`>` などの文字はそのまま送ります。テキストとして保存済みの項目では、編集時に上部に案内が表示され、「Markdown に変換」が用意されます。

- サーバーは `{変数}`、`[[ボタン]]` 以外で実際に書式を引き起こす文字にだけエスケープを付けるため、プレイヤーに見える文字は変わりません。
- 変換すると書式のツールバーが使えるようになります。

**旧版から移行する場合も 1 つずつ変更する必要はありません**。コマンド一覧の右上の「その他 → すべて Markdown に変換」で、現在の言語と現在編集している層（グローバルまたはあるペルソナ）ごとに一括で変換します。変換の前に件数と、そのうちエスケープが必要な件数を表示し、確認した後に書き込みます。

形式の選択は「高度なオプション」にあり、既定では閉じていて、この項目の既定の文面も一緒に表示します。

ニックネームや理由などの動的な値は引き続きサーバーでエスケープし、プレイヤーの入力でテンプレートのレイアウトが変わらないようにしています。成功度のフレーズ（「COC → 判定結果の成功度」の失敗など）、心理学の返信、好感度の称号なども文面です。

- Markdown として保存すると、判定の結果に入れた後も自分のスタイルを保ち、文章だけのプラットフォームでは文字だけを表示します。
- テキストとして保存すると、`**` などの文字は原文のとおり表示します。
- 編集のプレビューと実際の返信は同じルールで処理します。

編集するのはこの Markdown の原本 1 つだけです。保存時にサーバーが文章だけの版も作り直します。内蔵のテンプレートは起動 / 再読み込みのときに、ペルソナのテンプレートは読み込みのときに生成します。2 つの版は同じ `{変数}` を保ち、実際に返信するときに初めて実際の値を入れるため、表示の形式を切り替えても 1 つずつ保存し直す必要はありません。

### プリセットの読み込み

下部の「プリセットを読み込む」メニューで、編集の出発点を選びます。

- **従来 / 標準 / 高度なビジュアル**：その表示方式の完全な内蔵の文面、ボタン、ステータスバーを現在の返信に入れます。内容がある場合は先に確認し、ほかのランダムな返信と重みは保持します。保存すると反映されます。アカウントだけ別の表示方式を使っている場合は、ここで対応するプリセットを読み込めます。
- **カスタマイズを消去（既定に従う）**：保存済みのカスタムの文面を削除し、返信は再びグローバルの表示方式に従います。結果ごとに分けた項目では「継承に戻す」と表示します。

プリセットの読み込みはエディターの内容を変えるだけで、グローバルやアカウントの表示方式は変えず、既存のカスタムの文面が自動で置き換わることもありません。高度なビジュアルのプリセットは太字の見出しと引用ブロックでレイアウトし、絵文字は含みません。

### リアルタイムのプレビュー

プレビューの欄には次のものがあります。

- **プラットフォームの選択**：QQ 公式のグループチャット、C2C、チャンネルを別々に選べ、ほかに KOOK、Discord、OneBot / Milky / テキストがあります。チャンネルを QQ の Markdown としてプレビューすることはありません。
- **方式の選択**：従来、標準、高度なビジュアルと、`.bot text plain` の模擬。これらの選択はプレビュー専用で、保存済みのグローバル / アカウントの設定は変更しません。
- **文章での表示 / 送信の構造**：バックエンドは実際の文章 / カードのシリアライザーを使います。式は制限付きのローカルの数式描画で表示し、QQ クライアントのスクリーンショットではありません。CQ / メディアのアップロード、身元の対応付け、プラットフォームの権限は模擬しません。API が使えない場合はエラーを表示し、原文を代わりの結果のように見せることはしません。

テンプレートの変数は例の値を入れてプレビューします。これはレイアウトの確認専用で、実際のダイスを振ったりメッセージを送ったりはしません。

::: tip 表示方式全体の切り替え
**システム設定 → 返信と表示 → 返信文とビジュアル方式** で従来、標準、高度なビジュアルの文面を選べ、特定のプラットフォームやアカウントだけを上書きすることもできます。ペルソナは引き続き口調を、表示方式はレイアウトとインタラクションだけを制御します。
:::

> 文面を書き換えてもコマンドの処理は変わらず、外向けの言い回しだけが変わります。場面ごとに複数の口調を使い分けたい場合は、下の「ペルソナ」を使ってください。

## 判定結果ごとに返信全体を設定する

「COC → 結果ごとに分けた標準の返信」で、クリティカル、イクストリーム成功、ハード成功、成功、失敗、ファンブルの **返信全体** を、末尾の成功度のフレーズだけでなく個別に設定できます。ほかに BRP 用の「スペシャル」と、対抗用の「引き分け」もあります。

ほかの判定の機能の項目にも対応する成功度があり、個別に「この成功度の返信を個別に設定する」を有効にできます。継承の順序は次のとおりです。

```text
この種類の判定のその成功度の返信 → 標準の判定の同じ成功度の返信 → このコマンドの元の文面
```

設定していない成功度は引き継ぎを続け、固定の文章を自動でコピーすることはありません。「継承に戻す」をクリックすると、現在編集している層の上書きだけを削除します。ペルソナを編集するときは、ペルソナで設定していない同名の項目は先にグローバルの同名の項目を引き継ぎます。画面には現在の出所を表示し、引き継いだ文章をプレビューします。

| 判定 | 個別に設定できる結果 |
| --- | --- |
| COC `.ra/.rc/.rad`（シークレット判定を含む） | COC の 6 つの成功度。シークレット判定の詳しい返信は引き続き個人チャットにだけ送る |
| ボーナス / ペナルティ `.rb/.rp`、`.rab/.rap`、`.ra b/p` | それぞれ 6 つの成功度。技能 / 成功率のない純粋なボーナス・ペナルティダイスは成功・失敗を判定しない |
| BRP `.ba` | クリティカル、スペシャル、成功、失敗、ファンブル。スペシャルを COC のイクストリーム成功として扱うことはない |
| SAN `.sc`（ボーナス / ペナルティを含む） | COC の 6 つの成功度。文字が変わるだけで、喪失とシートからの減算は通常どおり行う |
| 成長 `.en` | 成功 / 失敗。成長の高い出目で判定し、COC の下方ロールの成功のルールは使わない |
| 心理学のシークレットロール `.rx` | 6 つの成功度の個人チャットでの詳しい結果。グループへの通知では引き続き結果を明かさない |
| 対抗 `.rav/.rcv` | 一方の勝ち / 負け / 引き分けで、それぞれ成功 / 失敗 / 引き分けの返信を使う |
| BRP の抵抗 `.bav` | 能動側の成功 / 失敗 |
| DND `.rdc` | 目標の難易度を指定したときに成功 / 失敗を判定する。難易度を指定しない `.rdc` と DND の `.rc` は通常の結果のまま |
| 死亡セーヴ `.ds` | 出目 20（クリティカル）、成功、失敗、出目 1（ファンブル）。安定 / 死亡の状態の案内は引き続き残す |

通常の `.r`、WOD の成功数のダイスプール、ダブルクロスの出目には全体の目標値がないため、成功 / 失敗に無理に分類することはありません。連続した判定では 1 回ごとに対応する成功度を選び、最初のダイスの結果でコマンド全体を代表させることはありません。結果の返信を何も設定していない場合は、元の出力の組み立て方を保ちます。

どの成功度でも、ネイティブの複数の返信、重み、ペルソナの上書き、入れ子の `{sample:…}` を使えます。たとえばボーナスダイスの「成功」を次のように設定できます。

```text
**{nick}** 的奖励骰检定：`{roll}/{rate}` **{level}**
{sample:好运站在你这边|这次抓住了机会}
```

汎用の変数には `{nick}`、`{attr}`、`{reason}`、`{roll}`、`{rate}`、`{level}`、`{res}`、`{result}`、`{outcome}` があります。`{result}` は判定に使う数字だけの値、`{roll}` はダイスの詳細、`{res}` は所属するコマンドの元の意味を保ちます。SAN の `{loss}/{final}`、成長の `{change}/{final}` などは対応する機能のエディターでだけ提供し、コマンドをまたいで共有する標準の成功度の返信には入れられません。カスタムの返信全体で理由を表示したい場合は、自分で `{reason}` を残してください。

プレビューでは選んだ成功度の例の値を使い、実際のダイスを振ったりメッセージを送ったりはしません。「コマンドの元の文面」を引き継ぐ場合、プレビューには代表のテンプレートを表示しますが、実際には理由、正気度の喪失、成長で変化したかなどに応じて元の変種を選びます。

既存のグローバル / ペルソナの文面と旧版から取り込んだ項目は、新しい結果の欄が増えたことで上書きされることはなく、新しい欄は既定で空です。ただし、これは旧版のすべての文面のマクロが互換になったという意味ではありません。詳しくは[旧版の文面の移行の範囲](/ja/guide/migration#カスタム文面とヘルプ)を参照してください。

## 旧版の判定の文面との互換

「COC → 旧版の判定の文面との互換」では、1 回分の成功度の短いフレーズと判定の前置きを別々に提供しています。SAN と成長の項目にもそれぞれの旧版のテンプレートがあります。**内蔵の互換の既定値は自動では有効になりません**。上書きを保存するか旧版の文面を移行した後に使われ、優先順位は次のとおりです。

```text
この種類の成功度の返信全体 → 標準の同じ成功度の返信全体 → 設定済みのネイティブのコマンドのテンプレート → 有効にした旧版の互換のテンプレート → ネイティブの既定のテンプレート
```

旧版の 1 回分の短いフレーズは成功度の文字にだけ影響し、複数回分は引き続き元の共有の成功度のフレーズを使います。通常のネイティブのテンプレートの `{level}` も、設定した対応するフレーズを使います。連続した複数回の判定で旧来の前置きを使う場合は、最初の互換の出力の前に 1 回だけ挿入します。シークレット判定では引き続き結果を個人チャットにだけ送り、グループには短い通知を残します。

文章だけの条件のマクロは入れ子にできます。

```text
{grade:rank?2={strSuccess}&1={strFailure}&0={strFumble}}
{case:loss?0=没有理智损失&else=理智减少{change}，剩余{final}}
{sample:今天精神不错|{case:loss?0=松了口气&else=保持冷静}}
```

`case` は項目の文字列で完全一致させ、`grade` は項目の値を超えない最大の数値のしきい値を選びます。`else=` で一致しなかったときの分岐を指定できます。条件そのものは文章を選ぶだけで、スクリプト、ネットワークのリクエスト、ファイルの操作は実行しません。

`{var:本次={ran:1~100}}{本次}`、`{len:nick}`、`{len:game.pls}`、`{expired:タイムスタンプの項目}`、`{at:}`、`{print:uid}` などの安全な関数も使えます。項目は現在の入口で使えるコンテキストに従います。`len` は文章を UTF-8 のバイト数で数え、現在のセッションのプレイヤー / GM の集合では人数を返します。`print` は現在のアカウントのキャッシュにある名前だけを読み、キャッシュがない場合は ID のままにします。

`{wait:1000}` は最終的な返信を 1 秒遅らせるよう求め、メッセージの受信は止めません。プレビューではこの制御の構文を取り除くだけで、実際には待ちません。1 つの返信で待てるのは最大 10 分で、キューには件数と大きさの上限があります。無効化、ブラックリスト、切断、プラグインの再読み込み、プログラムの再起動によって、まだ送っていない返信が取り消される場合があります。コマンドがすでに実行した管理の操作を遅らせることはありません。構文の全体と範囲は[安全な文章関数](/ja/develop/lua-mod#安全な文章の関数)を参照してください。

旧版の SAN の欄では、`{res}` は「ダイスの詳細 / SAN」、`{rank}` はファンブル 0、失敗 1、成功 2、ハード 3、イクストリーム 4、クリティカル 5 の順です。`{change}` は同じ正気度の喪失のダイスの詳細、`{loss}/{final}` は実際の喪失と残りの正気度です。これらの旧来の意味は互換の欄にだけ当てはまり、**新しい SAN の成功度の返信での `{res}` の数値の意味は変わりません**。成長の互換の欄の `{res}` は、旧版のダイス、技能値、成功度の説明を保ちます。

`{strEnRoll}` などの対応付け済みの参照は、現在の言語とペルソナで解決し、`{text:dice.compat.growth.base}` と明示して書くこともできます。参照は動的な関係を保ち、固定の文面をコピーすることはありません。参照先の複数の確率の返信や入れ子の sample も、出力のたびに選びます。循環や深すぎる参照には上限があり、プレイヤーのニックネームや理由の内容をマクロとして実行することはできません。

エディターのプレビューは同じバックエンドの解析を使い、現在の言語とペルソナも参照の解決に使います。旧来の欄を引き継ぐ場合は、対応する旧変数の意味で表示します。テンプレートの解析と Markdown / テキストの変換は、引き続き読み込みと保存のときにキャッシュします。取り込みや過去の修復のレポートは「バックアップと取り込み」と[移行の範囲](/ja/guide/migration#カスタム文面とヘルプ)を参照してください。

## ステータスバーと操作のヒントのコンポーネント

内蔵の文面、ペルソナの文面、高度な返信は、2 種類の意味的なコンポーネントを共有しています。エディターで例を直接挿入し、値や文字を現在の文面が対応する変数に置き換えてください。

```text
[[bar:HP|{hp}|{hpmax}]]
[[action:ダイスのコマンド|.r]]
```

ボタンの編集欄では、ボタンの文字と入力するコマンドを別々に入力します。QQ のタイトルは最大 10 文字で、長いタイトルは短くしますが、コマンドの引数は切り詰めません。コマンドのテンプレートは現在の返信の変数に対応しており、たとえば判定の文面では `[[action:もう一度判定|{command}]]` で元のコマンド、修正、理由を保てます。

コンポーネントは特定のプラットフォーム向けの Markdown の断片ではありません。Dice!Next は変数を置き換えた後、現在の表示方式に従って描画します。従来の方式では簡潔なデータを保ち、標準の方式では通常の強調を使い、高度なビジュアルの方式では文字のステータスバーと操作のヒントを生成します。QQ 公式に Markdown とインタラクションの権限がある場合、操作のヒントはコマンド入力のショートカットとして描画され、クリックするとまずクリックした人自身の入力欄に入り、すぐには実行しません。OneBot、Milky、またはリッチメッセージが失敗した場合は、引き続き `.r // ダイスのコマンド` のような読める文章を送り、自動で画像を生成することはありません。

高度なビジュアルの方式では、内蔵の使い方の中の `.コマンド // 説明` の行も認識します。たとえば `.bot on/off` からは `on` と `off` の 2 つの選択肢を生成し、`<名前>`、`[引数]` を含む使い方では入力が必要な位置にカーソルを置きます。ボタンは入力を手伝うだけで、最終的にはユーザーが確認して送信し、既存の権限の確認を回避することはありません。

### 文面の中の式

コマンドの文面とペルソナの文面には「式を追加」もあります。左に `$` を付けない TeX を、右に通常の文章の代わりの文字を入力します。たとえば判定の結果では次のようにします。

```text
[[math:\textcolor{#E5484D}{\frac{ {{roll}} }{ {{rate}} }}|{roll}/{rate}]]
```

式の中のテンプレートの変数は、TeX のグループの波括弧と区別するために二重の波括弧 `{{roll}}` を使い、右側の代わりの文字では引き続き `{roll}` を使います。変数の値はプログラムが式の中の数値や文字にエスケープするため、プレイヤーのニックネームが TeX のコマンドになることはありません。式でダイスを振り直すことはなく、この判定がすでに持っているデータを表示するだけです。項目の中の縦線には `\vert` を使い、コンポーネントの `|` の区切りや `]]` の終わりの目印は使わないでください。

式に対応した Markdown の表示では左の式を使い、従来の方式、強制的な文章のみ、文章だけのプラットフォームでは右の文字を使います。エディターでプラットフォームと文章のみのモードを切り替えて、両方の効果を確認できます。QQ の式の対応範囲はプラットフォームの実際の機能によります。ローカルのプレビューでは、式の中の HTML、外部のリンク、画像は実行しません。

## ランダムな文面 `{sample:…}`

2026-10-19 のローカルでの互換の追加では、テンプレート内の局所変数と小さな関数を加えましたが、まだインストールパッケージでの公開を待っています。例：

```text
{var:今日签={ran:1~100}}{nick} 抽到 {今日签} 号，再次引用还是 {今日签} 号。
```

`{var:名前?値}` は代入した結果も表示し、`{var:名前=値&別の名前=値}` は今回の描画の局所変数として保存するだけで、キャラクターシートやシステム設定には書き込みません。入れ子の sample、case、grade と組み合わせられます。

`{ran:下限~上限}` はゲームのダイスとは独立した整数の乱数で、上下限を含みます。`{len:項目}` は UTF-8 の文章のバイト数を返し、`{expired:項目}` は Unix 時刻が期限切れかを確認します。`{at:}` は現在のユーザーに、`{at:アカウント}` は指定したアカウントに、`{at:self}` は現在のボットにメンションし、いずれもプラットフォームが変換できる CQ のメンションのセグメントとして出力します。不正な対象ではセグメントを生成しません。`{print:uid}` / `{print:gid}` は現在の身元を表示し、アカウントを明示した場合も名前のために追加でネットワークに照会することはありません。

現在のコンテキストでは、`uid`、`gid`、`selfId`、`user.trust`、`user.favor`、読み取りロックされていない自分のキャラクターシートの値 `char.能力値` も読めます。`list_all_deck` などの目録の変数は、自動で更新される使い方の説明を書くのに向いています。詳しくは [Lua mod の自動の目録](/ja/develop/lua-mod#自動の目録)を参照してください。プレビューは同じバックエンドの解析を使いますが、例のデータだけを入れ、実際のグループメンバーや非公開のフォルダーを列挙することはありません。

元祖 Dice! のランダムな選択の構文は、その後の Release で公開され、beta.925 に含まれています。build 909 以前は対応していません。ダイスの返信やペルソナの文面に直接書けます。たとえば `dice.roll.result` を編集し、元の変数を残して次のように追加します。

```text
{nick} 掷骰：{res}
{sample:效果拔群|干得漂亮}
```

描画のたびに選択肢から等確率で 1 つを選び、`sample:` が結果に現れることはありません。ダイスの出目や判定のルールは変わりません。選択肢では、その文面がもともと対応している変数を参照でき、入れ子にもできます。

```text
{sample:本次结果是 {res}|{sample:效果拔群|干得漂亮}}
```

テキストと明示的な Markdown の文面に対応し、選ばれた選択肢だけを処理します。選択肢は半角の `|` で区切り、入れ子の波括弧の中の区切りを外側の候補として分けることはありません。カスタム返信の従来の `{甲|乙}` の省略形は残しており、ダイスとペルソナの文面では明示的な `{sample:甲|乙}` を使ってください。

## ネイティブの複数の確率の文面（公開済み、build 926）

ダイスの返信やペルソナの項目を編集するときは、「返信を追加」「この返信を削除」で複数の候補を管理できます。各候補に本文と整数の重みを個別に入力し、横に実際の確率を表示します。重み 1、3 は 25%、75% に対応します。0 にするとその候補を一時停止し、少なくとも 1 つは 0 より大きくする必要があります。候補は最大 256 件、候補の本文は合計で最大 64 KiB です。

1 回に選ぶ候補は 1 つだけで、改行はその候補の中の改行にすぎません。変数の挿入と書式のツールバーは現在の候補に対して働き、返信のキー全体で同じ出力の形式を使います。

旧来の {sample:甲|乙} を書き換える必要はありません。外側全体の sample は「外側の sample を等確率の複数の返信に変換」で展開でき、その後で各候補の重みを調整できます。文の途中や内側の sample が誤って分割されることはありません。ネイティブの候補の中でも sample を入れ子にできます。たとえば Markdown の形式を選んで次のように書きます。

```text
**{nick}** 掷骰：`{res}`
{sample:效果拔群|{sample:干得漂亮|再接再厉}}
```

通常のダイスの結果の {res} には式と結果が含まれます。各返信のキーではエディターに表示された変数だけを使え、プレビューの例にあるほかの変数を、どのコマンドでも使える変数とみなすことはできません。

プレビューでは、まず候補の重みで選び、次にその中の sample を解決し、最後に例の変数を入れます。「プレビューを引き直す」をクリックすると、別のランダムな結果を確認できます。1 回のプレビューの各送信の表現は同じ抽選の結果を共有します。実際のメッセージは送らず、ゲームのダイスの出目も消費しません。

保存時には各候補の Markdown / テキストの版をキャッシュし、送信のたびに文面全体を変換し直すことはしません。ペルソナの複製、取り込み・出力、再起動の後も、文章、重み、形式は保持されます。本体と WebUI の両方をアップグレードする必要があり、新しいフロントエンドは、対応していない古いバックエンドへのネイティブの確率の文面の保存を拒否します。

## ボットのペルソナ

**ペルソナ** は、上の返信文を上書きする 1 組の設定です。ペルソナを有効にすると、ペルソナの同名の項目が「既定（グローバル）」の文面より優先されます。ペルソナで書き換えていない項目は、引き続きグローバルのカスタムの文面か内蔵の文面に戻ります。あるペルソナに切り替えてから文面を編集すると、変更はそのペルソナにだけ保存されます。グループやチャンネルでは [`.rpmode`](/ja/use/fun) でペルソナを切り替えると、口調全体を一度に変えられます。

- **ペルソナのプルダウン**：「既定（グローバル）」を選ぶとグローバルの文面を、あるペルソナを選ぶとその専用の上書きを編集します。ペルソナを選ぶと、ページに「ペルソナ『…』を編集中」と表示されます。
- **ペルソナの管理**（ボタン）：ペルソナの新規作成 / 複製 / 名前の変更 / 削除、またはグローバルの既定への設定を行います。内蔵のペルソナは削除できません。グループの詳細の「機能の管理」で、個別のグループにアダプターやグローバルの既定を引き継がせたり、ペルソナを明示的にオフにしたり、独自の上書きのペルソナを選ばせたりできます。

このページの上部の「ペルソナの公開」をクリックし、まずボットのアカウントを選んでから、そのアカウントの既定のペルソナと、ユーザーが `.rpmode` で見て選べるペルソナの範囲を指定します：すべてのペルソナ、選んだペルソナだけ、またはユーザーによる切り替えを禁止。「選んだペルソナだけ」を選んだら、公開するペルソナにチェックを入れて保存します。設定はボットのアカウントごとに別々に保存され、上部の文面の編集用のペルソナのプルダウンで、ここでのアカウントの設定が変わることはありません。

アカウントの既定のペルソナとユーザーへの公開の一覧は互いに独立しているため、ボットにあるペルソナを固定で使わせながら、同じ役の少数のペルソナだけを公開し、別のボットの役が誤って一覧に現れるのを防げます。公開の一覧で追加の操作の権限が与えられることはありません。グループでの切り替えには引き続きグループの管理者、招待者、ダイスマスターの権限が必要で、個人チャットでの切り替えは現在のユーザーにだけ影響します。ダイスマスターは引き続き管理画面でグループに任意のペルソナを割り当てられます。プラットフォームの接続情報を編集しても、ここの設定は上書きされません。

チャットでの対応するコマンドは[娯楽と交流 → ボットのペルソナの切り替え](/ja/use/fun)を参照してください。

### ランダムな複数のペルソナ（公開済み、build 926）

「ペルソナの管理」で「ランダムな複数のペルソナ」を開き、複数の候補のペルソナを有効にしてそれぞれ重みを設定し、「ペルソナの確率を保存」をクリックします。基本の返信も候補にでき、確率の計算はネイティブの複数の文面と同じです。

1 回のコマンドではまずペルソナを 1 つ選び、返信全体で同じペルソナを使います。その後で各返信のキーが文面と内側の sample を選びます。書き換えていないキーは引き続きグローバルの文面か内蔵の文面に戻ります。ペルソナと文面の抽選には、ゲームのダイスの乱数の源は使いません。

優先順位は、個人チャットでの個人 / グループでの明示的な選択 → アカウントの既定のペルソナ → グローバルのランダムな候補 → グローバルの単一のペルソナ のままです。ペルソナの明示的なオフは引き続き有効です。.rpmode inherit またはグループの詳細の「継承」で、アカウント / グローバルの方針を再び使えます。.rpmode で状態を確認するとランダムな複数のペルソナを表示しますが、別途抽選はしません。

設定は再起動後も保持されます。単一のペルソナに戻すとグローバルのランダムな候補を消去します。ペルソナを削除すると候補から外し、重みが正の最後の候補を削除した場合は、すべての確率が 0 の候補を残さずに単一のペルソナ / 基本の返信に戻します。

## 取り込み / 出力

右上の `出力` / `取り込み` で、すべてのカスタムの文面とペルソナの上書きをバックアップまたは移行でき、複数のデプロイ間で同期するのに便利です。
