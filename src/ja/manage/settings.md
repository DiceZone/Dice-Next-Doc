# 基本設定

**管理パネル → システム設定 → 基本設定** で、ダイスマスター、コマンド、承認、画像、返信の動作を設定します。パネル自身のログインパスワードやポートなどは、同じグループの [WebUI 設定](#webui-設定ページ)で管理します。

ボットのキー、ハートビート、クラウドブラックリスト、クラウドのキャラクターシート、ログサイトは[クラウドサービス](/ja/manage/cloud-services)でまとめて管理し、画像のホスティングは引き続きこのページにあります。

外部の AI クライアントの接続、独立した認証情報、ツールの権限、呼び出しの記録は、同じグループの [MCP サービス](/ja/manage/mcp)で管理し、既定ではオフです。

## 更新の確認と自動更新

**管理パネル → プロジェクトについて → 更新の確認と自動更新** では、現在のバージョン、最新の Release、プラットフォーム向けのパッケージ、ダウンロード元、更新の段階をまとめて表示し、確認、ダウンロード、インストール、自動の方針の設定ができます。

右上のバージョンの表示をクリックしても、更新の欄に直接移動できます。ベータ版は `beta-3.0.0(123)`、正式版のビルドは `v3.0.0(123)` と表示し、新しいバージョンが見つかると横に赤い **New** が表示されます。サイドバーには固定のバージョン番号を表示しなくなり、上部バーでも「接続済み」のバッジをバージョン情報の代わりに使わなくなりました。ビルドの時刻は **UTC+8** で表示し、そのことを明記して、ブラウザのローカルのタイムゾーンには合わせません。

- 既定では 6 時間ごとに確認し、新しいバージョンが見つかっても **通知するだけ** で、勝手にダウンロードしたり再起動したりはしません。
- 「自動でインストールして再起動」を選ぶと **予約インストール** を有効にでき、既定は毎日 **04:00** です。プログラムは先にダウンロードと検証を行い、ダウンロード完了後の次の設定時刻に予約します。その日の時刻を過ぎていれば翌日に予約します。ブラウザのタイムゾーンではなく **基本設定のサーバーのタイムゾーン** を使い、パネルにはインストールの完全な日付、時刻、UTC オフセットを表示します。
- **予約が決めるのは、プログラムが自分から再起動する時刻だけです**。自動インストールの方針が有効でパッケージが準備できていれば、それより前の再起動でもあわせてインストールします。パネルからの再起動、終了後の再起動、OS の再起動、デーモンによる起動を含み、予約の時刻を待つ必要はありません。ダウンロードのみ / 通知のみの方針では、起動時にインストールしません。
- 予約と一時保存したパッケージは永続化されます。プログラムは自発的な再起動の予定を 1 分ごとに確認し、更新の操作が進行中の場合は先にそれを終えます。時刻やサーバーのタイムゾーンを変えると予約し直し、予約をオフにすると自発的な再起動の予定だけを取り消し、認可済みの更新は次の起動時にインストールします。起動時のインストールも止めたい場合は、方針を「ダウンロードのみ」か「通知のみ」に変えてください。自動の確認をオフにしても新しいバージョンを探すのをやめるだけで、既存の予定は取り消しません。「インストールして再起動」を直接クリックすることもできます。
- 新しいバージョンが見つかると、通知の仕組みで「新しいバージョンが見つかりました」を送ります。自動のダウンロード / インストールに成功すると「更新の結果」を、失敗すると「更新の失敗」を送ります。同じ Release の通知は 1 回だけです。既存の通知ウィンドウでイベントを個別に絞り込んでいる場合は、通知設定でこの 3 つの新しいイベントを追加でチェックしてください。
- ダウンロード元は 自動選択、GitHub のみ、内蔵ミラーのみ、カスタムミラー から選べます。自動モードでは GitHub への直接接続と内蔵ミラーを並行して試し、最初に成功してマニフェストが有効なものを使い、使える取得元を短期間キャッシュします。
- ダウンロード中は **ダウンロードをキャンセル** をクリックでき、「キャンセルしました」になってから再びダウンロードできます。接続、ダウンロード、検証、準備の段階はキャンセルできますが、実際のインストールはキャンセルできません。60 秒間データが増えない場合や、1 つの取得元で 20 分に達した場合は今回の転送を止め、設定に従ってほかの取得元を試します。すべての取得元が失敗するとエラーを表示し、プログラムを再起動せずに再試行できます。
- フロントエンドのリクエストがタイムアウトしても、バックエンドが止まったわけではありません。ページは状態を取得し直してから次の操作を許可します。状態がはっきりしないときは状態を更新し、ダウンロードやインストールを重ねてクリックしないでください。
- Release のパッケージは GitHub に書き換えられない安全なファイル名だけを使います。アップデーターは、過去のマニフェストで括弧が GitHub によってドットに正規化されたパッケージ名にも対応しています。ダウンロードに失敗すると HTTP の状態と curl の終了コードを両方表示するため、ファイルが存在しないのかネットワークの障害なのかを区別できます。
- 完全版パッケージのマネージャーモードは、「インストールして再起動」と任意の予約自動インストールに対応しています。Windows では `dice-next.exe`、POSIX マネージャーを含む新しい Linux/macOS のパッケージでは `start.sh` または `dice-next` を使います。beta.928 以前の Linux/macOS のパッケージは、先に一度手動で完全にアップグレードする必要があり、この機能は新しいパッケージの公開を待っています。コアを直接実行している場合は確認とダウンロードだけです。コンテナ内では確認と新しいバージョンの通知だけが残り、ダウンロードとインストールはサーバーが拒否します。イメージを更新してからコンテナを作り直してください。
- ダウンロードは Release のマニフェストのファイルサイズと SHA-256 と照合し、展開の前に絶対パスとパストラバーサルを遮断します。Windows では置き換えに失敗すると旧プログラムを自動で元に戻します。`config/`、データベース、ユーザーのファイルは置き換えの一覧に入らず、内蔵のファイルと同じパスでないサードパーティのプラグインも保持されます。
- SHA-256 は破損 / 一貫性の確認であり、独立したリリース署名ではありません。ミラー（特にカスタムミラー）を使うことは、その取得元を信頼することと同じです。迷う場合は「GitHub のみ」を選び、「通知のみ」のままにしてください。

アップグレードの完全な手順は[インストール → アップグレード](/ja/guide/install#アップグレード)を、API の項目は [API リファレンス → 更新のエンドポイント](/ja/develop/api#更新のエンドポイント) を参照してください。

## Master（ダイスマスター）

ダイスマスターのアカウントを追加 / 削除します（複数可、プラットフォームごとに区別）。ダイスマスターは最も高い権限を持ち、リモートでのオン・オフ、ブラックリスト・ホワイトリストなどの管理コマンドを使えます。

## QQ メールによる紐付けの確認

このページで専用の SMTP を設定して有効にすると、QQ 公式、Discord、KOOK のユーザーが個人チャットで QQ番号@qq.com を確認できるようになります。サーバー、ポート、アカウント、パスワードまたは認可コード、送信元のアドレスを入力します。465 では通常暗黙の TLS を、587 では STARTTLS を必須にします。パスワードは保存後に再表示されず、空欄のまま編集すると元の値を保持します。任意の受信アドレスは受け付けず、グループの所有の確認にも使いません。これはグローバルな設定で、ダイスマスターへの通知メールとは独立しています。ユーザーは常に `.bind qq <QQ番号>` と入力します。現在のクライアントに正式なボットのキーがあれば OAuth を優先し、なければ自動でメールを申請します。メールは `.bind confirm <8 桁の確認コード>` で完了し、キーがあってもメールを自分で選ぶ場合は `.bind qq <QQ番号> email` を使います。OAuth では Web ページで同意した後に `.bind confirm` を使い、失敗しても自動でメールを送ることはありません。コマンドと安全上の制限は [QQ メールの確認コード](/ja/use/cloud#qq-メールの確認コード)を参照してください。

## 式のエンジン

ダイスの式のエンジンは「グローバル → アダプターごと → アカウントごと」の段階で設定でき、アカウントごとの設定がアダプターごとより、アダプターごとがグローバルより優先されます。前のエンジンが「この構文には対応していない」と明示したときだけ次のエンジンを試します。0 による割り算、不正なダイスの面、ダイスの数の超過などの実行時のエラーはそのまま返し、エンジンを変えて振り直すことはありません。

| モード | エンジンの順序 | 向いている場面 |
|------|----------|----------|
| 拡張互換モード（既定） | Dice!Next → OneDice → DiceScript | できるだけ多くの式の構文に対応する |
| 互換モード | Dice!Next → OneDice | Dice!Next の動作を保ち、よく使う拡張のダイス式を補う |
| オリジナルモード | Dice!Next | 旧来の Dicebot 形式のネイティブな式だけを使い、互換のエンジンは使わない |
| カスタムモード | 1 つ以上のエンジンを選び、固定の優先順位を調整 | ダイスマスターの必要に応じて、使える構文と解析の順序を制御する |

::: info DiceScript C99 の互換の範囲
Dice!Next は独立して管理している [dicescript-c-lib](https://github.com/DiceZone/dicescript-c-lib) を通じて DiceScript を使っています。C99 のランタイムは、整数、浮動小数点数、文字列、null、配列、辞書、範囲、変数、computed value、関数、制御フロー、テンプレート、コンテナのメソッド、ホストのコールバックに対応しており、通常のダイス、連続した `d`、`kh/kl/dh/dl/min/max`、有利 / 不利、COC のボーナス / ペナルティダイス、Fate、WOD、DoubleCross にも対応しています。

通常の `.r` は引き続き「単一の式」の入口を使い、コマンドの後ろの判定の理由と確実に区切れるようにしています。キャラクターシートの値は DiceScript の変数として読み取れます。完全な文、永続的なコンテキスト、テンプレート、ネイティブの関数 / オブジェクト、カスタムのダイス、tagged VMValue のシリアライズは、ライブラリの完全な C API で提供されています。

代わりのエンジンの判定では、完全な VM の解析だけを行う API を使い、式を実行せず、ホストの変数にもアクセスせず、乱数も消費しません。完全な構文に対応していないときだけ次のエンジンに進み、評価に入った後のエラーでダイスを振り直すことはありません。
:::

カスタムモードでは、行の先頭のつまみをドラッグして並べ替えられ、**上から下が実際の優先順位** で、保存すると反映されます。上下の矢印をクリックするか、つまみにフォーカスしてキーボードの上下キーでも操作できます。オフにしたエンジンは下に並び、解析には加わりません。エンジンごとに過程の表示形式を保ち、たとえば OneDice の `1d6[4]=4` の `[4]` はそのダイスの出目を表し、ネイティブのエンジンは `1D6=4` を使います。

::: tip 代わりのエンジンへの切り替えで乱数を先に消費することはありません
まず正式な乱数の源を消費しない方法で、互換のエンジンが式を完全に解析できるかを判断してから、実際にダイスを振ります。そのため、前のエンジンが構文を拒否しても、こっそり出目を消費したり、後のエンジンの結果を変えたりすることはありません。
:::

## コマンドの接頭辞

反応する接頭辞を追加・削除します（既定は `.` `。` `!` `！` `/`）。メッセージがいずれかの接頭辞で始まるときだけコマンドとして扱い、保存するとすぐに反映されます。QQ 公式プラットフォームでは `/r` などの書き方を使えます。既存のカスタムの接頭辞の一覧は上書きしないため、必要であればここで `/` を追加してください。

## ダイスの乱数の源

**基本設定 → ダイスの乱数の源** で選んで保存します（全体の検索で「随机源」（乱数の源）と入力すると直接移動できます）。Dice!Next、OneDice、DiceScript、MCP のダイスに全体で適用され、すぐに反映されて永続的に保存されます。旧来の「ダイスのルール」ページは削除され、元のアドレスはここに自動で転送されます。

| 方式 | 特徴 |
|------|------|
| OS の安全な乱数（既定） | Windows は BCryptGenRandom、Linux は getrandom、macOS は getentropy を使います。OS は CPU のハードウェアの乱数や割り込みのタイミングなどのエントロピーを常に混ぜ込みます。アプリが乱数の状態を別に管理することはなく、ネットワークも不要です |
| OpenSSL の安全な乱数 | RAND_bytes を使い、OS のエントロピー源で種を与えた DRBG です。こちらもネットワークは不要です |
| CPU のハードウェアのエントロピー源 | 毎回 CPU の物理的なノイズのエントロピー源 RDSEED を読み、OS の安全な乱数とビットごとの排他的論理和を取るため、結果が OS の乱数より弱くなることはありません。x86-64 の CPU だけが提供し、対応していない場合は選べません。RDSEED が混雑している、または失敗した場合は、その回だけ自動で OS の乱数を使います |

3 つの方式のいずれも、1 回のダイスのコストは約 1 マイクロ秒で、余分なメモリは使いません。プラグインが自分で生成する乱数、毎日の運勢、プレビューの例はこの設定の影響を受けません。

**乱数の源の障害でダイスが止まることはありません。** 選んだ源が使えない場合は、ほかの安全な乱数の源に順に切り替え、すべて使えないときだけ非常用の疑似乱数（xoshiro256**）を使い、プログラムのログに WARN を 1 回記録します。源が回復すると自動で元に戻し、INFO を記録します。設定のカードには、最後のダイスで実際に使った源を表示します。実際には OS の API が失敗することはまれで、よくある原因は、getrandom のない 3.17 より古い Linux カーネル（CentOS 7 など）や、コンテナのセキュリティポリシーでの遮断です。

「真の乱数」のサービスを直接使わない理由：SealDice のコアは PCG（既定）、システムの CRNG、NIST AES-CTR-DRBG、中国国家規格の SM3（既定で無効。有効にするとエントロピーの収集に約 32 MB のメモリが必要）と混合モードを提供しています。OlivaDice は既定で Python のメルセンヌ・ツイスタを使い、任意で random.org から乱数を取得できます。Dice!Next は既定ですでに OS の安全な乱数を直接使っており、ハードウェアのエントロピー源の方式は CPU が対応している場合により直接的な物理的なノイズの源を提供します。オンラインの乱数のサービスはネットワークに依存し、頻度制限やプライバシーの問題もあるため採用していません。

## QQ 公式の SN 状態行

**基本設定 → 返信と表示 → QQ 公式の SN 状態行** で `.sn` の先頭の表示を調整します。全体の検索で「SN」「彩色文字」（色付きの文字）と入力すると直接移動できます。グローバル、アダプターの種類、個別のアカウントで設定でき、優先順位はアカウント > 種類 > グローバルです。保存するとすぐに反映され、引き継ぎに戻すこともできます。

| プリセット | 表示の仕方 |
|---|---|
| 色付きの文字（既定） | QQ の数式の形式 `scriptsize` と `\textcolor` を使い、既定は赤 `#E5484D` です。選ぶと下にカラーホイール、スポイト、よく使う色の見本、#RRGGBB の入力欄が表示され、色を直接変更できます。スポイトは画面の任意の場所から色を拾え（Esc で取り消し）、Chrome / Edge で、HTTPS または localhost でパネルを開いている必要があり、それ以外ではボタンを使えません。HTML の `<font>` は送りません |
| 引用 | Markdown の引用ブロック |
| 通常の文字 | 余分な装飾を付けない |
| カスタム形式 | Markdown を編集し、プレースホルダーで状態の内容を挿入する |
| 状態行をオフ | 先頭の状態を表示せず、プレイヤーの設定は残す |

ここで制御するのは見た目だけです。プレイヤーは引き続きグループで `.sn` または `/sn` を実行して自分の状態行をオンにし、`.sn off` でオフにします。`.setsn` でグループの既定の能力値を設定し、`.sn {nick} SAN{san}` で個人の内容を設定します。ほかのプラットフォームでの実際のグループ内の名前の動作は変わりません。

カスタム形式の例：

```text
> {sn}
```

```text
$\scriptsize\textcolor{#E5484D}{\text{{sn_tex}}}$
```

`{sn}` はエスケープ済みの Markdown の文字を挿入します。数式では `{sn_tex}` を `\text{…}` の中に置き、ニックネーム内のバックスラッシュや括弧などの文字を安全に扱えるようにしてください。形式には少なくとも 1 つのプレースホルダーを含め、最大 2048 UTF-8 バイトです。プレースホルダーを繰り返し挿入して状態行が 3000 バイトを超えた場合は、通常の状態の文字 1 つに戻ります。プリセットを切り替えても、編集したカスタム形式は失われません。プレビューは固定のサンプルデータを使い、最終的な表示は QQ のクライアントによります。

装飾のあるスタイルには Markdown が必要です。従来の文面の方式を選んだ場合、`.bot text plain` で文章だけに強制した場合、プラットフォームが形式をはっきり拒否した場合は、状態行は通常の文字になり、数式のコードは出力しません。状態とその後の本文は独立した段落で区切ります。

## BotMsg 追加情報

**基本設定 → 返信と表示 → BotMsg 追加情報** で、`.bot` の固定の情報の後に続く紹介、連絡先、ヘルプの案内を編集します。グローバル、アダプターごと、アカウントごとに設定でき、優先順位はアカウント > アダプター > グローバルです。空欄にすると追加情報を隠せます。

`.bot` の最初の 3 行は常にシステムが生成し、追加情報や旧来のヘッダーで置き換えることはできません。

1. プログラムのバージョン、ビルド番号、作者名。バックエンドに永続化された `i18n.default_locale` を使い、中国語では「希亚」、ほかの言語では「ShiaNyaa」と表示します。右上の WebUI の言語は現在のブラウザに保存されるもので、この既定の返信の言語は変わりません。
2. 現在のプログラムのコンパイラー、ビルドの時刻、アダプターの情報。
3. 現在のアカウントで実際に有効な互換の式のエンジン。既定では `OneDice V1 & DiceScript Compatible` と表示し、OneDice または DiceScript だけを有効にしている場合はその名前だけを、ネイティブのエンジンだけを使う場合は `Dice!Next Native` と表示します。

既定の追加情報は次のとおりです。

```text
Dice!Next 测试群：933145116
如有故障或建议欢迎加群反馈
使用 .help 查看帮助
```

（「Dice!Next テストグループ：933145116 / 不具合や提案はグループでお知らせください / ヘルプは .help で」）旧版から取り込む場合、`strBotMsg` は原文を保ち、末尾に改行して上の既定の説明を追加します。取り込み直しても重ねて追加されることはありません。`strBotHeader` も保持しますが、3 行の固定の情報の後ろに移します。すでにカスタムの説明があり、上書きを認可していない場合は、移行レポートで競合を知らせて既存の設定を保持します。

## 禁止語のフィルター

**セキュリティと権限** の区分にあり、元祖 Dice! のコマンドの禁止語の検出を再現しています。既定でオフで、**内蔵の語彙リストは一切付属しません**。ダイスマスターがページで保存したルールと、旧版の `conf/CustomCensor.json` から移行したルールだけが照合に使われます。

- 現在のコマンドの接頭辞で始まる受信メッセージだけを確認し、通常のグループチャットは走査せず、ボットの返信やプラグインの出力も変更しません。
- 照合では空白と ASCII の特殊記号を自動で飛ばし、英字の大文字・小文字を区別しません。1 つのコマンドが複数に一致した場合は最も高いレベルを使います。
- Master と信頼レベル 4 以上は検出を飛ばします。信頼レベル 1–3 では、元祖のルールに従って実際の処置を下げ、ルールのレベルがユーザーの信頼レベル以上のときだけ遮断します。
- 一致するとこのマシンのログに書き込み、対応するレベルの[ダイスマスターの通知ウィンドウ](/ja/manage/notice)に送ります。QQ 公式プラットフォームで同じ禁止語に再び引っかからないよう、通知のメッセージでは一致した言葉や元のコマンドを繰り返さず、詳しい内容はこのマシンのログにだけ残します。
- 有効にする前に、ページでコマンドを 1 つテストできます。テストではリアルタイムのメッセージと同じサーバー側の照合を使います。

| レベル | 動作 |
|------|------|
| Ignore (0) | このルールを無視する。旧版の無効の項目を残しておくのに使える |
| Notice (1) | 記録して日常の通知を送るだけで、コマンドは止めない |
| Caution (2) | ユーザーに注意してコマンドを遮断し、重要な通知を送る |
| Warning (3、既定) | ユーザーに警告してコマンドを遮断し、重要な通知を送る |
| Danger (4) | コマンドを拒否し、重大な通知を送る |
| Critical (5) | 旧データとの互換用。最も高いリスクとして扱い、Danger と同様にコマンドを拒否して、エラーの通知を送る |

チャットでもダイスマスターが `.admin censor` でルールの追加・削除やオン・オフができます。詳しくは[管理コマンド](/ja/use/admin#禁止語の管理)を参照してください。

## 友だち / グループ招待の承認

ボットが友だち申請とグループへの招待をどう自動処理するかを設定します。

| 項目 | 選べる方針 |
|------|----------|
| 友だち申請 | 自動で処理しない（手動）/ 誰でも自動で承認 / キーワードを含む場合だけ自動で承認 / 自動で拒否 |
| グループ招待 | 自動で処理しない（手動）/ 誰の招待でも自動で承認 / ホワイトリストと Master の招待だけ自動で承認 / すべて無視 / すべて拒否 |
| ブラックリストのグループの招待を自動で拒否 | スイッチ |
| 友だちではない人からのグループ招待を拒否 | 友だちではない人の招待を自動で拒否します。強制的にグループに追加された場合は、ボットが知らせてから自動で退出します（ダイスマスターとホワイトリストのユーザーは対象外） |
| グループ名のキーワードによる自動退出 | 参加後にグループ名を調べ、いずれかのキーワードを含めば自動で退出してダイスマスターに通知します（複数のキーワードは空白で区切る） |

## スイッチと送信の動作

### 返信文とビジュアル方式

返信の表示には 3 つの方式があり、切り替えるとすぐに保存されます。

- **従来の文面**：初期のバージョンの簡潔な言い回しと文章だけのレイアウトを使います。
- **標準の文面**：現在の標準の言い回しを使います。対応しているプラットフォームでは Markdown を描画し、対応していない場合は読みやすい文章に自動で変換します。
- **高度なビジュアルの文面**：標準の文面に、ステータスバーや操作のヒントなどの意味的なコンポーネントを加えます。QQ 公式では使い方の案内を、クリックすると入力欄に入るボタンにでき、文章だけのプラットフォームでは `HP [██████░░░░] 6/10`、`.r // ダイスのコマンド` などの安定した形で表示し、画像は生成しません。
- **範囲ごとの上書き**：グローバル、プラットフォームの種類、個別のアダプターのアカウントでそれぞれ選べ、優先順位はアカウント > プラットフォーム > グローバルです。上書きを解除すると、1 つ上の段階を引き続き引き継ぎます。
- **送信の性能**：Markdown の文面の文章だけの版は、読み込みや保存のときに前もって生成します。QQ 公式でカードが 2 回続けて拒否されると、10 分間は自動で文章だけを使い、その後また試します。

高度なビジュアルのプリセットはエディターにそのまま読み込め、本文、ボタン、ステータスバー、式を自由に変更できます。本文を変更しても既存のボタンが消えることはありません。旧来のカスタムの文面はそのままなので、必要なときに手動でプリセットを読み込んで調整してください。編集の方法は[コマンド一覧 → 返信文のカスタマイズ](/ja/manage/commands#返信文のカスタマイズ)を参照してください。

| 設定項目 | 説明 |
|--------|------|
| Windows 起動時の自動起動 | Windows へのサインインとともに自動で起動（Windows のみ） |
| Windows のトレイのヒントの文字 | 「ネットワークとシステム」タブで、トレイアイコンにマウスを合わせたときの名前を設定します。最大 10 文字、空欄なら `Dice!Next`。実際のポートを自動で付け加え、保存するとすぐに反映され、Windows でのみ変更できます |
| ログの画像を保存 | セッションログの画像を `data/logs/images` に保存し、Web ページの出力時に埋め込んで表示 |
| 自分のメッセージへの反応（セルフコントロール） | ボットのアカウント自身が送ったメッセージも処理し、ボットのアカウントで自分を操作できます。自分の発言の重複除去と、ボット間のループを防ぐ仕組みを内蔵し、既定でオフ |
| ロールの理由を無効にする | 有効にすると `.r` は結果だけを表示し、理由は表示しません。`.r 1d6 攻击` は 1d6 の結果だけを返し、文章だけを書いた場合はそのまま既定のダイスを振ります。既定はオフで、理由は通常どおり表示します |
| ロールした人の発言を引用 | 返信で、コマンドを実行したメッセージを QQ の「引用」の形で返信します |
| 自動のシートの要約（HP/SAN） | `.st` で基本の能力値を設定すると、HP / SAN / MP を自動で計算して要約を付けます（COC 系のルールのみ） |
| 長いメッセージをまとめて転送 | 返信がしきい値（既定 1200 文字）を超えると、チャットが埋まるのを防ぐため、まとめた転送の形で強制的に送ります（グループチャットのみ、OneBot のみ） |
| 分割して送る長さ | 長すぎる返信は自動で分割します（既定 600、漢字で約 300 文字。できるだけ改行の位置で区切る） |
| ユーザー名の囲み | 返信のユーザー名の前後に付ける記号（既定は `<` `>`、例：「\<希亚\>掷骰」。空欄＝囲まない） |

カスタムのトレイの名前は build 926 から対応し、`config/dice.json` の `tray_text` として保存されます。プラットフォームやアダプターのアカウントごとの上書きの対象ではありません。認証済みの `GET /api/system/tray` で `{ text, port, tooltip, supported }` を確認し、`PUT /api/system/tray` で `{ "text": "希亚骰" }` を送信することもできます。この API でポートは変更できません。名前は Unicode の文字数で数え、途中の改行や制御文字は使えません。

## 画像に関する設定

- **画像の送信方法**：返信に挿入した画像は `[img,file=ローカルのパス]` として保存し、送信時に base64 での埋め込み（既定。端末をまたいで使える）か HTTP のリンク（NapCat からこのマシンにアクセスできる必要がある）に変換します。
- **画像のホスティング（安定した画像のリンク）**：ログの画像をログサイトで長期間表示する方法を決めます。アップロードしない / サードパーティの画像ホスティング（汎用の multipart でのアップロード。ImgBB、sm.ms、Lsky（兰空）などに対応）/ ローカルのリンク（自前でホスティング。インターネットからの HTTPS が必要）。

## チャットと友だちの保守

- **チャットの記録の保存期間**：チャットのシミュレーターのメッセージを永続的に保存し（`chat.db`）、日数に応じて自動で整理します。
- **ユーザーグループ**：公式のユーザーグループを設定し、メンバーの参加を必須にするか、招待を許可するかを選べます。

### 友だち・グループ・ローカル記録の自動整理

このカードはグローバルな設定で、2 つのグループに分かれています。変更したら保存をクリックし、再起動は不要です。起動の約 5–6 分後に最初の確認を行い、その後は 12 時間ごとに確認します。

| 設定 | 実際の動作 | 0 の意味 |
| --- | --- | --- |
| ユーザーの記録の未活動期間（日） | 最後にメッセージを受け取った時刻でユーザーのプロフィールを整理します。古いプロフィールはコマンド / 作成の時刻を使います | オフ |
| グループの記録の未活動期間（日） | 最後のメッセージ / コマンドの時刻でグループ一覧の情報を整理し、新しいメッセージを受け取ると再び表示します | オフ |
| 友だちのコマンド未使用期間（日） | アダプターを呼び出して友だちを削除します。コマンドの記録がない場合は作成の時刻を参考にします | 友だちを削除しない |
| グループのコマンド未使用期間（日） | 現在のボットのアカウントが長いあいだコマンドを受け取っていないグループから退出します。通常のチャットはコマンドに数えません。退出の前に、何日使われていないかを伝える別れのあいさつを送ります | 活動がなくても退出しない |
| メンバーが何人を超えたら退出するか（人） | メンバー数が上限を厳密に超えたときに退出します。参加できるグループの数ではありません | 人数では退出しない |
| 1 回あたりに退出するグループの最大数（個） | 今回の退出の数を制限し、残りは次回に回します | **数を制限しない** という意味で、整理をオフにするわけではない |

ローカルの記録の整理では、友だちの削除やグループの退出の API は呼び出さず、キャラクターシート、セッションログ、本人確認の紐付け、プラグインの変数、グループのルール、権限は保持します。ユーザーのプロフィール内のニックネーム、好感度、回数はプロフィールと一緒に消えます。期限切れのグループ一覧の情報はしばらく表示されなくなり、実際のメッセージで記録が作り直されます。手動での削除 / 退出の目印が、通常のメッセージによって勝手に消されることはありません。

ダイスマスター、信頼済み / ホワイトリストのユーザーは整理の対象外です。グループのホワイトリスト、旧来の整理の免除 / 無視の設定、ログを記録中のグループは保護されます。不明または無効な活動の時刻を「長いあいだ活動がない」とみなすことはありません。友だちの削除とグループからの退出は、接続済みで対応する API に対応しているアダプターでだけ実行します。別のボットのアカウントの活動の記録で、現在のアカウントが退出すべきかを判断することはありません。グループの整理では先に退出のあいさつを送ってから退出を送信し、友だちの削除では個人チャットを送りません。

既存の定期タスクの設定、有効の状態、実行の仕方は変わりません。以前に定期タスクで自動退出を設定している場合は、同じ方針を 2 つ同時に有効にしないよう、先に確認してください。

## 旧版データの取り込み

旧版 Dice! のデータフォルダーのパスを入力すると、キャラクターシート、プレイヤーのプロフィール、ブラックリスト、カスタム返信、デッキ、mod などを一括で移行できます。同じ名前のデータを上書きするかどうかも選べます。詳しくは[データ移行](/ja/guide/migration)を参照してください。

## 元祖のグローバル設定

元祖 Dice! の console のグローバルな設定を再現し、グループごとに管理します。

| グループ | 内容 |
|------|------|
| 反応のスイッチ | 全体のサイレント。全体で `.jrrp` / `.me` / `.deck` / `.draw` / `.send` / `.help` を無効にする |
| デッキ / 表示 | デッキの `_` で始まるメタデータのキーを隠すか |

| クラウド / ネットワーク | クラウドでの表示など（「記録」と付いた項目は今のところ予約済み） |
| 外部へのリクエスト | カスタム返信の `{api:URL}` のスイッチとタイムアウト（既定でオフ。プライベートネットワークのアドレスは自動で遮断） |
| 自動の保守 | ローカルのユーザー / グループの記録の保持期間、友だち / グループのコマンド未使用による整理、1 回あたりの退出の上限（上記参照） |
| そのほかの互換 | プライベートモードなどの記録項目 |

全体でコマンドを無効にしても、効くのは一般のユーザーだけで、信頼レベル 4 以上 / ダイスマスターは制限されません。
:::

## WebUI 設定ページ

**管理パネル → システム設定 → WebUI 設定** で、管理パネル自身の設定を管理します。

管理パネルの画面は 1 つだけです（以前の V2 が正式版になり、旧来の画面はインストールパッケージに含まれなくなりました）。以前ブックマークした `/v1/`、`/v2/` のアドレスは、自動で管理画面のホームに戻ります。`config/webui.json` の旧来の `ui_version` の項目は使われなくなり、残しておいても起動に影響しません。

| 設定項目 | 説明 |
|--------|------|
| API Key | バックエンドの API にアクセスするための認証キーで、設定ファイルの `server/api_key` と同じ値 |
| 管理パネルのログインパスワード | 設定すると、パネルを開く前にパスワードの入力が必要になります（Cookie のセッション認証）。ログイン時にデバイスを 30 日間信頼することを選べ、プログラムを再起動しても復元されます。空にするとパスワードの再設定が必要になり、変更 / 消去すると既存のログインセッションは無効になります。同じマシンの複数のインストールは別々の Cookie を使い、ログアウトは現在のインスタンスにだけ影響します |
| 待ち受け IP とポート | パネルと API の待ち受けアドレス（`0.0.0.0` はすべてのネットワークアダプターで待ち受け）とポート（既定は 18088）。**変更後は再起動が必要です**（HTTP の待ち受けは起動時に割り当てるため、その場では切り替えられません）。保存後に「今すぐ再起動」をクリックできます |
| テーマ | ライト / ダーク / システムに従う |
| コンソールのログ | 最低記録レベル TRACE / DEBUG / INFO / SUCCESS / WARN / ERROR、既定は INFO。プロトコルのイベントの診断もレベルに従い、通常のハートビートは TRACE、ポーリングは DEBUG で、INFO に引き上げることはありません |

記録レベルは、それ以降にコンソールとファイルに書き込むログを制御します。ホーム画面の「最低表示レベル」は、現在のブラウザの記録を絞り込むだけです。表示レベルを下げても、以前に保存しなかった DEBUG／TRACE を補うことはできません。形式、プラグインの発生元、メッセージの対応付けの方法は[プログラムログ](/ja/manage/dashboard#プログラムログ)を参照してください。

設定の画面は機能ごとのタブに分かれており、保存は引き続き各項目のボタンまたはすぐに保存する旨の表示に従います。ブラウザで独立したウィンドウとしてインストールする方法は[インストール → 管理パネルをアプリとしてインストール](/ja/guide/install#管理パネルをアプリとしてインストール)を参照してください。
