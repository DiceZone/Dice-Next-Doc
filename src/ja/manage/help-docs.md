# ヘルプ文書

**管理パネル → ヘルプ文書** では、`.help` のすべてのヘルプの項目をまとめて表示し、検索、編集、管理ができます。

## ヘルプの出所

ヘルプの仕組みは統一された登録先で、項目は複数の出所から来ており、ページではラベルで区別しています。

| 出所 | 説明 | 編集できるか |
|------|------|----------|
| 内蔵 | プログラムに内蔵されたコマンドのヘルプ（i18n の文面） | 編集でき、ワンクリックで「既定に戻す」も可能 |
| カスタムのヘルプの項目 | 以前のコマンドで追加した、または旧版の `CustomHelp.json` から取り込んだ `help.topic.*` の項目 | 編集・削除できる |
| ルールパック・名前 | ルールパックと一緒に配布されたヘルプ | 読み取り専用（変更するにはルールパックを編集） |
| プラグイン・名前 / Lua モジュール・名前 | JS プラグイン / Lua mod と一緒に配布されたヘルプの項目 | 読み取り専用（変更するにはプラグインを編集） |
| 文書パック・名前 | `data/helpdoc/` などのフォルダーにある構造化されたヘルプのパック。プログラムと一緒に配布される場合も、ダイスマスターが追加する場合もある | 読み取り専用 |
| カスタム文書 | ダイスマスターが自分で作ったヘルプ（`data/help/*.md` に保存） | 編集・削除できる |

変更した内蔵のヘルプも「内蔵」のままで、追加で「カスタマイズ済み」と表示されるため、ユーザーが新しく作った文書と誤認されることはありません。ルールパックとプラグインのヘルプは **パックと一緒に配布** されます。パックを入れればヘルプが付き、削除すれば消えます。

過去のカスタムの項目は取り込み直す必要がなく、強制的にファイルに変換されることもありません。元の内容、言語、テキスト / Markdown の形式は、元の文章の上書き層に引き続き保存されます。旧データには「コマンドで作ったか、移行で取り込んだか」の信頼できる記録がないため、ページではすべてユーザー定義として扱い、出所を推測しません。

## 閲覧と検索

- 既定では左にヘルプのファイルの一覧、右に現在の項目を表示します。まず「ユーザー定義 / 内蔵のヘルプ / プラグイン / ルールパック / ヘルプ文書のパック / そのほかの出所」で絞り込み、次に具体的なプラグイン、パック、ファイルを選び、トピック名や内容で検索できます。
- 絞り込み、件数、ページ分けはサーバー側でカタログ全体に対して行い、現在のページだけに限りません。プラグインには JS と Lua の両方が含まれます。ルールパックに付属するヘルプ文書は引き続きルールパックに分類され、元の文書の出所の名前を保持します。
- 分割表示のページ分けにはページ番号のボタンと番号を直接入力しての移動があり、2 行に固定して、ときどき不規則に折り返すのを防いでいます。
- 自分で作った空の文書や、同じ名前の項目に隠されたファイルも管理の一覧に表示され、対応する注意が付きます。これによってチャットでの同名の項目の優先順位が変わることはありません。

## 視覚的な編集

左の項目を選んでから、右の「編集」をクリックするとダイアログが開きます。「文書を追加」ではカスタムのヘルプのファイル（名前と内容を入力）を作成し、保存するとすぐにグループで `.help <名前>` で調べられるようになります。過去のヘルプの項目も直接編集・削除でき、内蔵のヘルプは変更と既定への復元ができます。

文章の項目には実際の内容の言語を表示し、編集と削除はその言語に対して行い、ほかの言語の内容は残します。ある言語に項目がない場合は、ボットの設定に従って代わりの言語を使います。形式の選択はテキスト / Markdown の明示的な意味を保ち、閲覧時に `{sample:甲|乙}` を評価することはありません。保存せずに離れようとすると確認を求めます。

独立したカスタムのヘルプは、「コマンド一覧 → すべての文面」の未分類の文面として表示されなくなりました。そこにはヘルプ文書への入口があります。コマンドに関連付いた使い方の文章と、ペルソナの層での文章の編集は引き続き残っています。

## 取り込み / 出力

- **出力**：`kind: "dicenext.help"`、`version: 1` を持つ JSON をダウンロードし、カスタムのファイルと、すべての言語のヘルプの文章の上書き（過去の項目、内蔵のヘルプの変更、形式、確率の候補を含む）を別々に保存します。同じ名前のファイルと文章の項目は別々に保存し、互いに上書きしません。プラグイン、ルールパック、ペルソナの内容は含まないので、それらは対応するバックアップの入口を使ってください。
- **取り込み**：上の新しい形式のバックアップに対応し、旧来の `.json`（`{名前: 内容}` のオブジェクトまたは `name` / `content` を含む配列）と単一の `.md` / `.txt`（ファイル名が項目名）も引き続き受け付けます。先に入力全体を検証し、不正な名前や同じ言語の重複した項目を拒否します。既存の内容の上書きには確認が必要で、ネットワークのエラーで一部だけ成功した場合は、すべて成功したふりをせずに結果を報告します。

## チャットのコマンド

2026-10-19 に旧来のヘルプの別名に対応しました。項目の本文を `&対象のトピック` と書くと、検索時に対象へ転送されます。複数段階に対応し、ASCII の大文字・小文字を区別しません。コマンドで追加したり旧版から取り込んだりした文章の項目、カスタムのファイル、文書パックは、すべて同じ解決ルールを使います。現在の言語、ルールで優先される出所、検索範囲は保たれ、別名で範囲の制限を越えることはできません。16 段を超える循環や対象が見つからない場合は知らせ、一覧と出力では元の別名を保存したままで、前もって本文に固定することはありません。

グループでは `.help <項目>` でヘルプを調べます。`.helpdoc scope <出所>` でこのグループの検索範囲をある出所に固定でき（あるルールパックだけを調べるなど）、`.helpdoc default <出所>` で同じ名前の項目で優先する出所を設定できます（dnd5r を dnd3r より優先させるなど）。詳しくは[管理コマンド](/ja/use/admin)を参照してください。

::: tip
ヘルプの項目が多い場合、チャットでの `.help` は完全一致 / あいまい検索だけを行います。すべての項目を見渡したい場合は、このページの閲覧と検索を使ってください。
:::
