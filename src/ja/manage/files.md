# ファイル管理と画像リソース

入口：**データ管理 → ファイル管理 → 画像リソース**。

ファイルの一覧には名前、パス、サイズ、更新日時だけを表示し、サムネイルは読み込みません。画像を見たいときは「プレビュー」をクリックします。「画像コードをコピー」で得たコードは、返信、ダイスの文面、デッキなどにそのまま使えます。

## 画像の保存場所

このインスタンスの `data/images/` にまとめて保存します。

| フォルダー | 用途 |
| --- | --- |
| `reply/` | カスタム返信 |
| `text/` | ダイスの文面、ペルソナの文面 |
| `deck/<デッキのファイル名>/` | そのデッキの画像。完全なファイル名は `.json` を含み、内部のサブフォルダーも保持 |
| `plugin/<プラグイン名>/`、`mod/<mod 名>/` | 所属するプラグインや mod ごとにまとめて保存 |
| `chat/` | 自分でアップロードしたチャットの画像、お気に入りのスタンプ |
| `shared/` | 汎用の画像 |
| `cache/chat/`、`cache/log/` | 独自の整理ルールを持つチャット / セッションログのキャッシュ |

自分のフォルダーを新しく作れます。フォルダーは所属を表すだけで使える場所を制限するものではなく、全体での重複除去のために、あるデッキやプラグインの画像をほかのフォルダーへばらばらに移すこともありません。

## よく使う操作

- 検索、並べ替え、サーバー側でのページ分けに対応し、既定では 1 ページに 20 項目です。
- 複数を選択してからコピー、切り取り、削除、ZIP でのダウンロードができます。移動先のフォルダーに入って貼り付けると、同じ名前の上書きには確認が必要です。
- 各行にプレビューと画像コードのコピーがあり、「その他」ではパスのコピー、ダウンロード、参照の確認、名前の変更などができます。
- 画像の ZIP はサブフォルダーを保ったまま一括で取り込めます。受け付けるのは画像だけで、パッケージ内のスクリプトは実行しません。
- 返信、ダイスの文面、デッキ、プラグインのテンプレートの設定、チャットのシミュレーターは同じ画像の選択画面を共有し、新しい画像をアップロードすることも、既存のリソースを直接参照することもできます。

移動や名前の変更では、認識できた参照を更新し、古い画像コードや古いリンクも引き続き使えます。まだ参照されている画像は削除できません。先に参照を置き換えてからごみ箱に移すと、必要なときに復元できます。完全な削除は取り消せないので注意してください。

::: warning 動的なパスはすべてを静的に識別できません
プラグインは自分でパスを組み立てたり、外部のデータベースを読んだり、非公開のフォルダーを列挙したりする場合があります。参照が見つからなくても、必ず使われていないとは限りません。いきなり完全に削除せず、まずごみ箱に移して様子を見ることをおすすめします。画像の移行のためにソースコードが自動で書き換えられることはありません。
:::

## 移行とバックアップ

起動後、古い Next の画像フォルダーをバックグラウンドで整理します。問題が起きた場合は元のファイルを残し、移行の注意を表示します。旧 Dice! からの取り込みでは、元のボットは読み取りのみで、Next 側でデッキの画像をコピーして Next の参照を調整し、古いファイルは変更しません。

プラグイン / mod の非公開のリソースは名前ごとに整理します。登録済みの画像に対する Lua のファイルの読み書きは、パスの別名を通じて引き続き使えます。削除してよいと証明できない古い非公開のパスには互換のコピーを残し、動的な呼び出しを壊さないようにしています。

バックアップでは選んだ画像とパスの索引を保存します。部分的な復元では索引を統合するため、選ばなかった画像へのリンクも失われません。チャットとログのキャッシュは引き続き元の保持期間 / 削除のルールで整理され、返信やデッキなどの永続的なリソースが整理されることはありません。

管理とプレビューにはパネルへのログインまたは API キーが必要です。通常のプレビューで画像が公開されることはありません。HTTP での送信を設定すると、永続的なリソースにはランダムなトークン付きのリンクを生成できますが、キャッシュはリソースの共有の入口から公開されません。

デッキを画像ごとほかのボットへ移す方法は [`.deck` デッキパッケージ](/ja/use/deck#deck-牌堆包)を参照してください。
