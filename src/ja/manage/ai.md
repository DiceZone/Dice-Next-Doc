# AI

**管理パネル → AI** で OpenAI 互換の大規模言語モデルを接続し、ボットに返信の文章調整、翻訳、会話、NPC ロールプレイ、画像認識などの機能を与えます。サイドバーには **モデル / 会話 / NPC ロールプレイ / ナレッジベース / 返信の文章調整 / 返信の翻訳** の 6 つのサブページがあります（ナレッジベース以外は編集の状態を共有し、どのサブページで「保存」をクリックしてもすべてを保存します。ナレッジベースのページには専用の保存ボタンがあります）。

::: warning 費用と遅延
AI を有効にすると、関連する機能は設定したモデルの料金で課金され、AI が処理する返信には遅延が生じます（ネットワークと大規模言語モデルの応答速度によります）。各モデルにトークン数 / 費用の上限を設定してください。すべての AI 機能は失敗やタイムアウトの際に元に戻ります。文章調整 / 翻訳は原文を送り、会話は返信しません。
:::

## モデル

### 全体スイッチ

「AI を有効にする」はすべての AI 機能の全体スイッチで、オフにすると文章調整、翻訳、会話などがすべて無効になります（ほかのサブページは灰色になり、先に「モデル」ページでオンにするよう案内が出ます）。

### 全体のリクエストのパラメーター

すべての AI の呼び出しで共有するパラメーターです（文章調整 / 翻訳では原文に忠実にするため、別に低めの温度を使います）：temperature、top_p、最大トークン数、頻度のペナルティ、存在のペナルティ。

モデルの設定は **プロバイダー → モデル → 用途の割り当て** の 3 つのタブに分かれています。まず API とキーを入力し、次に使うモデルを並べ、最後にそれぞれの機能でどのモデルを使うかを決めます。

### プロバイダー

1 つのプロバイダーは 1 組の API のアドレスとキーに対応し、その配下のすべてのモデルで共有するため、同じサービスのモデルごとにキーを入力し直す必要はありません。

| 項目 | 説明 |
|------|------|
| 名前 | 自由に付ける名前（「OpenAI」「DeepSeek」「ローカルの Ollama」など） |
| 接続先 Base URL | OpenAI 互換の API のアドレス。`/v1` まで入力すればよい（例：`https://api.openai.com/v1`） |
| API Key | ローカルのモデルでは空欄でよい |

プロバイダーを無効にすると、その配下のすべてのモデルは呼び出されなくなります。まだモデルが使っているプロバイダーは削除できません。

### モデル

| 項目 | 説明 |
|------|------|
| 表示名 | 自由に付ける名前（「GPT-4o mini」「ローカルの Qwen」など） |
| プロバイダー | 「プロバイダー」タブで追加したものから選ぶ |
| モデル名 model | `gpt-4o-mini`、`qwen2.5`、`text-embedding-3-small` など |
| 種類 | **汎用モデル**：会話、文章調整、翻訳、画像認識、音声認識など。**埋め込みモデル**：文章をベクトルに変換するだけで、長期記憶の検索に使う |
| 画像の入力に対応 | 汎用モデルのみ。有効にしないと「画像認識」に割り当てられない |
| 入力の単価 / 出力の単価 | 100 万トークンあたりの単価。費用の集計に使う（埋め込みモデルは入力の単価のみ） |
| トークンの上限 / 費用の上限 | 0 = 無制限。上限を超えるとそのモデルの呼び出しを止め、同じ用途の次のモデルに自動で切り替える |

各モデルには使用済みのトークン数と累計の費用を表示し、「テスト」ボタンもあります。汎用モデルでは実際に 1 回会話し、埋め込みモデルでは実際に 1 回ベクトル化してベクトルの次元数を表示します。

### 用途の割り当て

機能ごとに使うモデルを指定します。

| 用途 | 説明 | 割り当てがない場合 |
|------|------|----------|
| 会話の返信 | グループでのボットの会話 | 最初に有効にした汎用モデル |
| 判断 | 待機中に話しかける前に、口をはさむかどうかを判断（下の「会話」を参照） | 「会話の返信」を使う |
| 文章調整 / 翻訳 | 返信の文章調整、`.lang` の翻訳 | 「会話の返信」を使う |
| 記憶の要約 / 事実の抽出 | グループの履歴の要約、長期記憶の抽出 | 「会話の返信」を使う |
| NPC ロールプレイ | NPC の返信（NPC に専用のモデルを設定していればそちらを優先） | 「会話の返信」を使う |
| NPC の感情の評価 | NPC の好感度の変化を評価 | 「NPC ロールプレイ」を使う |
| 画像認識 | メッセージの画像を認識。「画像の入力に対応」したモデルのみ選べる | 「会話の返信」のうち画像に対応したモデルを使う |
| 音声認識 | 音声を文章に変換 | 使えない |
| 埋め込み | 長期記憶のベクトル化。埋め込みモデルのみ選べる | 使えない |

各用途には複数のモデルを選べ、**使い方の方針** も選べます（既定は負荷分散）。

- **負荷分散**：そのとき処理中のリクエストが最も少ないモデルを選び、同じ場合は順番に使います。
- **ランダム**：毎回ランダムに 1 つ選びます。
- **順番優先**：一覧の順に最初のモデルを使い、失敗したときや上限を超えたときだけ次に切り替えます（上下の矢印で順序を変えられます）。
- **重みの割り当て**：重みの比率に従ってリクエストを振り分けます（重み 1–100）。

どの方針でも、呼び出しに失敗すると次の候補のモデルに自動で切り替えて再試行します（1 回あたり最大 3 つ）。ツールの呼び出しを伴う会話では、最初のラウンドで失敗したときだけモデルを切り替え、ダイスやシートの変更などの操作が二重に実行されないようにしています。

::: warning 埋め込みに指定できるモデルは 1 つだけ
保存済みの記憶のベクトルと、検索時のベクトルは同じモデルのものである必要があるため、「埋め込み」には 1 つのモデルしか選べません。埋め込みモデルを変えた後は、「会話」ページで長期記憶を消去して、ベクトルを生成し直してください。
:::

::: tip 旧バージョンからのアップグレード
旧バージョンでは、モデルごとに API のアドレスとキーを持ち、機能ごとにモデルを指定していました。アップグレード後の最初の起動で自動的に変換されます。「アドレス + キー」が同じモデルは 1 つのプロバイダーにまとめ、各機能で指定していたモデルは対応する用途の割り当てに変え、長期記憶の埋め込みの設定は 1 つの埋め込みモデルに変えます。変換前の元の設定は `dice.json` の `ai_backup_v1` にバックアップされます。
:::

## 会話

ボットがグループで人のように会話できるようにします（グループチャットでのみ有効）。

### 反応の方式（3 つの状態）

- **ボットへの @**：必ず返信し、クールダウンの制限を受けません。
- **キーワードに一致**（カンマ区切り、例：「骰娘, 在吗」）：必ず返信し、クールダウンの制限を受けません。
- **待機中の確率**（0–100）：それ以外のメッセージには確率に従ってランダムに話しかけ、「グループごとのクールダウン（秒）」の制限を受けます。高く設定しすぎると頻繁に口をはさむので注意してください。
- **待機中に話しかける前に判断する**：チェックすると、待機中の確率が当たったときに、まず「判断」の用途のモデルに今口をはさむべきかを判断させます（誰かが質問している、話題がボットに関係しているなど）。いいえと判断されれば返信しません。判断はごく短い結果だけを出力するため、返信を直接生成するより使用量が少なく、「判断」には安くて速いモデルを割り当てるのに向いています。@ やキーワードの一致のときは判断を通りません。

### 生成のパラメーター

文脈のラウンド数（このグループの最近のチャットの記録を文脈として読む）、返信の最大文字数、グループごとのクールダウンの秒数、返信時に送信者を @ するか、絵文字の出力を禁止するか、カスタムのフィルターの言葉（AI に渡す前に文章から透かし / 署名 / 連投の言葉を取り除く）、ペルソナとシステムプロンプト（空欄なら内蔵の既定を使い、「既定を読み込む」をクリックしてテンプレートをもとに変更できる）。

### グループの履歴の記憶（順次の要約）

会話が最近の範囲を超えると、それより前のチャットをまとめてグループの要約に圧縮して背景に注入し、ボットがより前のことを覚えていられるようにします。要約には「記憶の要約」の用途のモデルを使います。保持するラウンド数（まとめる単位の大きさ）、要約の文字数の上限、要約のプロンプトを設定でき、ページで各グループの保存済みの要約を確認 / 消去できます。範囲から外れたメッセージが 1 回分たまったときだけモデルを呼び出します（自然に頻度が制限され、費用も抑えられます）。

### 長期記憶（永続的な事実・ベクトル検索）

会話から長く覚えておく価値のある事実（キャラクターシート / シナリオ / 約束）を抽出し、ベクトル化して保存します。会話のときには、現在の話題との類似度で最も関連する数件を検索して注入します。先に「モデル」ページで種類が「埋め込みモデル」のモデル（`text-embedding-3-small` など）を追加し、「用途の割り当て → 埋め込み」で指定しておく必要があります。抽出には「事実の抽出」の用途のモデルを使います。検索する件数 Top-K、類似度の基準、グループごとの事実の上限、抽出のプロンプトを設定でき、保存済みの事実も同様に確認 / 消去できます。

### ツールの呼び出し

有効にすると、ボットは function-calling で実際の機能を呼び出し、自分で数字を作り上げることはしません（モデルが tools に対応している必要があります）。

| ツール | 説明 |
|------|------|
| `roll_dice` | 実際のダイスのエンジンでダイスを振る |
| `draw_deck` | デッキから引く |
| `get_attr` | 送信者のキャラクターシートの能力値を読む |
| `set_attr` | 送信者のキャラクターシートに書き込む（危険があるため既定でオフ） |
| `run_command` | 任意のコマンド / プラグインを実行（権限は送信者と同じ） |
| `search_help` | ヘルプ文書の項目を検索。ナレッジベースを有効にするとナレッジベースの検索に変わる |

「ツールの最大ラウンド数」で連続した呼び出しの回数を制限し、最後のラウンドでは強制的に文章の返信を出力させます。「会話」が有効なときだけ働きます。

### AI のホワイトリスト（アクセス制御）

有効にすると、ホワイトリストに入ったグループ / 個人チャットだけが AI の会話と NPC を使えます。ホワイトリストにないグループでは、グループ管理者が `.ai on` を送っても拒否され、認可されていないグループが API の費用を使うのを防ぎます。リストはグループ / プレイヤーの一覧から検索してチェックして追加します。ホワイトリストが制御するのは会話 / NPC / グループの記憶だけで、返信の文章調整と翻訳は全体の機能なので影響を受けません。

### 画像認識（マルチモーダル）

メッセージに画像が含まれる場合、マルチモーダルのモデルで画像の内容を認識し、得られた文章の説明を会話に注入して、ボットが「画像を理解」できるようにします。@ されたときやキーワードに一致したときなど、反応したときだけ認識します（費用を抑えるため）。認識には「画像認識」の用途のモデルを使います（モデルの「画像の入力に対応」を有効にする必要があります）。1 件あたりに認識する最大の枚数と、認識のプロンプトを設定できます。

**画像のリンクを直接渡す** のスイッチ：有効にすると QQ の画像のリンクをそのまま大規模言語モデルに渡します（速いが、リンクが期限切れになることがある）。無効にするとダウンロードしてから base64 でアップロードします（遅いが確実）。

スイッチの状態はほかの AI の設定と一緒に保存されます。オフにして保存した後、ページを開き直したりプログラムを再起動したりしてもオフのままになるはずで、`dice.json` を手動で編集する必要はありません。

### 音声認識

グループで音声が送られると、「音声認識」の用途のモデルで音声を文章に変換し、会話の反応の判断と返信に渡します（たとえば音声の中でキーワードを言っても反応できます）。OpenAI 互換の `/audio/transcriptions` に対応したモデル（Whisper、SiliconFlow の SenseVoice など）が必要です。「モデル」ページで汎用モデルとして追加し、「音声認識」に割り当ててください。

- **OneBot（NapCat など）**：`get_record` で mp3 を取得します。ボットと NapCat が同じマシンにない場合（Docker など）は、NapCat で base64 を返すオプションを有効にしてください。そうしないと音声ファイルを読めません。
- **Discord**：音声の添付ファイルを直接ダウンロードします。
- 音声 1 件ごとに音声認識のモデルへのリクエストが 1 回増えます。同じ音声の文字起こしは 1 回だけです。

## ナレッジベース

**AI → ナレッジベース** は、「どう使うのか / ある機能はあるのか / グループのルールは何か」といった質問にボットが根拠をもって答えられるようにするもので、モデルの使用量はできるだけ増やしません。

- **検索はこのマシンで行います**：キーワードでスコアを付け（BM25）、質問の書き換えや検索の要否の判断にモデルを呼び出すことはしません。約 1 万件の資料でも、1 回の検索は数十ミリ秒です。
- **関連する少量の資料だけを注入します**：関連度が基準に達した上位の数段落だけをプロンプトに加え、合計の文字数にも上限があります。雑談で関連する資料が見つからないときは何も加えません。
- **FAQ に直接回答します**：カスタムの項目で「直接回答する」にチェックすると、質問と項目の問い方が十分に似ている場合に項目の内容を原文のまま返し、**モデルを一切呼び出しません**。

### 資料の出所

| 出所 | 内容 |
|------|------|
| ヘルプの項目 | ヘルプの仕組みのすべての項目：内蔵のコマンド、ルールパック、プラグイン、カスタムのヘルプ文書。検索時に直接読むため、ヘルプを変更するとすぐに反映される |
| DiceNext のドキュメント | このドキュメントサイトの使い方の説明。プログラムと一緒にインストールされ、ネットワークへの接続は不要 |
| カスタムの項目 | ナレッジベースのページで入力した資料：グループのルール、世界観、よくある質問など |

### 設定

| 設定 | 説明 |
|------|------|
| 注入する最大の段落数 | 1 回の会話でプロンプトに加える資料の最大の段落数（1–8、既定は 3） |
| 関連度の基準 | 0–1。質問のキーワードが資料に含まれる割合がこれに達したときだけ注入する（既定は 0.45）。上げると無関係な資料が減り、下げるとより多く見つかる |
| 注入する文字数の上限 | 1 回に注入する資料の合計の文字数（既定は 1200）。入力のトークンを制御する |
| FAQ の直接回答 / 類似度 | 質問と問い方の類似度がこれに達すると直接返信する（既定は 0.6） |
| 意味による検索（カスタムの項目） | カスタムの項目についてベクトルの類似度も比べ、言い方が違っても見つけられるようにする。「用途の割り当て → 埋め込み」で埋め込みモデルを指定する必要があり、検索のたびに埋め込みモデルへのリクエストが 1 回発生する |

### カスタムの項目

各項目にはタイトル、内容、問い方（1 行に 1 つ）、タグ、「直接回答する」のスイッチがあります。問い方とタイトルは検索で重みが高く、FAQ の直接回答も問い方と比べます。JSON ファイルから一括で取り込めます。項目の配列、または `{"entries": [...]}` で、各項目に `title`、`content`、`questions`、`tags`、`direct` を含められます。項目は `data/knowledge/entries.json` に保存されます。

### 検索のテスト

ページにプレイヤーが尋ねそうな文を入力すると、どの資料に一致するか、それぞれの関連度、何文字注入されるか、FAQ の直接回答が働くかを確認できます。ページ上の現在の（まだ保存していない）設定を使うため、基準の調整に便利です。

ナレッジベースを有効にすると、ツールの呼び出しの `search_help` もナレッジベースの検索に変わります。会話のときに検索する質問からは、先に「反応のキーワード」（ボットの名前など）を取り除きます。

## NPC ロールプレイ

NPC（名前 / ペルソナ / 背景知識 / 反応する言葉）を定義します。グループのメッセージで NPC の名前が出たり、反応する言葉に一致したりすると、ボットはその NPC の身分、口調、知識で返信します（記憶とツールの呼び出しを使い、既定のボットの会話より優先されます）。宿屋の主人や謎の情報屋などを演じるのに使えます。

各 NPC には、反応する言葉（名前以外）、専用のモデル（任意）、限定するグループ（`onebot_v11:123456` など。空欄 = すべてのグループ）、ペルソナと背景知識（その役だけが知っている情報）を設定できます。**感情の記憶** を有効にすると、NPC はプレイヤーごとに好感度（-100〜100）と感情を保ち、関係に応じて口調が変わります。やり取りのたびにモデルで好感度の増減を評価します（リクエストが 1 回増えます）。

## 返信の文章調整

ダイス / 判定の返信を送る前に、大規模言語モデルでペルソナと状況に合わせて文章を整えます。方式は 2 つあります。

- **言い回しだけを整える**：数字 / 結果はそのままで、言い方だけを変えます。
- **状況に応じてロールプレイの描写を加える**：結果をもとに、ロールプレイの描写を加えます。

ペルソナ / スタイルとシステムプロンプトを設定できます（「既定を読み込む」で変更できます）。モデルは元の数字と成功 / 失敗の結果を厳密に保つ必要があります。サーバーが数字を検証し、書き換えられていれば自動で原文に戻します。失敗やタイムアウトのときも原文を送ります。

**対象の範囲**：文章調整と翻訳はどちらも、チェックした種類ごとに適用されます。ダイス/判定、デッキからの抽選、娯楽のコマンド（今日の運勢 / 狂気 / ランダムな名前など）、カスタム返信、プラグインの結果です。

## 返信の翻訳

`.lang` と組み合わせてカスタムの言語を実現します。まずページで言語を定義し（名前 + 切り替えのキーワード。例：名前「ドイツ語」、キーワード「de, german, 德语」）、グループ / 個人チャットで `.lang <キーワード>` を送ると切り替わります。返信はまず既定の言語で生成し、送信前に大規模言語モデルで目的の言語に翻訳します（キャッシュがあり、同じ文章で重ねて課金されません）。翻訳のプロンプトでは `{lang}` で目的の言語の名前を表せます。失敗やタイムアウトのときは自動で原文を送り、内蔵の言語に戻すか `.lang clr` で翻訳を止められます。

## チャットのコマンド

`.ai on/off` でグループごとにこのグループの AI 機能（会話 / NPC）をオン・オフできます。詳しくは[管理コマンド](/ja/use/admin)を参照してください。ホワイトリストモードが有効な場合、ホワイトリストにないグループでは `.ai on` も拒否されます。

::: tip AI がコマンドを遅くすることはありません
すべての大規模言語モデルの呼び出しは独立したバックグラウンドのキューで順に実行され、メッセージのスレッドを占有しません。AI の API が 30 秒止まっても、通常のコマンドはいつもどおりすぐに返信します。たまりすぎた場合は新しい AI の処理を捨てます（会話は返信せず、文章調整は原文に戻ります）。
:::

## 調査：DEBUG ログ

「WebUI 設定 → コンソールのログ」の最低記録レベルを **DEBUG** にすると、AI の処理の各段階を確認できます。

- 反応の判断：@ されたか、どのキーワードに一致したか、待機中の確率で何が出たか。判断のモデルの結論と理由。
- モデルの選択：用途、方針、試す順序、失敗後にどのモデルに切り替えたか。
- 各リクエストの完全な内容（システムプロンプト、文脈、ユーザーのメッセージ、ツールの一覧）、モデルの思考の過程と返信、失敗時の元の応答。
- ツールの呼び出しの引数と結果、画像認識 / 音声認識の結果。
- ナレッジベースの検索：スコアを付けた件数、かかった時間、一致した資料と関連度、FAQ の直接回答。
- 記憶の整理：今回まとめたメッセージ、更新後の要約、抽出した事実、飛ばした重複する事実、検索で一致した記憶と類似度。

モデルが出力した思考の過程（`<think>` の段落または `reasoning_content` の項目）はログにだけ書き込まれ、グループに送られることはありません。

::: warning DEBUG ログにはチャットの内容が含まれます
DEBUG レベルでは、グループのメッセージやキャラクターシートなどの内容をすべて記録します（API キーは書き込まれません）。調査が終わったら INFO に戻してください。
:::

::: tip まずテスト台でプレビュー
「コマンドテスト」ページで `.r` やチャットの内容を送ると、グループに入らなくても文章調整 / 翻訳 / 会話の効果を直接プレビューできます。[コマンドテスト](/ja/manage/playground)を参照してください。
:::
