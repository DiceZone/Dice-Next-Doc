# 管理パネルの概要

Dice!Next には Web 管理パネルが付属しています。ブラウザでサービスのアドレス（既定は `http://localhost:18088`）を開くと入れます。ほとんどの設定はパネルで行え、ファイルを編集する必要はありません。

ホーム画面のサーバー情報には、直近 **10 分間** の CPU とメモリの使用率を表示し、**5 秒** ごとに更新して、各サンプルの元の値を保持します。バックエンドは直近 1 時間の履歴を保持し、ホーム画面ではそのうち直近 10 分間だけをグラフにします。バックエンドを再起動すると改めて記録し始めます。履歴が 10 分に満たない場合は、実際のサンプルで表示します。最初の読み込みでは読み込み中の表示を出し、更新に失敗した場合は最新のスナップショットを残して知らせます。旧版のバックエンドに履歴がない場合は、このブラウザでの最近のサンプルを使います。

::: tip ログインとセキュリティ
- **ログインパスワード**：[WebUI 設定](/ja/manage/settings#webui-設定ページ)で管理パネルのログインパスワードを設定すると、パネルを開く前にパスワードの入力が必要になります（Cookie のセッション認証）。空欄で保存するとログインがオフになります。
- **API Key**：バックエンドの API のアクセスキーで、設定ファイルの `server/api_key` と同じ値です。
- パネルをインターネットに公開する場合は、必ず両方を設定してください。
:::

## 設定の横断検索

管理パネルの上部バーには設定の横断検索があり、デスクトップでは `Ctrl+K`（macOS では `⌘K`）でも開けます。検索ではページ名、機能の分類、具体的な設定、説明、よく使われる別名をまとめて照合します。たとえば `Markdown`、`敏感词`（禁止語）、`SMTP`、`密码`（パスワード）、`定时任务`（定期タスク）などです。結果には具体的な機能、所属するページ、内容の概要を表示し、別名だけで一致した場合は一致したキーワードも示します。たとえば「更新」や「升级」（アップグレード）で検索すると「更新の確認と自動更新」が表示され、「翻译」（翻訳）で検索すると「AI 翻訳（.lang のカスタム言語）」が直接表示され、対応するサブページと機能のカードへ移動できます。

結果を選ぶと対応するページを直接開きます。システム設定、通知設定、WebUI 設定の具体的な項目では、正しいタブに自動で切り替え、目的のカードまでスクロールして短時間強調表示します。検索のダイアログ、結果の一覧、キーボードでの選択はすべてパネル独自のスタイルを使い、ブラウザ標準のプルダウンには頼りません。

## 初心者向けチュートリアル

初心者向けチュートリアルでは、実際のページで関連する機能を強調表示し、読み取り専用のデモデータで画面を理解する手助けをします。デモは実際の動作データではなく、ボットの設定として保存されたり、実際の操作を実行したりすることはありません。チュートリアルを終了すると通常のページに戻ります。

## 動作の概要

- **状態のカード**：オンラインのアダプター、ユーザー、グループ、セッションログ、累計で応答したコマンドの数、稼働時間。どのカードもクリックでき、それぞれプラットフォームの接続、プレイヤー管理、グループ管理、セッションログ、コマンド一覧、データの統計（オンラインの履歴を含む）を開きます。
- **最近のログ**：時刻、レベル、モジュール、内容で表示し、既定の最低レベルは INFO です。検索、診断情報の展開、メッセージの関連付けに対応しています。実際に記録する基準は [WebUI 設定](/ja/manage/settings#webui-設定ページ)で変更します。

## プログラムログ

6 つのレベルの順序は **TRACE → DEBUG → INFO → SUCCESS → WARN → ERROR** です。既定の INFO では INFO、SUCCESS、WARN、ERROR を表示します。通常のプロトコルのハートビートは TRACE、一覧の更新、キャッシュ、成功した文面のプレビューのリクエストは DEBUG です。文面の保存や取り込みなどの管理操作は引き続き記録し、プレビューの失敗や処理時間の異常も対応するログを残します。SUCCESS は重要な操作の完了が確認されたことだけを表し、プレイヤーの判定の成功・失敗は通常の INFO です。

`[处理]`（処理）には、内蔵のコマンド、JS/Lua プラグイン、高度な返信などの処理した側、反応の方法、処理の結果、送信予定の内容を表示し、内部の msgID を割り当てます。`[消息]`（メッセージ）には、プラットフォーム向けに整形した後に実際に送信した内容と同じ msgID を残し、発生元は繰り返しません。分割、Markdown の代わりの再試行、プラットフォームの確認、失敗のいずれも対応付けられます。プラットフォームの操作には `[事件]`（イベント）を使います。msgID はプラットフォームのメッセージ ID ではなく、送信やプラットフォームの受理は、ユーザーが受け取った・読んだことを意味しません。

プラグインが `log/print/console` で自ら出したログには具体的な発生元を表示します。プラグインの実行中に送信を依頼しても、実行全体が成功したと前もって記録することはなく、終わっていない非同期の処理は待機中であることを示します。発生元が混在する場合はそれぞれの処理した側を残し、定期実行、Lua の sleepTime、プラグインをまたぐ非同期の続きの処理で、「最近実行したプラグイン」から発生元を推測することはありません。

ホーム画面では、最低表示レベルの選択、内容／モジュール／プラグイン／msgID の検索、「関連する記録を表示」のクリックができます。関連のウィンドウは一覧のレベルの絞り込みの影響を受けません。エラー自体にも発生元の詳細が付いているため、元の INFO の記録が最近の範囲にない場合も調査できます。C++ のファイル、行番号、関数、スレッド番号は「診断の詳細」で確認でき、通常のログの各行の先頭を占めることはありません。

時刻はミリ秒まで保持し、サーバーのタイムゾーンで表示して、ブラウザのタイムゾーンで計算し直すことはありません。ホーム画面では現在のプロセスの範囲の限られた最近の記録を保持し、最新の 500 件までを読み込み、1 日分のファイル全体を走査することはありません。完全な履歴と詳細は `data/logs/app/` の `.log` と `.jsonl` に保存されます。どちらのファイルも機密情報を伏せていますが、共有する前に未知の個人情報がないか確認してください。

## タスクトレイ（Windows）

- 起動後は **既定でコンソールウィンドウを隠し、タスクトレイに最小化** します（初回は通知を表示します）。設定の `dice/console_start_hidden` を `false` にすると、起動時にコンソールを表示する動作に戻せます。
- トレイアイコンにマウスを合わせるとポートを表示します（`Dice!Next(18088)` など。複数起動しているときの区別に便利です）。トレイのメニューから管理パネルを開く、コンソールを表示する、プログラムを終了することができます。
- build 926 以降、**システム設定 → 基本設定 → ネットワークとシステム → Windows のトレイのヒントの文字** で名前をカスタマイズできます。最大 10 文字の Unicode 文字で、空欄にすると `Dice!Next` に戻り、保存するとすぐに反映されます。ポートはプログラムが実際の待ち受けポートを自動で付け加えるため（例：`希亚骰(18089)`）、手動で入力する必要はありません。これはプログラム全体の設定で、アダプターによって変わることはなく、Windows でのみ変更できます。
