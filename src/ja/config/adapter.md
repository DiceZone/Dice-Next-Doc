# アダプター設定

Dice!Next はプラグイン式のアダプター構成を採用しています。アダプターは[管理パネル → アダプター管理](/ja/manage/adapter-manager)で追加・管理します。設定は `config/adapters.json` に保存され、次回の起動時にそのまま読み込まれます。

## OneBot v11 アダプター

設定の `connection_mode` に対応する 2 つの通信方式に対応しています。

| 方式 | `connection_mode` | 意味 | エンドポイントの入力内容 |
|------|-------------------|------|----------|
| 正方向 WebSocket | `forward_ws` | Dice!Next から OneBot クライアントへ接続する | 完全な WS のアドレス（例：`ws://127.0.0.1:3001/`） |
| 逆方向 WebSocket | `reverse_ws` | OneBot クライアントから Dice!Next へ接続してくる | **ポート番号**（例：`6700`）。Dice!Next がそのポートで待ち受ける |

逆方向モードでは、OneBot クライアントの逆方向 WS の接続先を `ws://<Dice!Next の IP>:<ポート>/` に設定します。このポートが受け付ける OneBot の接続は 1 つだけで、それ以上の接続はすぐに閉じられます。

::: tip 切断後の再接続（正方向 WS）
自動再接続は間隔を延ばしながら行います。最初の 10 回は 5 秒ごと、11〜20 回目は 60 秒ごとです。20 回連続で失敗すると自動再接続を止めて状態が「接続タイムアウト」になります。パネルで手動で再接続すれば復旧します（接続が 30 秒安定すると失敗回数は自動でリセットされます）。
:::

## 設定ファイルの項目

アダプターの配列は `config/adapters.json` に書かれます。

```json
{
  "adapters": [
    {
      "name": "MyQQBot",
      "type": "onebot_v11",
      "connection_mode": "forward_ws",
      "endpoint": "ws://127.0.0.1:3001/",
      "access_token": "",
      "enabled": true
    }
  ]
}
```

| 項目 | 説明 |
|------|------|
| `name` | アダプターの表示名 |
| `type` | プロトコルの種類。OneBot v11 は `onebot_v11` |
| `connection_mode` | `forward_ws` / `reverse_ws` |
| `endpoint` | 正方向：OneBot 側の WS のアドレス。逆方向：待ち受けるポート番号 |
| `access_token` | 接続トークン。空欄なら送信しない（正方向の接続では `Authorization: Bearer` ヘッダーで送信し、OneBot 側と同じ値にする） |
| `enabled` | 有効にするか |

## 管理パネルでの設定

**管理パネル → アダプター管理** を開き、接続を新規作成してプラットフォームに合わせて接続情報を入力し、保存して有効にします。パネルでの変更はすぐに反映され、再起動は不要です。

## 複数のアダプター

複数のアダプターを追加して、別々のアカウントに接続したり、予備の接続にしたりできます。

## Milky アダプター

プラットフォームの接続で **Milky** を選びます。API は HTTP で呼び出し、イベントは WebSocket で受け取ります。現在は `forward_ws` のみに対応し、Webhook での受信には対応していません。

| 項目 | 説明 |
| --- | --- |
| API アドレス（`endpoint`） | Milky サービスの HTTP / HTTPS のベースアドレス（例：`http://127.0.0.1:3000`）。OneBot の WS アドレスではありません |
| イベントアドレス（`eventEndpoint`） | WebSocket のアドレス（例：`ws://127.0.0.1:3000/event`）。空欄の場合は API アドレスから導きます |
| 接続方式（`connectionMode`） | `forward_ws`。Dice!Next からイベントサービスに接続します |
| Access Token（`accessToken`） | Milky サーバー側と同じ認証トークン。BDC のボット用キーではありません |

グループチャット / 個人チャット、グループメンバーとグループ内の名前、グループファイルと関連する管理機能に対応していますが、実際の操作はプロトコル側の実装とボットの権限に左右されます。一時的な個人チャットでは発生元のグループ情報を保持しますが、グループ番号を個人チャットの宛先として扱うことはありません。グループ履歴の 1 回の読み取りは、プロトコルの制限により 1〜30 件です。

接続サービスを認証なしでインターネットに直接公開しないでください。API につながってもイベントが接続されているとは限りません。メッセージに反応しない場合は、API アドレス、イベントアドレス、認証、サーバーのログをあわせて確認してください。

## QQ 公式ボットでできることの範囲

- グループチャット、C2C（1 対 1 のチャット）、チャンネルではできることが異なります。グループ / C2C の Markdown には対応するプラットフォームの権限が必要です。チャンネルはそれ自体が対応するメッセージ形式で送信するため、Markdown に同様に対応しているとは考えないでください。
- グループ情報、メンバー、管理、メッセージの取り消し、メニュー、チャンネルなどの公式 API が用意されており、[バックエンドの API アクション入口](/ja/develop/qq-official-api#バックエンドからの呼び出し入口)から `qq_*` アクションを呼び出せます。招待や許可リストが必要な API もあり、権限がない場合はプラットフォームのエラーがそのまま返されます。
- `.log export` はリッチメディアのファイル送信（`file_type=4`）に対応しています。アップロードは 200MB の上限で事前に確認しますが、実際に送信できるかはプラットフォームとアカウントの権限によります。ファイルが届かない場合は、ログサイトのリンクか WebUI からのダウンロードを使ってください。
- API に接続済みでオフラインのテストに通っていても、実際のアカウントのすべての場面で確認済みというわけではありません。調査するときはエラーコードと時刻を控え、AppSecret、トークン、プレイヤーの機密データは公開しないでください。

### 公式のニックネームとグループ名

グループメッセージ、グループでの @ メッセージ、1 対 1 のメッセージの `author.username` はニックネームのキャッシュに入ります。空の場合は既存のキャッシュを使い、「ユーザー」や OpenID で本当のニックネームを上書きすることはありません。キャッシュはボットの AppID ごとに分かれ、再起動後も使え、プレイヤーのプロフィールにも同期されます。メンバーの照会で得たニックネームも、メンバー一覧、イベント通知、プラグインのイベントで使われます。

接続に成功すると、Dice!Next はこのボットが把握していて、まだ退出していないグループの情報をバックグラウンドで先に取得します。最近メッセージの送受信があるときは後回しにし、空いているときにグループ名とメンバーのニックネームを順番に更新します。1 回に取得するのは 1 ページだけで、古くなった情報は約 1 時間ごとに更新し直します。新しいグループメッセージや参加イベントを受け取った場合も、そのグループが順番待ちに入ります。通常の `bot off` は名前の事前取得に影響せず、グループからの退出、グループ記録の削除、アダプターの停止で該当する更新が止まります。

グループメンバーの API は 1 ページあたり最大 30 人を返します。Dice!Next はページのカーソルを保存して取得を続けるため、3000 人でグループ全体を打ち切ることはありません。制限に達したときや 1 回分の取得が終わったときに一時停止し、少し後にバックグラウンドで続きを取得します。各ページで得たニックネームはすぐにキャッシュに入りますが、メンバー一覧とグループ管理に使うのは最後まで取得できた名簿だけです。カーソルの重複、異常なページ、リクエストの失敗によって、途中までの名簿が完全な名簿として扱われることはありません。

友だち追加のイベント `FRIEND_ADD` にはニックネームの項目がありません。同じ OpenID のニックネームがすでにある場合や、プラットフォームが提供する `union_openid` に対応するニックネームがある場合は、通知でそれを使えます。初めて現れ、既知の名前がまったくない場合は、引き続き不明なユーザーとして表示します。統一 ID は名前の再利用にだけ使い、アカウントの紐付け、キャラクターシートの統合、権限の共有を自動で行うことはありません。

グループ名は `GET /v2/groups/{group_openid}/info` の `group_name` から取得し、グループ情報に永続的に保存します。グループ情報、メンバー一覧、メンバー詳細の API にはプラットフォームの許可リストの権限が必要で、権限がない場合は `11253` が返されます。照会はバックグラウンドで行い、失敗したときは古い名前を残して間隔を空けて再試行します。メッセージの処理がニックネームを待って止まることはなく、途中までの名簿を完全な名簿として扱うこともありません。

API の根拠：[グループメッセージイベント](https://bot.q.qq.com/wiki/develop/api-v2/autogen/event/group_message_create.html)、[友だち追加イベント](https://bot.q.qq.com/wiki/develop/api-v2/autogen/event/friend_add.html)、[グループ情報](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_info.get.html)、[メンバー一覧](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_members.get.html)、[メンバー詳細](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_members_member_openid.get.html)。

### グループメンバーとインタラクションのイベント

公式アダプターの設定には 2 つのスイッチがあります。

- **グループメンバーの参加・退出イベントを購読する**：公式の `GROUP_MEMBER_EVENT (1<<24)` を使い、メンバーの参加・退出イベントを歓迎メッセージ、グループ管理、プラグインのイベントに渡し、メンバーのキャッシュを更新します。パネルで新規作成したアカウントでは既定でオンで、既存のアカウントは元の購読設定を保ちます。プラットフォーム側に対応する機能が必要で、保存後に再接続してください。
- **インタラクションイベントに自動で応答する**：既定でオンです。メッセージのボタンとクイックメニューのイベント（種類 11、12）に 1 回応答し、QQ クライアントの読み込み中の表示を終わらせます。コールバックを受け取ってもコマンドが実行されたわけではなく、コールバックのデータが自動でチャットのコマンドとして実行されることもありません。プラグインや外部の処理側で応答コードを選ぶ必要がある場合は、自動応答をオフにしてください。

メッセージのフィードバック、会話のクリア、ストーリー集、モデルの切り替え、ユーザー / グループの認可、購読テンプレートの認可の状態は、ネイティブプラグインのイベントフックで処理できます。認可の通知によって、ブラックリストが自動で解除されたり、ダイスが有効になったり、管理権限が付与されたりすることはありません。新しいタイムスタンプ、参照インデックス、カード、メッセージの場面のデータも保持します。重複して届いたイベントはメッセージ ID とメッセージインデックスで重複を除き、同じコマンドが二重に実行されないようにしています。

公式 API の呼び出し、ネイティブプラグインのフック、パラメーターの例は [QQ 公式 API v2](/ja/develop/qq-official-api) を参照してください。

## 返信文とビジュアル方式

**システム設定 → 基本設定 → 返信と表示 → 返信文とビジュアル方式** で、従来、標準、高度なビジュアルのいずれかの文面を選びます。設定はグローバル、アダプターの種類、個別のアカウントのそれぞれに適用でき、優先順位はアカウント > アダプターの種類 > グローバルです。部分的な上書きでは任意の方式を個別に選べ、旧来の 2 択の「グローバルのメインスイッチ」には縛られなくなりました。

| プラットフォーム | リッチテキストの表示 | 説明 |
| --- | --- | --- |
| OneBot v11 | 従来の文章 | OneBot の標準には、実装をまたいで使える統一されたカードのプロトコルがありません。 |
| Milky | 従来の文章とプロトコルのメッセージセグメント | QQ 公式ボットの Markdown 機能は使いません。 |
| Discord | Embed | Embed の長さの上限を超えるメッセージは従来の文章のままです。 |
| KOOK | CardMessage | 公式のカードメッセージ形式を使います。長すぎる内容は従来の文章のままです。 |
| QQ 公式ボット 2.0 | Markdown | プラットフォームでボットの Markdown 機能を有効にする必要があります。API が続けて拒否した場合、Dice!Next は一時的に遮断して従来の文章をそのまま送ります。 |

Markdown のテンプレートは、編集できる原本を 1 つだけ保持します。Dice!Next は内蔵の文面の読み込み、カスタム文面の保存、ペルソナの読み込みの際に、文章だけの版を自動で生成します。送信時には、発生元のアダプターとスコープの設定に基づいて版を選んでから、ニックネームやダイス式などの動的な変数を埋め込みます。従来の文面は過去の言い回しの上書き層を、標準の文面は現在の既定の文面を使い、高度なビジュアルの文面は同じ意味データにステータスバーと操作のヒントを加えます。そのため、ダイスマスターが食い違いやすい 3 つの版を管理する必要はありません。QQ 公式でインタラクションを有効にすると、使い方の行と `[[action:説明|.コマンド]]` が入力待ちのボタンになります。ほかのアダプターには引き続き完全な文章が届き、QQ 専用のタグが混ざることはありません。

## アダプターのペルソナの範囲

[コマンド一覧 → ペルソナの公開](/ja/manage/commands)でボットのアカウントを選ぶと、次の項目を個別に設定できます。これらの設定は、プラットフォームの接続の追加 / 編集ダイアログからは移動しました。

- **既定のペルソナ**：グローバルの設定に従うか、このボット専用のペルソナを固定します。
- **ユーザーのペルソナ選択**：すべてのペルソナを公開する、チェックしたペルソナだけを公開する、または一般ユーザーが `.rpmode` で切り替えることを禁止します。

既定のペルソナと公開リストは互いに独立しています。ダイスマスターは WebUI で、アダプターやグループに任意のペルソナをいつでも割り当てられます。公開リストが制限するのは、グループ管理者、招待者、個人チャットのユーザーがチャットのコマンドで見つけて選べる範囲だけです。これにより、複数のボットが同じキャラクターシートと返信データを共有しながら、それぞれのキャラクターの範囲を保ち、ふさわしくないペルソナを互いに見せずに済みます。

カード上のクリックできるボタンには、プラットフォームのインタラクションイベントと、その機能ごとの認可が必要です。Dice!Next がボタンを出すのは、ある機能で本当にユーザーに選んでもらう必要があり、そのプラットフォームの機能が使える場合だけです。管理や機密性の高い操作を汎用のボタンにすることはありません。

## QQ 公式ボット 2.0

アダプター管理ページで **QQ 公式ボット 2.0** を選びます。四角い QR コードの下にある「AppID と AppSecret を手動で入力」をクリックすると、認証情報の入力フォームに切り替わります。イベントの受信方式は WebSocket と Webhook から選べます。Webhook のコールバックアドレスは現在のページのドメインとデプロイ先のパスから生成され、追加後はカードの「接続方式」で確認・コピーできます。メッセージの送信には引き続き公式 API を使います。詳しくは[QQ 公式の接続方法](/ja/manage/adapter-manager#qq-公式ボット)を参照してください。

[2026-08-10 の QQ ボット 2.0 の機能更新](https://bot.q.qq.com/wiki/develop/api-v2/changelog.html#_20260810)以降、OpenAPI のリクエストはすべて `https://api.bot.qq.com` を使います。Dice!Next は認証、Gateway、プロフィール、共有リンク、メッセージ、リッチメディアなどのリクエストのドメインをこれに統一しており、旧ドメインは API の呼び出しには使いません。

「標準の文面」または「高度なビジュアルの文面」の方式では、アダプターは Markdown を送信できます。アダプターの編集ページで **Markdown の画像リソースの厳密な検証** を有効にできます。有効にすると、QQ プラットフォームが Markdown 内の画像を保存できない場合、メッセージ全体が失敗して文章だけの版に切り替わります。プラットフォーム本来の互換の動作を保つため、既定ではオフです。`config/adapters.json` での項目名は `force_verify_image_resource` です。同じアダプターが Markdown / カードの HTTP での拒否を 2 回続けて受けた場合、Dice!Next はその後 10 分間、事前に生成した文章をそのまま送ります。待機時間が終わると自動で再び試すため、手動での再接続は不要です。

QQ 公式プラットフォームは、本当の QQ 番号ではなく OpenID でユーザーとグループチャットを識別します。Dice!Next は確認済みの OneBot の QQ の身元を公式の OpenID と関連付けられるため、キャラクターシート、グループ設定、ログで同じ記録を使い続けられます。`.info` で現在のチャットの身元と紐付けの案内を確認できます。

::: warning グループの権限について
新しい公式のメッセージイベントに `member_role` がある場合、Dice!Next はそこに含まれる管理者／オーナーの役割を使います。ない場合は、ダイスマスターとこのアカウントで記録済みの招待者に関する互換のルールを引き続き使い、ニックネームで権限を判断することはありません。ミュート、参加の承認、自動承認のポリシーの API には **ボット自身がグループの管理者であること** が必要です。権限が足りない場合、QQ プラットフォームはリクエストを拒否し、パネルにエラーが表示されます。
:::

### 公式のグループ管理

**グループ管理 → QQ 公式ボットのアカウントを選択 → 公式のグループ管理** で次の操作ができます。

- 現在の全体ミュートの状態と、まだ有効なメンバーのミュートを照会し、メンバーの OpenID を指定してミュートの設定・解除を行う。
- 現在のグループで処理待ちの参加申請を取得し、認証メッセージ、質問への回答、経路、リスクの注意を確認して、手動で承認または拒否する。
- 参加の自動承認ポリシーを作成、有効化・無効化、メモの変更、実行、削除し、許可リストの QQ 番号を一括で追加・削除する。

Gateway の `GROUP_JOIN_REQUEST` イベントも統一されたイベントの処理系に接続されています。ダイスマスターに通知し、`.group auto pass` とグローバルなグループ参加申請のポリシーを使います。イベントの `join_request_id` は承認のリクエストとともにそのまま返されます。公式の自動承認ポリシーは QQ プラットフォームが実行するため、Dice!Next のローカルなキーワードによる自動承認と併用できます。

::: tip API の制限
参加申請のイベントには、ボットがグループの管理者であることと、`GROUP_AND_C2C_EVENT (1<<25)` の Intent が必要です。API の頻度制限、許可リストの資格、具体的なエラーコードは QQ 公式プラットフォームが管理しています。
:::

## Discord

アダプター管理ページで **Discord** を選び、Discord Developer Portal で作成した Bot Token を入力します。アダプターは Discord Gateway を通じてサーバーのチャンネルとダイレクトメッセージを受け取り、`@ボット コマンド`、チャンネルのメッセージ、ダイレクトメッセージに対応します。

Discord Developer Portal の Bot 設定で **Message Content Intent** を有効にしてください。有効にしないと、Discord は通常のメッセージの本文をボットに渡しません。

## KOOK

アダプター管理ページで **KOOK** を選び、ボットのトークンを入力します。アダプターは KOOK Gateway と REST API で接続し、サーバーのチャンネル、個人チャット、テキストと KMarkdown のメッセージ、`@ボット コマンド` に対応します。

## アダプターの開発

アダプターは共通のインターフェースで接続するため、ほかのプラットフォームも追加しやすくなっています。開発方法は[アダプター開発](/ja/develop/adapter-dev)を参照してください。

## よくある質問

- **接続できない**：エンドポイントのアドレスとポート、ファイアウォール、Access Token が一致しているかを確認してください。詳しいエラーはダッシュボードのログで確認できます。
- **状態が「接続タイムアウト」**：自動再接続が一時停止しています（20 回連続で失敗）。OneBot 側を直してから手動で再接続してください。
- **メッセージが届かない**：アダプターの状態が「接続済み」で、OneBot クライアントがメッセージのイベントを正常に送っているかを確認してください。

そのほかの確認方法は[トラブルシューティング](/ja/guide/troubleshooting)を参照してください。
