# 開発計画

## 実装済み · 文章のエディターと Markdown への移行（2026-11-04、未公開）

- 文章の編集のダイアログ：
  - 編集とプレビューを左右に並べ、それぞれスクロールします。狭い画面では切り替えのボタンを使います。
  - Markdown の書式のツールバーを加えました。文字を選ぶと太字、引用、リストにでき、Ctrl/⌘+B、I に対応します。
  - 変数ごとのスタイルの設定を削除しました。
  - 「プリセットを読み込む」のメニューに、元のプリセットの選択と元に戻すボタンをまとめました。
- 新しい文章は既定で Markdown です。プレーンテキストの文章は 1 件ずつワンクリックで変換でき、コマンドの一覧で言語とペルソナごとにまとめて変換することもできます。変換ではテンプレートの構文をそのまま残し、書式を起こす文字だけをエスケープするため、表示は変わりません。
- 高度な表示のプリセットと標準の文章からすべての絵文字を除き、太字の見出しと引用のブロックに変えました。QQ 公式の文書にある構文だけを使い、絵文字が再び入らないようにテストを加えました。
- 判定のレベル、対抗の結果、心理学の受領の返信、好感度の称号などの埋め込みの文章は、Markdown にした後もスタイルを保ち、編集のプレビューにもあわせて表示します。
- `.r` の展開の過程では元の式どおりに括弧とマイナスの記号を保ちます。たとえば `5-(-1)` が `5--1` と表示されることはもうありません。

## 実装済み · 乱数の源の代替、アプリとしてのインストール、コマンドの全体の検索（2026-11-04、未公開）

- ダイスの乱数の源が使えないときは別の安全な乱数の源に自動で代わり、すべて使えないときだけ緊急用の疑似乱数を使ってログに記録するため、ロールが中断されることはもうありません。CPU のハードウェアのエントロピーの源を加えました（RDSEED とシステムの乱数の XOR、x86-64 のみ）。乱数の源の設定は基本設定に移し、効果のなかった「ダイスのルール」の仮のページは削除しました。
- アプリとしてのインストール：バックエンドが `manifest.json` の提供を拒否していた（静的ファイルの許可リストに `.json` がなかった）ため、ブラウザーがインストールをまったく提案しなかった問題を修正しました。マニフェストは相対のアドレスに変え、内容をキャッシュしないページの移動の単位の Service Worker を加えました。ブラウザーがインストールを許すときは上部のバーに「アプリをインストール」のボタンを表示し、WebUI の設定で HTTPS の要件を説明します。
- コマンドの一覧に分類をまたぐ全体の検索を加えました。コマンドのテストは既定で画面の言語で返信します。バックアップのページは 4 言語すべてそろいました。
- QQ 公式：スキャンの QR コードがときどき 404 になる問題を修正し、内部の招待の API の権限なしのログを DEBUG に下げ、セッションのログに SN の状態行を記録しなくなり、SN の「色付きの文字」はカラーパレットや画面のスポイトで色を選べるようにしました。
- 判定と能力値の変更で計算のモジュールを共有しました。多段の補正で最初の項だけが計算される問題を修正し、乗除、べき乗、括弧、ダイス、複数の能力値、よく使う関数に対応しました。`.st` の加減の値は全体を計算します。
- ホームのグラフはバックエンドが取得した 1 時間の履歴を使うようにし、状態のカードをクリックして移動できるようにしました。
- ダッシュボードからデータベースのパスを削除し、macOS のシステムのアイコンを補い、「について」のページのプロジェクトの紹介を書き直しました。

## 完了 · WebUI V1 / V2 の 2 つの版の移行期間

- 現在の画面を V1（既定）と名付けました。V2 は WebUI の独立した `webui-v2` のブランチで開発し、「プレビュー版」と表示します。最初の版では Tailwind 4 と共通のコンポーネントのテーマの移行を終え、サイドバー、上部のバー、カード、フォーム、一覧のライト、ダーク、狭い画面での表示をそろえました。
- V2 には本物の hash のルーティングとページごとの読み込み、リモートのデータのメモリのキャッシュ、構造化されたフォームの検証、カレンダーと通知のコンポーネントを組み込みました。統計の推移のグラフはすべての日付、絞り込み、ダイスの目の分布、オンラインの履歴、ユーザー／グループのランキングを保ちます。書き込みの操作は自動で再試行せず、ページを離れるのを取り消すと下書きを保ちます。
- コンポーネントの単体テスト、ページとテーマのブラウザーでの回帰、Biome の品質の確認を加えました。2 つの UI の既存の業務の回帰も引き続き残します。共有のブラックリストの古い形式の解析と、版のサブフォルダーのアイコンのパスの修正は V1/V2 の両方にそろえました。
- 内容の幅の設定の代わりに版の選択を使い、`config/webui.json` に保存します。データとログインを共有し、ボットを再起動せずに切り替えられ、リソースがない場合は元に戻して案内します。
- Release では 2 つのリソースを同時にビルドし、5 つのプラットフォームの完全なパッケージにはどれも V1/V2 を含めます。ソースの記録には 2 つのブランチで実際にビルドした SHA を両方挙げます。
- V2 が正式に置き換わって V1 を削除するまでは、機能の追加や削除をすべて 2 つの UI にそろえ、翻訳、ヘルプ、検索、テストも一緒に保守する必要があります。この要件はリポジトリの `AGENTS.md` に書いてあります。[WebUI の設定](/ja/manage/settings#webui-設定ページ)を参照してください。

## リリース候補 · MCP サーバーの最初の版

- 既定ではオフで、ループバックでの直接の接続を優先します。本物の数学的なダイス、ヘルプの検索、機密でない動作の状態、具体的なカードごとに認可する読み取り専用の照会を提供します。
- 独立した Bearer の資格情報で、平文は作成／ローテーションのときにだけ表示します。権限の調整、明示的な延長、すぐの取り消しに対応します。権限を編集しても有効期間は延びず、BDC のキーやブラウザーのログインの状態は使い回しません。
- パネルでは接続の案内、認可の管理、クライアント／結果で絞り込めるサーバー側のページ分けの記録を提供します。Host／Origin の検証、ロック付きの読み取り、リクエストの流量の制限、作業量と整数のオーバーフローの保護を保ち、カードが無効になっても認可の無効化は妨げません。
- 管理の書き込みにクロスサイトの防御と不可分の保存を補いました。監査の障害で作成済みの資格情報が失われることはありません。タイムアウトしたときは操作の状態を確認でき、自動では再試行しません。ツールと管理のキューは分け、取り消すと処理中の照会の結果を捨てます。
- 異常からの回復では、現在の設定の読み戻しに成功してから操作のロックを外します。資格情報ごとの同時実行の上限、実行の期限、終了時の協調した取り消しを補いました。設定／メインのデータベースを復元すると古いキーは無効になり、認可の範囲は確認のために残し、作り直した後にだけ有効にできます。リソースだけの復元は影響を受けません。
- 公式の MCP SDK／Inspector との旧版と新版のプロトコルの結合テストを加え、一時的な証明書で検証した HTTPS の接頭辞のリバースプロキシの後ろで動かし、Windows／Linux の CI のテストに含めました。TLS の検証はオフにしていません。
- ツールを実行しないローカルの接続の自己確認を加えました。認可のページに、選んだカードの名前、所有するユーザー、無効の状態を補い、サーバーの時計で期限を判断し、保存している監査の中の直近の成功した呼び出しを表示します。
- 独立した Chromium のページでの操作の回帰を加えました。macOS のパッケージの作業に、HTTP と公式のクライアントの HTTPS の相互運用の確認を補いました。実際の macOS の結果はワークフローの実行で確認する予定です。
- メッセージの送信、設定の変更、任意のコマンド／プラグイン、カードの式の実行は開放せず、ユーザーの実行時の依存も増やしません。詳しくは [MCP サービス](/ja/manage/mcp)を参照してください。

## リリース候補 · 内蔵ログイン（OpenOPQ、実験的）

- プラットフォームの接続に内蔵ログインを加えました。パネルで QQ 番号と有効な BDC のボットの API Key を入力すると、プロトコルのクライアントをダウンロードして管理し、QR コードとダウンロードの進み具合を表示します。V1 / V2 の両方で対応します。
- プロトコルのクライアントはインストーラーに含めず、実行の前に一覧の署名、ファイルのサイズ、SHA-256 を検証し、異常な一覧は実行しません。管理の API はローカルのループバックを使い、通常の OneBot の設定と再接続の方針は変わりません。
- この機能には、センターが対応するシステムのプロトコルのクライアントと署名のサービスを提供する必要があり、まだ実験的な機能です。具体的な操作と境界は[内蔵ログイン](/ja/manage/adapter-manager#内蔵ログイン-openopq、実験的)を参照してください。

## 2026-10-05 · 予定時刻での更新のインストール

- Windows のマネージャーモードでは、先にダウンロードして検証し、サーバーのタイムゾーンで予定時刻にインストールできます。既定は午前 04:00 です。具体的な操作と再起動の回復のルールは[更新の設定](/ja/manage/settings#更新の確認と自動更新)を参照してください。

- `.game` は複数のグループで同じセッションに参加することに対応しました。開始時に順に推測できない 16 桁のセッション番号を作り、GM がほかのグループで `.game open <セッション番号>` を使うとセッションの状態を共有します。閉じると現在のグループだけに影響し、終了するとすべての参加したグループを外し、進行中のログを片付けます。
- データの管理に「ログの管理」を加えました。グループ、ログ、セッション名、セッション番号で検索、書き出し、削除ができ、セッション番号、参加したグループ、ログの状態を表示します。セッションをまたぐ書き出しは、各セッションのグループの発言を時刻でまとめ、`〔场景：群名〕`（場面：グループ名）で場面を示し、終了した後も過去の記録を書き出せます。
- ログの管理はログ/セッションの 2 つのタブに分けました。ログは並べ替えのできる表を使い、セッションのカードには GM、プレイヤー、作成時刻、状態ごとのログの統計を表示します。
