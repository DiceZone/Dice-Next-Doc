# よくある質問 FAQ

初めての利用、日常の保守、設定の復旧に関する質問をまとめています。起動失敗、アダプターの切断、コマンドへの無応答は[トラブルシューティング](/ja/guide/troubleshooting)も参照してください。

## 管理パネルのパスワードを忘れた {#reset-password}

サーバーの設定ファイルへのアクセスが必要です。ホスティングサービスでファイルを操作できない場合は、管理者に連絡してください。QQ の骰主アカウント、アダプターの Token、WebUI パスワードは別の認証情報です。

1. **先にパネルへの外部アクセスを制限します。** リバースプロキシの公開を一時停止する、接続元を自分の IP に限定するなどしてください。リセット後は初回パスワード設定が可能になるため、第三者による先行設定を防ぎます。
2. Dice!Next と、自動で再起動するサービス・監視プロセスを停止します。
3. 実際に使っている設定ディレクトリをバックアップします。通常は `config/` です。独自のパスやコンテナーは[設定の場所](#config-location)を確認してください。
4. `config/webui.json` をテキストエディターで開き、最上位の `password` の値だけを空文字列 `"password": ""` にします。他の項目は残してください。この断片でファイル全体を置き換えないでください。
5. 同じディレクトリの `webui_sessions.json` があれば削除し、保存済みの信頼済みデバイスのセッションを失効させます。古いセッションファイルは戻さないでください。
6. 起動し、アクセスを制限した入口から初回設定画面を開いて新しいパスワードを設定します。**8～64 文字**で、大文字・小文字の英字、数字、半角記号が必要です。空白、日本語・中国語、全角文字は使えません。
7. 新しいパスワードでログインできることを確認してから、通常のアクセスを再開します。

**空のパスワードは再設定を要求する状態であり、認証なしで使えるモードではありません。** 保存値がハッシュでも、復元や手動生成は不要です。設定画面で保存してください。データベース、キャラクターシート、プラグインの削除は必要ありません。

## デバイスを信頼したのに、またログインが必要になる {#login-session}

パスワードログインの信頼済みセッションは最大 30 日間です。ブラウザーの Cookie とサーバーの `config/webui_sessions.json` の両方が必要です。

- ブラウザー、プライベートウィンドウ、アクセス先を変えていませんか。`localhost`、`127.0.0.1`、独自ドメインは別のアドレスです。
- Cookie の削除や、終了時にサイトデータを消す設定がありませんか。
- 設定ディレクトリに書き込み権限があり、セッションファイルが残っていますか。再起動後も同じ設定ディレクトリを使っていますか。
- パスワード変更やログアウトを行っていませんか。対応するセッションは失効します。

外部アカウントのログインには別のセッション規則があります。すべてのログイン方法が 30 日間有効になるわけではありません。

## 設定ファイルはどこにある？ {#config-location}

配布パッケージのマネージャーで通常起動する場合、既定はインストール先の `config/` です。起動ログに読み込んだ設定ディレクトリが出ます。サービスの引数で別の場所を指定した場合はそのパスを使い、相対パスはプロセスの作業ディレクトリから判断してください。

コンテナー内の `config/` は、Docker / Compose で設定したホストのマウント先やボリュームに対応します。一時コンテナー内の別ファイルだけを変更しないでください。複数のボットでは、設定・データのディレクトリと待ち受けポートを分けます。

| 設定内容 | 既定のファイル |
| --- | --- |
| 待ち受けアドレス、ポート、DB パス、ログレベル | `config/server.json` |
| パネルのパスワードと画面設定 | `config/webui.json` |
| プラットフォーム接続とアダプター | `config/adapters.json` |
| 骰主、コマンド、返信動作、AI | `config/dice.json` |
| 友だち申請とグループ招待 | `config/events.json` |
| 既定の返信言語 | `config/i18n.json` |

項目の説明は[基本設定](/ja/config/basic)を参照してください。キャラクターシートやセッションログは、これらの JSON だけには保存されません。バックアップにはデータファイルも必要です。

## 設定を手動で変更するには？ {#edit-config}

通常は管理パネルを使います。開けない場合や設定を復旧するときは、次の手順で編集してください。

1. プログラムと自動再起動サービスを停止し、元ファイルを設定ディレクトリの外にバックアップします。
2. テキストエディターで **UTF-8** として保存します。構造を保ち、必要な項目だけを変更してください。
3. JSON を確認します。キーと文字列は半角の二重引用符で囲み、コメントや末尾カンマは使えません。真偽値は `true` / `false`、ポートなどの数値は引用符なしで書きます。
4. 起動して設定読み込みログと実際の動作を確認します。失敗したら停止し、バックアップを戻して再起動してください。

たとえば `config/server.json` のポートを数値 `18089` に変更する場合、ファイル内では直接 `"port": 18089` と書きます。外側に `"server": { ... }` を追加しません。`adapters.json` の最上位は配列です。他のオブジェクト形式のファイルとは異なります。

一項目の初期化のために設定ディレクトリ全体を削除したり、ネット上の例で既存ファイル全体を上書きしたりしないでください。バックアップの `.json` が別の設定区分として読み込まれないよう、手動バックアップはディレクトリ外に置きます。

## 変更が反映されない・再起動で戻ってしまう {#config-not-applied}

- 使用中のインスタンスのファイルか、保存に成功したか、実行ユーザーに書き込み権限があるか確認します。
- 実行中のパネル保存やコマンドなどで、手動変更が上書きされる場合があります。停止してから編集してください。
- ホットリロード対応でも、全項目が即時反映されるわけではありません。**待ち受けアドレスとポートは再起動が必要**です。他の不明な設定も再起動を予定して確認します。
- アダプター別、アカウント別、グループ別設定が全体の既定値を上書きする場合があります。適用範囲を確認してください。
- JSON の解析・検証に失敗した場合は、起動ログのファイル名とエラーを確認します。読み込み済みとは限りません。

## サーバー自身では開くのに、別の端末では開かない {#panel-access}

別端末の `127.0.0.1` / `localhost` は、その端末自身を指します。ボットサーバーのアドレスとポートを使い、待ち受けアドレス、ファイアウォール、クラウドのセキュリティグループを確認してください。

既定は `18088` ですが、使用中なら後続のポートに変わる場合があります。起動ログや `config/server.json` で確認し、リバースプロキシの転送先ポートも合わせてください。HTTPS とプロキシは[デプロイと運用](/ja/guide/deploy)を参照してください。

## バックアップやサーバー移転で何を保存する？ {#backup}

まずパネルでバックアップを作り、プラグイン、デッキ、画像、メディアなど必要な項目が選択されているか確認して、別端末にもダウンロードします。

手動の場合は **サービス停止後** に実際の設定ディレクトリと `data/` 全体をコピーし、それ以外の場所に置いた独自のプラグイン、リソース、DB も保存します。独自の主 DB パスは `server.json` の `db_path` を確認してください。稼働中に `.db` 一つだけをコピーすると未反映のデータが漏れる場合があります。

移転先の OS・アーキテクチャに合う完全な配布パッケージを入れ、設定とデータを復元します。Windows の実行ファイルをそのまま Linux に移すことはできません。絶対パス、権限、ポート、アダプターの接続先を確認し、二重ログインや処理の重複を避けるため旧サーバーを先に停止してください。旧 Dice のデータは[移行ツール](/ja/guide/migration)を使い、Next の DB を直接上書きしないでください。

## 更新後に空白、404、表示崩れになる {#webui-update}

まずインスタンスとポートが正しいか確認し、ページを再読み込みします。改善しなければ、実行ファイルだけを更新して WebUI を更新し忘れていないか確認してください。同じバージョンの完全なパッケージを使い、`web/dist/`、ランタイムライブラリー、付属リソースも更新します。異なる版のフロントエンドとバックエンドを混ぜたり、調査のために `config/` や `data/` を削除したりしないでください。

修復前に停止・バックアップし、[完全な更新手順](/ja/guide/install#アップグレード)でプログラムを更新します。プロキシ経由なら、静的ファイルの誤ったキャッシュや旧インスタンスへの転送も確認してください。

## 自動で更新をインストールできない {#auto-update}

インストールには配布パッケージのマネージャーによる起動が必要です。Windows は `dice-next.exe`、Linux/macOS は同梱の `start.sh` または `dice-next` を使います。`dice-next-server` の直接起動では確認・ダウンロードのみです。コンテナーは確認・通知のみなので、イメージを更新してコンテナーを再作成してください。

ダウンロード失敗時は表示されたエラー、配布元への接続、空き容量、書き込み権限を確認し、内蔵ミラーや GitHub を試します。不完全なパッケージを検証なしで入れないでください。予約インストールはサーバー設定のタイムゾーンを使います。自動インストールが有効でダウンロード済みなら、予定より早い再起動時にもインストールします。[更新設定](/ja/manage/settings#更新の確認と自動更新)を参照してください。

## 接続済みなのにコマンドに返信しない {#no-reply}

簡単な `.r 1d6` を送り、ホームの実行ログを確認します。

- **受信記録がない**：アダプターのログイン、イベント購読、プラットフォームからの配信を確認します。QQ 公式では `/r 1d6` を試し、設定済みのコマンド接頭辞も確認してください。
- **受信したが返信を生成しない**：`.bot off`、全体のサイレント、無効なコマンド、許可・拒否リスト、プラグインの規則を確認します。
- **返信を生成したが送信失敗**：プラットフォームの具体的なエラー、グループ所属、送信権限、内容の拒否を確認します。

[テスト画面](/ja/manage/playground)ではコマンド自体を確認できますが、成功しても実際のプラットフォームで送信できるとは限りません。書式、ボタン、画像の対応もアダプターごとに異なります。

## 不具合報告には何を書けばよい？ {#report}

バージョン、OS、アダプター種別、発生時刻、再現手順、期待した結果と実際の結果、同時刻の関連ログを添えてください。クラッシュ時はクラッシュレポートも必要です。保存場所は[トラブルシューティング](/ja/guide/troubleshooting)を参照してください。

共有前にパスワード、Token、API Key、AppSecret、セッションファイルの内容、無関係な私的会話を隠してください。**設定ディレクトリや DB 全体を公開しないでください。**「反応しない」だけよりも、再現できる一つのコマンドと対応するログが役立ちます。
