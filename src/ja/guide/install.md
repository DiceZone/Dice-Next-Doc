# インストール

現在は公開ベータ版です。Release では Windows（amd64 / arm64）、Linux（amd64 / arm64）、macOS（arm64）向けのパッケージを提供しています。コンテナでのデプロイについては Docker プロジェクトの説明を参照してください。

## ダウンロードと起動（Windows）

1. [GitHub Releases](https://github.com/DiceZone/Dice-Next/releases) から、お使いのプラットフォームとアーキテクチャに合った最新のベータ版パッケージを入手します。
2. 固定のフォルダーに **すべて展開** します（特殊文字を含まないパスを推奨）。システムの一時フォルダーには置かず、圧縮ファイルの中から直接ダブルクリックして起動しないでください。
3. Windows では **`dice-next.exe`** をダブルクリックして起動します。Linux/macOS ではパッケージ内の **`./start.sh`** の実行を推奨します。`dice-next` マネージャーがコアを起動します。初回起動時に `config/` とデータフォルダーが自動で作成されます。
4. 既定では **ウィンドウを表示せず、そのままタスクトレイに格納** されます（右下に通知が表示されます）。トレイアイコンを右クリックすると、Web パネルを開く／コンソールを表示／プログラムフォルダーを開く／終了 を選べます。
5. 管理パネルを開くには、トレイアイコンを右クリックして「Web パネルを開く」を選ぶか、ブラウザで **`http://localhost:18088`** にアクセスします。

よく使われるランタイム（VC++ ランタイム）は圧縮ファイルに同梱されているため、通常は追加のインストールは不要です。対応するのは 64 ビット版の Windows 10 / 11 のみです。

::: warning 一時フォルダーからの起動制限
build 926 以降、Windows のランチャーとコアはプログラムフォルダーと実際の作業フォルダーを確認します。システムの一時フォルダー（またはその下位フォルダー）にある場合は起動を拒否し、中国語と英語のメッセージを表示します。設定やデータが、いつ削除されてもおかしくない場所に残らないようにするためです。固定のフォルダーにすべて展開してから `dice-next.exe` を起動してください。
:::

::: tip ポート
既定のポートは `18088` です（`config/server.json` の `port` で変更できます）。起動時にポートが使用中の場合は、**次の空いているポートへ自動で移り、その値を設定に書き戻します**。トレイの「Web パネルを開く」を使えば、常に正しいアドレスが開きます。
:::

::: warning 多重起動の防止
同じデータ（同じプログラムフォルダー）で実行できるプロセスは 1 つだけです。重ねて起動した場合はデータの競合を避けるため自動で終了します。詳しくは[トラブルシューティング](/ja/guide/troubleshooting)を参照してください。
:::

## インストールの確認

起動後、次のアドレスにアクセスします。

- **管理パネル**：`http://localhost:18088`
- **状態確認**：`http://localhost:18088/api/system/status`

管理パネルが開けば、サービスは正常に動作しています。まず管理パネルの **WebUI 設定** でログインパスワードを設定し、[クイックスタート](/ja/guide/quickstart)に進んで QQ ボットを接続してください。

## 自動起動

管理パネル → システム設定 で **Windows 起動時の自動起動** を有効にできます（Windows へのサインイン時に起動。Windows のみ）。タスクスケジューラーを手動で設定する必要はありません。

## アップグレード

### 管理パネルからの自動更新

**管理パネル → プロジェクトについて → 更新の確認と自動更新** を開きます。

1. 「今すぐ確認」をクリックすると、GitHub Release の `update-manifest.json` から最新バージョンと現在のプラットフォーム向けパッケージを取得します。
2. 既定の「自動選択」では、GitHub への直接接続と内蔵ミラーを並行して試します。中国本土のネットワークが不安定なときは、先に成功したミラーを自動で使います。ミラーのみに固定したり、信頼できるカスタム HTTPS ミラーを指定したりすることもできます。
3. 「更新をダウンロード」をクリックすると、マニフェストのリポジトリ、プラットフォーム、アーキテクチャ、ファイル名、ファイルサイズ、SHA-256 を照合します。Windows では展開前にパストラバーサルとパッケージ構成も確認します。
4. 完全版パッケージのマネージャーから起動している場合は「インストールして再起動」をクリックできます。Windows では `dice-next.exe`、POSIX マネージャーを含む新しい Linux/macOS パッケージでは `start.sh` または `dice-next` を使います。マネージャーはコアが完全に終了するのを待ってから、プログラム、ランタイム、WebUI、ドキュメント、内蔵リソースを置き換えます。置き換えに失敗した場合は、プログラムファイルを逆順に元に戻します。

右上のバージョン表示をクリックすると更新欄が直接開き、新しいバージョンがあるときは赤い「New」が表示されます。ダウンロード中はキャンセルできます。「キャンセルしました」と表示されてから再試行してください。60 秒間データが増えない場合や、1 つの取得元で 20 分を超えた場合は転送を中止し、設定に従って別の取得元に切り替えます。失敗・キャンセル時に削除されるのは今回の未完了ファイルだけで、プログラムの再起動は不要です。検証とインストール準備の段階でもキャンセルできますが、実際のインストールが始まった後はキャンセルできません。

Web リクエストがタイムアウトしても、バックグラウンドの処理が止まったわけではありません。パネルが状態を取得し直すのを待つか、状態を更新してから操作してください。

::: warning Linux/macOS の初回アップグレード
beta.928 以前のパッケージには POSIX マネージャーがありません。一度サービスを停止し、`dice-next` を含む新しいパッケージで丸ごと上書きしてください。その後 `start.sh` または `dice-next` で起動すると、パネルからのワンクリックインストールと予約インストールが使えるようになります。WebUI だけを入れ替えたり、`dice-next-server` を直接実行したりしても、完全な自動更新は有効になりません。この機能は今後のリリースパッケージで提供されます。
:::

Linux/macOS のマネージャーはフォアグラウンドで動作するため、systemd / launchd による監視に向いています。サービスの起動先は `start.sh` または `dice-next` にしてください。マネージャーは作業フォルダーをインストールフォルダーに揃えるので、カスタムの設定フォルダーは絶対パスで指定してください。指定した引数は再起動後も維持されます。インストールフォルダーは実行アカウントから書き込める必要があります。アップデーターは sudo を要求せず、macOS の隔離属性も外さず、Gatekeeper も回避しません。

POSIX の更新では、展開後のサイズとファイル数を制限し、パストラバーサル、ハードリンク、特殊ファイルを拒否します。シンボリックリンクは `lib/` 内の安全なものだけを許可します。置き換えの前に、新しいコアとマネージャーが実行でき、動的ライブラリを読み込めるかを確認します。置き換えが中断した場合はトランザクション記録から復旧できます。元に戻すのはプログラムファイルだけで、データベースを自動でダウングレードすることはありません。新しいプログラムが正常に読み込まれた後に起きた問題は、バックアップを残したうえで手動で調査する必要があります。

自動確認は既定で有効で、6 時間ごとに実行し、更新が見つかったときは通知のみ行います。自動ダウンロードに変更することもできます。「自動でインストールして再起動」には Windows または新しい Linux/macOS のマネージャーモードが必要です。コアを直接実行している場合は確認とダウンロードのみ可能で、インストールはできません。コンテナでのデプロイでは確認と通知のみで、プログラムの更新をダウンロード・インストールすることはありません。新しいイメージを取得してコンテナを作り直してください。

マネージャーモードでは **予約インストール** も使えます。更新パッケージを先にダウンロード・検証しておき、指定した時刻にプログラムが自ら再起動してインストールします。初期値は **04:00** です。時刻はサーバーの設定に基づいて計算され、パネルには具体的な日付と UTC オフセットが表示されます。ダウンロード完了時点でその日の時刻を過ぎていれば、翌日に予約されます。自動インストールが有効でパッケージが準備済みのときは、予約時刻より前に再起動した場合にもインストールされます（手動での再起動、終了後の再起動、OS の再起動、デーモンによる再起動を含む）。予約が制御するのは、プログラム自身が行う再起動だけです。時刻やタイムゾーンを変更すると予約し直され、予約をオフにすると自発的な再起動の予定だけが取り消されます。ダウンロードしたパッケージを残したまま起動時にインストールしたくない場合は、「ダウンロードのみ」または「通知のみ」に変更してください。手動でのインストールは引き続き可能です。

::: tip コンテナのアップグレード
公式イメージには明示的なコンテナ用の目印があり、プログラムは Docker / Podman の目印、Kubernetes の環境変数、cgroup の情報でもコンテナを判定します。コンテナと判定した場合、WebUI では手動・自動のダウンロードとインストールが無効になりますが、バージョン確認は引き続き使えます。Compose でデプロイしている場合は `docker compose pull dice-next` を実行してから `docker compose up -d --force-recreate dice-next` を実行します。マウントした `config/` と `data/` はそのまま残ります。
:::

::: warning ミラーの信頼範囲
SHA-256 でダウンロードの中断や破損、マニフェストとパッケージの不一致は検出できますが、独立したリリース署名ではありません。内蔵ミラーやカスタムミラーを選ぶことは、その取得元を信頼することを意味します。サプライチェーンの安全性を重視する場合は「GitHub のみ」を使い、Release ページでバージョンを確認してください。
:::

### 手動でのアップグレード

[GitHub Releases](https://github.com/DiceZone/Dice-Next/releases) から対応するプラットフォームの新しいパッケージをダウンロードし、サービスを停止してから **プログラムファイルをすべて上書き** することもできます。exe、ランタイム、`i18n/`、`web/dist/`、`docs/`、パッケージ内の内蔵リソースをすべて更新する必要があります。

インストールパッケージで個人のデータが消えることはありません。

- 設定フォルダー `config/` はリリースパッケージに含まれていません。
- `data/` 内のデータベース、セッションログ、メディア、ユーザーが作成したリソースは保持されます。
- 内蔵の `data/helpdoc` はバージョンごとに更新され、`data/plugins` は内蔵ファイルを上書きし、それ以外のファイルを残す形で更新されます。

それでも、アップグレード前には管理パネルでバックアップを作成するか、`config/` と `data/` を手動でバックアップすることをおすすめします。

## 管理パネルをアプリとしてインストール

ブラウザがインストールに対応している場合、上部バーの右側に「アプリをインストール」ボタンが表示されます（狭い画面では「その他」メニュー内）。**WebUI 設定 → アプリとしてインストール** からも同じ操作ができます。ブラウザが対応していない、現在のアドレスが条件を満たさない、またはすでにインストール済みの場合はボタンが表示されず、設定カードに理由と代わりの方法が表示されます。ブラウザ自身の機能も使えます。Chrome / Edge ではアドレスバーのアイコンまたはメニューの「Dice!Next をインストール」、macOS の Safari では「Dock に追加」、iOS / iPadOS の Safari では「共有 → ホーム画面に追加」です。Firefox などのブラウザは Web アプリのインストールに対応していない場合があります。

**HTTPS を使うか、Dice!Next を実行しているコンピューターで `http://localhost:ポート` / `http://127.0.0.1:ポート` を開く必要があります。** `http://LAN の IP:ポート` でアクセスした場合、ブラウザのセキュリティ制限によりインストールできません。これは Dice!Next の不具合ではありません。ブラウザのセキュリティ制限を解除するのではなく、HTTPS のリバースプロキシを設定してください。マニフェストは相対アドレスを使っているため、リバースプロキシのサブパス（例：`https://example.com/dice/`）で公開している場合もインストールできます。

インストールされるのは現在のアドレスの管理パネルを開く独立したウィンドウだけで、**ボットのバックエンドがインストールされたり、バックグラウンドで起動したりすることはありません**。バックエンドは引き続き起動しておく必要があり、ログインの確認も変わりません。ブラウザのインストール条件を満たすため、パネルはページ遷移だけを扱う Service Worker を登録します。この Service Worker は **何もキャッシュせず**、すべてのリクエストを直接バックエンドに送ります。設定、ログ、管理 API がオフラインで読み込まれることはなく、バックエンドに接続できないときは接続に関するメッセージだけが表示されます。サーバーのアドレスが変わった場合は、新しいアドレスからインストールし直してください。
