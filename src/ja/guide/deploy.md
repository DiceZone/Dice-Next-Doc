# デプロイと運用

このページは、Dice!Next を長期間動かす場合（個人や小さなグループでのセルフホスト）を想定しています。基本的な起動方法は[インストール](/ja/guide/install)を参照してください。

## フォルダー構成

初回起動後、プログラムフォルダーはおおよそ次のようになります。

```
DiceNext/
├── dice-next.exe       # Windows の起動マネージャー
├── app/                # サービスのコア（Windows では dice-next-core.exe）
├── lib/                # Windows の実行時依存ファイル
├── config/             # 設定（機能ごとに分かれた JSON。初回起動時に自動生成）
├── data/              # データはすべてここに保存されます
│   ├── dice.db        #   メインのデータベース（ほかに cards.db / logs.db / chat.db など）
│   ├── decks/         #   デッキ
│   ├── rules/         #   ルール早見のライブラリ
│   ├── rulepacks/     #   ルールパック
│   ├── helpdoc/       #   カスタムヘルプ文書
│   ├── mod/  plugins/ #   Lua mod / JS プラグイン
│   ├── logs/          #   セッションログ、クラッシュレポート。動作ログは logs/app/
│   └── audit/         #   通知の監査記録
├── i18n/              # 多言語の文面（カスタム言語パックもここに置けます）
├── web/dist/          # 管理パネルのフロントエンド
└── docs/              # ロードマップ / コマンド表（パネルのページで使うデータ）
```

通常、設定とユーザーデータは `config/` と `data/` にあります。独自のパスを使う場合は外部の DB、プラグイン、リソースも保存してください。[バックアップと移転](/ja/guide/faq#backup)を参照してください。

## OneBot クライアントの接続

Dice!Next 自体は QQ にログインしません。OneBot v11 クライアント（NapCat、Lagrange、LLOneBot など）と組み合わせて使います。

1. OneBot クライアントで正方向 WS サーバーを有効にし、アドレス（例：`ws://127.0.0.1:3001/`）を控えます。
2. Dice!Next の[アダプター管理](/ja/manage/adapter-manager)で接続を新規作成し、通信方式に「正方向 WS」を選び、エンドポイントに上のアドレスを入力します。トークンは両側で同じ値にします。
3. 保存して有効にし、状態が「接続済み」になれば完了です。

接続が切れると自動で再接続します（5 秒ごとから 60 秒ごとへ間隔を延ばし、20 回連続で失敗すると一時停止して「接続タイムアウト」と表示します。手動で再接続できます）。

## バックグラウンドでの常駐

Dice!Next は単一の実行ファイルで、起動するとタスクトレイに常駐します。

- **自動起動**：管理パネル → システム設定 で「Windows 起動時に自動起動」を有効にします（Windows へのサインイン時に起動）。
- クラッシュ時の自動再起動など、より強い監視が必要な場合は任意のプロセス監視ツールを使ってください（例：nssm で Windows サービスとして登録）。

::: tip 作業フォルダー
Dice!Next は起動時に exe のあるフォルダーへ自動で移動します（リリースパッケージの場合）。そのため、自動起動・ダブルクリック・別の場所からの実行のいずれでも `config/` と `i18n/` を見つけられます。サードパーティの監視ツールを使う場合も、「作業フォルダー」はプログラムフォルダーに設定することをおすすめします。
:::

## セキュリティの推奨事項

- **WebUI のログインパスワードを設定する**：管理パネルの WebUI 設定ページで設定します。設定後は、すべての管理ページと `/api/*` にログイン（Cookie セッション）が必要になります。「このデバイスを 30 日間信頼する」にチェックすると、ブラウザや Dice!Next を再起動してもログイン状態が保たれます。信頼済みセッションは `config/webui_sessions.json` に保存されるため、このファイルは共有しないでください。
- **同じマシンの複数インスタンスは互いに干渉しない**：同じホストで複数の Dice!Next を動かす場合、インストールフォルダーごとに別のセッション Cookie を使うため、ポート番号だけで区別していてもログイン状態を奪い合いません。同じインスタンスでポートを変えても 30 日間の信頼状態には影響しません。旧バージョンからアップグレードした直後は、以前ほかのインスタンスにログイン状態を上書きされていたパネルで、一度だけ再ログインが必要になる場合があります。
- **管理パネルをそのままインターネットに公開しない**：リモートからアクセスする必要がある場合は、リバースプロキシ（nginx など）の後ろに置き、HTTPS と追加の認証や IP 制限を設定してください。
- **OneBot のトークンを大切に保管する**：トークンは QQ ボットの操作権限そのものです。
- **`{api:URL}` は既定でオフ**：必要なときだけ有効にし（`dice.api_enabled`）、ドメインの許可リスト（`dice.api_whitelist`）を設定してください。

::: warning AGPLv3 のネットワークサービス条項
Dice!Next は AGPLv3 ライセンスです。ソースコードを **改変** して **他者にサービスとして提供** する場合（ソフトウェア本体を配布せず、ネットワークサービスとして提供するだけの場合も含む）、利用者に対応するソースコードを提供する必要があります。詳しくは[ライセンス](/ja/other/license)を参照してください。
:::

## リバースプロキシ（任意）

ドメインと HTTPS で管理パネルにアクセスしたい場合は、nginx でローカルの `18088` にリクエストを転送できます（例）。

```nginx
location / {
    proxy_pass http://127.0.0.1:18088;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;   # パネルは WebSocket を使います
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
}
```

## バックアップとアップグレード

- **バックアップ**：パネルで作成し、選択項目を確認します。手動コピーは停止後に行い、実際の設定ディレクトリ、`data/`、その他の独自データも保存してください。
- **通常インストールのアップグレード**：サービスを停止 → 新しいパッケージを展開して丸ごと上書き → 再起動します。設定ファイルとデータベースは圧縮ファイルに含まれていないため上書きされません。詳しくは[インストール](/ja/guide/install#アップグレード)を参照してください。
- **コンテナでのデプロイのアップグレード**：コンテナ内では新しいバージョンの確認と通知だけを行い、サーバーは手動・自動のダウンロードとインストールを拒否します。新しいイメージを取得してからコンテナを作り直してください。実行中のコンテナのレイヤーにファイルを展開して上書きしないでください。マウントした `config/` と `data/` は保持されます。
- アップグレードの前に `data/` をバックアップしておくことをおすすめします。

## トラブルシューティング

| 症状 | 確認すること |
|------|----------|
| パネルが開かない | ポートが使用中で次のポートに移った / プロセスが起動していない / ファイアウォール。`data/logs/app/` を確認 |
| プログラムが異常終了する | `data/logs/crash_*.txt`（クラッシュレポート）を確認 |
| アダプターが接続できない | エンドポイントのアドレス / ポート / トークン。OneBot クライアントがオンラインか。「接続タイムアウト」は手動での再接続が必要 |
| コマンドに返信しない | グループが `.bot off` で停止されていないか / 全体のサイレント。[グループ管理とシステム](/ja/use/admin)を参照 |
| QQ に接続せずにデバッグしたい | [テスト台](/ja/manage/dashboard)を使う |

より詳しい手順は[トラブルシューティング](/ja/guide/troubleshooting)を参照してください。
