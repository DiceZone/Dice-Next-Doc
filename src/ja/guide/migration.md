# データ移行

旧版 Dice!（V2）から、変換可能なデータを Dice!Next に移行します。移行ツールは旧フォルダーをそのまま残し、ログイン情報や WebUI のパスワードはコピーしません。

::: warning 現在の対象範囲
これは「旧データフォルダーをそのまま新バージョンに持ち込む」機能ではありません。旧版と Dice!Next では保存構造、セッション管理のモデル、プラグインの実行環境が異なります。取り込み後も旧フォルダーは残しておき、テスト用グループでキャラクターシート、セッション、ログ、プラグインを確認してください。
:::

## 移行できる範囲

取り込みツールは旧版 Dice! のデータフォルダーにある元のファイル（バイナリの `.dat` / `.RDconf` 形式を含む）を直接解析し、変換して Dice!Next に書き込みます。

| 旧データ | ファイル | 移行先 |
|---------|------|--------|
| キャラクターシート | `user/PlayerCards.RDconf` と有効なバックアップ | 統合キャラクターシート：能力値、元の名前、シートの種類、式、ロック、シートの選択状態。旧能力値名にも対応し、グローバルなスコープは自動で変換 |
| ユーザーデータ | `user/UserConf.dat` | プレイヤーのプロフィール（ニックネーム / 信頼レベル / 好感度）と Lua 互換のユーザー設定。グループ内のニックネームは別に保持 |
| グループ設定 | `user/ChatConf.dat` / `ChatConf.RDconf` と有効なバックアップ | 選択したアカウントのグループ停止、無視、返信・コマンドのオン・オフ、COC のハウスルール、歓迎メッセージ。プラグイン変数は型を保持 |
| ブラックリスト | `conf/BlackList.json` | 有効なローカルのユーザー禁止。取り消し済みや無効な記録は復活させず、不明なクラウドの出所やグループ・関係者のポリシーは確認レポートに記載 |
| カスタム返信 | `conf/CustomMsgReply.json` | キーワード返信（複数の結果からランダム / 文章）。同等に変換できない制限は既定で無効にし、実行時の検証を通らない内容は原文のみ保持 |
| カスタム文面 | `conf/CustomMsg.json` | 返信文の上書き（簡体字中国語の層に書き込み）。`strBotMsg` / `strBotHeader` は [.bot の追加情報](/ja/manage/settings#botmsg-追加情報)に移し、原文を保持したうえで BotMsg の末尾に既定のフィードバック情報を追加 |
| カスタムヘルプ | `conf/CustomHelp.json` | 簡体字中国語のヘルプ項目として書き込み、[ヘルプ文書](/ja/manage/help-docs)の「ユーザー定義」で編集・削除可能。元の内容は保持し、無効な文面としては扱わない |
| ダイスマスター | `conf/console.yaml` / `Console.xml` | 選択したアカウントの Master 一覧と対応する動作設定。YAML を優先し、YAML が壊れていても古い XML の権限は使わない |
| 外部デッキ | `PublicDeck/` | JSON の内容を検証してから `data/decks/` に移動。入れ子になった同名ファイルには一意で安全な名前を付け、場所を特定できるローカルのメディアも移行 |
| Lua mod | `mod/` | `data/mod/`（ツリーごとコピーし、Lua mod サブシステムが認識） |
| Lua プラグイン | `plugin/` | `data/plugin/`（単一ファイルとフォルダー型のプラグインを個別にコピー） |
| グループ間リンク | `conf/LinkList.json` | 新しい `.link` のメッセージ転送：通常の QQ グループ間の `with/to/from` リンクと一時停止状態を移行 |
| 通知ウィンドウ | `conf/NoticeList.json` | 選択したアカウントの QQ 個人チャット・グループの通知と元のレベルマスク。旧来の共有ウィンドウは `.notice status/off` で管理可能 |
| カスタム禁止語 | `conf/CustomCensor.json` | システム設定の禁止語フィルター：Ignore〜Critical の数値レベルを保持し、ルールがあれば自動で有効化 |
| セッション | `user/session/*.json` | ランダムな 16 文字のセッション番号を生成して出所を記録。同じ出所の再取り込みでは同じものを使い、初期の記録やフォルダーのコピーは引き継ぎの確認が必要。ルーレットは残りのプールだけを復元 |
| セッションログ | `user/log/*.txt` とセッション内のログ状態 | 新しいログ保存領域：文章の記録を移行し、記録中 / 一時停止 / 終了の状態を復元 |

::: tip 補足
- カスタム文面とヘルプは **簡体字中国語** の層にのみ書き込みます。ほかの言語は Dice!Next 内蔵の文面のままです。
- 旧版の文面キー（`strXXX`）のうち、新バージョンに確認済みの対応先があり、実行時の引数も互換なものは自動で割り当てられます。例：ダイスの出目、成功度、デッキ、セッション、観戦、歓迎メッセージなど。**対応先がない、または引数が互換でないものも失われません**。「無効な文面」として保持され、管理パネルで確認して手動で移植できます。
- ユーザーとグループのスカラー値のカスタム設定は Lua 互換の設定領域に保持されます。旧版の内蔵機能がすべて新バージョンで同じ動作をするという意味ではありませんが、旧 Lua のルールは引き続きこれらの値を読み取れます。
- ユーザーとグループの変数にある真偽値、小数、空文字列、シリアライズ可能な構造は型を保ちます。旧来の関数は実行せず、同等に接続できない項目はレポートに記載します。
- デッキは拡張子だけでなく内容で検証します。デッキではないファイルは引き続きスキップし、理由を示します。
- キャラクターシートの技能値は新しいルールシステムに従います。真偽値や入れ子の原本を保持していても、それらが整数の技能として扱われるわけではありません。
- 旧バイナリファイルは 64 ビットと 32 ビットの `size_t` レイアウトの両方で完全に検証してから、データベースに書き込みます。失敗した試行で中途半端な記録が残ることはありません。旧来の関数は実行せず、入れ子の関数も未処理としてレポートに記載し、元のバイト列は旧ファイルに残ります。
- Lua の旧 Set 変数は集合のメソッドを取り戻し、ユーザー、グループ、セッション設定、キャラクターシート内での集合の変更も書き戻せます。通常の JSON 配列を勝手に Set として扱うことはありません。
:::

### キャラクターシートの読み書きとテキスト出力

`STR` や `HP` など登録済みの別名で、旧シートの元の項目を読み取れます。先にシートを一括で書き換える必要はありません。元の名前と標準名に異なる値が保存されている場合は両方を保持し、移行レポートで競合を知らせます。どちらの値を使うかはルールシステムに沿って判断してください。一方で他方を自動で上書きすることはありません。

式は統合キャラクターシートのデータを使うため、組み込みコマンド、Lua、JS のいずれからでも同じ値を読み取れます。編集、削除、全消去、シートの切り替えを行っても、互換用のコピーから古い式が再び現れることはなくなりました。全消去では文章、小数、構造を持つ能力値を削除しますが、名前、種類、ロックなどのメタデータは残します。

- 通常の整数の能力値だけの場合、`.st export` は従来どおり `.st 力量50 …`（力量 = STR）の形式で出力します。
- 式、文章、小数、構造を持つ能力値がある場合は `json {...}` を出力し、`.st json {...}` で再び取り込めます。この操作は現在のシートの編集可能な能力値を置き換え、書き込みロックに従います。出力の読み取りは読み取りロックに従います。
- コマンドで扱う JSON は 256 項目、64 KiB までです。大きなシートには完全な JSON シートの出力を使ってください。JSON の元シートの出力やクラウドシートのデータでは、競合する項目も捨てません。

### 初期のセッションとフォルダーのコピー

同じグループで同じ名前の、以前に取り込んだセッションや、同じ原本のフォルダーのコピーが見つかった場合、移行ツールはそのセッションと関連するログの取り込みをいったん止め、レポートは完了として表示されません。パネルに候補が一覧表示されます。

1. 同じセッションだと確認できた場合は、既存のセッションを選んで引き継ぎを適用します。元のセッション番号と現在の変数が保持されます。
2. データの上書きを有効にしていない場合、既存の変数は上書きしません。旧い値で置き換えたい場合は、上書きを明示的に有効にして確認してください。
3. 本当に別のセッションである場合は、独立した新しいセッションを作成することを明示的に選べます。既定では推測で統合することも、こっそり追加することもありません。

確認して移行を続けるたびに、まず新しい復元用のバックアップを作成します。キャラクターシートと旧セッションは引き続き共有の互換領域を使うため、アカウントを選んだからといって、すべてのデータがアカウントごとに分離されたとは限りません。

### 移行した画像のバックアップ

完全バックアップと、「リソース画像」にチェックした部分バックアップには、ルートの `image/` フォルダーとデッキと一緒に移行したメディアが含まれます。新しいバックアップ形式はバージョン 4 で、復元時にこれらのリソースも元に戻します。形式 1〜3 も引き続き対応しており、古いパッケージを復元しても、そこに含まれていないルートの画像が消えることはありません。バックアップと復元では、シンボリックリンクや Windows の再解析ポイントをたどりません。

## 移行の制限と、まだ自動で移行されないデータ

以下は移行の改善計画に入っています。該当するバージョンがリリースされるまで、取り込みツールは旧フォルダーの元ファイルを残し、勝手に削除することはありません。

| 旧版の場所 / データ | 現在の扱い | 理由と今後の方針 |
|---|---|---|
| `user/GameTable.toml` | 個別には移行しない | 旧版の連番を保存しているだけです。新しいセッション番号は予測できないランダムなコードを使うため、引き継げません。 |
| `conf/LinkList.json` 内の個人チャット、ディスカッショングループ、チャンネルのリンク | 移行しない | 新しい `.link` は通常のグループ間の転送のみに対応します。安全に対応付けられる QQ グループのリンクは自動で移行済みです。 |
| 旧セッション内の観戦者、デッキ、tables | 原本を保持し、確認が必要 | セッションの完全な原本とこれらの項目は互換情報として別に保存します。同等の動作状態がない部分は自動では有効にしません。レポートでは「保持のみ」と「接続済み」をはっきり区別します。 |
| プラグインが作成したフォルダー、任意のカスタムファイル | まだ移行しない | `plugin/` の本体はコピーします。プラグインが実行時に書き込む任意の場所は、用途を安全に推測できません。 |
| `CustomReply.json`、`CustomRegexReply.json` | 対応済み | 新しい `CustomMsgReply.json` がない、または空の場合に、新しいキーワード / 正規表現の返信ルールに変換します。 |
| 招待者、活動時刻、許可 / 禁止免除 / 無視などのグループの状態 | まだ移行しない | 新バージョンに明確で安全な対応先がある設定だけを移行できます。旧版でキャッシュされたグループ名は互換情報として保持し、現在のアダプターが読み取ったグループ名を直接上書きすることはありません。 |
| ブラックリストのグループ項目、関係者、外部 / クラウドの出所 | 保持してレポート | ユーザーの `local/ban/kick` など有効なローカル記録は移行できます。出所を証明できない記録や、旧来の禁止免除・信頼ポリシーが関わる記録は、ローカルの処分には変わりません。 |
| コンソール内のタスク、Git/WebUI の認証情報、古いクラウド設定 | 移行しない | 明確に対応する動作スイッチは取り込めます。実行可能なタスクや機密性の高い認証情報は、旧環境のものを使わずに設定し直す必要があります。 |
| `selfdata/` | JSON は接続し、その他の形式は原本を保持 | 最上位の JSON アーカイブは `data/self_data/` に移します。ほかの形式や入れ子のパスは有効になったように見せず、確認レポートに記載します。 |
| `CardTemp/`、`conf/censor/` の外部の語彙リスト | 元ファイルを保持 | `data/legacy-import-preserved/` に保存します。旧スクリプトは実行せず、確認されていない語彙リストを勝手に有効にすることもありません。 |
| ルートの `image/` | メディアを移行 | ローカルのメディアは相対パスを保ちます。安全に場所を特定できないデッキの参照は原文のまま残してレポートし、選択したフォルダーの外のファイルを読んだり、リンクをたどったりはしません。 |
| 日別の統計と過去の利用回数 | 統計システムには接続しない | 旧版の統計は集計方法が異なり、新バージョンの計測結果としては扱えません。参照できるよう旧フォルダーを残しておいてください。 |

## カスタム文面とヘルプ

旧版 Dice! のカスタム文面とヘルプは主に簡体字中国語のため、取り込みツールが **`zh-Hans` にのみ書き込む** のは想定どおりの動作です。繁体字中国語と英語では引き続き Dice!Next 内蔵の文面を使います。

- 新バージョンに 1 対 1 の対応先がある `strXXX` の文面は、対応するテンプレートに接続します。設定済みの新しいレベル別返信や組み込みコマンドのテンプレートは、既存の優先順位のまま使われます。
- 確認済みの旧プレースホルダー（`{pc}`、`{deck_name}`、`{game.log_name}` など）は、移行時に新しいプレースホルダーへ変換します。必要な引数が新バージョンにはもうない旧テンプレート（旧 `.log off/end` のログ名やファイル名のテンプレートなど）は無理に移行しません。
- 同等の対応先がない、またはプレースホルダーを安全に変換できない文面は、管理パネルの「無効な文面」に保存されます。失われることも、有効になったように見せかけることもありません。
- 新しい文面の対応先を追加するたびに、これらの無効な文面を確認し直します。意味の対応がはっきりしたキーは対応表に加え、意味の同等性を保証できないものはダイスマスターが手動で扱えるよう残します。

新しく追加した[判定結果ごとの返信](/ja/manage/commands#判定結果ごとに返信全体を設定する)は、既定で既存の文面を引き継ぎます。上書きを自動で書き込んだり、移行済みの文面を消したり、取り込み直しを求めたりはしません。互換の完全なテンプレートや成功度のフレーズは引き続き有効です。新しいレベル別の返信を自分で設定したときだけ、新しい継承の順序で返信全体を選びます。

以下の判定文面の不足は補われているため、旧来の短いフレーズを新しいレベル別の返信全体に書き直す必要はありません。

| 旧文面 | 新バージョンでの互換処理 |
| --- | --- |
| `strRollCriticalSuccess/strRollExtremeSuccess/strRollHardSuccess/strRollRegularSuccess/strRollFailure/strRollFumble` | 1 回の判定用の 6 つの独立したレベル別フレーズ。複数回判定のフレーズとは混同しない |
| `strCriticalSuccess/strExtremeSuccess/strHardSuccess/strSuccess/strFailure/strFumble` | 引き続き複数回の判定と SAN のレベル別フレーズとして使用 |
| `strRollSkill/strRollSkillReason` | 判定の前置き。連続する複数回の判定では前置きを 1 回だけ付ける |
| `strRollSkillHidden` | シークレット判定のグループ向けの通知。個人チャットで送る詳細な結果は明かさない |
| `strSanityRoll` | SAN の完全なテンプレートと、`rank/loss/change/final` の旧変数の意味を保持 |
| `strEnRoll/strEnRollNotChange/strEnRollFailure/strEnRollSuccess` | 成長の基本文、変化なし、失敗時の変化、成功時の変化をそれぞれ保持し、参照は基本文の変更に合わせて更新 |
| `strEnDefaultName` | 成長判定の既定の技能名 |

入れ子の `sample`、`case`、`grade` と、割り当て済みの旧文面への参照（`{strEnRoll}` など）に対応しています。JavaScript、Python、待機などの実行可能なマクロは実行しません。条件項目や変数に対応先がない場合、レポートでは「一部互換」と表示します。対応していないマクロ、不完全な構文、自分自身への循環参照は原文のまま残し、手動での移行を待ちます。**これは旧版のすべてのテンプレートマクロに対応しているという意味ではありません。**

新たに取り込んだ上記の互換文面は `legacy.strXXX` の原本を保持し、内容の異なる既存の対象を上書きしません。管理パネルの「バックアップと取り込み」では、項目ごとのレポートを表示・ダウンロードでき、接続済み、一部互換、保持のみ、競合によるスキップを区別して確認できます。「接続済み」は文面の対応先への割り当てに成功したという意味で、優先度の高い新しい返信を置き換えたという意味ではありません。

既存のデータベースは、アップグレード後の最初の起動時に、安全に対応付けられる過去の孤立した対応先を自動で補い、初期の `dice.crit/dice.fumble` の 1 回判定用フレーズの割り当てを修正します。グローバルとペルソナの記録はどちらも保持し、既存の対象（意図的に空にしたものを含む）は上書きしません。修復の記録は永続的に保存されるため、既定値に戻した後の次の起動で、消した旧文面が再び補われることはありません。信頼できる旧原本がない不足分は取り込み直す必要があり、修復の記録は現在の設定のリアルタイムな監査ではありません。

## 旧コマンドとの互換の範囲

Dice!Next は新しい保存領域、権限、プラグイン管理の上で旧来の書き方を直接実装しており、旧版のコアを並行して動かしているわけではありません。現時点で確認済みの主な移行ポイントは次のとおりです。

| 元の書き方 | Dice!Next の動作 |
|---|---|
| `.h` / `.H`、`.rh`、`.rs` | 短いシークレットダイスの別名と、最終値だけを出力する動作を保持。`.help` が `.h` に奪われることはない |
| `.coc/.coc7`、`.coc6`、`.cocd/.coc7d/.coc6d` | それぞれ第 7 版、第 6 版、詳細なキャラクター作成の結果を生成。旧来のレイアウト指定 `s` も受け付ける |
| `.help on/off`、`.jrrp on/off`、`.reply on/off` | グループごとに保存し、グループ管理 / 信頼の権限をそのまま使う |
| `.drawh` | 抽選結果を個人チャットで送り、グループにはシークレット抽選の通知だけを残す |
| `.pc nn/stat/cpy/copy/grp/tojson/type/temp` | 統合キャラクターシートとルールシステムに接続。コピーの順序は `コピー先=コピー元` |
| `.rule set <ルールブック>`、`.ruleset clear` | 統合されたルールブックの設定に接続。設定とクリアのどちらもグループ管理の権限を確認する |
| `.mod list/on/off/info` | 統合されたプラグイン一覧とグループごとのオン・オフに接続。更新、再読み込み、削除、再インストールは WebUI での確認のみ |
| `.user state/trust/tojson/diss` | 統合されたプレイヤーのプロフィール、権限、リストに接続。`diss` はプロフィールやシートを削除しない |
| `.strXXX <文面/show/reset/NULL>` | 監査済みの 1 対 1 の文面キーだけを統合された上書き表に書き込む。不明な `str…` は握りつぶさない |
| `.cloud update/black` | 再現しない。旧版のこの 2 つは状態を報告して Web ページへ案内するだけでした。バージョン番号は引数なしの `.bot` で確認でき、クラウドブラックリストのスイッチは Web の「システム設定」にあります。`.cloud` は現在、アカウントセンターの認可と[クラウドのキャラクターシート](/ja/use/cloud)の入口です |

::: danger 意図的に再現しないもの
- `.system cmd`：旧版のリモートシェル。リモートでのコード実行と同等の危険があります。
- `.user kill/clr`：チャットからプレイヤーやシートを元に戻せない形で削除する操作です。Web 管理パネルで二重に確認してください。
- `.mod update/reload/del/reinstall`：チャットからプラグインのファイルを置き換えたり削除したりはしません。
:::

JS プラグインの互換の元は **SealDice（`sealdice-core`）** であり、旧 Dice! の JS ではありません。フック、項目、制限について詳しくは [JS プラグイン API](/ja/develop/js-plugin-api) を参照してください。

## 移行の手順（管理パネル）

1. 旧版 Dice! のデータフォルダー（**`conf/` と `user/` を含む階層**）を、Dice!Next を動かしているマシンに置きます。
2. 管理パネル → **システム設定 → バックアップと復元 → 旧版データの取り込み** を開きます。
3. そのデータフォルダーの **完全なパス** を入力し、移行先の OneBot / Milky アカウントを選びます。共有の互換層は OneBot の共有設定にのみ書き込みます。QQ 公式の OpenID などの識別子は、旧 QQ 番号から推定できません。
4. 既定では既存の Next のデータを保持します。リソースファイルの上書きと、データベース・設定の上書きは別々の選択肢です。データの上書きを有効にすると再度確認を求められ、ほかの言語の文面が削除されることはありません。
5. 「取り込みを開始」をクリックします。サーバーはまず復元用のバックアップを作成し、バックアップに失敗した場合は移行を始めません。
6. レポートの失敗、無効化、競合、「保持のみ」の項目を確認します。移行した Lua プラグインは取り込みツールでは実行されません。確認したらプラグイン管理で再読み込みしてください。

対応する REST API は `POST /api/legacy/import` で、パラメーターは `{ "dir": "パス", "overwrite": false, "overwrite_data": false, "target_adapter_id": "アカウント ID" }` です。移行先のアカウントを指定しない場合は OneBot の共有互換層を使います。

API の通信が成功しても、移行が完全に成功したとは限りません。`data.ok`、`data.complete`、`data.errors`、`data.diagnostics` を確認してください。一部が失敗したレポートも返されるため、完了した段階の結果は失われません。BDC の移行の目印が外れるのは、完全に成功した場合だけです。

## 移行レポート

### 返信の参照の正規化

取り込みツールはまずデッキ、ヘルプ、グローバルな文面を取り込み、そのうえで実際に使えるリソースに基づいて、返信とクールダウン / 1 日の上限のメッセージ内の参照を処理します。あいまいさのない参照は自動で変換されます。

- `{デッキ}` / `{%デッキ}` → `{deck:デッキ}` / `{deck:%デッキ}`。その返信内での非復元 / 復元の抽選ルールを保ち、ファイルのデッキだけを参照します。
- ヘルプ項目 → `{help:項目}`、旧グローバル文面 → `{text:文面名}`。
- `{nick}` などのコンテキスト変数や既存の明示的な接頭辞はそのまま残し、エスケープされた内容は書き換えません。入れ子の `sample:` のすべての分岐も処理します。取り込み時に実際にカードを引いたりダイスを振ったりはしません。

変数とリソースが同名の場合、複数の種類に一致する場合、リソースが見つからない場合は、原文を残して理由をレポートします。確認待ちの参照が残っている旧来の返信だけが、互換のために接頭辞なしのデッキ検索を保持します。新しい返信は明示的な接頭辞を使うので、後からデッキを追加しても、既存の式やヘルプの参照が意図せず置き換わることはありません。

ダイスの式に見える部分も確認待ちとして記載します。旧来の接頭辞なしの式は評価に失敗すると原文が残りますが、明示的な `roll:` は失敗すると `?` を表示するため、文字の形だけで自動的に置き換えることはできません。意味を確認したうえで、手動で `roll:` を付けてください。

取り込み結果の `replyReferences` には、変換数、あいまいな件数、見つからなかった件数と、参照ごとのルール、位置、原文、対象、理由が含まれます。Web ページでは詳細を展開したり、JSON のレポートをダウンロードしたりできます。レポートは保存しておき、実際の用途に合わせて確認待ちの項目を修正してください。

すでに取り込んだルールも、元のデータから取り込み直せます。定義全体が同じルールはその場で更新され、重複して追加されることはなく、ダイスマスターが調整したオン・オフの状態と優先度も保持されます。後から不足していたリソースを補った場合も、もう一度取り込むと、確認待ちだった旧来の参照の正規化を試みます。

取り込みが完了すると、各項目の件数が返されます。

- キャラクターシートの数（と関係するユーザー数）、プレイヤーのプロフィール、ブラックリスト、カスタム返信、ヘルプ、文面（「無効な文面」の件数は別に集計）、Master の数
- デッキ、mod、プラグインの **成功 / 失敗 / スキップ** の詳細（ファイルごとに理由を記載）
- グループ設定：取り込んだ設定項目の数と関係するグループ数。グループ間リンク、通知ウィンドウ、禁止語のルール、セッション、ログとログメッセージの数

ページには項目ごとの結果、セッション / ログの集計、復元用バックアップとレポートの保存場所が表示されます。記録が多い場合は画面に表示する件数を制限し、完全なレポートはダウンロードできます。レポートはサーバーの `data/legacy-import-reports/` にも保存されます。旧ルールの原本が含まれる場合があるため、そのまま公開しないでください。

## 注意事項

- **移行前**：旧版のデータフォルダー全体をバックアップし、Dice!Next を動かすマシンからそのフォルダーにアクセスできることを確認してください。
- **繰り返し取り込める**：新しい移行記録は安定した出所の識別子を使うため、同じ出所のセッションが重複して追加されることはありません。既定では既存のデータを保持します。ログは追記されたメッセージ全体だけを自動で補い、元の本文が書き換えられている場合や新バージョンでメッセージが編集されている場合は、現状を保ってレポートします。出所の情報がない旧来の取り込み記録は手動での確認が必要で、推測で削除することはありません。
- **破損したファイル**：キャラクターシート、ユーザー、グループのバイナリファイルは、その種類のデータを書き込む前に完全に検証します。メインのファイルが壊れていれば有効なバックアップを試し、すべて壊れていればエラーを報告します。途中で切れた内容を成功として扱うことはありません。
- **一部の失敗**：フォルダー全体を 1 つのトランザクションとして扱うわけではないため、一部の段階はすでに書き込まれている可能性があります。レポートを確認し、必要であれば移行前のバックアップから復元してください。旧来の元フォルダーと確認待ちの原本はすべて保持されます。
- **移行後**：[テスト台](/ja/manage/dashboard)またはテスト用グループで、ダイス、判定、カスタム返信が期待どおりに動くか確認してください。
- 一部のコマンドの構文は Dice!Next で整理されています。違いについては[ダイスと判定](/ja/use/dice)を参照してください。

## 整理設定の移行

旧 Dice の `InactiveUserLine` / `InactiveGroupLine` は **ローカル記録の保持期間** です。それぞれ `dice/user_record_days` / `dice/group_record_days` に取り込まれ、基本設定の「ローカル記録の保持」で確認できます。これらによって友だちの削除やグループからの退出が有効になることはありません。ユーザーのプロフィールとグループ一覧の情報が整理される範囲については[基本設定](/ja/manage/settings#友だち・グループ・ローカル記録の自動整理)を参照してください。

`GroupClearLimit` は 1 回あたりに退出するグループ数の上限に対応します。旧来のグループ設定の「免清」（整理の免除）は整理の免除に、「忽略」（無視）は完全な無効化と整理の免除のまま、「免黑」（禁止の免除）はブラックリスト登録の免除に対応します。該当する `GroupInvalidSize`、`LeaveBlackQQ`、`ListenGroupKick`、`ListenGroupBan`、`KickedBanInviter`、`BannedBanInviter` の設定は、既存の互換方式で取り込みます。コンソールファイルに書かれていない項目は Dice!Next の既定値のままです（キック・ミュート時の自動ブラックリスト登録は既定でオフ）。データの上書きを許可していない場合は、既存の設定が優先されます。

初期の Dice!Next では、`InactiveUserLine` を友だちを削除するまでの日数として誤って割り当てていました。新しいバージョンでは以後の取り込みで修正していますが、すでに保存されている友だち削除の設定を推測でリセットすることはありません。旧版から移行したダイスマスターは「友だちのコマンド未使用期間」を確認し、友だちを削除しない場合は 0 に設定してください。既存の「自動退出」の定期タスクを、移行ツールが設定し直したり、無効にしたり、削除したりすることはありません。
