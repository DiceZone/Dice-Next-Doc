# デッキとランダムな抽選

Dice!Next は元祖 Dice! のデッキ形式と互換で、ゲームマスター（KP）のために実行時の一時デッキとインラインでのランダム機能を提供します。

## コマンド一覧

| コマンド | 説明 |
|------|------|
| `.draw` / `.drawh` | デッキから公開で引く / シークレットで引く |
| `.deck` | デッキの一覧表示 / 一時デッキの管理 / 既定のデッキの設定 |
| `.gacha` | ガチャ（ガチャ用のデッキ） |

## カードを引く `.draw`

```
.draw 塔罗牌        → 「塔罗牌」（タロット）デッキから 1 枚引く
.draw3 塔罗牌       → 3 枚続けて引く
.draw              → グループの既定のデッキから引く（先に .deck set が必要）
.drawh 塔罗牌       → 結果は引いた人の個人チャットに届き、グループにはシークレット抽選の通知だけが出る
```

### インラインのランダム（セッションの強い味方）

デッキを作らなくても、候補を `/` で区切るだけでランダムに 1 つ選べます。

```
.draw 红/蓝/绿      → 3 つの中からランダムに 1 つ選ぶ（赤 / 青 / 緑）
.draw3 左/中/右     → ランダムに 3 回選ぶ（左 / 中 / 右）
```

その場でダイスにランダムな判断を任せたいときに便利です。

## 一時デッキ `.deck new`

誰でも（管理権限のない KP を含む）グループ用の一時デッキを作れます。セッション中にとても便利です。

```
.deck new 出招 石头/剪刀/布   → グループの一時デッキ「出招」を作成（グー / チョキ / パー）
.draw 出招                    → 一時デッキから引く
.deck del 出招                → 一時デッキを削除
```

## セッション専用のデッキ `.deck session`

先に `.game new` でセッションを作成し、そのセッションの GM、グループ管理者、またはダイスマスターが、引いたカードを戻さないデッキを管理します。以下は現在の main ブランチに基づく内容です。お使いのパッケージに新しい入口が含まれているかは、対応する Release のソースのバージョンで確認してください。

```text
.deck session new 出场 甲/乙/丙       // 専用のデッキを作成
.deck session from 敌人 公共敌人堆   // 公開デッキをコピー。元のデッキは変更しない
.deck session range 编号 1 20 2      // 整数の範囲から 1、3、5…19 を生成
.deck session members 抽签名单       // 現在のアカウントがキャッシュしているグループメンバーからスナップショットを作成
.deck session rest 出场              // 残りの枚数を表示
.draw 出场                          // 1 枚引いて、戻さない
.deck session reset 出场             // すべてのカードを元に戻す
.deck session del 出场               // 指定した専用のデッキを削除
.deck session clr                    // このセッションの専用のデッキをすべて削除
```

`::2::甲` は甲が 2 枚という意味です。1 つのセッションで持てる専用のデッキは最大 10 個です。同じセッションに接続した複数のグループはカードのプールを共有し、異なるセッション同士は影響し合いません。残りの枚数は永続的に保存され、旧版の保存データの引いた状態も保持されます。カードがなくなった場合は明示的にリセットする必要があり、自動で補充したり、同じ名前の公開デッキから引いたりすることはありません。保存に失敗した場合、その回はカードが減りません。

引く順序は **セッション専用のデッキ → グループの一時デッキ → 公開のファイルデッキ** です。グループの一時デッキは引いたカードを戻す方式のままで、`.deck new/set/del/clr` の意味も変わりません。セッションの管理には上の明示的な `session` の入口を使います。引数 3 つの Lua の `drawDeck(gid, uid, name)` はセッションのカードのプールを共有し、引数 1 つの `drawDeck(name)` は引き続き公開デッキからだけ引きます。

数値の範囲には開始、終了、省略可能な正の整数のステップを指定します。開始と終了が逆の場合は入れ替え、数値を 1 つだけ書くと 0 からその数までになり、最大 10000 枚です。グループメンバーから生成するには、現在のアダプターのアカウントがオンラインで、メンバーのキャッシュが使える必要があり、別のボットで補って調べることはしません。キャッシュが空の場合は、現在のアカウントに更新を依頼して再試行を促し、空のデッキは作りません。重複を除いて 1 人 1 枚になり、ニックネームはスナップショットとして保存されるだけで、その後の名前の変更には追従しません。OneBot は既存のメンバーのキャッシュと名前の索引をそのまま使い、1 人ずつネットワークで名前を取得することはしません。生成されたカードの面は文字どおりの文章として保存され、ニックネーム内の `::枚数::` や `{テンプレート}` は実行されません。偽装された CQ コードやページ送りの制御文字は無害化されます。どちらの生成方法も、セッションの開始、GM / グループ管理者 / ダイスマスターの権限、保存失敗時の既存の保護に従います。

## 既定のデッキ `.deck set`

```
.deck set 塔罗牌    → グループの既定のデッキに設定（グループ管理者が必要）。以後は .draw だけで引ける
.deck default       → 現在の既定のデッキを表示
.deck clr           → 既定のデッキを解除
```

## デッキのファイル

デッキは JSON ファイル（`{"デッキ名": ["カード1", "カード2", …]}`。1 つのファイルに複数のデッキを入れられます）で、次の 2 つのフォルダーから読み込みます。

| フォルダー | 用途 |
|------|------|
| `decks/` | インストールパッケージに同梱される内蔵 / サンプルのデッキ（アップグレード時に置き換わる） |
| `data/decks/` | 自分のデッキ（アップロードも手動で置いたものもここ。アップグレードの影響を受けない） |

同じ名前のデッキは `data/decks/` のものが優先されます。手動でファイルを置いた後は、管理パネルで「再読み込み」をクリックするか再起動すると反映されます。

### WebUI でのアップロードと編集

[Web 管理パネル](/ja/manage/dashboard)の「デッキ管理」ページでは、次のことができます。

- `.json` のデッキまたは SealDice 形式の `.deck` パッケージを **アップロード**。JSON は `data/decks/` に保存し、画像はファイル名ごとに `data/images/deck/` に整理して再読み込みします。
- 左側でファイルを選び、右側でそのファイルの各デッキの項目を確認します。ページはページ番号のクリックや番号の入力で移動できます。
- ユーザーのファイルは **オンラインで編集・ダウンロード・削除** できます。内蔵のファイルはパネルとサーバーの両方で読み取り専用に制限されており、直接上書きや削除はできません。2 つの出所に同じ名前のファイルがあっても、それぞれ区別して表示し、間違ったファイルを読み書きすることはありません。
- 内蔵のファイルはダウンロードして保存できます。また、公開された空でない単一のデッキを **ユーザーのデッキファイルにコピー** してから編集できます。その項目のカードの原文は保持しますが、まとめ全体、ほかのサブデッキ、まとめのメタデータはコピーしません。参照は引き続き読み込まれている元のデッキに依存するため、単独で配布する場合は依存関係を別途確認してください。
- デッキの `_title`、`_author` などのメタデータを確認できます。
- すべてのデッキのフォルダーをワンクリックで **再読み込み** できます（追加・変更・削除したファイルがすべて反映されます）。

項目を編集するときは、元の重み、参照、複数行の文章、未知の拡張項目を保持し、保存せずに切り替えようとすると確認を求めます。空のオブジェクトを読み込んだときに「このデッキを読み込めません」となる問題は修正済みです。実際に読み込みに失敗した場合はエラーを表示して再試行でき、空の内容を読み込み成功として扱うことはありません。

### `.deck` デッキパッケージ {#deck-牌堆包}

「リソースを含めてダウンロード」では、ローカルの画像と、出所を静的に特定できる読み込み済みのファイルをまたぐデッキの依存関係を集め、`.deck` の ZIP を作成します。ローカルの依存関係がない場合は、引き続き JSON をダウンロードします。

パッケージ内の JSON と `assets/` はそのままルートに置き、**フォルダーをもう 1 段かぶせないでください**。画像の参照は `./assets/…` です。重み、エスケープ、入れ子の `sample` はそのまま保持し、出力時にカードを引いたり、テンプレートやプラグインを実行したりすることはありません。Next 独自の文章の構文が、ほかのエンジンで同じ意味になる保証はありません。

リモートの画像は自動ではダウンロードしません。ローカルの依存関係が足りない場合ははっきりとエラーを出し、不完全なパッケージを出力することはありません。動的に組み立てたデッキ名や画像のパスはすべて集められる保証がないため、自分で確認してください。

取り込みでは、先にパッケージの内容を検証してから上書きを確認します。各 JSON のデッキの画像はまとめて `data/images/deck/<そのファイル名>/` に置き、サブフォルダーも保持します。静的に参照されていない添付の画像は最初のデッキに入れ、注意を表示します。スクリプト、範囲外のパス、シンボリックリンク、暗号化された内容、大文字・小文字だけが異なる同名のファイルを含めることはできません。

アップロードするパッケージは 128 MiB まで、1 ファイルも 128 MiB まで、展開・整理後の画像は 512 MiB / 10000 個まで、JSON のデッキは最大 100 個です。上限を超える場合は分割してください。

画像だけを整理・参照する場合は[ファイル管理](/ja/manage/files)を使ってください。

チャットの `.deck` の一覧では、既定で `_` で始まるメタデータのキーを隠します（[基本設定](/ja/manage/settings)でこの非表示をオフにできます）。

### 旧版のデッキとの互換

- 次の **元祖 Dice! のデッキ形式** の構文に対応しています：サブデッキの参照 `{デッキ}`（戻さない）、`{%デッキ}`（戻す）、ダイスの式 `[1d6]`、重み `::N::カード`、エスケープ `\{` `\[`。
- [データ移行](/ja/guide/migration)で元祖 Dice! からアップグレードすると、`PublicDeck/` フォルダーの外部デッキは自動で検証されて `data/decks/` に取り込まれます。
- デッキのファイルは **UTF-8 エンコード** の JSON である必要があります。旧版から残っている GBK エンコードのファイルは、UTF-8 に変換してから置いてください。中国語のファイル名は問題ありません。

カードの面には `sample / case / grade / ran / len / expired / var / at / print / wait` などの[安全な文章関数](/ja/develop/lua-mod#安全な文章の関数)を入れ子にでき、`[1d{ran:6~6}]` のような明示的な計算にも対応しています。変数は現在のメッセージのコンテキストに従います。選ばれた分岐だけがカードを引き、ダイスを振り、待機を登録します。局所変数と戻さないサブデッキのプールは 1 回の展開の中で使い回し、1 回の描画では同じデッキのフォルダーのスナップショットを使います。

既存の画像 / CQ コード、重み、`\{` / `\[` のエスケープは引き続き使えます。ニックネーム、捕捉した文章、そのほかの実行時の項目は、`{デッキ}`、`[1d100]`、`{wait:1000}` を含んでいても再び解析されることはありません。メンバーから生成したスナップショットのカードも完全に文字どおり表示され、新しく追加したテンプレート機能によってメンバーのニックネーム内のコードが実行されることはありません。

::: tip デッキからヘルプ項目を参照する
カードの中の `{参照}` がデッキ名でない場合は、同じ名前の **ヘルプ項目** を探してその内容を展開します（溯洄 / OneDice の参照の意味）。ヘルプ文書と組み合わせて、複雑な抽選の構造を作れます。[ヘルプと言語](/ja/use/help)を参照してください。
:::
