# キーワードのカスタム返信

Dice!Next は柔軟なキーワードの自動返信に対応しており、[Web 管理パネル → 返信管理](/ja/manage/replies)で視覚的に組み立てられます。返信管理ページには **基本の返信**、**因果ルール**、**カウンター** の 3 つのタブがあります。

チャットでは `.reply on/off` でこのグループのカスタム返信を永続的にオン・オフできます（グループ管理者または信頼済みのユーザー）。`.group +禁用回复` でもオフにできます（[グループ管理とシステム](/ja/use/admin)を参照）。

## 基本の返信

### 一致の方式

| 種類 | 説明 |
|------|------|
| キーワード一致 | メッセージ全体が内容と **完全に等しい** ときだけ反応（大文字・小文字を区別しない） |
| 前方一致 | メッセージがその接頭辞で始まると反応 |
| 正規表現一致 | 正規表現が **メッセージ全体** に一致する必要があり、グループを捕捉できる。旧 Dice の全体一致と同じ |
| 部分一致 | メッセージにその内容が **含まれる** と反応（大文字・小文字を区別しない） |

1 つのルールで **複数の条件の AND / OR** の組み合わせと、**複数の結果からのランダム**（一致したら複数の返信から 1 つをランダムに送る）に対応し、優先度も設定できます。

正規表現は大文字・小文字を区別しない ECMAScript の方言を使い、全体一致のために `^` や `$` を自分で付ける必要はありません。たとえば `白(丽|麗).{0,6}` は「白丽／白麗」の後に 0–6 文字までしか許さず、7 文字が続くと反応しません。前方一致のように反応させたい場合は `白(丽|麗).*`、部分一致のようにしたい場合は `.*白(丽|麗).*` と書きます。

`.` は既定で改行に一致しません。改行も含めたい場合は `[\s\S]` を使います（例：`[\s\S]*白丽[\s\S]*`）。空白、タブ、改行はすべてメッセージの一部で、一致のプレビューでも前後の空白を自動で削りません。量指定子は ECMAScript の UTF-16 の単位で数えます。よく使う漢字は 1、多くの絵文字は 2 と数えるため、見た目の 1 文字とは一致しません。

これは ECMAScript の `i` モードで、PCRE ではなく、`u`、`m`、`s` などのフラグも自動では有効になりません。式の上限は 400 UTF-8 バイトです。一致の処理には引き続き入力、メモリ、実行時間の保護があり、全体一致に戻しても安全のための制限はなくなりません。

これまで Next の先頭一致の正規表現や、因果ルールの部分的な正規表現の検索に頼っていたルールは、前後に許す内容を明示してください（例：`abc.*`、`.*abc.*`）。プログラムが保存済みの式を書き換えることはありません。旧 Dice でもともとメッセージ全体で一致させていたルールは、`$` を付けたり取り込み直したりする必要はありません。

複数の返信には、管理パネルでそれぞれ重みを入力し、実際に選ばれる確率を確認できます。たとえば重み 3 と 1 は 75% と 25% になります。既定の重みは 1、範囲は 0–999999 で、0 は選ばれないことを表します。ルール全体の「反応する確率」と、各返信が選ばれる重みは別々に計算されます。

旧来の `::数字::` の目印は、旧データを取り込むときや読み込むときに独立した重みに変換されるため、取り込み直しは不要です。無効な目印は原文のまま残ります。正式なエディターでは独立した重みの項目を使うため、返信の文章内の `::数字::` は書いたとおりに送られます。

### 返信テンプレートの変数

返信の内容には `{…}` のプレースホルダーを使え、送信時にその場で置き換えられます。

| 変数 | 意味 |
|------|------|
| `{nick}` | 反応させた人の表示名（囲み記号付き。囲み記号は設定で変更可） |
| `{name}` | 反応させた人の表示名（キャラクターシートの名前 > `.nn` のニックネーム > QQ のニックネーム） |
| `{qqnick}` / `{card}` / `{pcname}` | QQ のニックネーム / グループ内の名前 / キャラクターシートの名前（囲みなし。`{qqnickw}` のように `w` を付けると囲みあり） |
| `{user}` | 反応させた人のアカウント |
| `{self}` | ボットの自称 |
| `{group}` | グループ番号 |
| `{date}` / `{time}` | 日付 / 時刻 |
| `{FormFeed}` | 強制的に改ページし、前後の内容を別々のメッセージに分ける。英字の大文字・小文字を区別せず、通常の改行ではない |
| `{$1}` `{$2}` … | 正規表現の捕捉グループ。前方一致の場合 `{$1}` = 接頭辞の後の内容、`{$0}` = メッセージ全体 |

元祖 Dice! 形式の旧変数名（`{pc}` など）も別名として使えるため、旧来の返信文をそのまま使えます。

たとえば `1 通目{FormFeed}2 通目` は 2 つの吹き出しで送られます。この目印はコマンドの文面、ペルソナ、デッキ、Lua mod のテンプレートでも使え、`sample:` の中に入れ子にもできます。明示的な改ページは、「長いメッセージを自動で分割」のスイッチやプラットフォームの自動分割の除外の影響を受けません。連続した、または先頭や末尾にある改ページで、空のメッセージが余分に送られることはありません。捕捉グループやニックネームに含まれる `{FormFeed}` はただの文章として扱い、再び実行されることはありません。

### 動的なコマンド

| 書き方 | 効果 |
|------|------|
| `{roll:3d6+2}` | ダイスの式を評価し、結果に置き換える |
| `{draw:塔罗牌}` | デッキから 1 枚引く |
| `{deck:塔罗牌}` / `{deck:%塔罗牌}` | ファイルのデッキを明示的に参照。前者はその返信内で戻さず、後者は戻す。グループの一時デッキに上書きされない |
| `{help:項目}` | ヘルプの項目を明示的に参照 |
| `{text:strHello}` | 旧版の CustomMsg から取り込んだグローバルな文面を明示的に参照 |
| `{a\|b\|c}` | 候補からランダムに 1 つ選ぶ |
| `{sample:甲\|乙}` | 旧版 Dice! のランダムな選択の構文で、等確率で 1 つ選ぶ。開発中で、この修正を含むバージョンが必要 |
| `{counter:名前}` | カウンターの現在値（因果ルールと組み合わせて使う） |
| `{api:URL}` | URL にリクエストし、返ってきた内容を返信に入れる |

旧データを取り込むと、あいまいさのない接頭辞なしの参照は上の明示的な接頭辞に正規化されます。`{デッキ}` / `{%デッキ}` はそれぞれ `{deck:デッキ}` / `{deck:%デッキ}` に変わり、戻す・戻さないのルールも保持されます。ヘルプとグローバルな文面はそれぞれ `help:`、`text:` に変わります。入れ子の `sample:` の各分岐も処理しますが、エスケープされた内容は書き換えず、取り込みの途中で実際にカードを引いたりダイスを振ったりすることもありません。

ダイスの式に見えるものは原文を残して確認待ちに記載します。文字の形だけでは評価が成功するとは限らず、旧来の接頭辞なしの式は失敗すると原文を残しますが、明示的な `roll:` は失敗すると `?` を表示するためです。意味を確認したうえで手動で `roll:` を付けられます。取り込みツールが勝手に失敗時の動作を変えることはありません。

同名の変数、複数の種類のリソースが同名の場合、見つからない参照は原文を残し、移行レポートに記載します。確認待ちの参照が残っている旧来の返信だけが、互換のために接頭辞なしのデッキの参照を保持するため、変数の意味がデッキに上書きされることはありません。新しく作る返信では明示的な接頭辞を使ってください。すでに取り込んだ旧来の返信も、元のデータから取り込み直せます。定義全体が同じ旧ルールはその場で更新され、重複して追加されることはなく、ダイスマスターが調整したオン・オフの状態と優先度も保持されます。

::: warning {api:URL} による外部へのリクエスト
`{api:}` はボットから外部の URL にリクエストを送らせるもので、**既定ではオフ** です。[基本設定](/ja/manage/settings)の「外部へのリクエスト」で有効にする必要があります。

安全のため、http/https のみを許可し、内部ネットワーク / ローカルのアドレスは自動で遮断します。設定ファイルでアクセスを許可するドメインの許可リスト（`dice.api_whitelist`）を設定できます。
:::

### 例

```
反応：天气
返信：今天{a|晴|多云|小雨}，记得带伞～

反応（正規表現）：^点歌 (.+)$
返信：已为你点播《{$1}》🎵

反応：今日运势
返信：{nick} 的运势：{draw:运势}
```

（天气 = 天気：「今日は {晴れ|曇り|小雨}、傘を忘れずに」、点歌 = 曲のリクエスト：「《{$1}》をリクエストしました」、今日运势 = 今日の運勢：「{nick} の運勢：{draw:運勢}」）

## 因果ルール（上級）

「因果ルール」は状態を持つ返信エンジンで、基本の返信に **条件の関門** と **アクションの連鎖** を加えたものです。視覚的なエディターで組み立てます。

因果ルールの正規表現の条件は基本の返信と同じで、メッセージ全体に一致する必要があります。たとえば `\d+` は数字だけのメッセージにしか一致しません。数字を含むメッセージに一致させたい場合は `.*\d+.*` と書きます。捕捉した変数は、実際に反応した条件から取ります。OR では一致した条件を、AND では最初の正規表現の条件を優先し、なければ最初の条件を使います。正規表現の条件では `{$0}` がメッセージ全体、`{$1}` などが捕捉グループです。前方一致の条件を捕捉元にした場合、`{$1}` は接頭辞の後の内容、`{$0}` はメッセージ全体です。捕捉したメッセージは文章として挿入するだけで、変数、デッキ、ダイスの式として再び実行されることはありません。

因果ルールは共有エンジンの長さの上限を引き継ぎます。式は 4096 UTF-8 バイト、入力は 64 KiB までで、実行時間とメモリの保護も引き続き有効です。

- **条件**：キーワード / 前方一致 / 正規表現 / 部分一致のほかに、ユーザーの絞り込み、グループの絞り込み、クールダウン（ユーザーごと / グループごと / 全体）、カウンターの判定（例：`チェックイン回数 ≥ 7`）を追加でき、複数の条件も AND / OR に対応します。
- **アクション**：返信を送る（複数からランダムも可）、カウンターの値の設定 / 加算 / リセット、API の呼び出し。
- **スコープ**：全体 / 指定したグループ / 指定したユーザー。優先度とオン・オフも設定できます。

「カウンター」タブと組み合わせると、チェックイン、回数制限付きの抽選、ポイントなどの遊びを作れます。カウンターの現在値は返信の中で `{counter:名前}` で参照できます。

## 画像の挿入

返信の内容には画像を入れられます。管理パネルで返信を編集するときに「画像を挿入」をクリックしてアップロードすると、画像はプラットフォームに依存しないコード `[img,file=<ローカルのパス>]` として保存され、送信時に各プラットフォームの画像メッセージに自動で変換されます。CQ コード / SealDice のコード（`[CQ:image,file=…]`、`[图片:…]`）を直接書くこともできます。

送信方法は システム設定 →「画像の送信方法」で選びます：**base64 で埋め込み**（既定。QQ のフレームワークがどの端末で動いていても届く）または **HTTP のリンク**（ホストを設定でき、QQ のフレームワークが動いている端末からアクセスできる必要がある）。
