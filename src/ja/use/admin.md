# グループ管理とシステム

グループの管理者とダイスマスター（Master）がボットの動作を制御するためのコマンドです。ほとんどの管理操作は [Web 管理パネル](/ja/manage/dashboard)でも行えます。

## ボットのオン・オフ

| コマンド | 説明 |
|------|------|
| `.bot` | バージョン / 状態を表示 |
| `.bot on` / `.bot off` | このグループでボットをオン / オフ（グループ管理者が必要） |
| `外置开` / `外置关` | 外部モード：内蔵のコマンドを止め、カスタム返信だけを残す |

`.bot` の情報にはヘッダー / フッターを設定できます（[基本設定](/ja/manage/settings)を参照）。

### グループごとの機能スイッチ

```text
.bot log on / off       → ログのコマンドと記録をオン / オフ
.bot reply on / off     → カスタム返信と因果ルールをオン / オフ
.bot roll on / off      → 内蔵のダイス、判定、イニシアチブ、技能の成長をオン / オフ
.bot plugin on / off    → プラグインのコマンド、メッセージのフック、ルールパックのコマンドをオン / オフ
.bot log                → ログ機能のスイッチを確認（ほかの 3 つも同様）
```

4 つの機能スイッチは既定でオンで、このグループの現在のボットアカウントにだけ適用され、変更にはグループ管理の権限が必要です。[グループ管理](/ja/manage/groups#機能の管理)でも操作できます。`on/off` を省略すると状態を確認でき、末尾にボットのアカウントを付けると対象を指定できます。サブスイッチをオンにしても、全体スイッチがオフのボットは起きず、完全な無効化やブラックリストも回避できません。もう一度 `.bot on` にしてもサブスイッチはリセットされません。

プラグインのスイッチは、各プラグイン自身のオン・オフの設定を変更しません。プラグイン内部でのダイスはプラグインのスイッチで制御し、内蔵のダイスのスイッチの対象にはなりません。キャラクターシートの管理やルールの選択など、ダイス以外の操作はダイスのスイッチの影響を受けません。`.bot reply` と `.reply on/off` は同じ設定を共有します。

現在のバージョンでは、`.bot off` はログの書き込みとタイマーを止めますが、ログのセッションは残します。「ログだけを記録する」場合は `.bot on` のままにして、[ログの説明](/ja/use/log#ログだけを記録する)に従って不要な機能をオフにしてください。初期のバージョンにあった、オフのときにも単独でログを記録する動作は、グループごとのスイッチの方式に置き換わりました。

### 現在のチャットを文章に切り替える `.bot text`

```text
.bot text              → 使い方と現在の状態を表示
.bot text plain        → 現在のグループまたは個人チャットで読みやすい文章だけを強制的に使う
.bot text rich         → ダイスマスターが設定した従来 / 標準 / 高度なビジュアルの方式に戻す
```

`plain` が止めるのは Markdown、カード、ネイティブのボタンなどのリッチメッセージの送信だけで、ペルソナの口調を書き換えたり、ダイスマスターが選んだ文面の方式を切り替えたりはしません。高度なビジュアル方式のステータスバーは `HP [██████░░░░] 6/10` のような文章に切り替わり、操作ボタンは `.r // ダイスのコマンド` と表示されるため、情報は欠けません。グループではグループの管理者、招待者、ダイスマスターが変更でき、個人チャットでは現在のユーザーと現在のアダプターにだけ影響します。

### 元祖の `.master` 互換の入口

ダイスマスターのみが使えます。管理者の追加・削除（旧来の `+アカウント/-アカウント` を含む）、clock、notice、censor、ブラックリストとホワイトリスト、リモートでの boton/botoff、dismiss など、対応済みの操作に対応し、Next の権限と設定の仕組みをそのまま使います。

これは任意のコマンドを実行するものではありません。旧版の reset/delete/groupclr など、互換になっていない操作ははっきりと知らせ、所有者を自動で書き換えたり設定を消したりはしません。定期的なプラグインのタスクの使い方は[定期タスク](/ja/manage/schedules)を参照してください。

## グループ設定 `.group`

```
.group                  → このグループの情報を表示（状態 / 記録 / 名前 / 観戦 / ブラックリストなど）
.group +禁用jrrp        → このグループで特定のコマンドを無効にする
.group -禁用jrrp        → 元に戻す
.group +禁用回复        → このグループのカスタム返信をオフにする
.group +禁用回复 -禁用help → 複数の項目を一度に調整
.group 123456 state     → 指定したグループを表示（対象のグループの権限を確認）
.group 123456 +禁用回复 → 指定したグループを調整
.group all +禁用回复    → 現在のボットアカウントのすべてのグループに一括で設定（ダイスマスターまたは信頼 5 以上）
.group clr              → 現在のアカウントのこのグループの機能設定をリセット
```

使えるグループの項目：`停用指令`（ボットの停止）、`禁用回复`（返信なし）、`禁用jrrp`、`禁用draw`、`禁用me`、`禁用help`、`禁用deck`、`禁用send`（それぞれのコマンドを無効化）。

指定したグループは個人チャットからも操作できます。現在のグループでの管理者の立場を、ほかのグループにそのまま使うことはできません。対象のグループが完全に無効化されている場合、これらのコマンドで解除することはできません。`clr` はほかのボットアカウントには影響せず、グループの身元の情報、強制ロック、終わっていないログを保持し、ログの内容も削除しません。旧来の共有設定がリセット後に再び有効になることもありません。`all` は符号（+/−）付きの項目だけを受け付け、一括での全消去には対応していません。

### グループの自動化 `.group auto`

効果を得るには、ボットがこのグループで **管理者以上の権限** を持っている必要があります。

```
.group auto                    → このグループの自動化の設定を表示
.group auto pass 暗号          → 参加の自動審査：認証メッセージに「暗号」（合言葉）が含まれていれば自動で承認（all = すべて承認）
.group auto kick 广告关键词    → 発言にキーワードを含む人を自動でグループから外す（广告关键词 = 広告のキーワード）
.group auto mute 刷屏词 10     → 発言にキーワードを含む人を 10 分間ミュート（刷屏词 = 連投の言葉）
```

キーワードを空欄にすると、その項目はオフになります。

## 観戦 `.ob`

```
.ob                     → ヘルプを表示
.ob join                → 観戦に加わる
.ob list                → 観戦者の一覧
.ob exit                → 観戦をやめる
.ob clr                 → グループ管理者またはセッションの GM が観戦者の名簿を空にする
.ob on / off            → このグループの観戦機能をオン / オフ（グループ管理者が必要）
```

## 参加時の歓迎 `.welcome`

```
.welcome 欢迎新人{at}   → グループ参加時の歓迎メッセージを設定（{at} などの変数に対応）
.welcome show / off     → 表示 / オフ
```

## グループからの退出 `.dismiss`

```
.dismiss                → ボットをこのグループから退出させる
```

グループのオーナー / 管理者 / 招待者 / 信頼の高いユーザーだけが使えます。ボットはまず退出のあいさつを送り、このグループのコマンドへの反応を止め、数十秒のランダムな待ち時間の後に実際に退出します（グループの記録は残り、「退出済み」として印が付きます）。

## メッセージのリンク `.link`

2 つのチャットのメッセージを互いに転送します（グループ間の連携 / 聴講。信頼レベル 3 以上が必要）。

```
.link with 12345678     → 対象のグループと双方向のリンクを作成
.link to / from グループ番号 → 一方向（このグループ → 対象 / 対象 → このグループ）
.link start / close     → このチャットのリンクを再開 / 一時停止
.link list / state      → すべてのリンク / このチャットの状態
```

## メッセージを残す `.send`

```
.send フィードバックの内容   → ダイスマスターにメッセージを残す
```

ダイスマスターは `.send group/user <id> <メッセージ>` で指定した相手に送れます。

## 言語 `.lang`

```
.lang                   → 返信の言語を表示 / 切り替え
.lang 简体 / 繁體 / en / 日本語 → このグループ（個人チャットでは自分）の返信の言語を切り替え
.lang clr               → 既定に戻す
```

詳しい説明（カスタム言語パックと AI 翻訳の言語を含む）は[ヘルプと言語](/ja/use/help)を参照してください。

## 権限の仕組み（信頼レベル）

Dice!Next は元祖の nTrust の権限の段階を移植しており、各ユーザーには 0–255 の **信頼レベル** があります。

| レベル | 意味 |
|------|------|
| 0 | 一般のユーザー |
| 1–3 | 信頼済みのユーザー（3 以上で `.link` などが使える） |
| 4 以上 | ボットの管理者（`.trust`、好感度の調整などが使える） |
| Master | ダイスマスター。最も高い権限 |

| コマンド | 説明 |
|------|------|
| `.trust @相手 / QQ番号 [レベル]` | 信頼レベルの確認 / 設定（管理者 4 以上が必要で、自分より低いレベルしか与えられない） |
| `.admin add/del <@/QQ>` | 管理者の付与 / 取り消し（ダイスマスターのみ） |
| `.admin list` | 管理者を一覧表示 |
| `.admin account-alias add <別名のID> <メインのID>` | 旧来のアカウントの権限の関連付けを作成：別名のアカウントの信頼 / Master の身分をメインのアカウントに基づいて計算（ダイスマスターのみ） |
| `.admin account-alias del <別名のID>` | 権限の関連付けを解除（ダイスマスターのみ） |
| `.admin account-alias list` | 権限の関連付けを一覧表示（ダイスマスターのみ） |

`.alias` は現在 [SealDice 形式のショートカット](/ja/use/fun#ショートカット-alias)に使われ、旧来のアカウントの権限の関連付けは `.admin account-alias` に移りました。既存の `dice/aliases` の設定は引き続き有効で、入力し直す必要はありません。これは権限を共有するだけで、キャラクターシートやニックネームなどのデータは統合せず、自動で `.bind` に変換されることもありません。プラットフォームをまたぐ本人確認とデータの統合には、引き続き[本人確認の紐付け](/ja/use/cloud)を使います。

## 禁止語の管理

ダイスマスターのみが使えます。WebUI の **システム設定 → セキュリティと権限 → 禁止語のフィルター** は、これらのコマンドと同じ設定を読み書きします。

```text
.admin censor status
.admin censor on
.admin censor off
.admin censor +=既定の Warning で追加
.admin censor +Danger=語0|語1
.admin censor -語0|語1
```

使えるレベルは `Ignore`、`Notice`、`Caution`、`Warning`（省略時の既定）、`Danger`、`Critical` です。`Critical` は旧データとの互換のためのもので、最も高いリスクとして扱います。チャットでの返信や通知でルールの原文を繰り返すことはなく、同じ機密な内容を再びプラットフォームへ送らないようにしています。

## ダイスマスターへの通知 `.notice`

現在のチャット（グループまたは個人チャット）をダイスマスターの通知ウィンドウにし、メッセージ、承認、実行時のエラーなどのイベントを受け取ります（ダイスマスターのみ）。

```
.notice on / off        → このチャットの通知をオン / オフ
.notice level 15        → 購読するレベルのマスクを設定（1 日常 / 2 重要 / 4 重大 / 8 エラー。足し合わせ可能、15 = すべて）
```

通知するイベントの個別の選択や、SMTP メール / Webhook による外部への送信は、Web 管理パネルの「通知設定」ページで設定します。

## ダイスマスター（Master）のコマンド

ダイスマスターは複数のグループとブラックリスト・ホワイトリストをリモートで管理できます。

| コマンド | 説明 |
|------|------|
| `boton` / `botoff [グループ番号]` | 指定したグループをリモートでオン・オフ |
| `blackqq [-]<id>` | ユーザーをブラックリストに登録 / 解除（接頭辞 `-` で解除、引数なしで一覧） |
| `blackgroup` / `whitegroup` | ブラックリストのグループ / ホワイトリストのグループ |
| `whiteqq` | 信頼済みのユーザー |

ダイスマスター以外がこれらのコマンドを使うと、丁寧に断られます。ダイスマスターは[基本設定](/ja/manage/settings)で設定します。

### システム情報 `.system`

```
.system info       → システム情報（OS、CPU、メモリ、このプロセスのメモリ）
.system stats      → 動作の統計（稼働時間、コマンド数、友だち / グループ / プレイヤー / 記録の数）
```

::: warning リモートシェルには対応しません
旧版の `.system cmd` は復活させていません。チャットのメッセージを OS のコマンドの入口にすべきではありません。システムの保守は、ホストの端末や管理された環境で行ってください。
:::

## 元祖の管理の互換の入口

以下の入口は Dice!Next の統合されたプレイヤーのプロフィール、権限、ブラックリストをそのまま使い、旧データを別に作ることはしません。

| コマンド | 動作 |
|------|------|
| `.user state` | 自分の信頼、コマンドの統計、プロフィールの作成日時、シートの数を表示 |
| `.user trust <@/ID> [レベル]` | 統合された `.trust` の確認 / 設定の処理に回す |
| `.user tojson [@/ID]` | プレイヤーのプロフィールとシートの索引を出力。他人のものを出力するには管理者の権限が必要 |
| `.user diss <@/ID> [理由]` | 管理者が対象をローカルのブラックリストに入れる |

`.user diss` はプレイヤーのプロフィールとキャラクターシートを保持するため、リストから外した後も引き続き使えます。旧版の `.user kill` / `.user clr` のような元に戻せない削除は、Web 管理パネルで確認したうえでしか実行できません。

旧版の `.cloud update` と `.cloud black` は提供しなくなりました。元祖でもこの 2 つは状態を報告して Web ページへ案内するだけでした。バージョン番号は引数なしの `.bot` で確認し、クラウドブラックリストのスイッチは Web の「システム設定」にあります。`.cloud` は現在、アカウントセンターの認可とクラウドのキャラクターシートの入口です。[クラウドと本人確認](/ja/use/cloud)を参照してください。

## ボットの名前 `.strSelfName` / `.strSelfCall`

ボットの対外的な名前と自称を設定します。システムレベルの設定です（ダイスマスター）。返信文の `{self}` は「自称 → 名前 → アダプターのログイン時のニックネーム → 骰娘（ダイス娘）」の順に値を取ります。

```
.strSelfName 小海   → ボットの名前を「小海」にする
.strSelfCall 本喵   → 自称を設定（{self} は自称を優先）
.strSelfName        → 現在の値を表示。reset または NULL を付けるとリセット
```

## 旧版の文面のコマンド `.strXXX`

ダイスマスターは、1 対 1 の対応を確認済みの元祖の文面キーを引き続き使えます。

```
.strRollDice show       → 現在の言語で対応付けられたダイスの文面を表示
.strRollDice 新しい文面  → 統合された文面の上書き表に書き込む
.strRollDice reset      → 上書きを削除し、Dice!Next の既定の文面に戻す
.strRollDice NULL       → 上書きを残したまま文面を空にする
```

受け付けるのは、本当に同じ意味の対応先があり、テンプレートの引数も互換の旧キーだけです。不明な `.str…` は互換層に握りつぶされず、ほかのコマンドやプラグインで処理できます。一括の編集、無効な旧キーの確認、ペルソナの文面には[管理パネル → コマンド一覧](/ja/manage/commands)を使ってください。

## プラットフォームをまたぐ本人確認の紐付け `.bind` / `.info`

同じ人でも、QQ 公式、Discord、KOOK、OneBot / Milky のチャットでは識別子が異なります。`.bind` は本物の QQ に関連付け、`.info` は身元の情報を表示します。入力は `.bind qq <QQ番号>` だけで十分です。現在のクライアントに正式なボットのキーがあれば OAuth を優先し、なければダイスマスターが設定した SMTP のメール確認を自動で使います。アイコンによる確認は廃止されました。

```
.info                → 現在のチャットの種類、正規の識別子、業務上の番号、紐付け済みの接続先を表示
.bind qq <本物の QQ 番号>    → QQ 公式 / Discord / KOOK の個人チャットで開始。確認方法は自動で選択
.bind confirm        → OAuth：Web ページで同意した後、元の個人チャットに戻って確認
.bind confirm <8 桁の確認コード> → メール：元の個人チャットで確認コードを送信。QQ の再入力は不要
.bind qq <本物の QQ 番号> email → メールを自分で選ぶ・切り替える。SMTP を有効にしている必要がある
.bind qq QQ-Official-<ボット ID>:<OpenID> → OneBot / Milky のチャットで逆方向に紐付け
.bind qqgroup QQ-Official-<ボット ID>:<グループの OpenID> → 対象の本物の QQ グループ内でオーナーか管理者が実行
.bind discord <ユーザー ID> / .bind kook <ユーザー ID> → OneBot / Milky のチャットでプラットフォームのユーザーを逆方向に紐付け
.cloud auth [write] / .cloud confirm → クラウドのキャラクターシートを個別に認可。紐付けの前提の手順ではない
```

紐付けた後は、OneBot に接続していなくても本物の QQ の身元が保持され、チャットをまたいでキャラクターシートや権限などを統一できます。詳しい設定と制限は[クラウドと本人確認](/ja/use/cloud#qq-メールの確認コード)を参照してください。メールでの確認ではグループの所有を証明できません。

OAuth で確認済みの QQ は申請した番号と一致している必要があり、失敗しても自動でメールを送ることはありません。旧来の `.bind email <QQ>` と `.bind qq <QQ> <確認コード>` は互換のためだけに残しています。

## 全体の設定（ダイスマスター）

[基本設定](/ja/manage/settings) →「元祖のグローバル設定」でまとめて設定できます。

- 全体のサイレント、全体での `.jrrp` / `.me` / `.deck` / `.draw` / `.send` などの無効化
- イベントへの反応のスイッチ（グループ参加の申請 / 参加時の反応 / 友だち申請 / 友だちの追加 / ブラックリストによるグループからの退出 / キックされたときの自動ブラックリスト登録 / ミュートされたときの自動ブラックリスト登録と退出）
- デッキの `_` で始まるメタデータのキーの非表示
- 活動のないグループから自動で退出するまでの日数、1 回あたりの整理の上限などの自動保守の項目
- 外部へのリクエスト `{api:}` のスイッチとタイムアウト

友だち / グループ招待の **承認のポリシー**（キーワードの合言葉、友だちではない人からの招待の拒否、強制的に追加されたグループからの退出、グループ名のキーワードによる自動退出、ブラックリストのグループからの自動退出など）もシステム設定で設定します。詳しくは[管理パネル](/ja/manage/settings)を参照してください。

## 定期タスク

[Web 管理パネル → 定期タスク](/ja/manage/schedules)で、毎日決まった時刻にグループ / 個人チャットへメッセージを送る（朝のあいさつ、セッションの案内など）ように設定できます。条件による実行（グループで何日活動がないかなど）や、退出などのアクションにも対応しています。決まった時刻にそれぞれの宛先へ送るもので、一斉送信ではありません。
