# セッションログ

Dice!Next はグループでのセッションの流れを記録できます。終了時にはログを整理してログサイトにアップロードし、グループファイルとしても送るため、振り返りや保管に便利です。

## コマンド一覧

| コマンド | 説明 |
|------|------|
| `.log new [名前]` | 新しく作成して記録を始める |
| `.log on` / `.log off` | 記録を再開 / 一時停止 |
| `.log end` | 記録を終了し、アップロードしてリンクを取得し、グループファイルを送る |
| `.log halt` | 今回の記録を強制終了（アップロードしない） |
| `.log list [ページ]` | このグループのログの一覧（ページ分け） |
| `.log get [名前]` | ログをもう一度アップロードしてリプレイのリンクを取得 |
| `.log del <名前>` | ログを削除 |
| `.log stat [名前]` | 統計（件数 / 参加者 / 時間帯 / 発言が最も多い人） |
| `.log export [名前]` | ログをグループファイルとしてだけ送る（ログサイトにはアップロードしない） |
| `.log type txt/html` | グループファイルの形式を設定（グループ管理者以上） |
| `.log time` / `.log timer` | セッションのタイマー |
| `.log masterget <グループ番号> [名前]` | ダイスマスターがほかのグループのログのリンクを取得 |
| `.log` | 現在の記録の状態を表示 |

名前を省略したサブコマンドは、このグループの最新のログを対象にします。

## 使い方の流れ

```
.log new 第一章     → 記録を開始（第一章 = 第 1 章）
…通常どおりセッション…
.log off            → 途中で一時停止（休憩）
.log on             → 戻って再開（返信で一時停止した位置のメッセージを引用するので場所がわかりやすい）
.log end            → 終了し、アップロードしてグループファイルを送る
```

1 つのグループで同時に記録できるログは 1 つだけです。セッションがうまくいかず記録を残したくない場合は、`.log halt` でそのまま打ち切れます。

## 記録される内容

記録するかどうかは、**グループの全体スイッチ、ログ機能のスイッチ、ログのセッションの状態** の組み合わせで決まります。`.bot off` または `.bot log off` は記録とタイマーを止めますが、セッションは残します。再びオンにすると、記録中だったログは記録を続けますが、`.log off` で手動で一時停止したログは自動では再開しません。オフのあいだのメッセージが後から補われることはなく、完全な無効化やブラックリストなどの制限も引き続き有効です。

- 発言、ダイスの結果、画像のアドレスを保持します。[ログの画像の保存](/ja/manage/settings#画像に関する設定)を有効にすると、画像をローカルにキャッシュし、HTML の出力時に埋め込めます。
- 終了時に自動でログサイトへアップロードし、共有できるリプレイのリンクを返します。同時にログを **グループファイル** として送ります。
- グループファイルの形式は `.log type` で決まります：`txt` のテキスト（既定）か、`html` の単体で完結した Web ページ（画像を埋め込み、オフラインでそのまま開けます）です。

### QQ 公式の SN 状態行

QQ 公式の返信の先頭に出る `.sn` の状態行は、グループ内の名前の代わりの表示にすぎず、すべての返信で繰り返されるため、**セッションログには書き込みません**。ログに記録するのは返信の本文だけです。チャットウィンドウと `.link` の転送では、引き続き返信全体を表示します。

### QQ 公式のスタンプ

- カスタムのスタンプは画像として公式の添付ファイルのアドレスを記録し、TXT、CSV、ログサイトへのアップロードでの画像の参照には標準の CQ コード（例：`[CQ:image,file=https://…]`）を使います。
- QQ 内蔵の絵文字は、文章の記録では `[表情]`（絵文字）と表示し、今のところ絵文字の ID から名前を推測することはしません。
- 古い記録の `<faceType=…>` の目印は出力時に互換のために変換します。カスタムのスタンプは、記録に画像のアドレスが残っている場合にだけ元の画像に戻せ、アドレスのないものは `[图片]`（画像）と表示します。
- ログサイトで「スタンプ画像のフィルター」を有効にすると、旧来の `<faceType=…>` の目印とその HTML エスケープした形も取り除きます。フィルターを無効にすると原文を残します。

## ログだけを記録する

グループの管理者が機能のスイッチを設定してから、通常のログの権限で記録を始めます。

```text
.bot on
.bot log on
.bot roll off
.bot reply off
.bot plugin off
.log new 第一章
```

その後は `.log off/on` で一時停止・再開し、`.log end` で終了します。通常の使い方に戻すときは、必要に応じて `roll`、`reply`、`plugin` を再びオンにしてください。AI、歓迎メッセージ、転送、自動化にはそれぞれ別のスイッチがあるため、不要であればそれらもオフにしてください。上の設定で、すべての管理や娯楽のコマンドが無効になるわけではありません。

## セッションのタイマー

```
.log timer on/off   → このグループのセッションのタイマーをオン / オフ
.log time           → 現在の記録の累計時間を表示
```

有効にすると、`.log new/on/off/end` で今回のセッションの時間を自動で開始 / 一時停止 / 累計します。

## ログサイトへのアップロード

- 既定では公式のログサイト `log-api.dice.zone` にアップロードし、既定で **DiceNext 専用の zstd JSON プロトコル** を使います。既存のインストールでは、以前に保存したプロトコルの選択を保持します。
- アドレスとプロトコルは[システム設定 → クラウドサービス → ログサイト](/ja/manage/cloud-services#ログサイト)で変更します。`dice/logsite_format` には `dicenext`（既定）、`seal`（SealDice V1）、`seal_v105`（Parquet）、`legacy`（旧版の複数に分けた txt の POST）を指定できます。自前のサイトに接続する場合は、そのサイトが対応するプロトコルを選んでください。
- アップロード先が **公式サイトではない** 場合、返信のリンクに「設定されているログサイトは公式サイトではありません。リンクの安全性はご自身で確認してください」という注意が付きます。

## Web での管理

### プラットフォームごとのファイル送信の違い

`.log export` はファイルを出力するだけで、ログサイトにはアップロードしません。OneBot / Milky のグループファイルの機能は、接続しているプロトコルクライアントによります。QQ 公式ボットはリッチメディアのファイル送信に対応していますが、ファイルの送信は引き続きアカウントの権限、プラットフォームの制限、アップロードの結果に左右されるため、ローカルでの出力の成功をプラットフォームがファイルを受け取ったこととは見なせません。

プラットフォームに拒否された場合やファイルが届かない場合は、`.log get` でアップロードしてリプレイのリンクを取得するか、下の Web での管理からダウンロードしてください。QQ 公式の API への接続と、実際の認証情報での端から端までの確認は別のものです。詳しくは[アダプター設定](/ja/config/adapter#qq-公式ボットでできることの範囲)を参照してください。

### パネルでのダウンロードと管理

Web 管理パネルの **データ管理 → セッションログ → ログ管理** では、次のことができます。

- すべてのグループの過去の記録（名前 / 作成者 / 開始と終了の時刻 / 件数 / 使用容量）を表示し、任意の列で並べ替え
- 使用容量には、ログのデータベースに実際に保存されている内容と、`data/logs/images` にあるそのログのローカルの画像が含まれます。画像の容量は別に表示します
- TXT または Excel（CSV）で出力し、HTML の Web 版をダウンロード
- 手動でログサイトにアップロードしてリンクを取得したり、確認ダイアログのうえで記録を削除したりできます。削除するとログのメッセージとローカルにキャッシュした画像もまとめて消去します

パネルのグループ管理には **グループファイルの表示とダウンロード** もあり、セッションで送ったログのグループファイルもここから直接取り出せます。
