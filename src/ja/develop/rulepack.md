# ルールパックの作成

ルールパック（Rule Pack）は、Dice!Next が **ルール、ヘルプ文書、プラグイン** を、**まとめてインストール / 有効化・無効化 / 削除できる** 1 つの単位にまとめたものです。ダイスマスターが管理画面で zip をアップロードし、プレイヤーがグループで `.set` で有効にすると、ルール一式がそのグループで有効になります。

> ひとことで言うと：**1 つの zip = 1 つのフォルダー + 1 つの `pack.json` のマニフェスト + フォルダーごとに置いたリソース** です。設定より規約を重視しており、対応するサブフォルダーにファイルを置くだけでシステムが自動で見つけるため、ファイルの一覧を手で書く必要はありません。

---

## 1. フォルダーの構成

```
自分のルールパック/
├── pack.json          ← 必須：パックのメタデータ（名前 / バージョン / 作者 / 有効化のキー）
├── rules/             ← ルールのファイル（能力値の別名 / 既定のダイス / カスタムコマンド / ヘルプ）
│   └── xxx.json
├── helpdoc/           ← ヘルプの早見（項目→内容。.help で検索できる）
│   └── xxx.json
├── lua/               ← Lua プラグイン（元祖 Dice! の mod。フォルダーまたは単一ファイル）
│   ├── あるモジュール/
│   └── ある単一ファイル.lua
└── js/                ← JS プラグイン（SealDice 互換）
    └── あるプラグイン.js
```

サブフォルダーはどれも **任意** です。`rules/` だけ（宣言だけのルール）、`lua/` だけ（プラグインだけのルール）、または任意の組み合わせにできます。フォルダー全体を **zip** にまとめれば配布できます。

::: tip まとめて入れる・外す
パックの削除 / 無効化 = このフォルダーの削除 / 名前の変更です（管理画面でワンクリックで行えます）。パック内のすべてのリソースがあわせて登録・解除され、残骸は残りません。
:::

## 2. `pack.json`（マニフェスト）

メタデータだけを書き、ファイルを 1 つずつ並べる **必要はありません**。

```json
{
  "name": "自分のクトゥルフ拡張",
  "id": "my-coc-extension",
  "version": "1.0.0",
  "author": "山田太郎 (QQ:12345678)",
  "description": "ルールのページのカードに表示する一言の紹介",
  "setKeys": ["mycoc"]
}
```

| 項目 | 説明 |
| --- | --- |
| `name` | パックの表示名 |
| `id` | 任意の安定したフォルダーの識別子。安全なファイル名の文字だけを使える。省略すると zip のファイル名か、唯一のルートフォルダーの名前を使う |
| `version` | バージョン番号（`1.0.0` など） |
| `author` | **作者**。他人の作品を変換するときは **必ず元の作者を残す** |
| `description` | 紹介 |
| `setKeys` | 有効化のキーの配列。プレイヤーは `.set <key>` で有効にする。例：`["mycoc"]` → `.set mycoc` |

> パック内の `rules/*.json` が自分で `set.keys` を宣言している場合、`setKeys` は省略できます（ルールの有効化のキーを自動で使います）。

::: warning 取り込みと更新
取り込みには有効な `pack.json` が必要です。システムはまず ZIP のパス、ファイル数、展開後のサイズを確認し、パストラバーサル、シンボリックリンク、異常な圧縮ファイルを拒否します。同じ `id`（またはフォルダーの識別子）のルールパックが黙って上書きされることはなく、既存のルールと重複する `.set` の有効化のキー、JS のファイル名、Lua の mod 名もはっきり拒否します。更新する前に古いパックを削除してください。取り込み、有効化・無効化、削除でホットリロードに失敗した場合は、ファイルの操作を自動で元に戻します。
:::

## 3. `rules/`：ルールのファイル

ルールのファイルは通常の JSON で、このルールシステムの能力値、コマンド、既定のダイスなどを定義します。有効にすると **内蔵のコマンドより優先** され、同じ名前のヘルプの項目も内蔵のものを上書きします。

```json
{
  "name": "自分のクトゥルフ拡張",
  "id": "my-coc-extension",
  "set": {
    "keys": ["mycoc"],
    "diceSides": 100
  },
  "alias": {
    "侦查": ["侦察", "观察", "spot"],
    "力量": ["str", "STR"]
  },
  "computed": {
    "理智上限": "99 - 克苏鲁神话"
  },
  "commands": {
    "disable": ["jrrp"],
    "alias": { "检定": "ra" },
    "add": {
      "稳定": {
        "output": "{nick} が安定の判定を行う：1d100={1d100}",
        "help": ".稳定 —— 安定の判定を 1 回行う"
      }
    }
  },
  "help": {
    "本规则": "これは自分のクトゥルフ拡張で、次の内容を含みます……"
  }
}
```

| ブロック | 役割 |
| --- | --- |
| `set.keys` | 有効化のキー。`set.diceSides` は有効にした後のこのグループの既定のダイスの面数 |
| `alias` | **能力値の同義語**：`正式な名前 → [別名…]`。`.st 侦察50`、`.ra 观察` のどちらも「侦查」（目星）として認識させる |
| `computed` | **派生する能力値**：ほかの能力値から式で計算する（正気度の上限など） |
| `commands.disable` | 内蔵のコマンドを遮断（有効にしたグループでは、これらのコマンドは何も返さない） |
| `commands.alias` | コマンドの別名：`入力する言葉 → 対象のコマンド`（`.检定` で `.ra` を実行） |
| `commands.add` | **カスタムコマンド**（DSL。下記参照）。値は文字列（出力テンプレート）か `{output, help}` のオブジェクト |
| `help` | パック単位のヘルプ：`トピック → 文章`。`.help <トピック>` で調べられる |

### カスタムコマンドの式（DSL）

`commands.add` の `output` テンプレートでは、`{…}` が評価されます。

| 書き方 | 意味 |
| --- | --- |
| `{nick}` `{user}` `{group}` `{self}` `{date}` `{time}` | ニックネーム / QQ 番号 / グループ番号 / ボットの自称 / 日付 / 時刻 |
| `{1d100}` `{3d6+2}` | ダイスを振る（1 つのコマンドの中で同じ式は 1 回だけ振る） |
| `{力量}` `{侦查}` | 送信者のキャラクターシートの能力値の値を取る |
| `{arg}` | コマンドの後ろに続く引数 |
| 四則演算 / 比較 / 三項 | `{力量 + 5}`、`{1d100 <= 侦查}`、`{1d100<=侦查 ? "成功" : "失敗"}` |
| `min/max/abs` | `{max(力量, 敏捷)}`、`{abs(hp - 10)}` |

能力値がない場合や関数が不明な場合、このコマンドはエラーではなく失敗の案内を返します。

::: warning 現在の能力値の対応付けの範囲の制限
パック内のカスタムコマンド、遮断の項目、Lua/JS プラグインはグループごとに有効になります。ただし、`alias`、`computed`、`defaults`、`derived` は現在も、プロセス全体の互換の登録先に入ります。複数のルールパックで、互いに矛盾する能力値の別名や既定値を宣言しないでください。これらの能力値の対応付けを完全なグループ単位の範囲にすることは、今後のリファクタリングの計画に入っています。
:::

## 4. `helpdoc/`：ヘルプの早見

構造化されたヘルプ文書で、**SealDice と互換** の形式です。1 つのファイルに複数の項目を入れられます。

```json
{
  "mod": "克苏鲁术语表",
  "author": "山田太郎",
  "brief": "よく使う用語の早見",
  "helpdoc": {
    "百分骰": "1d100 を振る。ほとんどの判定に使う。",
    "理智": "探索者の精神の安定度。0 になると永久的に狂気に陥る。",
    "SAN": "&理智"
  }
}
```

- キー = 項目名、値 = 内容です。プレイヤーは `.help <項目>` で調べます。
- 値が `&` で始まるものは **別名** です（`"SAN": "&理智"` は SAN が「理智」（正気度）を指すという意味）。
- SealDice の `.xlsx` の表形式のヘルプ文書は、`tools/convert_helpdoc.py` でこの形式に変換できます（下記参照）。

このパックを有効にしたグループでは、パック内の同じ名前の項目が内蔵 / ほかの出所より **優先** されます。

::: tip 3 つの「ヘルプ/早見」の入口の使い分け
ルールパックには似たものが 3 つあり、役割が異なります。

| 入口 | プレイヤーの調べ方 | 向いている内容 |
| --- | --- | --- |
| `helpdoc/` フォルダー（この節） | `.help <項目>` | 用語、技能、呪文などの **大量の早見の項目**。第一の選択肢 |
| `rules/*.json` の `help` ブロック | `.help <項目>` | あるカスタムコマンドに強く関係する **少量の説明** |
| `rules/*.json` の `entries` ブロック | `.rules <項目>` | 現在は **単独で置いたルールのファイルでだけ有効** で、ルールパックのバンドルではまだ接続されていません。今は使わないでください |

迷ったら `helpdoc/` にまとめてください。
:::

::: warning シートのテンプレートはまだパックで配布できません
`.pc build` で使うキャラクターシートのテンプレート（`card-templates/*.json`）は、現在ボットのローカルの `card-templates/` と `data/card-templates/` フォルダーからしか読み込まないため、**ルールパックの zip に入れても有効になりません**。また、変更後はボットの再起動が必要です。シートのテンプレートを配布したい場合は、ファイルを `data/card-templates/` に手動で置くようユーザーに案内してください。
:::

## 5. `lua/` と `js/`：プラグイン

複雑な処理（ネットワーク、状態の管理、複雑な判定）はプラグインに入れます。

- `lua/`：元祖 Dice! の Lua mod です。**フォルダー**（`reply/` の因果の返信、`script/`、`speech/` などを含む）でも、**単一の `.lua` ファイル**（`msg_order` で振り分け）でも構いません。
- `js/`：SealDice 互換の `.js` プラグインです。

::: warning パック内のプラグインは「グループごとに有効」になります
パック内のプラグインのコマンドは **既定では動きません**。`.set <key>` でこのパックを有効にしたグループでだけ反応します（ほかのグループや個人チャットには影響しません）。これが「グループ単位のルールの上書き」の要です。
:::

> プラグインを **全体で有効** にしたい（ルールの有効化に関係なくすべてのグループで使える）場合は、それはルールパックの一部ではありません。「拡張管理」で個別にアップロードしてください。

## 6. 有効化と優先順位

1. ダイスマスターが管理画面の「ルール」ページで **zip をアップロード** → 検証した後に `data/rulepacks/<id>/` にインストールします。ページには親のルールパックのカードが 1 つだけ表示され、ルール、ヘルプ、Lua、JS の子の項目は「パックの内容を表示」でまとめて確認でき、個別に編集できる重複した項目としてばらばらに表示されることはありません。
2. グループの管理者がグループで `.set <有効化のキー>`（例：`.set mycoc`）を送る → このグループのルールシステムが切り替わります。
3. `.set list` で使えるすべてのルールシステムを一覧表示し、`★` がこのグループで現在有効なものを示します。
4. 有効にすると、そのグループでは次のようになります。
   - パックの **カスタムコマンド / 別名 / 既定のダイス / 能力値の対応付け** が有効になり、**内蔵のコマンドより優先** されます。
   - パック内の **プラグインのコマンド** が有効になります。
   - パックの **同じ名前のヘルプの項目** が内蔵のものより優先されます。
5. 有効にしていないほかのグループでは、このパックのカスタムコマンドやプラグインは実行されません。能力値の対応付けの現在の制限は、上の注意を参照してください。

## 7. 既存の mod / プラグインをルールパックに変換する

既存の元祖 Dice! の Lua mod、単一ファイルの Lua/JS プラグインは、どれもルールパックに包めます。**変換するときは必ず元の作者の情報を残してください**（作者を尊重し、出所をたどれるようにするため）。

### スクリプトを使う（Lua mod / 単一ファイル）

```bash
python tools/convert_mod_to_pack.py <mod のパス> [有効化のキー] [出力先のフォルダー]
# 例：メイド RPG のルールの mod を、有効化のキー maid のルールパックに変換
python tools/convert_mod_to_pack.py server/data/mod/Maid-TRPG maid
```

スクリプトは次のことを行います。
- mod の `descriptor.json` / `<name>.json` から **name / author / version / brief** を読み取り、`pack.json` に書き込みます（**作者はそのまま保持**）。
- mod のフォルダーをそのまま `lua/` に入れます。
- descriptor に `helpdoc` があれば、`helpdoc/<name>.json` に抜き出します。
- 有効化のキーを自動で生成します（または指定したものを使います）。

生成した `pack.json` には、出所を示す `"convertedFrom"` の項目が付きます。変換したら zip にまとめれば配布できます。

### SealDice の Excel のヘルプ文書の変換

```bash
python tools/convert_helpdoc.py <元のフォルダー> <出力先のフォルダー>
```

SealDice の `.xlsx`（列は `Key | Synonym | Content | Description`）と `.json` のヘルプ文書をまとめてこの形式に変換し、パックの `helpdoc/` に入れます。

### 手動での変換

「フォルダーの構成」に従ってフォルダーを作り、`pack.json` を書き（**元の作者を記入**）、プラグインのファイルを `lua/` または `js/` に、ヘルプを `helpdoc/` に入れて zip にまとめます。

::: tip 能力値のテンプレートとルールブックについて（旧版の mod との互換）
- `model/*.xml` の `<any name='力量' alias='STR/str'>` のような **能力値の別名は自動で** `.st`/`.ra` **に統合** されるため、`.st STR50`、`.ra DEX` でそのルールシステムの能力値の名前をそのまま認識し、手で書く必要はありません。
- `rulebook/*.yaml`（`{rule, manual:{用語:説明}}`。COC の呪文/武器/神話、DND の呪文/モンスター/アイテム、メイド RPG のマニュアルなど）の項目は **自動で** `.help` **に統合** され、`.help 弓箭`（弓矢）、`.help 深层魔法`（深層魔法）でそのまま早見が出ます。
- `speech/*.yaml` のテンプレートの項目は通常どおり有効です。
- `model/*.xml` の `text='javascript'`/`text='dicexp'` の **単純な算術による派生 / 既定値**（`闪避 = 敏捷/2`、`生命 = (体质+体型)/10`、`理智 = 意志` など）は **自動で計算されて保存** されます。明示的に `.st` していない能力値を読むと式で計算し、新しい COC のシートで `.st` で基本の能力値を設定すると、HP/SAN/MP を自動で入れてシートの要約を付けます（設定ページで「自動のシート」をオフにできます）。
- **JS プラグインのルール**：`seal.gameSystem.newTemplate(ByYaml)` の `alias`（能力値の別名）と `defaultsComputed`（単純な算術による派生）も自動で `.st`/`.ra` に統合されるため、SealDice の JS の独自ルールシステムの能力値の名前をそのまま使えます。
- 複雑な式（条件 / 文字列 / `Math.max` / `$` の一時的な変数を含むもの）**だけ** はまだ変換しないため、`rules/*.json` の `computed` ブロックで自分で宣言してください。
:::

## 8. 最小限の完全な例

```
ポケットルール/
├── pack.json
├── rules/pocket.json
└── helpdoc/pocket.json
```

`pack.json`
```json
{ "name": "ポケットルール", "version": "1.0.0", "author": "あなたの名前", "setKeys": ["pocket"] }
```

`rules/pocket.json`
```json
{
  "name": "ポケットルール",
  "set": { "keys": ["pocket"], "diceSides": 100 },
  "commands": { "add": { "运势": { "output": "{nick} の今日の運勢：{1d100}/100", "help": ".运势 —— 今日の運勢を見る" } } },
  "help": { "ポケットルール": "最小限の例のルールパック。" }
}
```

`helpdoc/pocket.json`
```json
{ "mod": "ポケット早見", "author": "あなたの名前", "helpdoc": { "运势": "1d100 を振って今日の運勢を見る。" } }
```

パッケージの作成：`ポケットルール/` を `ポケットルール.zip` に圧縮 → 管理画面の「ルール」ページでアップロード → グループで `.set pocket` → `.运势` が使え、`.help 运势` で早見が出ます。

## 9. まとめ

| やりたいこと | 置き場所 |
| --- | --- |
| 能力値の同義語 / 既定のダイス / 派生する能力値 | `rules/*.json` の `alias` / `set` / `computed` |
| 簡単なカスタムコマンド（テンプレート + ダイス + 能力値） | `rules/*.json` の `commands.add`（DSL） |
| 内蔵のコマンドの遮断 / 名前の変更 | `rules/*.json` の `commands.disable` / `alias` |
| 早見の項目 | `helpdoc/*.json` |
| 複雑な処理（ネットワーク / 状態 / 複雑な判定） | `lua/` または `js/` のプラグイン |
| メタデータ（名前 / 作者 / 有効化のキー） | `pack.json` |
