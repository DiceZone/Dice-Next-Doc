# Lua mod リファレンス

Dice!Next は原版 Dice! の Lua mod と単一ファイルのプラグインとの互換を保ち続けています。2026-10-15 のローカルの実装で TOML、条件、イベント、入れ子のモジュール、安全な数値のテンプレートを拡張しましたが、今回のインストーラーにはまだ含まれていません。コミュニティの資料の一部で検証していますが、それによって任意の古い mod が完全に動くとは言えません。移植の前に、このページの最後にある境界と使っているバージョンを確認してください。

::: tip 新しいプラグインは JS がおすすめ
Lua の仕組みの位置づけは **原版の生態系を引き継ぐこと** です。一から新しいプラグインを書くなら [JS プラグイン](/ja/develop/plugin-quickstart)をおすすめします。API がよりモダンで、設定項目や保存領域の管理などのパネルとの連携もより充実しています。
:::

## mod の 3 つの形

| 形 | 場所 | 説明 |
| --- | --- | --- |
| 記述ファイル + フォルダー（原版の標準の形） | `data/mod/<名前>.json` + `data/mod/<名前>/` | 対で存在する。`<名前>.json` は登録用のファイル（メタデータ + helpdoc + speech）で、フォルダーにリソースを置く |
| 記述ファイルだけ | `data/mod/<名前>.json` | 照会系の mod（COC の技能の照会のような helpdoc だけのパック）は json が 1 つだけ |
| 単一ファイルのプラグイン | `data/plugin/<名前>.lua` | `msg_order` の接頭辞のコマンドのプラグイン |

**アップロード**：管理パネルの「プラグイン管理」→「プラグインをアップロード」で、`.lua`、`.json`、`.zip` に対応します。zip は自動で展開して配置します。json とフォルダーの対のパック、複数の mod をまとめたライブラリ全体の圧縮ファイル、`model/`/`rulebook/` だけを含むルール系のパックのいずれも認識します。**無効化/削除** はパネルで管理します。無効化は名前に `.disabled` の接尾辞を付ける操作（json とフォルダーは対で扱う）で、削除は記述ファイルとフォルダーをまとめて消します。

## 記述ファイル（`<名前>.json` / `descriptor.json`）

```json
{
  "mod": "好感度",
  "author": "作者",
  "ver": "1.0",
  "brief": "一言の紹介",
  "helpdoc": { "好感": "現在の好感度を確認……", "好感排行": "&好感" },
  "speech": { "自称": "骰娘" }
}
```

| 項目 | 説明 |
| --- | --- |
| `mod` または `title` | 表示名 |
| `author` / `ver`（または `version`）/ `brief` | メタデータ |
| `helpdoc` | 項目の表。トピックは ASCII の大文字・小文字を区別しない。`.help` の照会につながり、`&トピック` で mod をまたいで何段階でも転送できる |
| `speech` | テンプレートの項目（`{key}` の展開用）。文章、または均等にランダムで選ぶ文章の配列。キーは ASCII の大文字・小文字を区別しない |

解析では末尾のカンマとコメントを許容します（実際のコミュニティの mod によくあります）。

## リソースのフォルダーの意味

| サブフォルダー | 内容 | 説明 |
| --- | --- | --- |
| `reply/*.lua` / `reply/*.toml` | `msg_reply` / TOML の返信のルール | キーワードで起動する返信の処理（下記を参照）。TOML は複数行、引用符付きのキー、インラインテーブルなどの構文に対応するが、動作は引き続き安全の境界の制限を受ける |
| `script/*.lua` | 関数のスクリプト | `loadLua()` と `echo={lua=...}` から呼ぶ |
| `speech/*.yaml` | テンプレートの項目 | 平らな文章または文章の配列で、全体のテンプレートにまとめる。キーは ASCII の大文字・小文字を区別しない |
| `model/*.xml` | 能力値のテンプレート | COC7.xml など。このフォルダーを含む mod は「ルール系」とみなし、ルール管理のページに表示する |
| `rulebook/*.yaml` | ルールブック | 現在のルールの優先、親のルールの継承、トピックの照会、制御された tape |
| `event/*.lua` | 定期 / イベントの宣言 | cycle、サーバーのタイムゾーンの clock、安全なライフサイクル / メッセージのフック |

リソースは階層に分けて置けます。入れ子のモジュールは `親.子` の管理 ID を使い、親を無効にすると子も実行されません。同じ名前のフォルダーと単一ファイルのプラグインは別々の ID を使い、管理の操作が誤ったファイルを指さないようにします。読み込みは `mod_order.json` の順序を保ち、スクリプトは名前空間ごとに登録され、後から読み込んだものが上書きします。リソースを登録するだけで、リソースのフォルダーにある Lua をすべて自動で実行するわけではありません。シンボリックリンク、Windows のジャンクション、パスの横断は許可しません。

スクリプト名は ASCII の大文字・小文字を区別しません。たとえば `loadLua('Tools.Ping')` と `loadLua('tools.ping')` は同じ全体のスクリプトを探し、後から読み込んだ mod が優先されます。`script/Tools/init.lua` は `loadLua('Tools')` で呼べ、Next の明示的な `Tools.init` の書き方も残しています。これによって絶対パスや `..` が許されることはありません。

## msg_reply の因果のルール（reply/*.lua）

各ファイルはまっさらな全体の `msg_reply` の表の中で実行され、その後に中のルールを列挙します。

```lua
msg_reply['好感'] = {
  keyword = { match = { '{自称}好感' } },   -- prefix / search も使える
  limit = { cd = 10, user_var = { trust = { at_least = 0 } } },
  echo = function(msg)
    local favor = getUserConf(msg.uid, '&favor', 0)
    return '現在の好感度：' .. favor
  end,
}
```

| 項目 | 説明 |
| --- | --- |
| `keyword.match` | 完全に等しいときだけ起動（文字列または配列。先に `{テンプレート}` を展開するので `{自称}好感` が使える） |
| `keyword.prefix` | 接頭辞で一致し、残りの文章を `msg.suffix` に入れる |
| `keyword.search` | 含まれていれば一致 |
| `keyword.regex` | 実行時間の制限付きの ECMAScript の `i` による全体の一致。旧版の 400 バイトの入力の上限を保つ。`u` でないモードは UTF-16 の単位で数える |
| `limit.cd` | クールダウンの秒数。`{user=10, grp=30}` で別々に設定できる |
| `limit.user_var.trust.at_least` | 信頼のレベルのしきい値 |
| `limit.grp_id` / `limit.user_id` | ID / ID の一覧。`{nor={...}}` で指定した ID を除外する。グループ ID の `0` は個人チャットを表し、空の一覧は制限しない |
| `limit.prob` | 百分率の起動の確率。0 は旧版の「追加の制限なし」の意味を保つ |
| `limit.today` | 1 日の回数の制限で、サーバーのタイムゾーンで日付が変わる。共有の名前と user / chat / global の範囲に対応 |
| `limit.lock` | 上限付きでブロックしない同期のロック。共有の名前と範囲に対応し、Lua が一時停止している間もロックを持つ |
| `limit.self_var` / `limit.user_var` / `limit.grp_var` | ボット自身、ユーザー、グループの変数の真偽または比較の条件 |
| `limit.dicemaid` | ignore / only / off。ホストのボットの一覧で判断し、メッセージで偽った身元は信用しない |
| `echo` | 関数、固定の文章、文章の候補の配列、または `{lua="スクリプト名 / インラインの Lua"}`。古い JS / Python は実行しない |

ルールは `echo` と少なくとも 1 種類の `keyword` があるときだけ取り込まれます。返信の文章はもう一度テンプレートの展開を受けます。`echo` で `msg` の表に書き込んだ項目（`msg.favor = 5` など）は返信の中で `{favor}` として参照できます。

### TOML、条件、優先度

`reply/*.toml` は toml++ で解析し、複数行の文字列、引用符付きのキー、複雑な表、インラインテーブル、配列に対応します。返信は Match / Prefix / Search / Regex、`rule` / `type="Game"`、固定の文章、Lua、文章の候補に対応します。候補には `::重み::` を使え、さらに `{sample:甲|乙}` を入れ子にできます。空の返信、副作用だけのもの、一時停止の待機も処理済みとみなされ、AI などの最後の受け皿の返信はもう起動しません。

条件は真偽、equal、neq、at_least、at_most、more、less と、上の表の一覧 / 確率 / 回数 / ロックに対応します。複数の比較の条件はすべて満たす必要があります。スカラーのクールダウンはチャットの窓口ごとに数え、共有の回数は範囲と名前を明示できます。表の宣言と旧式の `limit="prob:50;grp_id:!0;cd:10"` の文章の両方に対応します。不明または無効な条件は診断を記録してルール全体を飛ばし、無条件の許可にはなりません。

フォルダーのモジュールは「進行中のセッションのルール → Match → 最長の Prefix → Search → Regex」の順で選び、同じ階層のフォルダーは読み込みの順で上書きします。キーワードの ASCII の大文字・小文字は旧版と互換で、単一ファイルのプラグインは元の一致の習慣を保ちます。1 つのメッセージで 1 つの返信を選び、旧版の複数の Regex が続けて発言する動作は再現しません。

### 定期と安全なイベント

`event/*.lua` の `trigger.cycle` は 1 秒から 7 日まで、単位は second / minute / hour / day に対応します。すべてのモジュールを読み込んだ直後に 1 回実行してから予定し直します。`trigger.clock` は `{hour=4, minute=0}` またはこうした表の一覧に対応し、サーバーのタイムゾーンを使い、逃した日付の分は実行し直しません。

使えるフック：`StartUp`、`DayEnd`、`DayNew`、`Message`、`FriendRequest`、`FriendAdd`、`GroupRequest`、`GroupAdd`、`GroupWelcome`、`GroupDecrease`、`GroupRecall`、`GroupUpload`、`Poke`、`LogEnd`。具体的な通知は、引き続きアダプターがその受信のイベントを提供するかどうかによります。`StartUp` はホストの起動時にだけ起動し、再読み込みでは起動しません。日付の境界のイベントはサーバーの日付の変化に従って実行します。

リクエストのフックは拒否できますが、ホストの方針を越えて承認することはできません。フックが失敗するとリクエストは保留のまま残ります。メッセージと tape はブラックリスト、無効化、内容の遮断、グループごとのプラグインのスイッチに従い、資格情報 / 復旧の管理のコマンドが飲み込まれることはありません。`LogEnd` は制御されたログのパスと既定のアップロードの制御だけを提供し、任意のファイルの公開は戻しません。認可、審査、クラウドのブラックリストの方針を上書きするフックは実行しません。

`LogEnd` は `.log end` または `.game over` がログを閉じて精算を終えた後に呼ばれます。`log_file`（実際の書き出しのファイル名）、`log_path`（絶対パス）、`log_id`、`log_name`、`log_count` と、uid / gid / fromUser / fromQQ / fromGroup / platform / adapterId / selfId / msgid / time を読めます。ファイル名はユーザーが入力できる表示用のタイトルではなく、既定の書き出しはローカルの画像を公開しません。セッションの終了のフックが動くときには元のセッションはすでに片付けられており、変更できる古い Session のオブジェクトは残りません。

cycle、clock、起動 / 日付の境界の動作では `sleepTime` で一時停止して続きを実行できます。すぐに結果が必要なメッセージ、承認、通知、tape のフックは同期で実行し、`sleepTime` でホストの決定を遅らせることはできません。一時停止できない呼び出しでは即座に戻り、メッセージのスレッドをブロックしません。

イベントの動作には Lua の関数、スクリプト名、インラインの Lua を使えます。対応していない動作 / 起動の条件が混ざっている場合はまとめて報告し、対応している半分だけを実行することはありません。コールバックとロックのキューには数の上限があり、再読み込み / 破棄で古いタスクを取り消します。起動したプラットフォームとアカウントは遅延の後も保たれ、元のアカウントがオフラインでも別のアカウントで送ることはありません。

フォルダーのファイル / インラインの文章のスクリプトの一時的な全体の変数は実行ごとに分けられ、遅延して続きを実行するときはその回の環境を保ちます。`loadLua` の子のスクリプトは入口とその回の変数を共有します。`eventMsg` で入れ子にほかのコマンドを起動した後は外側のメッセージを戻し、外側の返信が内側のニックネーム、ユーザー ID、変数を借りることはありません。メッセージをまたいで保存したいデータは、前回のスクリプトが残した全体の変数に頼らず、設定やキャラクターシートの API を使ってください。登録済みの Lua の関数は Next の元のクロージャーの機能を保ちます。これは任意のコードのために完全に独立した LuaState や安全なサンドボックスを作るものではありません。

### XML のモデルとルールブック

XML は能力値の別名、CDATA、基本の実体参照、読み取り専用の数値の式に対応します。算術、比較、短絡、三項、能力値の既定値、floor / ceil / round / min / max などの許可された関数を含みます。たとえば `Math.floor(this.力量/2)` は変換できますが、スクリプトのブロック、代入、動的な呼び出し、任意の JavaScript は実行しません。変換できない能力値には互換の診断を表示します。モジュールの順序、有効化と無効化、再読み込みでテンプレートも更新され、ネイティブのルールパックの優先度は変わりません。

ルールブックは現在のルールの優先、親のルールの継承、名前付きのトピックの照会に対応します。tape は進行中のセッション、参加者、グループごとのスイッチが許すときだけ実行します。

## msg_order の単一ファイルのプラグイン（data/plugin/*.lua）

```lua
msg_order['选择'] = 'choose'

function choose(msg)
  local opts = {}
  for w in msg.suffix:gmatch('[^%s]+') do opts[#opts+1] = w end
  return '決まりました：' .. opts[ranint(1, #opts)]
end
```

`msg_order[トリガーの語] = "全体の関数名"` です。トリガーの語は長さの降順で一致させます（長い語が優先）。関数は `msg` の表を受け取り、戻り値の最初の項目が返信になります。

プラグインで `sleepTime(ms)` を呼ぶと、Dice!Next は現在の Lua の処理を一時停止してメッセージのスレッドを返し、時間になったら元の位置から続きを実行します。そのため古いプラグインの分割して遅延する返信が、メッセージの受信をブロックすることはもうありません。プラグインの再読み込みは、まだ再開していない古いコルーチンを取り消し、読み込み解除したコードが実行されないようにします。

古い単一ファイルのプラグインは、引き続き io.open で入口のスクリプトと同じ階層のリソースを読めます。プラグインに付属する生成済みのキャッシュに作者のパソコンの古い絶対パスが残っている場合、Dice!Next は最初に開くのに失敗した後、パスの横断のない plugin/… の末尾だけを現在の data/plugin のフォルダーに対応付け直します。ファイルの監査ログも UTF-8 / CP936 が混ざったパスを自動で整え、不正なエンコーディングでホストのプロセスが終了することはもうありません。

### task_call の定期の入口

旧式の単一ファイルのプラグインは、ダイスマスターが定期的に起動する全体の関数を登録できます。

```lua
task_call = task_call or {}
task_call['dailynews'] = 'sendDailyNews'

function sendDailyNews()
  -- ニュースを取得して内容を整え、自分から sendMsg(...) する
end
```

登録した後は、ダイスマスターがチャットで毎日の実行時刻を管理します。

```text
.admin clock + dailynews 07:30
.admin clock list
.admin clock - dailynews
```

タスクはシステムのタイマーの永続化を使い、管理パネルの「定期タスク」の一覧に表示され、無効化、すぐに実行、削除ができます。時刻は古いプラグインの文書によくある `7:30` と標準の `07:30` の両方に対応し、保存時には 2 桁の時に揃えます。`task_call` のタスクには固定のグループ / ユーザーの対象がなく、送り先はプラグインの関数が `sendMsg` で自分で決めます。

原版の空白なしの書き方 `.admin clock+dailynews=7:30` にも対応します。現在のグループ / 個人チャットで通常のプラグインのコマンドを定期的に呼ぶには、`.admin clock + 本群早报 07:30 .dailynews` を使えます（`本群早报` はタスク名）。これにより、現在のアカウントと窓口のスコープを持つ標準の「プラグインのコマンドを実行」のタスクが作られ、WebUI で完全に編集できます。

DailyNews のようなプラグインが使う `eventMsg(".admin notice group/QQ … +8")` と `eventMsg(".send notice 8 …")` は、Dice!Next の統一の通知の窓口に対応付けられます。この内部の橋は上の 2 種類の古い通知のコマンドだけを認識し、Lua の `eventMsg` にダイスマスターのほかの管理権限を与えることはありません。

### ルーレットのプラグインの旧版の自分へのミュートの呼び出し

古いルーレットなどのプラグインは、よく次の書き方を使います（`分` は整数で、秒ではありません）。

```lua
eventMsg(".group " .. msg.fromGroup .. " ban " .. msg.fromQQ .. " 1", 0, getDiceQQ())
```

Next はこうした呼び出しに制御された互換を用意しています。現在の送信元のアカウント、現在のグループ、現在起動したユーザー自身へのミュートだけを許可し、時間は 0～43200 分（0 はミュートの解除）です。ボットがこのグループの管理権限を持つことを確認できている必要があり、グループのオーナーとグループの管理者はミュートできません。グループの無効化、ブラックリスト、全体の沈黙、グループごとのプラグインのスイッチは引き続き有効で、権限のキャッシュの準備ができていない場合は更新を求めて理由を記録するだけです。

旧版の任意の仮想のメッセージの最高の信頼のレベルは戻しません。グループをまたぐ、対象のユーザーを替える、仮想のメッセージやその遅延の続きで権限を借り続ける、といったことはすべて拒否されます。WebUI のテスト台や定期タスクの仮想のコマンドも同じく権限を借りられません。この互換の橋は汎用の `.group ban` の管理の入口ではなく、時間の式にも対応しません。ほかの `eventMsg` は引き続き通常のコマンドの権限を通ります。

仮想の個人チャットのボット自身は実行するだけで受領の返信を送りません。通常のグループチャット / ユーザーの個人チャットでは通常どおり返信します。OneBot は有効なイベントの `self_id` から現在のアカウントの身元を補い、欠けている / ゼロの値は既知の身元を上書きせず、無効な対象はプラットフォームに送りません。既存のプラグインはこの行を変える必要はありません。

## msg のオブジェクト

`echo` の関数と `msg_order` の関数が受け取る `msg`：

| メンバー | 説明 |
| --- | --- |
| `msg.uid` / `msg.gid` | 送信者 / グループの ID。QQ では通常は数字、ほかのプラットフォームでは文字列のこともある。個人チャットでは gid は 0 |
| `msg.platform` | 現在のメッセージのプラットフォーム（`onebot_v11`、`qq_official`、`discord`、`kook` など） |
| `msg.nick` | 送信者の QQ のニックネーム（グループ内の名前では上書きしない） |
| `msg.card` | **現在のグループ内の名前**。未設定または個人チャットでは `""` |
| `msg.fromMsg` | メッセージの全文。`msg.suffix` は接頭辞で起動したときの残りの文章 |
| `msg:echo(text)` | テンプレートを展開した後、自分からメッセージを送る |
| `msg:format(text)` | テンプレートの展開だけを行う |
| `msg:get(key, def)` / `msg:inc(key, n)` | このメッセージの変数を読む / 増やす |
| `msg.char` / `msg.pc` | 送信者のキャラクターシート（Actor のオブジェクト） |
| `msg.user` / `msg.grp` | ユーザー / グループの設定の代理（読み書きでそのまま保存） |
| `msg.game` | セッションのオブジェクト（`.game new` で始めた後に使える。`msg.game:message(text)` で一斉送信） |
| `msg.at` | `[CQ:at,qq=送信者]` の文章 |

```lua
-- 現在のメッセージの送信者のグループ内の名前。なければ QQ のニックネームに戻す
local displayName = msg.card ~= '' and msg.card or msg.nick

-- 現在のグループで紐付けたキャラクターシートの能力値。5 番目の引数 false で gid をグループのスコープとして強制的に扱う。
-- Discord、KOOK、QQ 公式ボットなど数字でないグループ ID では必ず付ける。
local skill = getPlayerCardAttr(msg.uid, msg.gid, '侦查', -1, false)
```

| 関数 | 説明 |
| --- | --- |

```lua
local before = getFavor(msg.uid)

local success, delta, value = growFavor(msg.uid)
```

`msg_order`、`reply echo` と、そこからの `loadLua()` の呼び出しの連鎖は `msg.platform` を自動で引き継ぎます。プラグインの読み込みの段階や、メッセージから離れたほかのコードで呼ぶ場合は platform を明示的に渡す必要があります。プラットフォームや uid がない場合は `nil` を返し（`growFavor` は `false, 0, 0` を返す）、データは書き込みません。

**動作**

| 関数 | 説明 |
| --- | --- |
| `sendMsg(text, gid, uid)` | 自分からメッセージを送る（gid が空 = 個人チャット） |
| `eventMsg(text, gid, uid)` | 文章を誰かが送ったメッセージとして完全なコマンドの流れに通す（`eventMsg('.rd100', msg.gid, msg.uid)` など） |
| `drawDeck(gid, uid, デッキ名)` | 現在のグループの Session の専用のデッキを優先して引き（戻さない）、同じ名前の専用のデッキがないときだけ公開のデッキから引く |
| `loadLua(名前)` | フォルダー型の mod は `script/<名前>.lua` を優先して実行する。旧式の単一ファイルのプラグインも入口のスクリプトと同じ階層のサブフォルダーに対応する（`a.b` のドット区切りのパスに対応） |
| `askExtra(table)` | プラットフォームの拡張の照会（アダプターに渡す。OneBot の動作など） |

```lua

sendMsg('[CQ:music,type=custom,url=リンク,audio=音声のURL,title=タイトル,content=紹介,image=表紙のURL]', msg.gid, msg.uid)
```

| ライブラリ | 説明 |
| --- | --- |
| `http.get(url)` → `ok, body`、`http.post(url, body, headers)` | 既定で公開のネットワークの HTTP(S) を許可し、内部のネットワーク / ループバック / 危険な URL は常に遮断する。厳格なモードではさらに外部 API のスイッチと許可リストが必要。`http.urlEncode/urlDecode` |
| `json.encode/decode`、`yaml.parse/dump` | `require("json")` / `require("yaml")` でも使える |

`package.path` には mod のフォルダーと `data/plugin` が含まれているので、プラグインをまたぐ `require` が使えます（コミュニティでよく使われる `lua_useful_extensions` など）。

Windows では、古い単一ファイルのプラグインを読み込むときに GBK / CP936 のソースを自動で認識して変換します。プラグインが `sendMsg`、`eventMsg`、JSON のエンコーダー、アダプターに渡す文章も、有効な UTF-8 に揃えます。復元できない不正なバイトは置き換えの文字で表示し、JSON のシリアライズの例外が突き抜けてプロセスが終了することはもうありません。

## Lua API の完全なシグネチャとオブジェクトのメソッド

この節では、現在のランタイムが直接登録しているすべての Lua プラグインの API を示します。引数名の `?` は省略できることを表し、特に記載がない限り書き込みの関数は戻り値を持ちません。

### データ、メッセージ、プラットフォーム

| API | 引数と戻り値 | 説明 |
| --- | --- | --- |
| `getUserConf(uid, key, default?)` | 値 / `default` / `nil` | ユーザーの永続的な設定。uid が `nil` のときは `{[uid]=value}` の表を返し、ランキングに使える。 |
| `setUserConf(uid, key, value)` | — | value が `nil` のときは削除する。 |
| `getGroupConf(gid, key, default?)` / `setGroupConf(gid, key, value)` | 値 / — | グループの永続的な設定。value が `nil` のときは削除する。 |
| `getUserToday(uid, key, default?)` / `setUserToday(uid, key, value)` | 値 / — | 現在の日付で分ける。ない場合は既定で 0 を返す。 |
| `getFavor(uid, platform?)` | number / `nil` | 内蔵の好感度を読む。メッセージの呼び出しのスタックでは現在のプラットフォームを自動で引き継ぐ。 |
| `setFavor(uid, value, platform?)` | number / `nil` | 内蔵の好感度を上書きし、新しい値を返す。 |
| `addFavor(uid, delta, platform?)` | number / `nil` | 内蔵の好感度を増減し、新しい値を返す。 |
| `growFavor(uid, platform?)` | `success, delta, value` | 内蔵の好感度の成長のルールで判定して書き戻す。 |
| `sendMsg(text, gid?, uid?)` | — | gid が空でなければグループに送り、gid が空なら uid に個人チャットで送る。 |
| `eventMsg(text, gid?, uid?)` | — | 文章をそのユーザーが送ったメッセージとして、完全なコマンド/返信の流れにもう一度入れる。`{fromMsg=, gid=, uid=}` も渡せる。 |

| `askExtra({action=..., params=...})` | 表 / 文字列 / `nil` | プラットフォームのネイティブの動作を渡す。現在応答できるのは OneBot のアダプターだけで、QQ 公式、Discord、KOOK は `nil` を返す。 |

| `mkDirs(path)` | boolean | フォルダーを作る。 |
| `loadLua(name)` | スクリプトの戻り値 | フォルダー型の mod は `script/<name>.lua` を優先して実行する。旧式の `data/plugin/*.lua` も入口と同じ階層のパスに戻る。たとえば `loadLua("求签/月老灵签")` は `data/plugin/求签/月老灵签.lua` を読む。`a.b` は引き続き `a/b.lua` に対応する。 |

`key` が `&` で始まるときは、先に現在の mod の speech の項目を解決します。これは古い mod でよくある項目の別名の書き方です。

### キャラクターシートと Actor

```lua
-- 現在のグループで紐付けたシート：QQ の数字のグループでは getPlayerCard を使える。プラットフォームをまたぐなら Actor で false を明示する。
local pc = Actor(msg.uid, msg.gid, false)
local hp = pc:get('hp') or 0
pc:set('hp', hp - 1)
pc.san = 60                 -- 項目への代入は set と同じ

-- シートの名前で読む（2 番目の引数が文字列のシートの名前、または byName=true を明示）
local named = getPlayerCardAttr(msg.uid, '备用卡', 'hp', 0, true)
```

| `Actor(uid, scope, byName?)` | Actor | キャラクターシートの代理を作る。プラットフォームをまたぐグループ ID では、scope をグループとして扱うよう `false` を明示する。 |

## テンプレートの項目（speech）

### 安全な文章の関数

通常の文章、ネイティブのカスタム返信、ファイルのデッキ、Lua の speech は安全な文章の関数を共有します：`sample`、`case`、`grade`、`ran`、`len`、`expired`、`var`、`at`、`print`、`wait`。テンプレート内の JS / Python は実行せず、テンプレートからホストの設定やファイルを読み書きすることもありません。`wait` は非同期で待ち、メッセージのスレッドを眠らせません。各入口で読める項目は引き続きそのメッセージのコンテキストにより、プレビューは待機もメッセージの送信もしません。

```text
{var:本次={ran:1~100}}今回は {本次}、もう一度表示しても {本次}
{case:user.trust?0=ユーザー&else=信頼済みのユーザー}
{grade:user.favor?0=普通&100=親密&else=不明}
```

`{var:名前?値}` は代入して表示し、`{var:名前=値&別の名前=値}` は代入だけを行います。その回の描画だけで有効で、ドット区切りのパスでキャラクターシート、ユーザーのデータ、権限を変えることはできません。`ran` は順序付きの整数の上下限（両端を含む）を受け付け、`expired` は項目の整数の Unix 時刻がすでに過ぎたかを判断します（ない、または無効な場合は期限切れとみなす）。ランダムな文章はゲームのダイスの目とは独立しています。

`len` は文字列では UTF-8 のバイト数を返します。Lua のメッセージの Set / 通常の表では要素の数を返し、`__len` / `__pairs` は呼びません。数値と真偽値は 0 を返します。通常のコマンドの文章やデッキでも `{len:game.pls}` / `{len:game.gms}` で現在のセッションのプレイヤー / GM の人数を確認できます。局所の変数は引き続き文字列です。集合の長さの確認には作業量の上限があり、任意のオブジェクトのシリアライズを開放するものではありません。

`{print:uid}` / `{print:gid}` は現在のユーザーまたはグループの名前と ID を表示し、`{print:master}` / `{print:self}` は現在のプラットフォームとアカウントのダイスマスターまたはボットを表示します。`{print:uid=12345}` / `{print:gid=12345}` で ID を指定でき、`gid=0` は個人チャットを表します。現在のメッセージまたは送信元のアカウントのキャッシュだけを使い、その場でネットワークで名前を調べたり、ほかのアカウントから名前を借りたりはしません。名前がない場合は識別できる ID を残し、一致するダイスマスターがいない場合は `[无主]`（主なし）を表示します。キャッシュの名前に含まれる偽の CQ の動作や制御文字は無害化します。

`{wait:1000}` は文字を出力せず、返信を遅らせることだけを求めます。選ばれた複数の分岐の待ち時間は足し合わされ、1 つの項目は `0 < ミリ秒 < 600000` が必要で、1 つの返信は最大 10 分まで待ちます。通常のメッセージの最終的な返信は非同期でキューに入り、最大 256 件 / 16 MiB です。送信の前に送信元のアカウントがオンラインか、ブラックリスト、無効化の状態を再確認し、アカウントの変更、関連するグループのプラグイン / 返信 / ルールの権限の変化、プラグインの再読み込み、プログラムの再起動で古い待機を取り消します。変数、ランダムな結果、ダイスの目はキューに入る前に決まり、時間になって計算し直すことはありません。すでに実行した管理の操作を遅らせることはなく、承認などのすぐに返す必要がある決定にも使いません。

Lua の一時停止できるメッセージの処理の中で `msg:format('文字{wait:1000}')` や `msg:echo('文字{wait:1000}')` を使うと、`sleepTime` のコルーチンの仕組みを使い、時間になると呼び出した場所から続きを実行します。再読み込みで古いコルーチンは取り消されます。プレビューと一時停止できない同期の呼び出しは文章を整えるだけで、待機は行いません。

`msg:format()` / `msg:echo()` はこのメッセージの表のスカラーの項目と、読み取りを許可したドット区切りのパスを取り込みます。`msg:get('temp.count')`、`msg:get('user.trust')` で入れ子の項目を読め、真偽値の false が失われることはもうありません。内部の `__*` の項目と関数は拒否し、`_G`、任意の SelfData、ホストの設定へ暗黙に突き抜けることはありません。`msg:inc()` は引き続きこのメッセージの局所の変数を増やすもので、これによって永続的な書き込みの権限が増えることはありません。

ニックネーム、捕捉した文章、ユーザーのデータ、プラグインの項目は通常のデータとして挿入し、テンプレートとして解析することはもうありません。`\{ran:1~100}` などのエスケープした書き方は原文を保ちます。ループ、サイズ、階層、作業量の制限は引き続き有効です。

### 自動の目録

`{list_all_deck}` は公開のデッキとこのグループの一時的なデッキを一覧にし、`{list_extern_deck}` はユーザーのファイルが提供する公開のデッキだけを一覧にします。アンダースコアで隠した項目は表示しません。`{list_extern_order}` / `{list_reply_deck}` は、現在のアカウント、グループ、ユーザーの範囲にあるネイティブのカスタム返信と Lua の拡張のトリガーの語を一覧にします。前者は有効な SealDice の JS プラグインのコマンドも一覧にし、現在設定しているコマンドの接頭辞を使います。

JS の目録は変更できないコマンドのスナップショットだけを読み、読み込み、実行、再読み込みの後に更新します。目録の一覧の作成では JS のランタイムに入らず、getter / Proxy を読まず、`solve` も呼びません。Lua の静的なユーザー、グループ、自身の設定の条件は読み取り専用で確認できます。speech の動的なキーを実行する必要がある、SelfData のファイルを読む必要がある、権限を確認できないといった項目は、安全のために省きます。目録の一覧の作成で返信を実行したり、確率を抽選したり、クールダウン / 1 日の回数を消費したりはしません。

`{list_dice_sister}` は、このグループの現在のアカウントのメンバーのキャッシュで認識したボットだけを一覧にし、インスタンス全体の全体のアカウントの一覧は公開しません。目録は最大 200 項目 / 32 KiB を表示し、切り詰めたときは省略記号を付けます。照会でアカウントをまたいだ補いの照会は起こりません。

返信の文章の `{key}` は次の順で解決します：メッセージの変数 → speech の項目（各 mod の `speech/*.yaml` と記述ファイルの `speech{}` をまとめたもの。値が `&` で始まるものは別名）→ 内蔵の `{self}`（ボットの自称）。再帰的な展開に対応します。

speech のキーは ASCII の大文字・小文字を区別しません。たとえば `{reply_spells_list}` で `Reply_Spells_List` を参照できます。メッセージの変数は、まず同じ名前に完全に一致する項目を取り、次に ASCII の大文字・小文字を区別しない互換の照会を行います。中国語のキーは書き換えません。

YAML と JSON の記述ファイルはどちらも文章の配列に対応し、参照するたびに均等にランダムで 1 つを選んでから、その中の変数 / sample を展開します。最初の 1 つだけを表示するのではありません。空の配列は空の文章を返し、別名は引き続き配列を指せます。

```yaml
Roll_Reply:
  - "{nick}：{sample:お見事|効果は抜群}"
  - "{nick} の番です！"
roll_alias: "&ROLL_REPLY"
```

これらの変更は 2026-10-16 のローカルの互換の仕上げに属します。使っているインストーラーに含まれているかは、実際のソースのバージョンを確認してください。ResourceSearchEngine、求签（おみくじ）/ DailyNews、PC_Inventory、PC_Slots はコピーで受け入れの確認をしました。テストではネットワークとメッセージの送信の代役を使っており、外部のサービスや実際のアカウントへの配信は保証しません。プラグイン自身のソースのエラーをホストがこっそり書き換えることもありません。

### ヘルプの項目と参照

`helpdoc` は、有効なすべての mod をまとめた大文字・小文字を区別しない名前空間を使い、同じ名前のトピックは読み込みの順で上書きします。ヘルプの一覧は `{help:トピック}` と一致し、`&トピック` の別名は mod をまたいで何段階でも転送できます。循環する別名で一覧が止まることはありません。通常の `.help` は Next の元の内蔵 / JS のヘルプの優先度と検索の範囲の絞り込みを保ち、最終的に選ばれた mod の項目だけを描画します。

ヘルプの内容の参照は「メッセージの変数 → mod のヘルプのトピック → speech → 内蔵の変数」の順で解決し、sample を含められます。例：

```json
{"helpdoc":{"ダイスの使い方":"{nick}、.r d100 と入力すれば OK。","ロールのヘルプ":"&ダイスの使い方","目次":"{ロールのヘルプ}"}}
```

`.help 目次` と Lua の返信の `{help:目次}` は、どちらも現在のニックネームを取り込みます。通常の返信の `{トピック}` がそれによって自動でヘルプの照会に変わることはありません。ヘルプが必要なときは `{help:トピック}` と明示的に書いてください。

テンプレートの展開は最大 24 階層、10,000 回の変数 / 参照の解決までです。1 つの結果は最大 4 MiB、途中の文章は合計で最大 32 MiB です。サイズや作業量の制限を超えると空の文章を返し、任意のスクリプトは実行しません。画像の URL / CQ の参照は画像のファイルのサイズでは数えず、テンプレートに直接埋め込んだ Base64 は文章として扱います。

## 原版との互換についての説明

よく使う全体の API と `Set/Context/SelfData/Actor/GameTable/http` のオブジェクトの層はつながっており、`getUserConf(nil, field)` の列挙、`&key` の受け皿、3 引数の `drawDeck`、単一ファイルの `task_call` と `sleepTime` を含みます。`require('Set')`、`Actor`、`GameTable`、`SelfData` は公開の別名を使えます。次の境界は引き続き残っており、任意の古いパックを損失なく再現することは約束できません。

| 対応していない項目 | 説明 |
| --- | --- |
| 古い JS / Python の動作と任意の XML のスクリプト | 実行しない。SealDice の JS のエンジンは旧 Dice! の JS API と同じではなく、XML は安全な数値の式だけを変換する |
| 古いリモートのインストールと安全の方針の上書き | `.mod get/update/reinstall` のダウンローダーは戻さず、無効化、ブラックリスト、内容の遮断、リクエストの承認を回避することは許可しない |
| 複数の返信 / 比較の過去の動作 | 1 つのメッセージで 1 つの返信を選ぶ。複数の比較の操作はすべて満たす必要があり、緩い部分一致や連続した大量の発言は再現しない |
| 外部の Lua のバイトコード | 読み込まず、文章の Lua だけを受け付ける。リソースの発見とキューには深さ / 数の上限がある |
| バイナリの C の拡張（`.dll`） | 既存のランタイムのライブラリの検索の方針に従う。プラットフォームと Lua の ABI に一致する必要があり、厳格なモードでは検索のフォルダーをさらに制限する。今回はネイティブのライブラリを読み込む権限を新しく加えない |
| 古いホストに特有のオブジェクト | 個人チャット / チャンネルの古いセッションは引き続き自動では有効にならない。`LogEnd` はよく使う項目を補ったが、古いログ / Session のオブジェクトと項目ごとに完全に同じであることは保証しない |

移行で問題があれば、mod のファイルを添えて気軽に報告してください。

設定の底層は文字列の列を使っていますが、Lua の値は型のエンコードで文章、真偽値、数値、空の文字列、集合を区別します。エンコードしていない過去の値は引き続き互換のルールで読みます。正規表現のエンジンは原版の C++ の locale / POSIX の拡張と同じであることを保証せず、400 バイトの上限も実行時間の制限の代わりではありません。完全な実装の状態、残っている違い、テストの範囲は[メインリポジトリの互換の記録](https://github.com/DiceZone/Dice-Next/blob/main/docs/legacy-mod-compatibility.md)を参照してください。
