# 牌堆与随机抽取

Dice!Next 兼容原版 Dice! 牌堆格式，并提供给主持人（KP）的运行时临时牌堆与内联随机工具。

## 指令总览

| 指令 | 说明 |
|------|------|
| `.draw` / `.drawh` | 公开抽取 / 暗抽牌堆 |
| `.deck` | 查看牌堆列表 / 管理临时牌堆 / 设置默认牌堆 |
| `.gacha` | 抽卡（gacha 牌堆） |

## 抽牌 `.draw`

```
.draw 塔罗牌        → 从「塔罗牌」牌堆抽一张
.draw3 塔罗牌       → 连抽 3 张
.draw              → 抽本群默认牌堆（需先 .deck set）
.drawh 塔罗牌       → 结果私聊发给抽取者，群里只发暗抽回执
```

### 内联随机（跑团神器）

无需建堆，直接给候选项用 `/` 分隔即可随机选一：

```
.draw 红/蓝/绿      → 在三项中随机选一个
.draw3 左/中/右     → 随机选 3 次
```

适合临场让骰子帮忙做随机决定。

## 临时牌堆 `.deck new`

任何人（含没有管理权限的 KP）都能为本群建立临时牌堆，跑团时非常实用：

```
.deck new 出招 石头/剪刀/布   → 建立本群临时牌堆「出招」
.draw 出招                    → 从临时牌堆抽取
.deck del 出招                → 删除临时牌堆
```

## 团务私有牌堆 `.deck session`

先通过 `.game new` 建立团务，再由本团 GM、群管或骰主管理不放回牌堆。以下以当前 main 为准，所用安装包是否包含新增入口请核对对应 Release 的源码版本：

```text
.deck session new 出场 甲/乙/丙       // 创建私有牌堆
.deck session from 敌人 公共敌人堆   // 复制公共牌堆，不修改来源
.deck session range 编号 1 20 2      // 从整数范围生成 1、3、5…19
.deck session members 抽签名单       // 从当前账号缓存的本群成员建立快照
.deck session rest 出场              // 查看剩余数量
.draw 出场                          // 抽走一张，不放回
.deck session reset 出场             // 恢复全部牌
.deck session del 出场               // 删除指定私有牌堆
.deck session clr                    // 清空本团私有牌堆
```

`::2::甲` 表示两份甲；一个 Session 最多 10 个私有牌堆。接入同一团务的多个群共用牌池，不同团务互不影响；剩余牌数持久保存，旧版存档的已抽状态也会保留。抽空后必须显式重置，不会自动补牌或改抽同名公共牌堆。保存失败时本次不扣牌。

抽取优先级为：**团务私有牌堆 → 本群临时牌堆 → 公共文件牌堆**。本群临时牌堆仍有放回，`.deck new/set/del/clr` 原有含义不变；团务管理使用上面的显式 `session` 入口。Lua 三参 `drawDeck(gid, uid, name)` 共用团务牌池，一参 `drawDeck(name)` 仍只抽公共牌堆。

数字范围可写起点、终点和可选的正整数步长；起终点反写会交换，仅写一个数表示从 0 到该数，最多 10000 张。群成员生成要求当前适配器账号在线且成员缓存可用，不会改用另一个机器人补查。空缓存会请求当前账号刷新并提示重试，不创建空牌堆；去重后每人一张，昵称仅保存快照，不跟随更名。OneBot 直接使用已有成员缓存和姓名索引，不逐人联网取名。生成牌面按字面文本存储，昵称中的 `::份数::` 或 `{模板}` 不会被执行，伪造的 CQ 代码及分页控制字符会中和。两种生成方式仍遵守开团、GM / 群管 / 骰主权限和原有保存失败保护。

## 默认牌堆 `.deck set`

```
.deck set 塔罗牌    → 设为本群默认牌堆（需群管理），之后直接 .draw 即可
.deck default       → 查看当前默认牌堆
.deck clr           → 清除默认牌堆
```

## 牌堆文件

牌堆是 JSON 文件（`{"牌堆名": ["卡面1", "卡面2", …]}`，一个文件可含多个牌堆），从两个目录加载：

| 目录 | 用途 |
|------|------|
| `decks/` | 随安装包分发的内置/示例牌堆（升级时会被替换） |
| `data/decks/` | 用户自己的牌堆（上传/手动放置都在这里，升级不受影响） |

同名牌堆以 `data/decks/` 的为准。手动放入文件后，在管理面板点「重载」或重启即可生效。

### WebUI 上传与编辑

在 [Web 管理面板](/manage/dashboard) 的「牌堆管理」页可以：

- **上传** `.json` 牌堆或海豹布局 `.deck` 包，JSON 保存到 `data/decks/`，图片按文件名归档到 `data/images/deck/` 并重载；
- 左侧选择文件、右侧查看该文件的各牌堆条目；分页支持点选页码与输入跳页。
- 用户文件可**在线编辑、下载或删除**；内置文件由面板与服务端共同限制为只读，不能直接覆盖或删除。两种来源即使文件名相同，也分别标识，不会读写错文件。
- 内置文件可下载留存，也可把公开、非空的单个牌堆**复制为用户牌堆文件**后再编辑；保留该条目的卡面原文，但不复制整个合集、其他子牌堆或合集元数据。引用仍依赖已加载的原牌堆；若需独立分发，应另外核对依赖。
- 查看牌堆的 `_title`、`_author` 等元数据；
- 一键**重载**所有牌堆目录（新增/修改/删除的文件都会反映）。

编辑条目时保留原始权重、引用、多行文本及未知扩展字段，未保存切换会提示。空对象读取导致“无法读取这个牌堆”的问题已修复；真正加载失败时会显示错误并允许重试，不把空内容当成已加载成功。

### `.deck` 牌堆包 {#deck-牌堆包}

「连同资源下载」会收集本地图片，以及能静态定位来源的已加载跨文件牌堆依赖，生成 `.deck` ZIP。没有本地依赖时仍下载 JSON。

包内 JSON 和 `assets/` 直接放在根目录，**不要再套一层文件夹**，图片引用为 `./assets/…`。权重、转义和嵌套 `sample` 原样保留，导出时不抽牌、不执行模板或插件；Next 专有文本语法不保证在其他引擎中语义等价。

远程图片不自动下载；本地依赖缺失时会明确报错，不导出残缺包。动态拼接的牌堆名或图片路径无法保证全部收集，请自行核对。

导入时会先校验包内容，再确认覆盖；每个 JSON 牌堆的图片集中放入 `data/images/deck/<该文件名>/`，保留子目录。未被静态引用的附带图片归到首个牌堆并显示提醒。不能包含脚本、越界路径、符号链接、加密内容或大小写冲突的重名文件。

上传包不超过 128 MiB，单文件不超过 128 MiB，解压及归档后的图片不超过 512 MiB / 10000 个，最多 100 个 JSON 牌堆；超过限制请拆分。

单独整理或引用图片，使用 [文件管理](/manage/files)。

`.deck` 聊天列表默认隐藏 `_` 开头的元数据键（可在[系统设置](/manage/settings)关闭该隐藏）。

### 旧版牌堆兼容

- 支持以下**原版 Dice! 牌堆格式**语法：子牌堆引用 `{牌堆}`（不放回）、`{%牌堆}`（放回）、骰子表达式 `[1d6]`、权重 `::N::卡面`、转义 `\{` `\[`。
- 使用[数据迁移](/guide/migration)从原版 Dice! 升级时，`PublicDeck/` 目录下的外置牌堆会自动校验并导入到 `data/decks/`。
- 牌堆文件需为 **UTF-8 编码**的 JSON；旧版遗留的 GBK 编码文件请先转成 UTF-8 再放入。中文文件名没有问题。

卡面可嵌套 `sample / case / grade / ran / len / expired / var / at / print / wait` 等[安全文本函数](/develop/lua-mod#安全文本函数)，支持 `[1d{ran:6~6}]` 这类显式计算；变量以当前消息上下文为准。只有选中的分支会抽牌、掷骰或登记等待，局部变量与不放回子牌池在一次展开内复用；一轮渲染使用同一份牌堆目录快照。

原有图片 / CQ 码、权重及 `\{` / `\[` 转义继续保留。昵称、捕获文本和其他运行时字段不会再次解析，即使包含 `{牌堆}`、`[1d100]` 或 `{wait:1000}`。从成员生成的快照牌面仍完全按字面展示，不因为新增模板能力执行成员昵称中的代码。

::: tip 牌堆里引用帮助词条
卡面中的 `{引用}` 若不是牌堆名，会尝试查同名**帮助词条**并展开其内容（溯洄 / OneDice 引用语义），可以和帮助文档配合做出复杂的抽取结构。参见[帮助系统](/use/help)。
:::
