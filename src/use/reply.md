# 关键词自定义回复

Dice!Next 支持灵活的关键词自动回复，可在 [Web 管理面板 → 回复管理](/manage/replies) 可视化编排。回复管理页有三个选项卡：**基础回复**、**因果规则**、**计数器**。

聊天里可用 `.reply on/off` 持久开关本群自定义回复（群管理或受信任用户）；也可用 `.group +禁用回复` 关闭（见[群管与系统](/use/admin)）。

## 基础回复

### 匹配方式

| 类型 | 说明 |
|------|------|
| 关键词匹配 | 整条消息与内容**完全相等**才触发（忽略大小写） |
| 前缀匹配 | 消息以某前缀开头触发 |
| 正则匹配 | 正则表达式（从消息**开头**匹配）并可捕获分组 |
| 搜索匹配 | 消息**包含**该内容即触发（忽略大小写） |

一条规则支持**多条件 AND / OR** 组合，以及**多结果随机**（命中后从多条回复里随机选一条发送），并可设置优先级。

多条回复可在管理面板为每条单独填写权重，并查看实际抽取概率。例如权重 3 与 1 对应 75% 与 25%；默认权重为 1，范围 0–999999，0 表示不抽取。整条规则的「触发概率」与每条回复的抽取权重分别计算。

旧版 `::数字::` 标记会在导入或读取旧数据时转换为独立权重，无需重新导入；无效标记保留原文。正式编辑器已使用独立权重字段，回复文字中的 `::数字::` 将按原文发送。

### 回复模板变量

回复内容里可以使用 `{…}` 占位符，发送时实时替换：

| 变量 | 含义 |
|------|------|
| `{nick}` | 触发者显示名（带包裹符号，包裹符号可在配置中改） |
| `{name}` | 触发者显示名（人物卡名 > `.nn` 昵称 > QQ 昵称） |
| `{qqnick}` / `{card}` / `{pcname}` | QQ 昵称 / 群名片 / 人物卡名（干净无包裹；加 `w` 后缀如 `{qqnickw}` 则带包裹） |
| `{user}` | 触发者账号 |
| `{self}` | 骰子自称 |
| `{group}` | 群号 |
| `{date}` / `{time}` | 日期 / 时间 |
| `{$1}` `{$2}` … | 正则捕获分组；前缀匹配时 `{$1}` = 前缀之后的内容，`{$0}` = 整条消息 |

原版 Dice! 风格的旧变量名（如 `{pc}`）也有别名兼容，旧回复文案可直接沿用。

### 动态指令

| 写法 | 效果 |
|------|------|
| `{roll:3d6+2}` | 求值骰子表达式，替换为结果 |
| `{draw:塔罗牌}` | 从牌堆抽一张 |
| `{deck:塔罗牌}` / `{deck:%塔罗牌}` | 显式引用文件牌堆；前者在当前回复内不放回，后者放回，不受本群临时牌堆覆盖 |
| `{help:词条}` | 显式引用帮助词条 |
| `{text:strHello}` | 显式引用从旧版 CustomMsg 导入的全局文案 |
| `{a\|b\|c}` | 在候选中随机选一个 |
| `{sample:甲\|乙}` | 旧版 Dice! 随机分项语法，等概率选一项；开发中，需包含该修复的版本 |
| `{counter:名称}` | 当前计数器值（配合因果规则） |
| `{api:URL}` | 请求一个网址，把返回内容填进回复 |

旧版数据导入时，会将无歧义的裸引用规范化为上述显式前缀。`{牌堆}` / `{%牌堆}` 分别转为 `{deck:牌堆}` / `{deck:%牌堆}`，保留放回规则；帮助、全局文案分别转为 `help:`、`text:`。嵌套 `sample:` 的各个分支都会处理，但转义内容不会改写，导入过程中也不会实际抽牌或投骰。

疑似骰子表达式会保留原文并列入待确认项，因为字符形式不能保证求值成功，且旧裸表达式失败时保留原文，而显式 `roll:` 失败时显示 `?`。确认含义后可以手工添加 `roll:`，导入器不擅自改变失败行为。

同名变量、多个资源类型同名及未找到的引用保留原文，列入迁移报告；仅仍有待确认引用的旧回复保留裸牌堆引用兼容，变量含义不会被牌堆覆盖。新建回复请使用显式前缀。已经导入过的旧回复可以再次导入原数据；完整定义相同的旧规则会原位升级，不重复新增，并保留骰主调整过的启停状态与优先级。

::: warning {api:URL} 外部请求
`{api:}` 会让骰子向外部网址发起请求，**默认关闭**。需在[系统设置](/manage/settings)的「外部请求」中开启。

出于安全考虑，仅允许 http/https，并自动拦截内网 / 本机地址；可在配置文件中设置允许访问的域名白名单（`dice.api_whitelist`）。
:::

### 示例

```
触发：天气
回复：今天{a|晴|多云|小雨}，记得带伞～

触发（正则）：^点歌 (.+)$
回复：已为你点播《{$1}》🎵

触发：今日运势
回复：{nick} 的运势：{draw:运势}
```

## 因果规则（进阶）

「因果规则」是带状态的回复引擎，比基础回复多了**条件门槛**与**动作链**，用可视化编辑器编排：

- **条件**：关键词 / 前缀 / 正则 / 搜索之外，还可加 用户过滤、群过滤、冷却时间（按人 / 按群 / 全局）、计数器判断（如 `打卡次数 ≥ 7`），多条件同样支持 AND / OR。
- **动作**：发送回复（可多条随机）、计数器 设值 / 累加 / 重置、API 调用。
- **作用域**：全局 / 指定群 / 指定用户，并可设优先级与启停。

配合「计数器」选项卡可以做出打卡、抽奖限次、积分之类的玩法；计数器当前值可在回复里用 `{counter:名称}` 引用。

## 插入图片

回复内容支持图片：在管理面板编辑回复时点「插入图片」上传，图片以平台中立码 `[img,file=<本地路径>]` 保存，发送时自动转换成对应平台的图片消息。也可直接写入 CQ 码 / 海豹码（`[CQ:image,file=…]`、`[图片:…]`）。

发送形式在 系统设置 →「图片发送方式」选择：**base64 内嵌**（默认，QQ 框架跑在任何设备都能收到）或 **HTTP 链接**（可配主机，需 QQ 框架所在设备能访问）。
