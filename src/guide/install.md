# 安装部署

当前为公测（Beta）阶段。Release 提供 Windows（amd64 / arm64）、Linux（amd64 / arm64）与 macOS（arm64）发行包；容器化部署请参阅 Docker 项目说明。

## 下载与运行（Windows）

1. 在 [GitHub Releases](https://github.com/DiceZone/Dice-Next/releases) 获取与你的平台和架构相符的最新公测包。
2. **完整解压**到一个固定文件夹（路径建议不含特殊字符），不要放在系统临时目录中，也不要在压缩包里直接双击程序。
3. Windows 请双击 **`dice-next.exe`** 启动；Linux/macOS 推荐执行包内 **`./start.sh`**，由 `dice-next` 管理器启动核心。首次启动会自动生成 `config/` 与数据目录。
4. 程序默认**不显示窗口，直接最小化到系统托盘**（右下角弹气泡提示）。右键托盘图标可「打开网页面板 / 显示控制台 / 打开应用目录 / 退出」。
5. 打开管理面板：托盘右键 →「打开网页面板」，或浏览器访问 **`http://localhost:18088`**。

压缩包内已附带常见运行库（VC++ 运行时），一般无需额外安装；仅支持 64 位 Windows 10 / 11。

::: warning 临时目录启动限制
从 build 926 起，Windows 启动器和核心程序会检查程序目录及实际运行目录。若位于系统临时目录或其子目录，会拒绝启动并弹出中英双语提示，避免配置与数据留在随时可能被清理的目录中。请先完整解压到固定目录，再启动 `dice-next.exe`。
:::

::: tip 端口说明
默认端口 `18088`（可在 `config/server.json` 的 `port` 修改）。若端口被占用，启动时会**自动顺延到下一个可用端口并写回配置**——此时用托盘的「打开网页面板」总能打开正确地址。
:::

::: warning 单实例
同一套数据（同一个程序目录）只能运行一个进程，重复启动会自动退出，避免数据冲突。详见[故障排查](/guide/troubleshooting)。
:::

## 验证安装

启动后访问：

- **管理面板**：`http://localhost:18088`
- **状态检查**：`http://localhost:18088/api/system/status`

如果管理面板能打开，说明服务已正常运行。建议先在管理面板的 **WebUI 设置**里设置一个登录密码，然后去[快速开始](/guide/quickstart)接入你的 QQ 机器人。

## 开机自启

管理面板 → 系统设置里可开启**开机自启动**（随 Windows 登录自动启动，仅 Windows）。无需再手动配置任务计划。

## 升级

### 管理面板自动更新

打开**管理面板 → 关于项目 → 检测与自动更新**：

1. 点“立即检查”，程序从 GitHub Release 的 `update-manifest.json` 获取最新版本与当前平台安装包。
2. 默认“自动选择”会并行探测 GitHub 直连和内置镜像；中国大陆网络不稳定时会自动采用先成功的镜像，也可强制仅镜像或填写可信的自定义 HTTPS 镜像。
3. 点“下载更新”后，程序核对清单仓库、平台、架构、文件名、文件大小与 SHA-256。Windows 还会在解压前检查路径穿越和包结构。
4. 使用完整包的管理器启动时，可点“安装并重启”：Windows 使用 `dice-next.exe`；含 POSIX 管理器的 Linux/macOS 新包使用 `start.sh` 或 `dice-next`。管理器等待核心完全退出后替换程序、运行库、WebUI、文档与内置资源；替换失败时逆序回滚程序文件。

右上角的版本文字可直接打开更新区域，有新版本时显示红色 New。下载阶段支持取消：等待“已取消”后可重试；连续 60 秒无新增数据或单个来源尝试超过 20 分钟时会终止本次传输，并按配置换源。失败 / 取消只清理本次未完成文件，不要求重启程序。校验和安装准备阶段也可取消，但已经开始的正式安装不能取消。

网页请求超时并不代表后台任务停止，应等待面板重新获取状态，或点击刷新状态后再操作。

::: warning Linux/macOS 首次升级
beta.928 及更早的包没有 POSIX 管理器，需要停服后完整覆盖到包含 `dice-next` 的新包一次。后续用 `start.sh` 或 `dice-next` 启动，面板才开放一键及定时安装；仅换 WebUI 或直接运行 `dice-next-server` 不会启用完整自动更新。此能力尚待新发行包发布。
:::

Linux/macOS 管理器在前台运行，适合由 systemd / launchd 监控；服务入口应指向 `start.sh` 或 `dice-next`。管理器将工作目录统一为安装目录，自定义配置目录请传入绝对路径；后续重启保留参数。安装目录需对运行账号可写，更新器不请求 sudo、不移除 macOS 隔离属性，也不绕过 Gatekeeper。

POSIX 更新会限制解包大小与数量，拒绝目录穿越、硬链接和特殊文件，仅允许 `lib/` 内部的安全符号链接。替换前探测新核心和管理器的可执行性、动态库加载；替换中断可由事务记录恢复。仅程序文件回滚，不自动降级数据库；程序成功加载后的业务故障仍需保留备份并人工排查。

自动检查默认开启、间隔 6 小时、发现更新后仅通知。你可以改为自动下载；“自动安装并重启”需要 Windows 或新版 Linux/macOS 管理器模式。直接运行核心时可检查 / 下载，不能安装。容器部署只检查并通知，不下载或安装程序更新；请拉取新镜像并重新创建容器。

管理器模式还可开启**定时安装**：先下载并校验更新包，在指定时间主动重启安装，初始时间为 **04:00**。时间按服务器设置计算，面板显示具体日期和 UTC 偏移；下载完成时当天时间已过，则安排到次日。自动安装开启且包已就绪时，任何提前发生的重新启动都会顺带安装，包括手动重启、退出后再次打开、系统重启和守护进程拉起。定时仅限制程序主动发起的重启。修改时间或时区会重新安排；关闭定时只取消主动重启计划。若想保留下载包却不在启动时安装，请改为“仅下载”或“仅通知”；仍可手动安装。

::: tip 容器升级
官方镜像带有明确的容器标记，程序也会用 Docker / Podman 标记、Kubernetes 环境变量和 cgroup 信息兜底识别。检测到容器后，WebUI 会禁用手动与自动下载 / 安装，但版本检查仍可使用。Compose 部署可执行 `docker compose pull dice-next`，再执行 `docker compose up -d --force-recreate dice-next`；挂载的 `config/` 与 `data/` 会保留。
:::

::: warning 镜像信任边界
SHA-256 可以发现下载中断、损坏或清单与安装包不一致，但不是独立的发行签名。选择内置或自定义镜像代表信任该来源；对供应链要求较高时，请使用“仅 GitHub”，并在 Release 页面核对版本。
:::

### 手动升级

也可以从 [GitHub Releases](https://github.com/DiceZone/Dice-Next/releases) 下载对应平台的新包，停服后**完整覆盖程序文件**——exe、运行库、`i18n/`、`web/dist/`、`docs/` 与包内内置资源都需要更新。

个人数据不会被安装包清空：

- 配置目录 `config/` 不在发行包内；
- `data/` 下的数据库、跑团日志、媒体与用户自建资源会保留；
- 内置 `data/helpdoc` 会随版本刷新，`data/plugins` 采用覆盖内置文件但保留其他文件的方式更新。

升级前仍建议从管理面板制作备份，或手工备份 `config/` 与 `data/`。

## 将管理面板安装为应用

WebUI 提供应用清单与图标。打开要管理的服务器地址后，可使用浏览器提供的安装入口：Chrome / Edge 地址栏图标或菜单中的安装应用；macOS Safari 的“添加到程序坞”；移动端浏览器的“添加到主屏幕”。入口是否出现及名称由浏览器决定。

使用 HTTPS，或本机 `http://localhost:端口` / `http://127.0.0.1:端口`。普通 HTTP 局域网 / 公网地址可能不显示推荐安装入口，不要为此关闭浏览器安全限制。

安装的只是当前地址的管理面板独立窗口，**不会安装或后台启动机器人后端**。后端仍需运行，登录校验不变；没有 Service Worker、离线管理或管理 API 缓存。服务器地址改变后需从新地址重新安装。
