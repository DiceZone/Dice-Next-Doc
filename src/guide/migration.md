# 数据迁移

从旧版 Dice!（V2）迁移可转换的数据到 Dice!Next。迁移器会保留旧目录，且不会复制登录凭据或 WebUI 密码。

::: warning 当前范围
这不是“把旧数据目录原样搬进新版”的功能。旧版与 Dice!Next 的存储结构、团务模型和插件运行环境并不相同；导入完成后，请保留旧目录并在测试群核对人物卡、团务、日志与插件。
:::

## 已支持的迁移范围

导入器直接解析旧版 Dice! 数据目录的原始文件（含二进制 `.dat` / `.RDconf` 格式），转换写入 Dice!Next：

| 旧版数据 | 文件 | 迁移到 |
|---------|------|--------|
| 人物卡 | `user/PlayerCards.RDconf` 及有效备份 | 统一人物卡库：属性、原名、卡类型、表达式、锁定与选卡绑定；兼容旧属性名，全局作用域自动转换 |
| 用户数据 | `user/UserConf.dat` | 玩家档案（昵称 / 信任等级 / 好感）及 Lua 兼容用户配置；群内昵称单独保留 |
| 群配置 | `user/ChatConf.dat` / `ChatConf.RDconf` 及有效备份 | 选定账号的群停用、忽略、回复/指令开关、COC 房规与欢迎词；插件变量保留类型 |
| 黑名单 | `conf/BlackList.json` | 有效的本地用户封禁；撤销/无效记录不复活，未知云来源和群/关联人策略列入确认报告 |
| 自定义回复 | `conf/CustomMsgReply.json` | 关键词回复（多结果随机 / 文本）；不能等价转换的限制默认停用，无法通过运行时校验的内容只保留原稿 |
| 自定义文案 | `conf/CustomMsg.json` | 回复文案覆盖（写入简体中文层） |
| 自定义帮助 | `conf/CustomHelp.json` | `.help` 词条覆盖（写入简体中文层） |
| 骰主 | `conf/console.yaml` / `Console.xml` | 选定账号的 Master 列表与支持的运行设置；YAML 优先，损坏时不采用过期 XML 权限 |
| 外置牌堆 | `PublicDeck/` | 校验 JSON 内容后迁入 `data/decks/`；嵌套同名文件生成唯一安全文件名，并迁入可定位的本地媒体依赖 |
| Lua 模组 | `mod/` | `data/mod/`（整棵复制，由 Lua 模组子系统识别） |
| Lua 插件 | `plugin/` | `data/plugin/`（单文件和目录型插件单独复制） |
| 跨群链接 | `conf/LinkList.json` | 新版 `.link` 消息转发：迁入普通 QQ 群之间的 `with/to/from` 链接及暂停状态 |
| 通知窗口 | `conf/NoticeList.json` | 所选账号的 QQ 私聊/群聊通知及原级别掩码；旧共享窗口可用 `.notice status/off` 管理 |
| 自定义敏感词 | `conf/CustomCensor.json` | 系统设置中的敏感词拦截：保留 Ignore–Critical 数字等级；有规则时自动启用 |
| 团务会话 | `user/session/*.json` | 生成随机 16 位团号并记录来源；同源重导复用，早期记录或目录副本需确认衔接，轮盘只恢复剩余池 |
| 跑团日志 | `user/log/*.txt` 与 session 内日志状态 | 新版日志库：迁入文本记录，恢复进行中 / 暂停 / 已结束状态 |

::: tip 说明
- 自定义文案 / 帮助只写入**简体中文**层，其他语言保留 Dice!Next 自带文案。
- 旧版文案键（`strXXX`）中在新版有已核对的对应槽位、且运行时参数兼容的会自动映射；例如骰点、成功等级、牌堆、团务、旁观、欢迎词等。**没有对应槽位或参数不兼容的不会丢**——会以「无效文本」形式保留，可在管理面板中查看后手工移植。
- 用户与群的标量自定义配置会保留到 Lua 兼容配置空间；这不表示每个旧版内置功能在新版都具有同一行为，但旧 Lua 规则可继续读取这些值。
- 用户与群变量的布尔、小数、空字符串和可序列化结构会保留类型。旧函数不执行，不能等价接入的字段会列入报告。
- 牌堆按内容校验，不只根据扩展名判断；非牌堆文件仍跳过并给出原因。
- 人物卡的原生技能值仍遵循新版规则系统；保留布尔/嵌套原稿不表示它们会被当作整数技能。
- 旧二进制文件会分别完整校验 64 位与 32 位的 `size_t` 布局，通过后才写入数据库；失败尝试不会留下半份档案。旧函数不执行，嵌套函数也会列入待处理报告，原始字节仍保留在旧文件中。
- Lua 的旧 Set 变量会恢复集合方法，并支持用户、群、团务配置及人物卡中的集合修改写回；不把普通 JSON 数组擅自当成 Set。
:::

### 人物卡读写与文本导出

`STR`、`HP` 等已登记别名可读取旧卡中的原始字段，不要求先批量改写卡片。若原名和标准名保存了不同值，原数据均保留，迁移报告提示冲突；请按规则系统确认，不自动选一个值覆盖另一个。

表达式使用统一人物卡数据，原生指令、Lua 和 JS 读取一致。修改、删除、清空和选卡切换不再让旧表达式从兼容副本重新出现；清空会删除文本、小数和结构属性，但保留名字、类型与锁等元数据。

- 只有普通整数属性时，`.st export` 仍使用原来的 `.st 力量50 …` 写法。
- 有表达式、文本、小数或结构属性时，输出 `json {...}`，可用 `.st json {...}` 重新导入。该操作替换当前卡的可编辑属性，遵守写锁；读取导出遵守读锁。
- 指令 JSON 限制为 256 个字段、64 KiB，超大卡请使用完整 JSON 卡导出。JSON 原始卡导出与云卡数据不丢弃冲突字段。

### 早期团务和目录副本

发现已有的同名、同群旧导入团务，或相同原稿的目录副本时，迁移器先暂停该团及其关联日志的迁入，报告不会显示完整完成。面板会列出候选：

1. 若确认是同一团，选择已有团务并应用衔接，保留原团号和当前变量。
2. 未开启数据覆盖时，不覆盖已有变量；需用旧值替换时要明确开启覆盖并确认。
3. 确实是另一份团务时，可明确选择新建独立团务；默认不猜测合并，也不偷偷新增。

每次确认后继续迁移都会先创建新的恢复备份。人物卡与旧团务仍使用共享兼容空间，不能据账号选择推断所有数据都完成了账号级隔离。

### 迁入图片的备份

完整备份及勾选「资源图片」的局部备份会包含根目录 `image/` 和牌堆迁入的媒体。新版备份格式为 4，恢复时会同时还原这些资源；仍支持格式 1–3，恢复旧包不会清空它未包含的根目录图片。备份与恢复不跟随符号链接或 Windows 重解析点。

## 迁移限制与尚未自动迁移的数据

下列内容已经列入迁移改进计划。在对应版本发布前，导入器会保留旧目录中的原文件，不会擅自删除：

| 旧版位置 / 数据 | 当前处理 | 原因与后续方向 |
|---|---|---|
| `user/GameTable.toml` | 不单独迁移 | 它只保存旧版自增序号；新版团号使用不可预测的随机编码，因此不能沿用。 |
| `conf/LinkList.json` 中的私聊、讨论组、频道链接 | 不迁移 | 新版 `.link` 仅支持普通群之间的转发；可安全对应的 QQ 群链接已自动迁入。 |
| 旧会话内的观察者、牌堆、tables | 原稿保留，需确认 | 完整会话原稿与这些字段另存为兼容信息；没有等价活动状态的部分不自动启用。报告明确区分“仅保留”和“已接入”。 |
| 插件自建目录、任意自定义文件 | 尚未迁移 | `plugin/` 本体会复制；插件运行时自行写入的任意位置无法安全推断用途。 |
| `CustomReply.json`、`CustomRegexReply.json` | 已支持 | 在较新的 `CustomMsgReply.json` 缺失或为空时，转换为新版关键词/正则回复规则。 |
| 邀请人、活动时间、许可/免黑/忽略等群状态 | 尚未迁移 | 仅能迁移在新版有明确且安全对应项的设置。旧缓存群名会以兼容信息保留，不会直接覆盖当前适配器读取到的群名。 |
| 黑名单的群条目、关联人、外部/云黑来源 | 保留并报告 | 用户 `local/ban/kick` 等有效本地记录可迁入；无法证明来源或涉及旧免黑/信任策略的记录不变成本地处罚。 |
| 控制台中的任务、Git/WebUI 凭据、过时云设置 | 不迁移 | 明确对应的运行开关可导入；可执行任务和敏感凭据需重新配置，不沿用旧环境。 |
| `selfdata/` | JSON 接入，其他格式原稿保留 | 顶层 JSON 存档迁入 `data/self_data/`；其他格式与嵌套路径不伪装成已生效，列入确认报告。 |
| `CardTemp/`、`conf/censor/` 外置词库 | 原文件保留 | 保存于 `data/legacy-import-preserved/`，不执行旧脚本、不擅自启用未经确认的词库。 |
| 根目录 `image/` | 媒体迁入 | 本地媒体保留相对路径；不能安全定位的牌堆引用留原文并报告，不读取所选目录外的文件或跟随链接。 |
| 每日统计与历史使用计数 | 不自动接入统计系统 | 旧统计口径与新版不同，不能当作新版测量结果。请保留旧目录以便查阅。 |

## 自定义文案与帮助

旧版 Dice! 的自定义文案和帮助以简体中文为主，因此导入器**只写入 `zh-Hans`** 是预期行为；繁体中文和英文继续使用 Dice!Next 内建文本。

- 有新版一对一槽位的 `strXXX` 文案会接入对应模板；已设置的新等级回复、原生指令模板仍按现有优先级使用。
- 迁入时会把已核对的旧占位符（如 `{pc}`、`{deck_name}`、`{game.log_name}`）转换为新版占位符。新版已不再提供必要参数的旧模板（例如旧 `.log off/end` 的日志名、文件名模板）不会强行迁入。
- 没有等价槽位或无法安全转换占位符的文案会保存在管理面板的「无效文本」中，不会丢失也不会冒充已经生效。
- 每次扩充新版文案槽位时，会重新核对这批无效文本；能找到明确语义对应的键会加入映射，无法保证语义等价的仍保留给骰主手工处理。

新增的[按检定结果分级回复](/manage/commands#按检定结果设置完整回复)默认继承原有文案，不会自动写入覆盖、清除已迁入文本或要求重新导入。已兼容的完整模板和成功等级短语继续生效；只有主动配置新等级回复时，才按新的继承链选择完整回复。

以下检定文案缺口已补齐，无需把旧短句改写成新等级的完整回复：

| 旧文案 | 新版兼容处理 |
| --- | --- |
| `strRollCriticalSuccess/strRollExtremeSuccess/strRollHardSuccess/strRollRegularSuccess/strRollFailure/strRollFumble` | 单轮检定的六个独立等级短句，不混同多轮短句 |
| `strCriticalSuccess/strExtremeSuccess/strHardSuccess/strSuccess/strFailure/strFumble` | 继续作为多轮检定和 SAN 的等级短句 |
| `strRollSkill/strRollSkillReason` | 检定前缀；连续多轮只加一次前缀 |
| `strRollSkillHidden` | 暗检定群回执，不泄露私聊详细结果 |
| `strSanityRoll` | 保留 SAN 完整模板及 `rank/loss/change/final` 的旧变量含义 |
| `strEnRoll/strEnRollNotChange/strEnRollFailure/strEnRollSuccess` | 成长基础文本、未变化、失败变化、成功变化分别保留，引用随基础文本修改而更新 |
| `strEnDefaultName` | 默认成长技能名称 |

支持嵌套 `sample`、`case`、`grade`，以及已映射旧文本的引用（如 `{strEnRoll}`）；不会执行 JavaScript、Python、等待等可执行宏。条件字段或变量无法对应时，报告标为「部分兼容」；不支持的宏、语法不完整和循环自引用保留原文，等待人工迁移。**这不是旧版全部模板宏的全覆盖声明。**

新导入的上述兼容文本会保留 `legacy.strXXX` 原稿，不覆盖已有且内容不同的目标。管理面板「备份与导入」可查看、下载逐项报告，区分已接入、部分兼容、仅保留、冲突跳过。「已接入」表示成功映射到文本槽，不表示替换了优先级更高的新回复。

已有数据库会在升级后的首次启动自动补回能安全对应的历史孤立槽位，并修正早期 `dice.crit/dice.fumble` 的单轮短句映射。全局与人格均保留原记录，不覆盖已有目标（包括主动设为空的目标）。修复记录持久保存；恢复默认后，下一次启动不会把已清除的旧文案重新补回。没有可靠旧原稿的缺口仍需重新导入，修复记录不是当前配置的实时审计。

## 旧版指令兼容边界

Dice!Next 直接复用新版存储、权限与插件管理实现旧写法，不运行一套平行的旧内核。当前已核对的迁移重点如下：

| 原版写法 | Dice!Next 行为 |
|---|---|
| `.h` / `.H`、`.rh`、`.rs` | 短暗骰别名与仅最终值输出均保留；`.help` 不会被 `.h` 抢占 |
| `.coc/.coc7`、`.coc6`、`.cocd/.coc7d/.coc6d` | 分别生成 7 版、6 版及详细制卡结果；接受旧排版标记 `s` |
| `.help on/off`、`.jrrp on/off`、`.reply on/off` | 按群持久保存，沿用群管理 / 信任权限 |
| `.drawh` | 私聊发送抽牌结果，群里只留暗抽回执 |
| `.pc nn/stat/cpy/copy/grp/tojson/type/temp` | 接到统一人物卡与规则系统；复制顺序为 `目标卡=来源卡` |
| `.rule set <书>`、`.ruleset clear` | 接到统一规则书设置；设置和清除都校验群管理权限 |
| `.mod list/on/off/info` | 接到统一插件清单与分群启停；更新、重载、删除、重装仅在 WebUI 确认 |
| `.user state/trust/tojson/diss` | 接到统一玩家档案、权限和名单；`diss` 不删除档案或卡片 |
| `.strXXX <文本/show/reset/NULL>` | 仅已审计的一对一文案键写入统一覆盖表；未知 `str…` 不会被吞掉 |
| `.cloud update/black` | 不复刻。旧版这两条只报告状态并把人指向网页；版本号看不带参数的 `.bot`，云黑开关在网页「系统设置」。`.cloud` 现为账号中心授权与[云人物卡](/use/cloud)入口 |

::: danger 刻意不复刻
- `.system cmd`：旧版远程 Shell，风险等同远程代码执行。
- `.user kill/clr`：聊天中不可逆删除玩家或卡片；请在 Web 管理面板二次确认。
- `.mod update/reload/del/reinstall`：聊天中不替换或删除插件文件。
:::

JS 插件的兼容来源是 **SealDice（海豹）`sealdice-core`**，不是旧 Dice! JS；具体钩子、字段和限制见 [JS 插件 API 参考](/develop/js-plugin-api)。

## 迁移步骤（管理面板）

1. 把旧版 Dice! 的数据目录（**内含 `conf/` 与 `user/` 的那一层**）放到运行 Dice!Next 的这台机器上。
2. 打开管理面板 → **系统设置 → 备份恢复 → 导入旧版数据**。
3. 填写该数据目录的**完整路径**，选择要迁入的 OneBot / Milky 账号。共享兼容层只写 OneBot 共享设置；QQ 官方 OpenID 等身份不能凭旧 QQ 号推算。
4. 默认保留已有 Next 数据。资源文件覆盖与数据库/配置覆盖是两个独立选项；启用数据覆盖会再次确认，其他语言文案不会被删除。
5. 点「开始导入」。服务器先创建恢复备份；备份失败则不开始迁移。
6. 核对报告的失败、停用、冲突和“仅保留”项。迁入的 Lua 插件不会由导入器执行，确认后在插件管理中重新加载。

对应 REST 接口为 `POST /api/legacy/import`，参数 `{ "dir": "路径", "overwrite": false, "overwrite_data": false, "target_adapter_id": "账号ID" }`。不指定目标账号时使用 OneBot 共享兼容层。

接口传输成功不等于迁移完整成功：请检查 `data.ok`、`data.complete`、`data.errors` 和 `data.diagnostics`。部分失败的报告仍会返回，避免丢失已经完成阶段的结果。只有完整成功才可能移除 BDC 迁移标记。

## 迁移报告

### 回复引用规范化

导入器先导入牌堆、帮助与全局文案，再根据实际可用资源处理回复及冷却 / 日限提示语中的引用。无歧义引用会自动转换：

- `{牌堆}` / `{%牌堆}` → `{deck:牌堆}` / `{deck:%牌堆}`，保留当前回复内不放回 / 放回规则，并只引用文件牌堆。
- 帮助词条 → `{help:词条}`；旧全局文案 → `{text:文案名}`。
- `{nick}` 等上下文变量及已有显式前缀保持不变，转义内容不改写；嵌套 `sample:` 的所有分支均会处理。不会在导入时实际抽牌或投骰。

变量与资源同名、同时匹配多个类型、未找到资源时，保留原文并报告原因。仅仍有待确认引用的旧回复保留裸牌堆查找兼容；新回复使用显式前缀，避免新增牌堆后意外覆盖原有表达式或帮助引用。

疑似骰子算式也列入待确认项：旧裸表达式求值失败会保留原文，而显式 `roll:` 失败会显示 `?`，不能仅根据字符形式自动替换。确认含义后可手工添加 `roll:`。

导入结果中的 `replyReferences` 包含转换数、歧义数、未找到数及每处引用的规则、位置、原文、目标和原因。网页可展开明细或下载 JSON 报告。请保留报告，按实际用途修正待确认项。

已经导入过的规则可重新导入原数据：完整定义相同的规则原位升级，不重复新增，保留骰主调整的启停状态与优先级；后续补齐资源后，再次导入也会尝试规范化仍待确认的旧引用。

导入完成后返回各项数量，包括：

- 人物卡数（及涉及的用户数）、玩家档案、黑名单、自定义回复、帮助、文案（另计「无效文本」条数）、Master 数
- 牌堆、模组与插件的**成功 / 失败 / 跳过**明细（逐文件列出原因）
- 群配置：导入的设置项数与涉及群数；跨群链接、通知窗口、敏感词规则、团务会话、日志和日志消息数量

页面会展示逐项结果、团务/日志汇总、恢复备份与报告位置；大量记录限制屏幕展示数量，完整报告可下载。报告同时保存在服务器的 `data/legacy-import-reports/`，可能包含旧规则原稿，请勿直接公开。

## 注意事项

- **迁移前**：备份旧版完整数据目录；确保该目录可被 Dice!Next 所在机器访问。
- **可重复导入**：新迁移记录使用稳定来源身份，同源团务不重复新增。默认保留已有数据；日志只自动补入完整追加消息，原正文被改写或新版消息已编辑时保留现状并报告。旧导入记录缺少来源依据时需人工确认，不会猜测并删除它们。
- **损坏文件**：人物卡、用户及群的二进制文件先完整校验，再写入该类数据；主文件坏了会尝试有效备份，全部损坏会报告错误，不把截断内容当成功。
- **部分失败**：不是全目录原子事务，部分阶段可能已写入；请核对报告，必要时使用迁移前备份恢复。旧源目录和待确认原稿均保留。
- **迁移后**：在[测试台](/manage/dashboard)或测试群验证掷骰、检定、自定义回复是否符合预期。
- 部分指令语法在 Dice!Next 做了规范化，差异见[掷骰与检定](/use/dice)。
