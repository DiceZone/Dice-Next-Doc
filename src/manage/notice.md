# 通知设置

**管理面板 → 系统设置 → 通知设置**，按接收窗口管理通知来源、订阅范围与审计日志。

## 通知窗口

页面支持卡片／列表、搜索和服务器端分页。卡片显示接收对象的昵称、帐号和头像；点击编辑再调整订阅事件。

点击顶部的添加按钮，先选择**一个通知窗口**：一个群、一个用户、一个收件邮箱或一个 Webhook。聊天窗口再选择发送帐号，可选择同平台的多个帐号；邮件和 Webhook 也各自作为一个独立窗口管理。同一个目标不能重复新增，请编辑已有窗口。

随后配置这个窗口的监听来源（全部适配器、一个或多个平台、一个或多个骰娘帐号）及订阅范围（全部通知、按级别、按具体事件）。系统更新等没有具体来源帐号的事件由「同时接收程序级通知」单独控制。弹窗顶部保存，内容区域独立滚动，宽屏分两列，窄屏改为单列。

历史上指向同一窗口的多条规则会归并展示，各条规则的来源与事件范围仍独立保存，不会扩大订阅。例如「帐号 A 的好友通知」和「帐号 B 的错误通知」不会被合成「A、B 的所有好友和错误通知」。如果旧规则使用不同的发送帐号，默认保留，只有明确选择统一发送帐号后才会改变。

来源过滤与发送帐号选择独立：明确指定的发送帐号不会在失败后擅自换号；自动选择模式才会按既有策略尝试同平台可用帐号。

也可在聊天里发 `.notice on`（仅骰主）把当前窗口设为通知窗口，详见[管理指令](/use/admin)。

每个窗口可**逐项勾选**要接收的通知事件；事件按四个区域分组：

| 区域 | 级别值 | 包含事件 |
|------|--------|----------|
| 例行通知 | 1 | 信任、帐号权限关联、定时任务与通知订阅变更 |
| 重要通知 | 2 | 好友与群申请、骰娘入退群、禁言与群管理员权限、各类主动退群规则、群开关、任务触发、全局静默、更新进度；敏感词实际级别依规则变化 |
| 关键通知 | 4 | 骰娘管理权限、黑白名单与骰娘名单变更 |
| 错误通知 | 8 | 运行错误、退群请求失败、更新失败 |

用指令 `.notice level <n>` 订阅时（1 例行 / 2 重要 / 4 关键 / 8 错误，可叠加，15 = 全部），默认勾选对应区域的全部事件。

这与程序日志的 TRACE／DEBUG／INFO／SUCCESS／WARN／ERROR 过滤不同。从旧版导入的空事件列表会保留级别订阅语义，并按实际生效事件显示；明确切换到按事件订阅且清空列表，才是不接收事件。

更新检测属于系统事件，没有具体来源群。自动安装结果由管理器重启后回报，并核对实际运行版本。级别订阅包含新增的同级事件；已经逐项筛选的规则不会被擅自扩展，请按需勾选新增事件。

## 通知如何表达结果

```text
[骰娘被踢出群聊] 骰娘被小明(3569827618)踢出群未归星璇(792364383)。
适配器 OneBot:3626455591
```

主动退群分成“请求已提交，等待平台确认”和平台实际回执。明确的被踢／解散事件优先于此前的主动请求；原因未知就明确写未知，不仅凭操作者帐号推断。

好友与加群申请会写出申请人、群、处理决定与依据。审批调用只提示“已提交自动同意／拒绝”，关系建立由实际平台事件确认。

名称优先使用事件及来源帐号缓存，再查历史记录；没有可靠名称则保留帐号，不编造昵称。面板密码登录没有可核实 QQ 身份时会如实注明。插件错误保留插件名、操作和真实解释器错误（含真实行号），不推测底层没有报告的根因。

## 邮件与 Webhook 窗口

不在 QQ 上也能收到通知：

### SMTP 邮件推送

优先复用权限／身份验证页面的共享 SMTP 配置，窗口只需填写一个收件邮箱，不需要重复填写 SMTP 口令；共享发送配置未设置时兼容旧通知 SMTP。465 使用 SSL，587 等按邮件传输设置执行。

没有有效 SMTP 配置时，编辑器会显示提示并阻止保存，点击「配置 SMTP」可在新标签页打开已有设置。返回后会刷新配置状态，原窗口草稿保留。旧通知 SMTP 凭据不会因编辑或删除收件窗口而被清除。

邮件主题为 `[Dice!Next] 事件标题`，正文与聊天通知一致，不在变更通知里暴露授权码等信息。

### Webhook 推送

新增窗口时选择 Webhook，填写完整 HTTP(S) 地址。地址未填写或无效时会提示，并提供定位到地址输入框的按钮。

内置通用 JSON、企业微信、钉钉、飞书预设。选择对应类型即可生成文本消息请求体；钉钉或飞书机器人启用加签时，在高级选项填写签名密钥，发送时生成时间戳与签名。机器人自身的关键词、IP 白名单等限制仍需按服务商要求配置。通用 JSON 默认使用 `POST`，格式保持兼容：

```json
{ "ts": "…", "level": 2, "op": "group_left", "title": "骰娘被踢出群聊", "msg": "[骰娘被踢出群聊] …", "origin": "onebot_v11:792364383" }
```

`op` 是稳定订阅键；`title` 随具体结果区分被踢、主动退群、解散。邮件与 Webhook 同样受规则的级别／事件及来源过滤控制；兼容旧全局渠道。

### 高级请求与通知变量

高级选项支持 `POST`／`PUT`／`PATCH`、静态 JSON 请求头和自定义 JSON 请求体。「请求体示例」只在浏览器内预览，不会发送网络请求。切换预设会恢复该类型模板。

变量写在 JSON 的字符串值中；完整占位符会保留变量类型，例如 `"severity": "{{level}}"` 发送时为数字。通知正文中的引号、换行会自动进行 JSON 转义，不要手动转义整段正文。

```json
{
  "summary": "{{title}}",
  "text": "{{message}}",
  "severity": "{{level}}",
  "source": { "adapter": "{{adapter_id}}", "group": "{{group_name}}" }
}
```

| 变量 | 内容 |
| --- | --- |
| `{{message}}` | 完整通知正文 |
| `{{title}}` | 本条事件的标题 |
| `{{time}}` | 服务器配置时区的通知时间 |
| `{{level}}`／`{{level_name}}` | 通知级别数字／名称 |
| `{{event}}`／`{{origin}}` | 稳定事件键／发生地标识 |
| `{{platform}}`／`{{adapter_id}}`／`{{account_id}}` | 来源平台／适配器 ID／骰娘帐号 |
| `{{group_id}}`／`{{group_name}}` | 来源群 ID／群名 |
| `{{user_id}}`／`{{user_name}}` | 来源用户 ID／昵称 |

系统事件可能没有群、用户或来源帐号，对应值为空，不编造身份。变量只替换一次，不会执行脚本，也不会继续解析通知正文里恰好出现的占位符；URL、请求头及 JSON 对象键不参与替换。

请求体模板须为 64 KiB 以内的 JSON 对象，嵌套最多 16 层；渲染后最大 256 KiB。请求头只支持字符串值，不允许换行或覆盖 Host、Content-Length 等受保护字段。Webhook 地址、签名密钥、自定义请求头和请求体中的凭据不参与列表搜索，受限管理员查看时会被遮蔽。

企业微信文本超过服务商长度限制时会安全截断，完整内容仍可在审计详情查看。Webhook 的 HTTP 错误或预设服务商返回的失败状态会记入本地日志，不把“提交请求”当作成功送达。

测试窗口时只尝试这个窗口配置的发送帐号或渠道，即使旧规则原本同时包含其他接收渠道，也不会顺带向它们发送。手动测试可绕过窗口暂停和日常事件订阅；全局测试仍只使用启用的规则。测试不修改订阅，也不等于平台最终送达。

## 审计日志

全部通知事件持久化在 `data/audit/notice_*.jsonl`，可回溯时间、级别、事件、发生地与内容。通知不回推产生它的同一聊天，避免和指令回复重复；按修改后的订阅投递，已关闭的窗口不会临时恢复一次通知自己。

表格每行固定高度，过长内容单行省略，点击内容打开详情弹窗，查看完整正文与事件信息。窄屏可横向滚动表格，表头不会逐字换行。

同来源同种错误短时间合并，不屏蔽其他群或插件的新错误。通知窗口本身不可达只记本地错误日志，不能再生成自己的失败通知，避免无限嵌套；详细平台原因保留在本地结构化日志。

完整模板审阅稿在主程序仓库 `docs/notification-templates.md`，逐项列出触发条件、级别、文案与信息缺失时的处理。

::: tip
无论有没有配置通知窗口，事件都会写入审计日志——窗口和推送只决定「有没有人被主动告知」。
:::
