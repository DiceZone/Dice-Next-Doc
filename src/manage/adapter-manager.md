# 适配器管理

**管理面板 → 平台连接**，添加、启停与监控连接。连接状态每几秒自动刷新，无需手动刷新页面。

## 添加适配器

QQ 官方机器人已添加后，可前往 **高级回复 → 卡片与按钮**，或使用账号卡片「更多 → 卡片与按钮」快捷入口，按账号可视化编辑单聊菜单和指令面板。具体场景、条目限制与关联操作见 [QQ 官方 API v2 能力](/develop/qq-official-api#可视化编辑)。

点击「添加连接」，表单为**渐进式引导**：先选连接方式，选定后才出现地址等后续字段。

支持 OneBot v11、Milky、QQ 官方机器人、Discord、KOOK，以及实验性的 OpenOPQ 内置登录。先选择平台，再按该平台填写凭据和端点；下表的连接模式说明针对 OneBot v11，Milky 和内置登录参见下方专节，其他平台使用各自的连接字段。

| 字段 | 说明 |
|------|------|
| 适配器名称 | 识别用显示名 |
| 适配器类型 | 按实际平台选择；此表以 OneBot v11 为例 |
| 连接模式 | 正向 WebSocket / 反向 WebSocket |
| 连接地址 / 端口 | 正向填端点地址（如 `ws://127.0.0.1:3001`）；反向填本程序监听的端口 |
| Access Token | 认证令牌（可选），留空则不校验 |

- 连接模式旁有 **? 帮助图标**，悬停显示正向 / 反向的详细说明；选定后表单内也会显示对应提示。
- 正向地址会**自动纠正**协议头（漏写补 `ws://`，`http/https` 自动转 `ws/wss`），非法地址与端口有即时校验提示。

### OneBot v11：连接已登录的 QQ 客户端

1. 在支持 OneBot v11 的框架（如 NapCat）中登录骰娘 QQ，打开框架的网络配置。
2. **正向连接**：在框架中新增 WebSocket 服务端并保存，记下监听地址、端口和令牌。在 Dice!Next 的「平台连接 → 添加连接」选 OneBot v11、正向 WebSocket，填写该服务端地址和相同令牌。
3. **反向连接**：在 Dice!Next 选反向 WebSocket，指定空闲端口并启用。在卡片「连接方式」复制框架能访问的地址，再到框架中新增 WebSocket 客户端，粘贴地址，填入相同令牌并启用。
4. 用另一个 QQ 给骰娘发送 `.r 1d6`，确认收到骰点。若一直等待连接，检查是否两边都设成了服务端。分开部署时，从主动连接的一端检查地址；容器内的 `127.0.0.1` 指向该容器自身。

### 传输模式说明

| 模式 | 行为 | 框架处配置 |
|------|------|------|
| 正向 WebSocket（`forward_ws`） | 本骰作为 WS 客户端，**主动连接**登录框架的 OneBot v11 WS 服务端 | 选「WebSocket服务端 / 主动WebSocket / 正向WebSocket」，填框架监听端口 |
| 反向 WebSocket（`reverse_ws`） | 本骰作为 WS 服务端在本地端口监听，**等待框架连入** | 选「反向WebSocket / 被动WebSocket / WebSocket客户端」，填 `ws://本机IP:端口` |

::: tip 区分正向 / 反向
按「谁主动发起连接」区分：正向＝Dice!Next 去连框架；反向＝框架来连 Dice!Next。两端配置要一一对应。
:::

反向 WS 适配器可点「连接方式」查看**连接信息**。地址来自运行 Dice!Next 的服务器，不是打开面板的电脑：

- **本机**：`127.0.0.1`，只适用于框架与骰子运行在同一台服务器。
- **内网**：读取服务器的活动 IPv4 网卡；多网卡、VPN 或容器环境可选择地址。
- **公网**：后台通过外部服务查询服务器的 IPv4 出口地址，不再复用内网 IP。

服务器地址发生变化时，点击「刷新地址」。若仍未取得公网地址，可手动填写框架能访问的地址。

::: warning 公网 IP 不等于端口可达
公网连接仍需确认 NAT／容器端口映射、服务器防火墙与安全组。地址检测不会自动开放端口或修改这些设置；内网无 IPv4 或外部查询不可用时，不影响使用正确的手动地址。
:::

## QQ 官方机器人

1. 在 [QQ 开放平台](https://q.qq.com/) 创建机器人。
2. 在「添加连接 → QQ 官方机器人」扫码授权，或手动填入该应用的 AppID 和 AppSecret。选择 WebSocket 后保存并启用；选择 Webhook 则还需按下文复制回调地址，在开放平台完成事件订阅与回调验证。
3. 将机器人添加到群聊，@机器人并发送 `/r 1d6`。若私聊正常但群聊没有入站日志，检查群消息事件订阅和触发方式。

选择 **WebSocket** 或 **Webhook** 接收事件。卡片会直接显示实际连接方式，点击「连接方式」可查看连接说明。

- 登录区为方形二维码，点击下方「手动输入 AppID 与 AppSecret」可切换为凭据表单。编辑已有账号时直接显示凭据，AppSecret 留空表示保留。机器人真实 QQ 号由官方 API 获取，无需手填。
- 选择 Webhook 后，表单会按当前面板访问域名及部署路径生成回调地址；添加成功后也会打开连接信息，可复制地址到 QQ 开放平台。例：面板地址为 `https://dice.example/bot/#/adapters`，回调地址为 `https://dice.example/bot/qq-official/webhook`。反向代理需将该路径转发到骰子服务，QQ 必须能从公网访问它；本机地址仅供本地查看。同一个 AppID 只配置一个 Webhook 适配器。
- 通过 `127.*`、`localhost`、IP 地址或 HTTP 访问面板时，会提示 Webhook 的部署要求：回调服务器具有公网 IP，域名配置有效 TLS 证书，以公网可访问的 HTTPS 地址接收事件。已配置反向代理时，从它的 HTTPS 域名打开面板再复制地址；不具备这些条件请选择 WebSocket。此提示不阻止保存，也不代表面板已验证公网可达性。
- WebSocket 由骰子主动连接 QQ，无需配置回调地址。界面中的 WebSocket 对应配置文件的 `receiveMode: gateway`，旧配置保持兼容。
- QQ 开放平台的部分接口（如群成员列表）仅向受邀或已加入白名单的应用开放。未获授权的应用读取群成员列表时，可能收到「应用无接口访问权限」（40012010），因此部分成员的昵称可能无法显示。遇到此错误，可在 QQ 开放平台核对该应用的接口权限。
- 「高级选项」收纳 Markdown 图片资源强校验、群成员进出事件订阅、自动回应互动事件、富回复样式和快捷操作。**新建**默认 Markdown、消息按钮，群成员事件订阅与自动回应互动事件均开启；已有账号编辑时保留原设置。图片资源强校验默认关闭。

## Milky 连接

1. 在 QQ 协议端登录账号、启用 Milky 服务，记下 HTTP 基址与配置的 Access Token。
2. 在「添加连接 → Milky」输入基址，例如 `http://127.0.0.1:8080`，令牌与协议端一致。此例对应的事件地址是 `ws://127.0.0.1:8080/event`。使用反代前缀时保留该前缀；事件服务单独部署时填写实际的 WS 地址。
3. 保存并启用，用另一个账号发送 `.r 1d6`。没有入站消息时检查事件 WS 与反代升级配置；已收到指令但发不出回复时检查 HTTP API 的地址、鉴权和响应。

API 填 HTTP / HTTPS 基址，事件使用 WebSocket；事件地址可单独设置，留空由 API 基址推导 `/event`。当前不支持 Webhook。不要把 OneBot 的端点直接作为 Milky 地址，详见[Milky 配置](/config/adapter#milky-适配器)。

## 内置登录（OpenOPQ，实验性）

**首次扫码**：填写的是要登录的骰娘 QQ 号。保存并启用后，从该账号卡片打开登录窗口，等协议端启动并显示二维码，用对应账号的手机 QQ 扫码并确认。过期时在窗口刷新二维码。等窗口显示账号在线后，从另一账号发送 `.r 1d6` 验证收发。若尚未出现二维码，先看窗口显示的是下载、启动还是密钥错误。

在「添加连接」中选择「内置登录」，填写 QQ 号及有效的 **BDC 骰娘 API Key**。保存并启用后，Dice!Next 从中心下载对应系统的协议端，在本机启动，并在登录弹窗里展示下载进度、二维码、在线状态或失败原因。

- 账号设备数据和日志保存在 `data/openopq/<适配器ID>/`，执行档放在 `runtime/openopq/<版本>/`。删除适配器也会删除对应账号的本地设备数据与日志。

这是实验性的第三方协议登录，不是 QQ 官方机器人接口，不保证平台登录成功或长期稳定。请保护好骰娘 API Key 和本地账号数据。

## Discord

1. 在 [Discord Developer Portal](https://discord.com/developers/applications) 创建应用，在 **Bot** 页取得 Bot Token，并在 **Privileged Gateway Intents** 开启 **Message Content Intent**。Dice!Next 连接时会请求这项权限。
2. 使用应用的服务器安装链接，以 `bot` 身份邀请机器人加入目标服务器。在测试文字频道授予查看频道、发送消息的权限。
3. 在「平台连接 → 添加连接 → Discord」填写 Bot Token，保存并启用。到测试频道直接发送普通文字 `.r 1d6`。若连接被关闭并报告 4014，检查该应用是否已获准并开启所请求的 Intent；若仅一个频道无法回复，检查该频道的权限覆盖。

## KOOK

1. 在 [KOOK 开发者中心](https://developer.kookapp.cn/) 创建机器人应用，取得 Bot Token，选择 WebSocket 接收事件。
2. 通过机器人的邀请链接将它添加到目标服务器，允许它查看测试文字频道并发送消息。
3. 在「平台连接 → 添加连接 → KOOK」填入 Bot Token，保存并启用。在该频道发送 `.r 1d6`，确认回复来自新添加的机器人。若连接鉴权失败，检查是否误填了 Webhook 的验证凭据；若已在线却收不到回复，检查机器人所在服务器和频道权限。

## 骰娘云服务密钥

适配器的骰娘 API Key 入口保留，与[云服务 → 骰娘密钥](/manage/cloud-services#骰娘密钥)读写同一份配置。它不是平台 Access Token；现有密钥无需因入口迁移重新填写。

## 编辑 / 测试 / 删除

- **编辑**：修改后保存，适配器会按新配置重连。**适配器平台类型创建后不可修改**（需换平台请删除重建）。
- **测试**：检查端点是否可达。
- **重连**：手动立即重连。
- **删除**：移除该适配器。

## 断线重连与退避

连接断开后自动重连，采用退避策略：前 10 次每 5 秒重试 → 第 11~20 次每 60 秒重试 → 超过 20 次暂停并显示「**连接超时**」状态（区别于「已禁用」），此时点「启用」可手动恢复重连。连接需保持 30 秒以上才重置重试计数，避免「短暂连上又断」导致无限快速重连。

连接异常时，可在[运行概览](/manage/dashboard)的最近日志里查看详细的连接 / 收发信息排查。
