# 适配器管理

**管理面板 → 平台连接**，添加、启停与监控连接。连接状态每几秒自动刷新，无需手动刷新页面。

## 添加适配器

QQ 官方机器人已添加后，可前往 **高级回复 → 卡片与按钮**，或使用账号卡片「更多 → 卡片与按钮」快捷入口，按账号可视化编辑单聊菜单和指令面板。具体场景、条目限制与关联操作见 [QQ 官方 API v2 能力](/develop/qq-official-api#可视化编辑)。

点击「添加连接」，表单为**渐进式引导**：先选连接方式，选定后才出现地址等后续字段。

支持 OneBot v11、Milky、QQ 官方机器人、Discord、KOOK，以及实验性的 OpenOPQ 内置登录。先选择平台，再按该平台填写凭据和端点；下表的连接模式说明针对 OneBot v11，Milky 和内置登录参见下方专节，其他平台使用各自的连接字段。

| 字段 | 说明 |
|------|------|
| 适配器名称 | 识别用显示名 |
| 适配器类型 | 按实际平台选择；此表以 OneBot v11 为例 |
| 连接模式 | 正向 WebSocket / 反向 WebSocket |
| 连接地址 / 端口 | 正向填端点地址（如 `ws://127.0.0.1:3001`）；反向填本程序监听的端口 |
| Access Token | 认证令牌（可选），留空则不校验 |

- 连接模式旁有 **? 帮助图标**，悬停显示正向 / 反向的详细说明；选定后表单内也会显示对应提示。
- 正向地址会**自动纠正**协议头（漏写补 `ws://`，`http/https` 自动转 `ws/wss`），非法地址与端口有即时校验提示。

### 传输模式说明

| 模式 | 行为 | 框架处配置 |
|------|------|------|
| 正向 WebSocket（`forward_ws`） | 本骰作为 WS 客户端，**主动连接**登录框架的 OneBot v11 WS 服务端 | 选「WebSocket服务端 / 主动WebSocket / 正向WebSocket」，填框架监听端口 |
| 反向 WebSocket（`reverse_ws`） | 本骰作为 WS 服务端在本地端口监听，**等待框架连入** | 选「反向WebSocket / 被动WebSocket / WebSocket客户端」，填 `ws://本机IP:端口` |

::: tip 区分正向 / 反向
按「谁主动发起连接」区分：正向＝Dice!Next 去连框架；反向＝框架来连 Dice!Next。两端配置要一一对应。
:::

反向 WS 适配器可点「连接方式」查看**连接信息**。地址来自运行 Dice!Next 的服务器，不是打开面板的电脑：

- **本机**：`127.0.0.1`，只适用于框架与骰子运行在同一台服务器。
- **内网**：读取服务器的活动 IPv4 网卡；多网卡、VPN 或容器环境可选择地址。
- **公网**：后台通过外部服务查询服务器的 IPv4 出口地址，不再复用内网 IP。

程序启动后后台预检测，每 15 分钟更新缓存。打开弹窗只读取缓存，不重新发起公网检测；「刷新地址」可手动检测。读取失败、检测失败与检测中分别提示，刷新失败时会明确标记仍在显示的旧地址；没有地址时不能复制占位文字。

公网查询使用固定的 HTTPS 地址服务：[ipify](https://www.ipify.org/)及 [AWS checkip](https://docs.aws.amazon.com/batch/latest/userguide/create-a-base-security-group.html)。只用于获知服务器的出口 IPv4，不上传配置、帐号或密钥。系统 `curl` 不可用、网络不通或查询超时时会提示未获取，不阻塞程序启动或消息收发。

::: warning 公网 IP 不等于端口可达
公网连接仍需确认 NAT／容器端口映射、服务器防火墙与安全组。地址检测不会自动开放端口或修改这些设置；内网无 IPv4 或外部查询不可用时，不影响使用正确的手动地址。
:::

## Milky 连接

API 填 HTTP / HTTPS 基址，事件使用 WebSocket；事件地址可单独设置，留空由 API 基址推导 `/event`。当前不支持 Webhook。不要把 OneBot 的端点直接作为 Milky 地址，详见[Milky 配置](/config/adapter#milky-适配器)。

## 内置登录（OpenOPQ，实验性）

在「添加连接」中选择「内置登录」，填写 QQ 号及有效的 **BDC 骰娘 API Key**。保存并启用后，Dice!Next 从中心下载对应系统的协议端，在本机启动，并在登录弹窗里展示下载进度、二维码、在线状态或失败原因。两套 WebUI 均支持。

- 默认正向 WebSocket；端口和连接凭据由程序分配，不必填写远程地址。只有协议端支持时才选反向模式。
- 执行档不随 Dice!Next 安装包分发；下载须通过清单签名、大小和 SHA-256 校验，中心必须提供当前系统的版本。没有有效 Key、网络不可达或中心暂未提供该平台时，会显示错误，不会跳过校验。
- 当前协议端重启后需要重新扫码。登录窗口可刷新二维码、取消扫码或断开 QQ；「测试连接」只检查现有实例，不启动第二份协议端。
- 账号设备数据和日志保存在 `data/openopq/<适配器ID>/`，执行档放在 `runtime/openopq/<版本>/`。删除适配器也会删除对应账号的本地设备数据与日志。
- 中心拒绝 Key（401 / 403）后停止自动重试，修改 Key 或手动重连后再试；普通 OneBot 适配器不受这套托管逻辑影响。

这是实验性的第三方协议登录，不是 QQ 官方机器人接口，不保证平台登录成功或长期稳定。请保护好骰娘 API Key 和本地账号数据。

## 骰娘云服务密钥

适配器的骰娘 API Key 入口保留，与[云服务 → 骰娘密钥](/manage/cloud-services#骰娘密钥)读写同一份配置。它不是平台 Access Token；现有密钥无需因入口迁移重新填写。

## 编辑 / 测试 / 删除

- **编辑**：修改后保存，适配器会按新配置重连。**适配器平台类型创建后不可修改**（需换平台请删除重建）。
- **测试**：检查端点是否可达。
- **重连**：手动立即重连。
- **删除**：移除该适配器。

## 断线重连与退避

连接断开后自动重连，采用退避策略：前 10 次每 5 秒重试 → 第 11~20 次每 60 秒重试 → 超过 20 次暂停并显示「**连接超时**」状态（区别于「已禁用」），此时点「启用」可手动恢复重连。连接需保持 30 秒以上才重置重试计数，避免「短暂连上又断」导致无限快速重连。

连接异常时，可在[运行概览](/manage/dashboard)的最近日志里查看详细的连接 / 收发信息排查。
