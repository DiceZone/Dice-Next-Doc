# 人工智能

**管理面板 → 人工智能**，为骰娘配置对话、NPC、知识库、回复润色、翻译、识图与语音识别。除「模型」页外，页面开关即时保存并生效；文本与参数修改后保存当前页，不会连带提交其他页面的草稿。知识库默认开启，已明确关闭的配置会保留，仍受 AI 总开关控制。

::: warning 费用与延迟
开启 AI 后，相关功能会按你配置的模型计费，且被 AI 处理的回复会有延迟（取决于网络与大模型响应速度）。请给每个模型设好 token / 费用限额。所有 AI 功能失败或超时都会回退：润色 / 翻译发原文，对话不回复。
:::

## 模型

### 总开关

「启用人工智能」是所有 AI 功能的总开关，关闭时润色、翻译、对话等全部不生效（其它子页会置灰并提示先到「模型」页打开）。

### 全局请求参数

所有 AI 调用共用的参数（润色 / 翻译会另用较低温度以求忠实）：温度 temperature、top_p、最大 token、频率惩罚、存在惩罚。

模型设置分为三个选项卡：**提供商 → 模型 → 用途分配**。先填接口和密钥，再列出要用的模型，最后决定每个功能用哪些模型。

### 提供商

提供商和模型通过弹窗添加、编辑，页面只展示摘要条目，可启停、编辑、删除。提供商预设包含 DeepSeek、OpenAI、Claude、火山引擎、SiliconFlow；选择后自动填入接口地址，只需填写 API Key。自定义接口仍可手动填写。Claude 使用官方 OpenAI 兼容接口，省略其不支持的采样参数组合。模型页修改后需点击页面「保存」生效。

一个提供商对应一组接口地址和密钥，旗下所有模型共用，同一家服务不必每个模型重复填写 Key。

| 字段 | 说明 |
|------|------|
| 名称 | 自定义名称，如「OpenAI」「DeepSeek」「本地 Ollama」 |
| 接入地址 Base URL | OpenAI 兼容接口地址，填到 `/v1` 即可，如 `https://api.openai.com/v1` |
| API Key | 本地模型可留空 |

停用提供商后，旗下所有模型都不再调用。仍有模型使用的提供商不能删除。

### 模型

模型预设包括 `deepseek-flash`、`deepseek-v4-pro`，以及 SiliconFlow 的嵌入模型 `BAAI/bge-m3`。预设只填充配置，不会擅自启用付费功能。费用估算统一为美元／百万 token：截至 2026-11-11，DeepSeek 使用尖峰、未命中缓存价格（Flash 输入 $0.30 / 输出 $1.20，Pro 输入 $1.32 / 输出 $3.96）；`BAAI/bge-m3` 普通版免费。费用可以编辑，实际价格与可用性以 [DeepSeek](https://api-docs.deepseek.com/quick_start/pricing/) 和 [SiliconFlow](https://siliconflow.cn/pricing) 为准。

| 字段 | 说明 |
|------|------|
| 显示名 | 自定义名称，如「GPT-4o mini」「本地 Qwen」 |
| 提供商 | 从「提供商」页已添加的里选 |
| 模型名 model | 如 `gpt-4o-mini`、`qwen2.5`、`text-embedding-3-small` |
| 类别 | **通用模型**：对话、润色、翻译、识图、语音识别等；**嵌入模型**：只把文字转成向量，用于长期记忆检索 |
| 支持图片输入 | 仅通用模型。开启后才能分配到「图像识别」 |
| 输入价 / 输出价 | 每百万 token 单价，用于费用统计（嵌入模型只有输入价） |
| token 上限 / 费用上限 | 0 = 不限；超限后该模型停止调用，自动改用同一用途的下一个模型 |

每个模型显示已用 token 与累计费用，并有「测试」按钮：通用模型实测一次对话，嵌入模型实测一次向量化并显示向量维度。

### 思考模式、输出额度与峰谷价格 {#model-request-options}

编辑模型时可以设置：

- **思考模式**：自动、开启或关闭。自动通常保留服务商默认值；仅当模型和识图页都为自动时，官方 DeepSeek 的识图请求默认关闭思考。识图页的明确选择优先于模型设置。
- **思考参数格式与强度**：自动对官方 DeepSeek 地址或 `deepseek` 开头的模型名使用 `thinking`，其他模型使用 `reasoning_effort`；中转可以手动选择。开启时可选择低、中、高强度，实际支持范围以服务商为准。服务商不支持这些参数时，保持自动。
- **单次输出额度**：0 使用用途默认值；非 0 覆盖普通文本请求的额度，识图则取模型额度与识图专属额度的较小值。它与累计 token 上限不同；思考模型可能把思考与正式答案一起计入额度，开启思考时应提高额度。
- **输入、输出与缓存命中单价**：单位为 USD／百万 token。只有上游返回缓存命中用量时才按缓存价估算；没有报告的输入按普通输入价计算。旧配置未设置缓存价时沿用输入价。
- **谷时价格**：可开关，并设置每日起止时间、固定 UTC 时差，以及谷时输入／缓存输入／输出单价。其余时间使用常规价格。按请求发起时间判断，允许跨午夜；包含起点、不包含终点，起止相同不启用任何谷时时段。时区不跟随浏览器或服务器，也不自动切换夏令时。

费用是本地估算，不会改变服务商实际计费，也不追溯重算已累计金额。最终以服务商账单为准。累计 token／费用上限不会每天重置；开始调用前检查累计用量，并发或本次调用仍可能使总数超过阈值。模型返回了计费用量，即使正文为空或生成被截断，也会记录这笔用量。

模型页修改后保存。识图页的思考选择即时保存，输出额度与超时随当前页面参数保存。

### 用途分配

默认展示对话回复、决策、图像识别、语音识别、嵌入。润色、翻译、记忆摘要、事实抽取、NPC 与情绪评估收在「高级用途设置」中。

为每个功能指定使用的模型：

| 用途 | 说明 | 未分配时 |
|------|------|----------|
| 对话回复 | 骰娘在群里聊天 | 第一个启用的通用模型 |
| 决策 | 待机搭话前判断要不要插话（见下文「对话」） | 沿用「对话回复」 |
| 润色 / 翻译 | 回复润色、`.lang` 翻译 | 沿用「对话回复」 |
| 记忆摘要 / 事实抽取 | 群历史摘要、长期记忆抽取 | 沿用「对话回复」 |
| NPC 扮演 | NPC 回复（NPC 设了专属模型时优先用专属模型） | 沿用「对话回复」 |
| NPC 情绪评估 | 评估 NPC 好感变化 | 沿用「NPC 扮演」 |
| 图像识别 | 识别消息图片，只能选「支持图片输入」的模型 | 沿用「对话回复」里支持图片的模型 |
| 语音识别 | 把语音转成文字 | 不可用 |
| 嵌入 | 长期记忆的向量化，只能选嵌入模型 | 不可用 |

每种用途可以选多个模型，并选择**使用策略**（默认负载均衡）：

- **负载均衡**：每次选正在处理的请求最少的模型，相同时轮流使用。
- **随机选择**：每次随机选一个。
- **顺序优先**：按列表顺序用第一个，失败或超过限额才换下一个（可用上下箭头调整顺序）。
- **分配权重**：按权重比例分配请求（权重 1–100）。

无论哪种策略，调用失败时都会自动换下一个候选模型重试（每次最多试 3 个）。带工具调用的对话只在第一轮失败时换模型，避免掷骰、改卡等操作被重复执行。

::: warning 嵌入只能指定一个模型
已存的记忆向量和检索时的向量必须来自同一个模型，所以「嵌入」只能选一个模型。更换嵌入模型后，请在「对话」页清空长期记忆，让向量重新生成。
:::

::: tip 从旧版本升级
旧版本每个模型都自带接口地址和 Key，各功能分别指定模型。升级后首次启动会自动转换：相同「地址 + Key」的模型合并成一个提供商，各功能原先指定的模型转成对应用途的分配，长期记忆的嵌入设置转成一个嵌入模型。转换前的原始设置备份在 `dice.json` 的 `ai_backup_v1` 中。
:::

## 对话

让骰娘在群里像真人一样聊天（仅群聊生效）。

### 触发方式（三态）

- **被 @骰娘**：必定回复，不受冷却限制。
- **命中关键词**（逗号分隔，如「骰娘, 在吗」）：必定回复，不受冷却限制。
- **待机概率**（0–100）：其余消息按概率随机搭话，受「每群冷却(秒)」限制，别设太高否则会频繁插话。
- **待机搭话前先判断**：勾选后，待机概率命中时先请「决策」用途的模型判断此刻要不要插话（例如有人在提问、话题和骰娘有关），判断为否就不回复。判断只输出很短的结果，比直接生成回复省用量，适合给「决策」分配便宜、快速的模型。被 @ 或命中关键词时不经过判断。

### 生成参数

上下文轮数（读取本群近期聊天记录作为上下文）、回复最大字数、每群冷却秒数、回复时是否 @ 发送者、是否禁止输出 emoji、自定义过滤词（喂给 AI 前从文本里删掉水印 / 签名 / 刷屏词），以及人设与系统提示词（留空用内置默认，可点「载入默认」在模板基础上修改）。

### 群历史记忆（滚动摘要）

点击「已存群摘要／已存事实 → 查看」，在大弹窗中按群组选择记忆。关系图每页展示最多 8 个节点，支持搜索；点击节点可查看完整内容、编辑或删除。编辑事实会重新生成向量，失败则保留原内容；删除摘要保留已整理消息的水位线，避免立即从旧记录重建。后台整理不会覆盖编辑期间已经修改或删除的摘要。

对话超出近期窗口后，把更早的聊天按批压缩成一份群摘要注入背景，让骰娘记得更久之前的事。摘要用「记忆摘要」用途的模型；可配置保留轮数（折叠批大小）、摘要字数上限与摘要提示词；可在记忆弹窗中查看、编辑、删除已存的各群摘要。仅当滑出窗口的消息攒够一批才调用模型（天然限频、控成本）。

### 长期记忆（持久事实 · 向量检索）

从对话里抽取值得长期记住的事实（人物卡 / 剧情 / 约定），向量化存库；聊天时按当前话题相似度检索最相关的几条注入。需要先在「模型」页添加一个类别为「嵌入模型」的模型（如 `text-embedding-3-small`），并在「用途分配 → 嵌入」指定；抽取用「事实抽取」用途的模型。可配置检索条数 Top-K、相似度阈值、每群事实上限与抽取提示词；同样可查看、编辑、删除已存事实。

### 工具调用

开启后骰娘用 function-calling 调用真实功能，而不是自己编数字（需模型支持 tools）：

| 工具 | 说明 |
|------|------|
| `roll_dice` | 掷骰，走真实骰子引擎 |
| `draw_deck` | 抽牌堆 |
| `get_attr` | 读发送者人物卡属性 |
| `set_attr` | 写发送者人物卡（有风险，默认关闭） |
| `run_command` | 执行任意指令 / 插件（权限同发送者） |
| `search_help` | 在帮助文档里查词条；开启知识库时改为搜索知识库 |

「最大工具轮数」限制连环调用次数，最后一轮强制输出文本回复。仅在「对话」开启时生效。

### AI 白名单（访问控制）

开启后，只有白名单内的群 / 私聊能使用 AI 对话与 NPC；非白名单群即使群管发 `.ai on` 也会被拒绝，防止未授权群消耗 API 费用。名单从群组 / 玩家列表搜索勾选添加。白名单只控制对话 / NPC / 群记忆；回复润色与翻译是全局功能，不受影响。

### 图像识别（多模态）

图片统一先由骰娘下载、校验后以 Base64 上传，不再提供「图链直传」。每张图片默认上限 **1024 KB**，可设置 1–8192 KB；超限、下载失败、格式不支持的图片不会提交模型，日志会说明原因。该限制针对文件大小，不能等同于 token 数；视觉计费还受分辨率和模型影响。

识图使用「图像识别」用途中支持图片的模型。缓存按实际图片内容、识图提示词与候选模型区分，避免不同图片共用描述。需要决策时，先识图再把描述交给决策模型。识图失败会明确告知对话模型没有读到图片，不能把猜测当作识图结果。

#### 识图没有结果或描述不对？ {#vision-empty-result}

识图默认输出额度为 **2048 tokens**，超时 **60 秒**，可在「人工智能 → 对话与记忆 → 图像识别」调整；不再固定为 300 tokens。官方 `deepseek-flash` 支持图片，自动模式默认关闭其识图思考；要开启思考，请同时提高输出额度并适当延长超时。

日志会区分「达到输出上限」「只返回思考没有正文」「空正文」「内容被拒绝」和 HTTP 错误，并显示模型、结束原因和实际请求额度。失败时尝试该用途的备用模型（最多三个候选），所有候选都失败时不把不完整描述写进缓存，也不会把思考过程冒充识图结果。

每张实际提交的图片会记录内容指纹、大小和关联消息；同一条链上可继续查模型结果、决策和最终回复。指纹不是图片地址，不记录 Base64 或密钥。不同指纹表示输入内容不同；相同输入也不保证模型一定识别正确。更换提示词、模型请求设置或识图设置后，会重新识别。多实例请求的临时文件相互隔离，避免共享系统临时目录时覆盖请求。


### 语音识别

群里发语音时，用「语音识别」用途的模型把语音转成文字，再交给对话做触发判断和回复（例如语音里提到关键词也能触发）。需要支持 OpenAI 兼容 `/audio/transcriptions` 接口的模型，如 Whisper、SiliconFlow 的 SenseVoice；在「模型」页按通用模型添加，再分配到「语音识别」。

- **OneBot（NapCat 等）**：通过 `get_record` 取得 mp3。骰娘与 NapCat 不在同一台机器时（如 Docker），请在 NapCat 开启返回 base64 的选项，否则读不到语音文件。
- **Discord**：直接下载语音附件。
- 每条语音会额外请求一次语音识别模型；同一条语音只转写一次。

## 知识库

**人工智能 → 知识库**，让骰娘回答「怎么用 / 有没有某功能 / 团规是什么」这类问题时有据可查，同时尽量不增加模型用量：

- **检索在本机完成**：按关键词计分（BM25），不调用模型改写问题或判断要不要查。约一万条资料每次检索几十毫秒。
- **只注入相关的少量资料**：相关度达到阈值的前几段才加进提示词，总字数有上限；闲聊找不到相关资料时什么都不加。
- **FAQ 直接回答**：自定义条目勾选「直接回答」后，问题和条目的问法足够相似时，原文回复条目内容，**完全不调用模型**。

### 资料来源

| 来源 | 内容 |
|------|------|
| 帮助词条 | 帮助系统里的全部词条：内置指令、规则包、插件、自定义帮助文档。检索时直接读取，修改帮助后立即生效 |
| DiceNext 文档 | 本文档站的使用说明，随程序安装，不需要联网 |
| 自定义条目 | 在知识库页录入的资料：团规、世界观、常见问题等 |

### 设置

| 设置 | 说明 |
|------|------|
| 最多注入段数 | 每次对话最多加进提示词的资料段数（1–8，默认 3） |
| 相关度阈值 | 0–1，问题里的关键词被资料覆盖的比例达到它才注入（默认 0.45）。调高减少无关资料，调低找到更多 |
| 注入字数上限 | 每次注入的资料总字数（默认 1200），控制输入 token |
| FAQ 直接回答 / 相似度 | 问题与问法的相似度达到它（默认 0.6）就直接回复 |
| 语义检索（自定义条目） | 为自定义条目额外比较向量相似度，换了说法也能找到。需要在「用途分配 → 嵌入」指定嵌入模型；每次检索会请求一次嵌入模型 |

### 自定义条目

每个条目有标题、内容、问法（每行一个）、标签和「直接回答」开关。问法与标题在检索时权重更高，FAQ 直接回答也按问法比对。可以从 JSON 文件批量导入：条目数组，或 `{"entries": [...]}`，每条可含 `title`、`content`、`questions`、`tags`、`direct`。条目保存在 `data/knowledge/entries.json`。

### 检索测试

在页面输入一句玩家可能问的话，可以看到会命中哪些资料、各自的相关度、会注入多少字，以及是否触发 FAQ 直接回答，用的是页面上当前（尚未保存）的设置，方便调阈值。

开启知识库后，工具调用里的 `search_help` 也改为搜索知识库。对话时检索的问题会先去掉「触发关键词」（如骰娘的名字）。

## NPC 扮演

定义 NPC（名字 / 人设 / 背景知识 / 触发词）。群里消息提到 NPC 名字或命中触发词时，骰娘以该 NPC 的身份、口吻、知识回复（复用记忆与工具调用，优先于默认骰娘对话）。可用于扮演旅店老板、神秘线人等。

每个 NPC 可设置：触发词（除名字外）、专属模型（可选）、限定群（如 `onebot_v11:123456`，留空 = 全部群）、人设与背景知识（只有角色知道的信息）。**情绪记忆**开启后，NPC 对每个玩家维护好感度（-100~100）与情绪，语气随关系变化；每次互动后用模型评估好感增减（额外一次请求）。

## 回复润色

掷骰 / 检定类回复发送前，用大模型按人设与情境润色。两种方式：

- **仅润色措辞**：保留数字 / 结果，只改说法。
- **按情境增加 rp 描述**：在结果基础上加入角色扮演描写。

可设置人设 / 风格与系统提示词（可「载入默认」修改）。模型须严格保留原始数字与成功 / 失败结果——服务端会校验数字，被改坏时自动回退原文；失败或超时也发原文。

**覆盖范围**：润色与翻译都按类别勾选生效——掷骰/检定、牌堆抽取、娱乐指令（今日人品 / 疯狂 / 随机名等）、自定义回复、插件结果。

## 回复翻译

配合 `.lang` 实现自定义语言：先在页面定义语言（名称 + 切换关键词，如名称「德语」、关键词「de, german, 德语」），群里 / 私聊发 `.lang <关键词>` 即可切换。回复先按默认语言生成，发送前由大模型翻译成目标语言（带缓存，同文本不重复计费）。翻译提示词可用 `{lang}` 占位目标语言名。失败或超时自动发原文；切回内建语言或 `.lang clr` 即停用翻译。

## 聊天侧指令

`.ai on/off` 可分群开关本群 AI 功能（对话 / NPC），详见[管理指令](/use/admin)。白名单模式开启时，非白名单群 `.ai on` 也会被拒绝。

::: tip AI 不会拖慢指令
所有大模型调用都在独立的后台队列串行执行，不占用消息线程——即使 AI 接口卡住 30 秒，普通指令也照常秒回；堆积过多时直接丢弃新的 AI 任务（对话不回、润色回退原文）。
:::

## 排查：DEBUG 日志

INFO 日志记录同一条 AI 消息的触发原因、使用的模型、识图／转写结果、决策判断与理由、生成的回复，并关联到发送 msgID。文字消息也使用同一链条；被 @、关键词、NPC 直接触发时说明跳过决策，待机决策关闭时也有说明。发送成功／失败继续由消息日志记录。图片 Base64 与 API Key 不写入日志。DEBUG 用于进一步查看上下文和模型请求。

把「WebUI 设置 → 控制台日志」的最低记录级别调到 **DEBUG**，可以看到 AI 处理的每一步：

- 触发判断：被 @、命中哪个关键词、待机概率掷出多少；决策模型的判断与理由。
- 选模型：用途、策略、尝试顺序，以及失败后换了哪个模型。
- 每次请求的完整内容（系统提示、上下文、用户消息、工具列表）、模型的思考过程与回复，失败时的原始响应。
- 工具调用的参数与结果、图像识别 / 语音识别的结果。
- 知识库检索：计分条数、耗时、命中的资料与相关度、FAQ 直接回答。
- 记忆整理：本次折叠了哪些消息、更新后的摘要、抽取到的事实、跳过的重复事实、检索命中的记忆与相似度。

模型输出的思考过程（`<think>` 段或 `reasoning_content` 字段）只写入日志，不会发到群里。

::: warning DEBUG 日志包含聊天内容
DEBUG 级别会记录群聊消息与人物卡等完整内容（API Key 不会写入）。排查完毕后请调回 INFO。
:::

::: tip 先在测试台预览
可在「指令测试」页发 `.r` 或聊天内容，直接预览润色 / 翻译 / 对话效果，无需进群。见[指令测试](/manage/playground)。
:::
