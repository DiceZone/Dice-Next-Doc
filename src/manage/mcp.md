# MCP 服务

**管理面板 → 系统设置 → MCP 服务**。这是让外部 AI 客户端调用 Dice!Next 能力的服务端，与骰娘自身的 AI 对话及工具调用设置相互独立。

::: info 开发版功能
本页描述 MCP 服务端首版。使用前请确认主程序和 WebUI 都包含该功能；安装旧版 WebUI 或主程序不会自动获得接口。
:::

## 可以做什么

| 工具 | 能力 | 限制 |
| --- | --- | --- |
| `roll_dice` | 使用真实 Dice!Next 数学解析器掷骰，返回结果、各骰出值与过程 | 如 `d100`、`2d6+3`；不执行 OneDice／DiceScript 脚本、插件或模板 |
| `search_help` | 搜索已加载的帮助文档 | 返回原文，最多 20 条，长正文截断；不执行文档中的变量或代码 |
| `get_status` | 查询版本与运行时长 | 不返回密钥、账号、连接地址或完整配置 |
| `get_character_card` | 读取明确授权的人物卡 | 按具体卡片编号授权，遵守锁读限制，不求值公式或修改绑定 |

首版**不提供**发送消息、修改人物卡、执行任意指令／插件、改设置、重启或更新程序的工具。帮助和人物卡中的文字是数据，不应被 AI 当作新的操作授权。

## 创建授权

1. 骰主登录面板，打开 **MCP 服务**。受限管理员不能读取或修改此页的授权。
2. 点击 **创建凭据**，填写应用／使用人标签，选择允许的工具与有效期（1–365 天，默认 30 天）。
3. 如需读取人物卡，搜索卡名或所属用户 ID，明确勾选具体卡片。留空不能获得“全部人物卡”权限。
4. 创建后将凭据保存到 AI 客户端。**明文只显示一次**，不会保存在浏览器，服务端仅持久化 SHA-256 摘要；丢失后可重新生成，或撤销后重新创建。
5. 开启 **启用 MCP 服务** 并保存。创建凭据本身不会开启服务。

修改工具／卡片范围、停用、撤销和过期检查均在每次请求重新执行，不依赖客户端是否主动断开连接。

- **编辑授权**默认保留原到期时间；只有打开“重新计算有效期”才从保存时起按所填天数续期，不会悄悄恢复已过期的凭据。
- 在客户端条目的**更多操作 → 重新生成凭据**中可原地轮换。旧凭据立即失效，新明文只展示一次；工具／卡片范围、启用状态和到期时间均不变。记得更新 AI 客户端配置。
- 卡片删除或锁读后仍可停用凭据、移除读卡权限或撤销授权。卡片所有者发生变化时不会自动转移授权：须先移除该卡的授权并保存，再明确重新选择。

MCP 专用凭据不能代替 WebUI Cookie、BDC 密钥或管理 API Key；反过来也不能用这些凭据登录 MCP。

授权列表按**服务器时间**显示到期状态，页面打开期间定时更新，并提醒 7 天内到期的条目，不受浏览器电脑时钟偏差影响。不会自动续期，也不会额外发送到期通知。

“最近保留的成功调用”只统计当前保留的 5,000 条审计记录中的成功工具调用，不包括初始化、自检或修改授权。没有记录不代表从未使用；审计存储不可读时会明确提示，不会冒充“从未使用”。

编辑读卡授权时，已选卡片会显示名称、所属用户及当前读取状态。删除与锁读统一提示“人物卡不存在或已锁定读取”，不猜测具体原因；所属用户变化时会提示重新授权。此处只查询卡片摘要，不返回属性内容。

### 保存、超时与恢复

页面读取等待上限为 10 秒，修改操作为 20 秒。网络中断或超时**不代表修改失败**：页面会暂停继续修改，并提供“核对操作状态”，不会自动重复创建或轮换凭据。

核对状态后还会重新读取服务器上的配置和凭据列表；回读失败时继续保留操作锁与原编辑内容，不会拿旧列表冒充最新状态。可稍后再次核对。

- 仍在处理：稍后再次核对，不要重复提交。
- 已保存但未收到一次性凭据：在列表中找到对应条目，确认后手动“重新生成凭据”；无法重新读取已丢失的明文。
- 未生效：核对后可重新提交。
- 状态未知：可能是程序重启或临时状态记录已清理。先核对当前设置和凭据，不能把“未知”当成失败。状态记录仅临时保留，最多 128 条，不保存凭据明文。

配置采用单文件原子保存。若提示“修改已生效，但调用记录未能保存”，权限变更已经生效，新凭据仍可正常保存；请检查 `data/audit` 的写入权限与剩余空间，不要重复执行刚才的操作。

### 从备份恢复后

恢复配置或主数据库时，**MCP 总开关和旧授权会停用，旧密钥失效**，防止备份把已经撤销的密钥重新带回。授权名称、工具和人物卡范围仍保留，供骰主核对。

1. 打开 MCP 服务，核对保留下来的授权范围。
2. 对仍要使用的条目选择“重新生成凭据”，安全保存新明文并更新 AI 客户端。
3. 明确启用所需授权；已过期的还需要重新计算有效期。
4. 开启并保存 MCP 总开关。仅重新开启总开关或编辑授权，不能让旧密钥恢复有效。

仅恢复牌堆、图片、插件等资源、不覆盖配置或主数据库时，不会重置 MCP 授权。Windows 和其他平台均由核心在启动时统一应用恢复。配置或数据库快照写入失败时会中止启动，保留恢复保护标记，修好存储后重试；不要手动删除标记来绕过保护。

## 连接客户端

服务采用 **Streamable HTTP**，接口路径为 `/mcp`。同服务器客户端可使用页面显示的 `http://127.0.0.1:端口/mcp`；远端客户端应使用可访问的 HTTPS 地址。反代含路径前缀时，保留该前缀。

以下是通用连接参数，不是所有客户端都通用的配置文件格式；按客户端要求填入 URL、传输类型与请求头：

```json
{
  "transport": "streamable-http",
  "url": "http://127.0.0.1:18088/mcp",
  "headers": {
    "Authorization": "Bearer <MCP_TOKEN>"
  }
}
```

无需在骰娘所在机器额外安装 Node／Python，也不需要把模型 API Key 填入此页。调用端须支持 HTTP MCP 与自定义 Bearer 凭据；仅支持本地 stdio 的客户端不能直接连接此入口。首版不提供自动 OAuth 登录。

支持 `2026-07-28` 的无会话协议，以及 `2025-11-25`、`2025-06-18` 的初始化兼容；不提供旧版 HTTP+SSE 端点或 stdio 启动方式。协议消息与请求头由 MCP 客户端构造，不需要用户手写。

## 本机与远程访问

### 本机连接自检

连接指引中提供 **本机连接自检**。不填写凭据时，检查已保存的服务开关、审计存储是否可写及是否存在可用凭据。可填写已有的 MCP 凭据，进一步验证本机协议处理器的初始化和工具列表，并检查某个工具是否获准使用。

自检不创建临时授权、不执行工具、不连接任意网址；所填凭据仅用于本次检查，完成后清空，不保存在浏览器、不记录到日志，也不回显到结果。无效、停用、撤销或过期的凭据统一显示“凭据被拒绝”；限流或面板请求失败不会被误报成凭据无效。

::: warning 自检通过不等于公网可用
自检只验证本机协议逻辑，不验证监听端口可达性、公网 DNS、TLS 证书、反向代理或浏览器来源。仍需在实际 AI 客户端测试真实地址；不能用自检通过替代远程连接验证。
:::

### 配置访问范围

默认关闭远程访问，仅接受回环连接，拒绝带代理转发信息的请求；同时检查 `Host`。这是请求级限制，不会更改 WebUI 既有监听地址。

- 远程访问必须主动开启，并配置精确的 Host 白名单，例如 `dice.example.com` 或 `dice.example.com:8443`。不使用 `*`，不含协议或路径。
- 公网入口应使用 HTTPS。直接远程明文请求会被拒绝；本机反代终止 TLS 时，须由骰主确保公网入口只提供 HTTPS，并限制对后端明文端口的访问。不会因为伪造 `X-Forwarded-Proto` 就信任远程明文连接。
- 本机反代即使连接来自回环地址，也应在代理中明确限制 `/mcp`，不要把“本机模式”当成公网访问控制的替代品。
- 原生客户端通常不发送 `Origin`。如浏览器客户端需要跨来源访问，须另设精确来源，例如 `https://ai.example.com`；默认不允许任何浏览器来源，不接受 `null` 或通配符，也不使用 Cookie 作为 MCP 鉴权。

主机名忽略大小写；浏览器来源会统一大小写并合并 HTTP／HTTPS 默认端口（80／443）。这不会放宽子域名或非默认端口限制，例如 `https://ai.example.com:8443` 仍须单独授权。

管理页面的跨站防护与 MCP 客户端来源白名单相互独立：授权 AI 网页访问 `/mcp`，不等于授权它修改骰娘的 MCP 设置。反代请保留浏览器的 `Origin`、`Sec-Fetch-Site` 及 `X-Dice-MCP-Request` 请求头，不要为 `/api/system/mcp` 开放跨来源写入。原生管理 API Key 调用仍可使用 JSON 请求。

## 调用记录与限制

页面提供服务端分页的调用记录，持久化保留最近 **5,000 条**。可按客户端和成功／拒绝／失败结果组合筛选，条数与分页均按筛选后的结果计算。点击记录中的客户端名称可查看该客户端的历史，已撤销的客户端记录仍可筛选。记录授权客户端、操作、时间和结果，**不保存凭据、请求参数或人物卡内容**。

每个凭据每分钟最多 60 个请求，另有连接来源限流。单次请求最多 32 KiB，结果最多 64 KiB；数学表达式最多 256 字节、16 层括号、1,000 个随机出值、单骰最多 1,000,000 面，整数溢出会返回错误而不是继续计算。帮助单次最多遍历 10,000 条／4 MiB 正文，达到上限会明确返回 `search_truncated`。查询失败、被撤销或越权时不会执行其他工具作为回退。

工具与管理请求使用独立的后台工作队列，等待队列均有上限。繁忙或排队超过 5 秒返回 `503`，不会继续堆积并阻塞网页服务线程。每个凭据同时只能有一个排队或执行中的工具调用；其他并发调用返回 `429`，未执行工具，可在前一次结束后重试。连接初始化和工具目录查询不占此名额。

工具执行还有 5 秒的协作取消期限，程序退出时也会通知查询取消；过期或取消后不返回查询结果。不会强杀 C++ 线程；底层暂时无法中断的系统／数据库调用，需要返回后才能检查取消状态。查询结束后会再次核对授权，期间已撤销／停用或缩小范围的结果不会返回给客户端。

调用记录存储在 `data/audit/mcp.db`；选择备份“审计记录”时，会使用 SQLite 快照包含当前记录，不需要关闭服务。

常见错误：`401` 检查专用凭据、有效期与启用状态；`403` 检查访问来源、Host／Origin 和工具／卡片授权；`429` 稍后再试；`503` 检查繁忙状态和审计存储，管理修改应先核对操作状态；`404` 确认 MCP 总开关、接口地址及客户端支持的协议／方法。
