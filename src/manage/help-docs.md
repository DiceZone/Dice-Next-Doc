# 帮助文档

**管理面板 → 帮助文档**，汇总所有 `.help` 帮助条目，可搜索、编辑与管理。

## 帮助来源

帮助系统是统一注册表，条目来自多个来源，页面用标签区分：

| 来源 | 说明 | 可否编辑 |
|------|------|----------|
| 内置 | 随程序内置的指令帮助（i18n 文案） | 可编辑，可一键「还原为默认」 |
| 自定义帮助词条 | 历史指令添加或从旧版 `CustomHelp.json` 导入的 `help.topic.*` 词条 | 可编辑、可删除 |
| 规则包 · 名称 | 随规则包分发的帮助 | 只读（要改请编辑规则包） |
| 插件 · 名称 / Lua模块 · 名称 | 随 JS 插件 / Lua 模组分发的帮助词条 | 只读（要改请编辑插件） |
| 文档包 · 名称 | `data/helpdoc/` 等目录里的结构化帮助包，可能随程序分发，也可能由骰主添加 | 只读 |
| 自定义文档 | 骰主自建的帮助（存于 `data/help/*.md`） | 可编辑、可删除 |

修改过的内置帮助仍属于「内置」，额外标注「已自定义」，不会被误认为用户新建文档。规则包与插件的帮助**随包分发**——装包即得帮助，卸载即消失。

历史自定义词条不需要重新导入，也不会被强制转成文件：原始内容、语言与纯文本 / Markdown 格式继续保存在原来的文本覆盖层。旧数据没有可靠记录“由指令创建还是由迁移导入”，页面统一归为用户自定义，不猜测来源。

## 浏览与搜索

- 默认左侧帮助文件库、右侧当前条目；可先按「用户自定义 / 内置帮助 / 插件 / 规则包 / 帮助文档包 / 其他来源」筛选，再选择具体插件、包或文件，并搜索主题名或内容。
- 筛选、计数和分页在服务端对完整目录执行，不限于当前页。插件类同时包含 JS 和 Lua；规则包附带的帮助文档仍归入规则包，保留原来的文档来源名。
- 分栏分页提供页码按钮及直接输入跳页，固定为两行，避免偶尔多出不规则换行。
- 自建空文档、被同名条目遮蔽的文件仍出现在管理列表，并显示相应提示；这不改变聊天侧同名词条优先级。

## 可视化编辑

选中左侧条目后，在右侧点「编辑」打开弹窗；「新增文档」创建自定义帮助文件（填名称 + 内容），保存后群里立刻可用 `.help <名称>` 查询。历史帮助词条也可直接编辑、删除；内置帮助可修改并恢复默认。

文本词条显示实际内容语言，编辑与删除针对该语言，保留其他语言内容；某语言没有词条时会按骰子配置回退。格式选择保留纯文本 / Markdown 的显式语义，不在浏览时抽取 `{sample:甲|乙}`。未保存时离开会提示确认。

独立自定义帮助不再显示为「指令列表 → 全部文本」中的未归类文案；该处提供帮助文档入口。与指令关联的用法文本以及人格层的文本编辑仍保留。

## 导入 / 导出

- **导出**：下载带 `kind: "dicenext.help"`、`version: 1` 的 JSON，分别保存自定义文件与全部语言的帮助文本覆盖（包括历史词条、内置帮助修改、格式和概率候选）。同名文件与文本词条分开保存，不相互覆盖；不包含插件、规则包或人格内容，后者请用对应的备份入口。
- **导入**：支持上述新版备份，继续兼容旧 `.json`（`{名称: 内容}` 对象或含 `name` / `content` 的数组）与单个 `.md` / `.txt`（文件名即条目名）。先校验整份输入，拒绝非法名称和同一语言的重复词条；覆盖现有内容需确认，网络错误造成部分成功时会报告结果而不是假装全部成功。

## 聊天侧指令

群里用 `.help <条目>` 查询帮助；`.helpdoc scope <来源>` 可把本群搜索域锁定到某来源（如只查某规则包），`.helpdoc default <来源>` 设置同名词条的优先来源（例如让 dnd5r 压过 dnd3r），详见[管理指令](/use/admin)。

::: tip
帮助条目很多时，聊天里 `.help` 只做精确 / 模糊查询；想通览全部条目请用本页浏览与搜索。
:::
