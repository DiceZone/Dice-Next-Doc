# 系统设置

**管理面板 → 系统设置 → 系统设置**，骰主在这里完成全局配置。与面板自身相关的设置（登录密码、端口等）在同组的 [WebUI 设置](#webui-设置页) 页。

## 检测与自动更新

**管理面板 → 关于项目 → 检测与自动更新**集中显示当前版本、最新 Release、平台安装包、下载来源与更新阶段，并提供检查、下载、安装及自动策略设置。

- 默认每 6 小时检查一次，发现新版本时**仅通知**，不会擅自下载或重启。
- 发现新版本时会通过通知系统发送“发现新版本”；自动下载 / 安装成功发送“更新结果”，失败发送“更新失败”。同一 Release 只提醒一次。已有通知窗口若逐项筛选事件，需要在通知设置中额外勾选这三个新增事件。
- 下载来源可选：自动选择、仅 GitHub、仅内置镜像、自定义镜像。自动模式并行探测 GitHub 直连与内置镜像，使用最先成功且清单有效的来源，并短期缓存可用来源。
- Release 安装包只使用 GitHub 不会改写的安全文件名；更新器也兼容历史清单中圆括号被 GitHub 规范化为点号的安装包名。下载失败会同时显示 HTTP 状态和 curl 退出码，便于区分文件不存在与网络故障。
- Windows 通过 `dice-next.exe` 启动时支持“安装并重启”和可选自动安装；直接运行核心、Linux 与 macOS 目前只支持检测与下载，需停服后手动覆盖。
- 下载会核对 Release 清单中的文件大小和 SHA-256，并在解压前拦截绝对路径与目录穿越；Windows 替换失败会自动恢复旧程序。`config/`、数据库和用户文件不会进入替换清单，未与内置文件同路径的第三方插件也会保留。
- SHA-256 是损坏 / 一致性校验，不是独立发行签名。使用镜像（尤其自定义镜像）等同信任该来源；不确定时请选择“仅 GitHub”并保持“仅通知”。

完整升级流程见[安装部署 → 升级](/guide/install#升级)，接口字段见[API 参考 → 更新接口](/develop/api#更新接口)。

## Master（骰主）

添加 / 移除骰主账号（支持多个、按平台区分）。骰主拥有最高权限，可使用远程开关、黑白名单等管理指令。

## 表达式引擎

掷骰表达式可按“全局 → 分适配器 → 分账号”分层设置；分账号设置优先于分适配器，分适配器优先于全局。系统只在前一个引擎明确表示“不支持该语法”时继续尝试下一个引擎；除零、非法骰面、骰数超限等执行错误会直接返回，不会换引擎重新掷骰。

| 模式 | 引擎顺序 | 适用场景 |
|------|----------|----------|
| 增强兼容模式（默认） | Dice!Next → OneDice → DiceScript | 尽量兼容更多表达式语法 |
| 兼容模式 | Dice!Next → OneDice | 保留 Dice!Next 行为，并补充常用扩展骰式 |
| 原始模式 | Dice!Next | 只使用旧版 Dicebot 风格的原生表达式，不启用兼容引擎 |
| 自定义模式 | 自选一个或多个引擎，并调整固定优先级 | 按骰主需要控制可用语法和解析顺序 |

::: info DiceScript C99 兼容范围
Dice!Next 通过独立维护的 [dicescript-c-lib](https://github.com/DiceZone/dicescript-c-lib) 接入 DiceScript。C99 运行时已覆盖整数、浮点数、字符串、空值、数组、字典、区间、变量、computed value、函数、控制流、模板、容器方法与宿主回调，并支持普通骰、连续 `d`、`kh/kl/dh/dl/min/max`、优势/劣势、COC 奖励/惩罚骰、Fate、WOD 和 DoubleCross。

普通 `.r` 仍使用“单个表达式”入口，以便与指令后的检定理由可靠分隔；人物卡数值可作为 DiceScript 变量读取。完整语句、持久上下文、模板、原生函数/对象、自定义骰与 tagged VMValue 序列化由库的完整 C API 提供。

回退探测使用完整 VM 的只解析接口，不执行表达式、不访问宿主变量，也不消耗随机数。只有完整语法不支持时才进入下一个引擎；已经进入求值后的错误不会重复掷骰。
:::

自定义模式中的顺序是**固定优先级**，不是每次掷骰随机洗牌。固定顺序便于复现结果、定位兼容差异，也避免同一表达式在不同消息中被不同引擎解释。

::: tip 回退不会提前消耗随机数
系统会先用不消耗正式随机源的方式判断兼容引擎能否完整解析表达式，再执行实际掷骰。因此前一个引擎拒绝语法时，不会偷偷消耗骰点或改变后一个引擎的结果。
:::

## 指令前缀

增删触发前缀（默认 `.` `。` `!` `！`）。消息以任一前缀开头才会被当作指令；保存后即时生效。

## 好友 / 加群邀请审批

设定机器人如何自动处理好友申请与加群邀请：

| 项目 | 可选策略 |
|------|----------|
| 好友申请 | 不自动处理（人工）/ 任意人自动通过 / 含关键词才自动通过 / 自动拒绝 |
| 加群邀请 | 不自动处理（人工）/ 任意人邀请自动通过 / 仅白名单与 Master 邀请自动通过 / 忽视所有 / 拒绝所有 |
| 黑名单群邀请自动拒绝 | 开关 |
| 拒绝非好友邀请加群 | 非好友邀请自动拒绝；若被强行拉入群，骰娘提示后自动退群（骰主与白名单用户豁免） |
| 群名关键词自动退群 | 入群后查询群名，含任一关键词即自动退群并通知骰主（空格分隔多个关键词） |

## 日志站

`.log end` 上传跑团日志的目标站点，可自建（兼容 SealDice 上传协议）：

- **日志站 API 地址**：改成非官方地址时会显示第三方站点提示。
- **上传协议**：SealDice 兼容（默认，zlib 压缩 JSON）/ SealDice V105（Parquet 列式）/ DiceNext 专属（zstd 压缩）/ 旧版（多段 txt POST）。

## 心跳上报

将骰娘在线状态上报到公开心跳站 [heart.dice.zone](https://heart.dice.zone)：骰娘会出现在心跳广场、可被搜索，骰主还能在心跳站面板查看在线时长、会话数等统计，并配置离线提醒。

**接入步骤**：

1. 在 [account.dice.zone](https://account.dice.zone/dashboard/bindings) 的“骰子绑定”页面为骰娘生成 API Key；
2. 回到管理面板 → 平台连接，在对应适配器中填写该骰娘的 API Key；
3. 到系统设置 → 心跳上报打开开关并保存；
4. 点「立即测试」确认上报成功；状态行会显示最近一次上报结果与时间。

| 配置项 | 说明 |
|------|------|
| 服务地址 | 默认官方 heart.dice.zone，可改为自建服务 |
| 骰主信息 | 昵称与 QQ 均为可选。两项都留空时，自动取骰主列表中第一位 OneBot 骰主的 QQ，并从玩家档案读取昵称；任一项填写后，手工填写的整组信息优先，不再自动读取 |
| 适配器身份凭证 | API Key 按骰娘分别配置；此处显示已配置数量并链接到平台连接页面 |
| 公开展示 | 关闭后不出现在心跳广场与搜索；不影响展柜等其他页面读取在线状态 |
| 上报间隔 | 180–480 秒（默认 240）。上线立即报一次，之后周期保活 |

正常退出时会自动补报一次离线；进程崩溃或断网时，服务端超过判定窗口仍会自动标记离线并结算本次在线时长。客户端内置状态防抖，避免重复上报触发频控。

## 戳一戳

被戳一戳时的反应：可开关；「映射指令」优先（把戳一戳当被戳者发的一条消息跑，可填 `.jrrp`、插件指令或自定义回复触发词），留空则发「回复文本」。

## 入群欢迎设置

全局的欢迎词**最低延迟**与**最低冷却**（秒），防止新人连续进群时欢迎词刷屏。各群自己的欢迎词、延迟、冷却在[群组管理 → 功能管理](/manage/groups)里设置，实际生效值不会低于这里的下限。

## 开关与发送行为

### 回复展示形式

“启用 Markdown / 富消息”是全局主开关，切换后立即保存：

- **关闭**：QQ 官方、Discord、KOOK 与 OneBot 全部发送传统文本；模板里的粗体、行内代码等标记先转换成可读文字，不会原样泄漏星号等格式符。
- **开启**：QQ 官方优先 Markdown、Discord 使用 Embed、KOOK 使用 CardMessage；平台拒绝富消息或回复超长时自动回退传统文本，OneBot 始终保持文本。
- **作用域覆盖**：全局开启后，可以切换到分适配器或分账号作用域单独关闭；局部开启不能绕过关闭的全局主开关。
- **发送性能**：Markdown 文案的传统文本版本在加载或保存时预先生成；切换开关后发送管线直接选择对应版本，不会在每次回复、每个分段重复转换。QQ 官方连续两次拒绝卡片后会自动使用传统文本 10 分钟，再恢复探测。

回复模板及变量样式的编辑方法见[指令列表 → 自定义回复文案](/manage/commands#自定义回复文案)。

| 设置项 | 说明 |
|--------|------|
| 开机自启动 | 随 Windows 登录自动启动（仅 Windows） |
| 保存日志图片 | 跑团记录中的图片落地到 `data/logs/images`，导出网页时内嵌显示 |
| 自响应消息（自控） | 骰娘账号自己发的消息也会被处理，可用骰娘账号自控；内置自回声去重与跨骰防环护栏，默认关闭 |
| 引用投掷对象发言 | 回复以 QQ「引用」样式回复触发指令的那条消息 |
| 自动卡面（HP/SAN 摘要） | `.st` 设定基础属性后自动算出生命 / 理智 / 魔法并附摘要（仅 COC 类规则） |
| 长消息合并转发 | 回复超过阈值（默认 1200 字符）强制以合并转发形式发送，防刷屏（仅群聊、仅 OneBot） |
| 分段发送长度 | 回复超长自动分段（默认 600，约 300 汉字；尽量在换行处切分） |
| 用户名包裹 | 回复里用户名的前后缀（默认 `<` `>`，如「\<希亚\>掷骰」；留空＝不包裹） |

## 图片相关

- **图片发送方式**：回复里插入的图片以 `[img,file=本地路径]` 保存，发送时转换为 base64 内嵌（默认，跨设备通用）或 HTTP 链接（需 NapCat 能访问本机）。
- **图床（稳定图片链接）**：决定日志图片如何在日志站长期可见——不上传 / 第三方图床（通用 multipart 上传，适配 ImgBB、sm.ms、兰空等）/ 本地链接（自托管，需公网 HTTPS）。

## 聊天与好友维护

- **聊天记录保留期**：模拟聊天的消息持久化保存（`chat.db`），按天数自动清理。
- **用户群**：设置官方用户群，可选强制成员加群、允许邀请。
- **自动清理好友**：超过设定天数无互动的好友自动清理（0＝关闭）。

## 导入旧版数据

填入旧版 Dice! 的数据目录路径，一键迁移角色卡、玩家档案、黑名单、自定义回复、牌堆、mod 等，可选是否覆盖同名数据。详见[数据迁移](/guide/migration)。

## 原版全局设置

复刻原版 Dice! 的 console 全局配置，按组管理：

| 分组 | 内容 |
|------|------|
| 响应开关 | 全局静默；全局停用 `.jrrp` / `.me` / `.deck` / `.draw` / `.send` / `.help` |
| 牌堆 / 显示 | 是否隐藏牌堆 `_` 元数据键 |
| 事件响应 | 加群请求 / 入群反馈（欢迎词）/ 好友请求 / 好友添加 |
| 云 / 网络 | 云端可见性等（标「记录」项暂为预留） |
| 外部请求 | 自定义回复 `{api:URL}` 开关与超时（默认关闭，自动拦截私网地址） |
| 自动维护 | 用户 / 群不活跃上限天数、单次清群上限等 |
| 其他兼容 | 私用模式、黑名单用户自动退群等记录项 |

> 标注「记录」的项目会保存配置，但行为尚未联动，属于为兼容预留。

::: tip 指令禁用对信任用户无效
全局停用某指令仅对普通用户生效，信任等级 4 及以上 / 骰主不受限制。
:::

::: info 骰主通知已移至「通知设置」页
通知窗口、事件订阅、SMTP / Webhook 推送与审计日志现在统一在[通知设置](/manage/notice)页管理。
:::

## WebUI 设置页

**管理面板 → 系统设置 → WebUI 设置**，管理面板自身的设置：

| 设置项 | 说明 |
|--------|------|
| API Key | 访问后端 API 的认证密钥，与配置文件 `server/api_key` 保持一致 |
| 管理面板登录密码 | 设置后打开面板需先输入密码（Cookie 会话认证）；留空保存即关闭登录；修改 / 清除会使现有登录会话失效；可一键退出登录 |
| 运行 IP 与端口 | 面板与接口的监听地址（`0.0.0.0` 表示监听所有网卡）与端口（默认 18088）。**修改后需重启生效**（HTTP 监听在启动时绑定，无法热切换），保存后可点「立即重启」 |
| 主题偏好 | 浅色 / 深色 / 跟随系统 |
| 控制台日志 | 详细模式开关：开启记录全部事件（含心跳、接口响应，均为可读解释），关闭则只记录消息与重要事件 |
