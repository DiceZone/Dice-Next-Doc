# 基础设置

**管理面板 → 系统设置 → 基础设置**，配置骰主、指令、审批、图片与回复行为。面板自身的登录密码、端口等在同组的 [WebUI 设置](#webui-设置页) 管理。

骰娘密钥、心跳、云黑名单、云人物卡及日志站统一在[云服务](/manage/cloud-services)管理；图床仍在本页。

外部 AI 客户端的连接、独立凭据、工具权限和调用记录在同组的 [MCP 服务](/manage/mcp)管理，默认关闭。

## 检测与自动更新

**管理面板 → 关于项目 → 检测与自动更新**集中显示当前版本、最新 Release、平台安装包、下载来源与更新阶段，并提供检查、下载、安装及自动策略设置。

也可点击右上角的版本文字直达更新区域。Beta 版本显示为 `beta-3.0.0(123)`，正式构建为 `v3.0.0(123)`；发现新版本时旁边显示红色 **New**。侧栏不再展示固定版本号，顶栏不再使用“已连接”徽章代替版本信息。编译时间按 **UTC+8** 显示并明确标注，不跟随浏览器本地时区。

- 默认每 6 小时检查一次，发现新版本时**仅通知**，不会擅自下载或重启。
- 选择“自动安装并重启”后，可开启**定时安装**，默认每天 **04:00**。程序先下载并校验，安排到下载完成后的下一次设定时间；当天时间已过则安排到次日。使用**基础设置中的服务器时区**，不是浏览器时区，面板会显示完整安装日期、时间与 UTC 偏移。
- **定时只决定程序何时主动重启**。自动安装策略开启且包已就绪时，任何提前发生的重新启动都会顺带安装，包括面板重启、退出后重新打开、系统重启及守护进程拉起；不必等到定时窗口。仅下载 / 仅通知策略不会在启动时安装。
- 计划与暂存包持久化。程序每分钟检查一次主动重启计划，更新操作进行中时会先完成。修改时间或服务器时区会重新安排；关闭定时只取消主动重启计划，已授权更新仍会在下一次启动时安装。若要同时禁止启动时安装，应将策略改成“仅下载”或“仅通知”。关闭自动检查只停止寻找新版本，不取消已有计划。也可直接点击“安装并重启”。
- 发现新版本时会通过通知系统发送“发现新版本”；自动下载 / 安装成功发送“更新结果”，失败发送“更新失败”。同一 Release 只提醒一次。已有通知窗口若逐项筛选事件，需要在通知设置中额外勾选这三个新增事件。
- 下载来源可选：自动选择、仅 GitHub、仅内置镜像、自定义镜像。自动模式并行探测 GitHub 直连与内置镜像，使用最先成功且清单有效的来源，并短期缓存可用来源。
- 下载期间可点**取消下载**，等待“已取消”后再次下载；连接、下载、校验和准备阶段可取消，正式安装不可取消。连续 60 秒没有新增数据或单个来源尝试达到 20 分钟时会停止本次传输，并按配置尝试其他来源；所有来源失败后显示错误，可重试，不需要重启程序。
- 前端请求超时不表示后台已停止。页面会重新获取状态后才开放下一步操作；状态暂不确定时可以刷新状态，不应重复点击下载或安装。
- Release 安装包只使用 GitHub 不会改写的安全文件名；更新器也兼容历史清单中圆括号被 GitHub 规范化为点号的安装包名。下载失败会同时显示 HTTP 状态和 curl 退出码，便于区分文件不存在与网络故障。
- 完整包的管理器模式支持“安装并重启”与可选定时自动安装：Windows 使用 `dice-next.exe`，包含 POSIX 管理器的新 Linux/macOS 包使用 `start.sh` 或 `dice-next`。beta.928 及更早的 Linux/macOS 包需先手动完整升级一次；该能力待新包发布。直接运行核心仅检测、下载。容器内只保留检查和新版本通知，下载与安装由服务端拒绝；请更新镜像后重新创建容器。
- 下载会核对 Release 清单中的文件大小和 SHA-256，并在解压前拦截绝对路径与目录穿越；Windows 替换失败会自动恢复旧程序。`config/`、数据库和用户文件不会进入替换清单，未与内置文件同路径的第三方插件也会保留。
- SHA-256 是损坏 / 一致性校验，不是独立发行签名。使用镜像（尤其自定义镜像）等同信任该来源；不确定时请选择“仅 GitHub”并保持“仅通知”。

完整升级流程见[安装部署 → 升级](/guide/install#升级)，接口字段见[API 参考 → 更新接口](/develop/api#更新接口)。

## Master（骰主）

添加 / 移除骰主账号（支持多个、按平台区分）。骰主拥有最高权限，可使用远程开关、黑白名单等管理指令。

## QQ 邮箱绑定验证

在本页配置专用 SMTP 并启用，供 QQ 官方、Discord、KOOK 用户在私聊中验证 QQ号@qq.com。
填写服务器、端口、账号、密码或授权码与发件邮箱；465 通常使用隐式 TLS，587 使用强制 STARTTLS。
密码保存后不回显，留空编辑保留原值。不接受任意收件邮箱，也不用于群归属验证。
此配置为全局设置，与骰主通知邮件独立。用户统一输入 `.bind qq <QQ号>`：当前客户端有正式骰娘 key 时优先 OAuth，否则自动申请邮件。
邮件用 `.bind confirm <8位验证码>` 完成；有 key 但主动选择邮件时，用 `.bind qq <QQ号> email`。OAuth 则网页同意后用 `.bind confirm`，失败不会自动发送邮件。
指令和安全限制见[QQ 邮箱验证码](/use/cloud#qq-邮箱验证码)。

## 表达式引擎

掷骰表达式可按“全局 → 分适配器 → 分账号”分层设置；分账号设置优先于分适配器，分适配器优先于全局。系统只在前一个引擎明确表示“不支持该语法”时继续尝试下一个引擎；除零、非法骰面、骰数超限等执行错误会直接返回，不会换引擎重新掷骰。

| 模式 | 引擎顺序 | 适用场景 |
|------|----------|----------|
| 增强兼容模式（默认） | Dice!Next → OneDice → DiceScript | 尽量兼容更多表达式语法 |
| 兼容模式 | Dice!Next → OneDice | 保留 Dice!Next 行为，并补充常用扩展骰式 |
| 原始模式 | Dice!Next | 只使用旧版 Dicebot 风格的原生表达式，不启用兼容引擎 |
| 自定义模式 | 自选一个或多个引擎，并调整固定优先级 | 按骰主需要控制可用语法和解析顺序 |

::: info DiceScript C99 兼容范围
Dice!Next 通过独立维护的 [dicescript-c-lib](https://github.com/DiceZone/dicescript-c-lib) 接入 DiceScript。C99 运行时已覆盖整数、浮点数、字符串、空值、数组、字典、区间、变量、computed value、函数、控制流、模板、容器方法与宿主回调，并支持普通骰、连续 `d`、`kh/kl/dh/dl/min/max`、优势/劣势、COC 奖励/惩罚骰、Fate、WOD 和 DoubleCross。

普通 `.r` 仍使用“单个表达式”入口，以便与指令后的检定理由可靠分隔；人物卡数值可作为 DiceScript 变量读取。完整语句、持久上下文、模板、原生函数/对象、自定义骰与 tagged VMValue 序列化由库的完整 C API 提供。

回退探测使用完整 VM 的只解析接口，不执行表达式、不访问宿主变量，也不消耗随机数。只有完整语法不支持时才进入下一个引擎；已经进入求值后的错误不会重复掷骰。
:::

自定义模式中的顺序是**固定优先级**，不是每次掷骰随机洗牌。固定顺序便于复现结果、定位兼容差异，也避免同一表达式在不同消息中被不同引擎解释。

::: tip 回退不会提前消耗随机数
系统会先用不消耗正式随机源的方式判断兼容引擎能否完整解析表达式，再执行实际掷骰。因此前一个引擎拒绝语法时，不会偷偷消耗骰点或改变后一个引擎的结果。
:::

## 指令前缀

增删触发前缀（默认 `.` `。` `!` `！` `/`）。消息以任一前缀开头才会被当作指令；保存后即时生效。QQ 官方平台可使用 `/r` 等写法。已有自定义前缀列表不会被覆盖，需要时可在此补上 `/`。

## 掷骰随机源

在**基础设置 → 掷骰随机源**选择并保存（全局搜索“随机源”可直达），全局应用于 Dice!Next、OneDice、DiceScript 与 MCP 掷骰，立即生效并持久保存。旧的“骰子规则”页面已移除，原地址会自动跳到这里。

| 方案 | 特点 |
|------|------|
| 操作系统安全随机（默认） | Windows 使用 BCryptGenRandom，Linux 使用 getrandom，macOS 使用 getentropy。系统会持续混入 CPU 硬件随机、中断时序等熵；应用不额外维护随机状态，不依赖网络 |
| OpenSSL 安全随机 | 使用 RAND_bytes，由系统熵源播种的 DRBG；同样不依赖网络 |
| CPU 硬件熵源 | 每次读取 CPU 的物理噪声熵源 RDSEED，再与操作系统安全随机按位异或，结果不弱于系统随机。仅 x86-64 CPU 提供，不支持时该选项不可选；RDSEED 繁忙或失败时本次自动改用系统随机 |

三种方案每次掷骰的开销都约为 1 微秒，不占额外内存。插件自行生成的随机数、每日运势与预览示例不受此选项控制。

**不会因随机源故障停止掷骰。** 所选来源不可用时，依次改用另一个安全随机源；全部不可用时才使用应急伪随机（xoshiro256**），程序日志记录一次 WARN，来源恢复后自动切回并记录 INFO。设置卡片会显示最近一次掷骰实际使用的来源。实际中系统接口极少失败，常见原因是 Linux 内核早于 3.17（如 CentOS 7）没有 getrandom，或容器的安全策略屏蔽了它。

为什么不直接用“真随机”服务：海豹核心提供 PCG（默认）、系统 CRNG、NIST AES-CTR-DRBG、国密 SM3（默认禁用，启用需约 32 MB 内存采集熵）及混合模式；青果默认使用 Python 的梅森旋转，可选从 random.org 拉取随机数。Dice!Next 默认已直接使用系统安全随机，硬件熵源方案在 CPU 支持时提供更直接的物理噪声来源；在线随机服务依赖网络、存在限流与隐私问题，因此未采用。

## QQ 官方 SN 状态行

在**基础设置 → 回复与显示 → QQ 官方 SN 状态行**调整 `.sn` 的顶部显示；全局搜索“SN”“彩色文字”可直达。支持全局、适配器类型、单个账号，优先级为账号 > 类型 > 全局，保存后立即生效，可恢复继承。

| 预设 | 显示方式 |
|---|---|
| 彩色文字（默认） | 使用 QQ 公式格式 `scriptsize` 与 `\textcolor`，默认红色 `#E5484D`；选中后下方出现色盘、取色器、常用色块和 #RRGGBB 输入框，可直接改颜色。取色器可从屏幕任意位置吸取颜色（Esc 取消），需 Chrome / Edge 且通过 HTTPS 或 localhost 打开面板，其他情况按钮不可用。不发送 HTML `<font>` |
| 引用 | Markdown 引用块 |
| 普通文字 | 不加额外装饰 |
| 自定义格式 | 编辑 Markdown，用占位符插入状态内容 |
| 关闭状态行 | 不显示顶部状态，保留玩家设置 |

此处只控制外观；玩家仍需在群内执行 `.sn` 或 `/sn` 开启自己的状态行，`.sn off` 关闭。`.setsn` 设置群默认属性，`.sn {nick} SAN{san}` 设置个人内容。其他平台的真实群名片行为不变。

自定义格式示例：

```text
> {sn}
```

```text
$\scriptsize\textcolor{#E5484D}{\text{{sn_tex}}}$
```

`{sn}` 插入已经转义的 Markdown 文字；公式中请把 `{sn_tex}` 放在 `\text{…}` 内，用于安全处理昵称中的反斜线、括号等字符。格式至少包含一个占位符，最多 2048 UTF-8 字节；反复插入占位符导致状态行超过 3000 字节时退回一份普通状态文字。切换预设不会丢失已编辑的自定义格式。预览使用固定示例数据，最终显示以 QQ 客户端为准。

装饰样式需要 Markdown：选择传统文本方案、用 `.bot text plain` 强制纯文本，或平台明确拒绝格式时，状态行降级为普通文字，不输出公式代码。状态与后面的正文用独立段落分隔。

## BotMsg 附加说明

在**基础设置 → 回复与显示 → BotMsg 附加说明**编辑 `.bot` 固定信息之后的介绍、联系方式或帮助提示。支持全局、分适配器和分账号设置，优先级为账号 > 适配器 > 全局；留空可隐藏附加说明。

`.bot` 的前三行始终由系统生成，不能通过附加说明或旧版页眉替换：

1. 程序版本、构建号与作者名。使用后端持久化的 `i18n.default_locale`：中文显示“希亚”，其他语言显示“ShiaNyaa”。右上角的 WebUI 语言保存在当前浏览器，不改变此默认回复语言。
2. 当前程序的编译器、编译时间与适配器信息。
3. 当前账号实际启用的兼容表达式引擎。默认显示 `OneDice V1 & DiceScript Compatible`；只开启 OneDice 或 DiceScript 时仅显示对应名称，只使用原生引擎时显示 `Dice!Next Native`。

默认附加说明为：

```text
Dice!Next 测试群：933145116
如有故障或建议欢迎加群反馈
使用 .help 查看帮助
```

从旧版导入时，`strBotMsg` 保留原文，并在末尾另起一行追加上述默认说明；重复导入不会重复追加。`strBotHeader` 也会保留，但移动到三行固定信息之后。已有自定义说明且未授权覆盖时，迁移报告会提示冲突并保留现有设置。

## 敏感词拦截

位于**安全与权限**分区，复刻原版 Dice! 的指令敏感词检测。功能默认关闭且**不附带任何内置词表**；只有骰主在页面保存的规则，或从旧版 `conf/CustomCensor.json` 迁入的规则会参与匹配。

- 只检查以当前指令前缀开头的入站消息，不扫描普通群聊，也不修改骰娘回复或插件输出。
- 匹配自动跳过空格和 ASCII 特殊符号，英文大小写不敏感；一条指令命中多项时取最高等级。
- Master 与信任等级 4 及以上跳过检测。信任等级 1–3 会按原版规则降低实际处置：只有规则等级不低于用户信任等级时才拦截。
- 命中会写入本机日志并发到对应级别的[骰主通知窗口](/manage/notice)。为避免 QQ 官方平台二次触发同一平台敏感词，通知消息不复述命中词和原指令，详细内容只保留在本机日志。
- 页面可在启用前测试一条指令，测试使用与实时消息相同的服务端匹配器。

| 等级 | 行为 |
|------|------|
| Ignore (0) | 忽略这条规则，可用于保留旧版禁用项 |
| Notice (1) | 仅记录并发送例行通知，不阻止指令 |
| Caution (2) | 提醒用户并拦截指令，发送重要通知 |
| Warning (3，默认) | 警告用户并拦截指令，发送重要通知 |
| Danger (4) | 拒绝指令，发送关键通知 |
| Critical (5) | 兼容旧数据；按最高风险处理，与 Danger 一样拒绝指令，并发送错误通知 |

聊天侧也可由骰主使用 `.admin censor` 增删或开关规则，详见[管理指令](/use/admin#敏感词管理)。

## 开关与发送行为

### 回复文案与视觉方案

回复展示可选择三种方案，切换后立即保存：

- **传统文案**：使用早期版本的简洁措辞和纯文字排版。
- **标准文案**：使用当前标准措辞；支持的平台渲染 Markdown，不支持时自动转成可读文字。
- **高级视觉文案**：在标准文案上加入状态条、操作提示等语义组件；QQ 官方可把用法提示变成点击后填入输入框的按钮，纯文本平台则显示为 `HP [██████░░░░] 6/10`、`.r // 掷骰指令` 等稳定形式，不生成图片。
- **作用域覆盖**：全局、平台类型和单个适配器账号可以分别选择，优先级为账号 > 平台 > 全局；清除覆盖后继续继承上一级。
- **发送性能**：Markdown 文案的纯文字版本在加载或保存时预先生成。QQ 官方连续两次拒绝卡片后会自动使用纯文字 10 分钟，再恢复探测。

回复模板及变量样式的编辑方法见[指令列表 → 自定义回复文案](/manage/commands#自定义回复文案)。

| 设置项 | 说明 |
|--------|------|
| 开机自启动 | 随 Windows 登录自动启动（仅 Windows） |
| Windows 托盘提示文字 | 「网络与系统」选项卡内设置托盘图标悬停名称，最多 10 个字符，留空使用 `Dice!Next`；自动追加实际端口，保存后立即生效，仅 Windows 可修改 |
| 保存日志图片 | 跑团记录中的图片落地到 `data/logs/images`，导出网页时内嵌显示 |
| 自响应消息（自控） | 骰娘账号自己发的消息也会被处理，可用骰娘账号自控；内置自回声去重与跨骰防环护栏，默认关闭 |
| 引用投掷对象发言 | 回复以 QQ「引用」样式回复触发指令的那条消息 |
| 自动卡面（HP/SAN 摘要） | `.st` 设定基础属性后自动算出生命 / 理智 / 魔法并附摘要（仅 COC 类规则） |
| 长消息合并转发 | 回复超过阈值（默认 1200 字符）强制以合并转发形式发送，防刷屏（仅群聊、仅 OneBot） |
| 分段发送长度 | 回复超长自动分段（默认 600，约 300 汉字；尽量在换行处切分） |
| 用户名包裹 | 回复里用户名的前后缀（默认 `<` `>`，如「\<希亚\>掷骰」；留空＝不包裹） |

自定义托盘名称从 build 926 起支持，保存为 `config/dice.json` 的 `tray_text`，不属于平台或适配器账号覆盖项。也可通过已认证的 `GET /api/system/tray` 查看 `{ text, port, tooltip, supported }`，使用 `PUT /api/system/tray` 提交 `{ "text": "希亚骰" }`；端口不可通过此接口修改。名称按 Unicode 字符计数，不允许内部换行或控制字符。

## 图片相关

- **图片发送方式**：回复里插入的图片以 `[img,file=本地路径]` 保存，发送时转换为 base64 内嵌（默认，跨设备通用）或 HTTP 链接（需 NapCat 能访问本机）。
- **图床（稳定图片链接）**：决定日志图片如何在日志站长期可见——不上传 / 第三方图床（通用 multipart 上传，适配 ImgBB、sm.ms、兰空等）/ 本地链接（自托管，需公网 HTTPS）。

## 聊天与好友维护

- **聊天记录保留期**：模拟聊天的消息持久化保存（`chat.db`），按天数自动清理。
- **用户群**：设置官方用户群，可选强制成员加群、允许邀请。
### 自动清理好友、群聊与本地记录

此卡片是全局设置，分为两组；修改后点击保存，不需要重新启动。启动约 5–6 分钟首次检查，之后每 12 小时检查。

| 设置 | 实际行为 | 0 的含义 |
| --- | --- | --- |
| 用户记录不活跃期限（天） | 按最后收到消息时间清理用户档案；旧档案回退到指令/建档时间 | 关闭 |
| 群记录不活跃期限（天） | 按最后消息/指令时间清理群列表资料，收到新消息后恢复显示 | 关闭 |
| 好友未使用指令期限（天） | 调用适配器删除好友；无指令记录时参考建档时间 | 不删好友 |
| 群聊未使用指令期限（天） | 退出当前骰娘账号长期没有收到指令的群；普通聊天不算指令 | 不因不活跃退群 |
| 超过多少群成员时退出（人） | 成员数量严格超过上限时退出，不是可加入的群数 | 不按人数退群 |
| 每轮最多退出群数（个） | 限制本轮退群数量，剩余留到下轮 | **不限制数量**，并非关闭清理 |

本地记录清理不会调用删好友/退群接口，保留人物卡、跑团日志、身份绑定、插件变量、群规则和权限。用户档案内的昵称、好感度和计数随档案清除；群列表资料到期后暂不显示，实际消息会重新建档。手工移除/退群标记不会被普通消息擅自清除。

骰主、信任/白名单用户免清；群白名单、旧版免清/忽略设置以及正在记日志的群受保护。未知或无效活动时间不会被当作“很久没活动”。好友删除与退群只在已连接且支持相应接口的适配器上执行；不会因另一个骰娘账号的活动记录判断当前账号该退群。

现有定时任务的配置、启用状态和执行方式不变。若以前已通过定时任务设置自动退群，请先核对，避免同时启用两个相同策略。

复刻原版 Dice! 的 console 全局配置，按组管理：

|------|------|

## WebUI 设置页

**管理面板 → 系统设置 → WebUI 设置**，管理面板自身的设置：

管理面板只有一套界面（原 V2 已转为正式版，旧版界面不再随安装包提供）。以前收藏的 `/v1/`、`/v2/` 地址会自动跳回后台首页；`config/webui.json` 中旧的 `ui_version` 字段不再使用，保留也不影响启动。

| 设置项 | 说明 |
|--------|------|
| API Key | 访问后端 API 的认证密钥，与配置文件 `server/api_key` 保持一致 |
| 管理面板登录密码 | 设置后打开面板需先输入密码（Cookie 会话认证）；登录时可选择信任设备 30 天并跨程序重启恢复。留空保存即关闭登录，修改 / 清除会使现有登录会话失效；同机多套安装使用独立 Cookie，退出只影响当前实例 |
| 运行 IP 与端口 | 面板与接口的监听地址（`0.0.0.0` 表示监听所有网卡）与端口（默认 18088）。**修改后需重启生效**（HTTP 监听在启动时绑定，无法热切换），保存后可点「立即重启」 |
| 主题偏好 | 浅色 / 深色 / 跟随系统 |
| 控制台日志 | 最低记录级别 TRACE / DEBUG / INFO / SUCCESS / WARN / ERROR，默认 INFO；协议事件诊断仍遵守级别，正常心跳 TRACE、轮询 DEBUG，不提升到 INFO |

记录级别控制之后写入控制台和文件的日志；首页的“最低展示级别”只筛选当前浏览器中的记录。降低展示级别不能补出此前未保存的 DEBUG／TRACE。格式、插件来源和消息对应方式见[程序日志](/manage/dashboard#程序日志)。

设置工作区按功能分选项卡，保存行为仍以各项按钮或即时保存提示为准。浏览器安装独立窗口的方法见[安装部署 → 将管理面板安装为应用](/guide/install#将管理面板安装为应用)。
