# 指令列表

**管理面板 → 指令列表**，一处查看全部指令并**自定义骰娘的回复文案**，同时管理骰娘的**人格**。

页面顶部有人格下拉、「人格管理」和「人格开放」按钮，下方按分类分选项卡展示所有可编辑文本。

## 选项卡

| 选项卡 | 内容 |
|---|---|
| 全部文本 | 所有指令的回复文案（可逐条自定义） |
| 全部变量 | 文案里可用的变量说明 |
| 无效文本 | 引用了但已不存在的孤立文案键（便于清理） |
| 掷骰 | 表达式掷骰、骰池和掷骰错误提示 |
| COC | COC 检定、理智、技能成长，以及 BRP 检定与对抗；含成功等级短语 |
| DND | DND 建卡、属性检定、先攻与相关规则 |
| 团务 | 跑团日志、会话和团务操作 |
| 互动 | 牌堆、娱乐、AI 对话和骰娘人格切换 |
| 工具 | 人物卡、属性管理、昵称等实用功能 |
| 管理 / 权限 / 系统 | 群与账号管理、权限提示、系统设置及旧版文案兼容 |

「全部文本」按 **指令示例 → 描述 → 键名 → 当前文本** 展示，每列标题均可点击切换升序 / 降序，窄屏卡片模式也提供排序选项。搜索可同时匹配指令示例、功能描述、原版键名和当前文本，并可按功能分类筛选。没有固定指令的自动事件与共用提示会明确标注，不生成不存在的指令。

各功能分组也可直接展开编辑相应文案，例如「COC → 检定结果等级」可修改大成功、极难、困难、普通成功、失败和大失败。BRP 保留独立的功能条目与结果文案，但与 COC 共用选项卡。人物卡功能归入「工具」，牌堆、娱乐与 AI 归入「互动」。导入或扩展带来的未知文案仍保留在「全部文本」中，标为未归类。

每条文本右侧的 `编辑` 可改写；被改过的条目会标一个 `●`，可一键**还原**为默认文案。「系统 → 旧版文案兼容」也收录 `.strSelfName` / `.strSelfCall` 的回执；名称与自称本身仍使用专用配置，不改成普通模板覆盖。

「工具 → 快捷指令」收录 `.alias` / `.&` / `.a` 的管理回执、列表和调用结果前缀；标题旁的问号可查看完整用法。文案专属变量包括 `{shortcut}`（快捷名称）、`{source}`（群/个人）、`{command}`（展开后的目标指令）、`{list}`（列表），预览使用本语言的示例值，不执行目标。调用前缀与正文自动分行；可以把前缀设为空以隐藏它，但不会改变目标逻辑或开关。旧账号权限关联的回执仍在「权限 → 账号别名」，对应 `.admin account-alias`，不会被新快捷指令文案覆盖。

## 自定义回复文案

骰子几乎所有回复（掷骰结果、检定成功 / 失败、各种提示）都以模板文本存储，可在此改写口吻，并使用变量：

- 指令专属变量以浅色 chip 展示在编辑器里；
- 通用变量（标 **全局变量**）用「插入全局变量」按钮插入，如 `{nick}`、`{user}` 等。

每条文案都明确保存一种输出格式：

编辑弹窗把格式、变量样式等低频操作收进「高级选项」，窄屏默认收起，宽屏默认展开；内容区域可滚动，保存 / 放弃按钮不覆盖编辑区。折叠只改变显示，不清空已有属性。

- **纯文本**：默认选择，也是旧版自定义文案、插件回复和历史人格文案的兼容格式。用户输入的 `**`、`#`、`>`、下划线等字符会按原文发送，不会被猜测为 Markdown 后误删。
- **Markdown**：仅在明确选择后启用。QQ 官方机器人、Discord、KOOK 等支持 Markdown 的平台会按富文本发送；OneBot 等纯文本平台直接使用保存时自动生成的纯文字版本，保留可见文字、CQ 码和骰子表达式。

编辑器会列出当前模板已经使用的变量，并允许逐个选择 **普通 / 粗体 / 斜体 / 行内代码 / 删除线**。选择非普通样式时，编辑器会直接把安全的 Markdown 包装写进模板并自动切换为 Markdown 格式；因此人格、导入导出和模板还原都能沿用同一份可见文本，不依赖隐藏配置。昵称、理由等动态值仍会在服务端转义，避免玩家输入改变模板排版。

你只需编辑这一份 Markdown 原稿。保存时服务端会同步重建纯文字版本；内置模板在启动 / 重载时生成，人格模板在载入时生成。两种版本会保留相同的 {变量}，等真正回复时才代入实际值，所以切换展示形式不需要逐条重存，也不会使用上一次回复的数据。

编辑弹窗下方同时提供两种实时示例：

- **平台选择**：QQ 官方群聊、C2C 与频道分别选择，另有 KOOK、Discord、OneBot / Milky / 纯文本；频道不会预览成 QQ Markdown。
- **方案选择**：传统、标准、高级视觉，并可模拟 `.bot text plain`；这些选择只用于预览，不修改已保存的全局/账号配置。
- **文字示意 / 传输结构**：后端使用实际文本/卡片序列化器；不是客户端截图，不模拟 CQ/媒体上传、身份映射、QQ 数学排版或平台权限。接口不可用时显示错误，不以原文冒充降级结果。

模板变量会用示例值代入预览；这只用于查看排版，不会执行真实骰点，也不会发送消息。

切换变量的粗体、斜体、代码或删除线时，会替换该变量局部已有的嵌套标记，不重复堆叠；外围整句排版与乘法运算不受影响。

::: tip 切换整套展示方案
到 **系统设置 → 回复与显示 → 回复文案与视觉方案** 可选择传统、标准或高级视觉文案；也可以只覆盖某个平台或账号。人格继续控制口吻，展示方案只控制排版与交互。
:::

> 改写文案不会改变指令逻辑，只改变对外措辞。想给不同场景多套口吻，请用下面的「人格」。

## 按检定结果设置完整回复

在「COC → 按结果分级的标准回复」中，可分别设置大成功、极难成功、困难成功、成功、失败和大失败的**完整回复**，而不只是末尾的等级短语。另有 BRP 用的「特殊成功」与对抗用的「平局」。

其他检定的功能条目中也有对应等级，可单独开启「单独设置此等级回复」。继承顺序为：

```text
本类检定的该等级回复 → 标准检定的同等级回复 → 此指令原有文案
```

未设置的等级保持继承，不会自动复制一份固定文本。点击「恢复继承」只删除当前编辑层的覆盖；编辑人格时，人格没有设置的同名项先继承全局同名项。界面会显示当前来源，并预览继承的文本。

| 检定 | 可单独设置的结果 |
| --- | --- |
| COC `.ra/.rc/.rad`，含暗检定 | 六个 COC 等级；暗检定的详细回复仍只发私聊 |
| 奖励 / 惩罚 `.rb/.rp`、`.rab/.rap`、`.ra b/p` | 各自六个等级；无技能 / 成功率的纯奖励、惩罚骰不判成功失败 |
| BRP `.ba` | 大成功、特殊成功、成功、失败、大失败，不把特殊成功冒充 COC 极难成功 |
| SAN `.sc`（含奖励 / 惩罚） | 六个 COC 等级；仅改变文字，损失与人物卡扣减照常进行 |
| 成长 `.en` | 成功 / 失败，按成长的高骰判定，不套用 COC 的低骰成功规则 |
| 心理学暗骰 `.rx` | 六个等级的私聊详细结果，群回执仍不透露结果 |
| 对抗 `.rav/.rcv` | 第一方胜 / 负 / 平局，分别使用成功 / 失败 / 平局回复 |
| BRP 抵抗 `.bav` | 主动方成功 / 失败 |
| DND `.rdc` | 指定目标难度后判成功 / 失败；不指定难度的 `.rdc` 与 DND `.rc` 保持普通结果 |
| 死亡豁免 `.ds` | 自然 20（大成功）、成功、失败、自然 1（大失败）；稳定 / 死亡状态提示仍保留 |

普通 `.r`、WOD 成功数骰池和双十字点数没有整体目标值，不会强行归入成功 / 失败。连续检定逐次选择对应等级，不用第一骰的结果替代整条指令；没有配置任何结果回复时，保留原来的输出组织方式。

每个等级都可使用原生多条回复、权重、人格覆盖及嵌套 `{sample:…}`。例如奖励骰「成功」可设置：

```text
**{nick}** 的奖励骰检定：`{roll}/{rate}` **{level}**
{sample:好运站在你这边|这次抓住了机会}
```

通用变量包括 `{nick}`、`{attr}`、`{reason}`、`{roll}`、`{rate}`、`{level}`、`{res}`、`{result}`、`{outcome}`。`{result}` 是纯数字判定值；`{roll}` 是掷骰详情；`{res}` 保留所属指令原有含义。SAN 的 `{loss}/{final}`、成长的 `{change}/{final}` 等只在相应功能的编辑器中提供，不能放进跨指令共用的标准等级回复。自定义完整回复若要展示理由，应自行保留 `{reason}`。

预览使用所选等级的示例值，不执行真实骰点，也不发送消息。继承「指令原有文案」时，预览展示代表模板；实际仍根据理由、理智损失、成长是否变化等选择原有变体。

既有全局 / 人格文案及旧版导入项不会因为新增结果槽位而被覆盖；新槽位默认留空。不过这不代表旧版所有文案宏都已兼容，详见[旧版文案迁移边界](/guide/migration#自定义文案与帮助)。

## 旧版检定文本兼容

「COC → 旧版检定文本兼容」分别提供单轮等级短句与检定前缀；SAN 和成长条目内还有各自的旧版模板。**内置兼容默认值不自动启用**，保存覆盖或迁入旧文案后才使用，优先级为：

```text
本类等级完整回复 → 标准同等级完整回复 → 已设置的原生指令模板 → 已启用的旧版兼容模板 → 原生默认模板
```

旧版单轮短句只影响等级文字，多轮仍用原来的共享等级短句；普通原生模板中的 `{level}` 也会采用已设置的对应短句。连续多轮采用旧前缀时，只在第一条兼容输出前插入一次。暗检定仍只向私聊发送结果，群内保留简短回执。

纯文案条件宏支持嵌套：

```text
{grade:rank?2={strSuccess}&1={strFailure}&0={strFumble}}
{case:loss?0=没有理智损失&else=理智减少{change}，剩余{final}}
{sample:今天精神不错|{case:loss?0=松了口气&else=保持冷静}}
```

`case` 以字段字符串精确匹配，`grade` 选取不超过字段值的最大数值阈值；可用 `else=` 指定未命中分支。这里只执行文本选择，不执行脚本、等待、网络请求或文件操作。

旧版 SAN 槽中，`{res}` 是「掷骰详情 / SAN」，`{rank}` 依次为大失败 0、失败 1、成功 2、困难 3、极难 4、大成功 5；`{change}` 是同一次理智损失掷骰的详情，`{loss}/{final}` 是实际损失和剩余理智。这些旧含义只适用于兼容槽，**不会改变新 SAN 等级回复中 `{res}` 的数字含义**。成长兼容槽中的 `{res}` 保留旧版掷骰、技能值和等级描述。

`{strEnRoll}` 等已映射引用会在当前语言、人格下解析，也可明确写成 `{text:dice.compat.growth.base}`。引用保留动态关系，不复制固定文案；被引用的多条概率回复和嵌套 sample 仍在每次输出时选择。循环或过深引用有上限，不能把玩家昵称或理由中的内容当作宏再执行。

编辑器预览使用同一后端解析器，当前语言和人格也带入引用解析；继承旧槽时会按对应旧变量含义展示。模板解析及 Markdown / 纯文本转换仍在载入、保存时缓存。导入或历史修复报告见「备份与导入」，详见[迁移边界](/guide/migration#自定义文案与帮助)。

## 状态条与操作提示组件

内置文案、人格文案和高级回复共用两种语义组件。编辑器可直接插入示例，再把数值或文字替换成当前文案支持的变量：

```text
[[bar:HP|{hp}|{hpmax}]]
[[action:掷骰指令|.r]]
```

组件不是某个平台的 Markdown 片段。Dice!Next 会在变量替换后按当前展示方案渲染：传统方案保留简洁数据，标准方案使用常规强调，高级视觉方案生成字符状态条与操作提示。QQ 官方在具备 Markdown 与交互权限时，会把操作提示渲染成指令输入快捷项，点击后先填入点击者自己的输入框，不会立即执行；OneBot、Milky 或富消息失败时仍发送 `.r // 掷骰指令` 这类可读文字，不会自动生成图片。

高级视觉方案还会识别内置用法中的 `.指令 // 说明` 行。例如 `.bot on/off` 会分别生成 `on` 和 `off` 两个待选项，含 `<名字>`、`[参数]` 的用法会把光标停在待填写的位置。按钮只是帮助填写，最终仍由用户确认发送，原有权限检查不会绕过。

## 随机文案 `{sample:…}`

旧版 Dice! 的随机分项语法已随后续 Release 发布，beta.925 包含；build 909 及之前不支持。可在掷骰回复或人格文案中直接填写，例如编辑 `dice.roll.result`，保留原有变量并追加：

```text
{nick} 掷骰：{res}
{sample:效果拔群|干得漂亮}
```

每次渲染按分项等概率抽取一项，`sample:` 不会出现在结果中。不改变骰点或检定规则。候选项可以引用该文案原本支持的变量，也可嵌套：

```text
{sample:本次结果是 {res}|{sample:效果拔群|干得漂亮}}
```

支持纯文本和显式 Markdown 文案；只会处理被选中的分项。各项用半角 `|` 分隔，嵌套大括号内部的分隔符不拆成外层候选。自定义回复原有 `{甲|乙}` 简写保留；掷骰与人格文案请使用明确的 `{sample:甲|乙}`。

## 原生多条概率文案（已发布，build 926）

编辑掷骰回复或人格条目时，可用「添加回复」「删除此条」管理多个候选。每条单独填写正文和整数权重，旁边显示实际概率：权重 1、3 对应 25%、75%；0 暂停该条，至少一条必须大于 0。最多 256 条，候选正文合计最多 64 KiB。

每次只抽取一条候选，换行只是该条内部的换行。插入变量和设置变量样式针对当前候选；整个回复键使用同一种输出格式。

旧版 {sample:甲|乙} 不需改写。完整外层 sample 可通过「将外层 sample 转为等概率多条回复」展开，再调整各条权重；句子中间或内层 sample 不会被误拆。原生候选内也可继续嵌套 sample，例如选择 Markdown 格式，填写：

```text
**{nick}** 掷骰：`{res}`
{sample:效果拔群|{sample:干得漂亮|再接再厉}}
```

普通掷骰结果的 {res} 包含表达式与结果；各回复键只能使用编辑器列出的变量，不能把预览示例中的其他变量当作任意指令都支持的变量。

预览先按候选权重抽取，再解析其中的 sample，最后代入示例变量。点击「重新抽取预览」可查看另一个随机结果；一次预览的各传输表示共享同一次抽取。不发送真实消息，也不消耗游戏骰点。

保存时缓存每条候选的 Markdown / 纯文本版本，不在每次发送时重新转换整套文案。复制人格、导入导出和重启保留文本、权重及格式。需要同时升级本体与 WebUI；新版前端会拒绝向不支持的旧后端保存原生概率文案。

## 骰娘人格

一套**人格**是对上述回复文案的一组覆盖。启用人格时，人格中的同名条目优先于「默认（全局）」文案；人格没有改写的条目仍会回退到全局自定义文案或内置文案。切到某个人格后编辑文案，改动只保存到该人格；群或频道内用 [`.rpmode`](/use/fun) 切换人格即可整体换一套口吻。

- **人格下拉**：选「默认（全局）」编辑全局文案，或选某人格编辑其专属覆盖。选中人格时页面会提示「正在编辑人格『…』」。
- **人格管理**（按钮）：新建 / 复制 / 重命名 / 删除人格，或设为全局默认。内置人格不可删除。群详情的「功能管理」可以让单个群继承适配器或全局默认、明确关闭人格，或选用自己的覆盖人格。

点击本页顶部的「人格开放」，先选择机器人账号，再指定该账号的默认人格，以及用户通过 `.rpmode` 能看到和选择的人格范围：全部人格、仅选中的人格或禁止用户切换。选择「仅选中的人格」后，勾选要开放的人格并保存。设置按机器人账号分别保存；顶部用于编辑文案的人格下拉不会改变这里的账号设置。

账号默认人格与用户开放列表彼此独立，因此可以让机器人固定使用某个人格，同时只开放少量同角色人格，避免另一个机器人的角色意外出现在列表中。开放列表不会授予额外操作权限：群内切换仍需要群管理员、邀请人或骰主权限，私聊切换只影响当前用户。骰主仍可在后台为群绑定任意人格。编辑平台连接信息不会覆盖这里的设置。

聊天侧对应指令见[娱乐与互动 → 骰娘人格切换](/use/fun)。

### 随机多人格（已发布，build 926）

在「人格管理」打开「随机多人格」，启用多个候选人格，分别设置权重，再点击「保存人格概率」。基础回复也可作为候选，概率计算与原生多条文案相同。

一次指令先抽取一个人格，整个回复使用同一个人格；再由各回复键抽取文案和内层 sample。未改写的键仍回退到全局文案或内置文案。人格与文案抽取不使用游戏骰点随机源。

优先级保持为：私聊个人 / 群聊明确选择 → 账号默认人格 → 全局随机池 → 全局单人格。明确关闭人格仍然有效；.rpmode inherit 或群详情的「继承」可重新使用账号 / 全局策略。.rpmode 查询状态时显示随机多人格，不额外抽取。

配置重启后保留。切回单人格会清空全局随机池；删除人格时从池中移除，若最后一个正权重候选被删除，恢复单人格 / 基础回复，不保留全零概率池。

## 导入 / 导出

右上角 `导出` / `导入` 可备份或迁移全部自定义文案与人格覆盖，便于在多台部署间同步。
